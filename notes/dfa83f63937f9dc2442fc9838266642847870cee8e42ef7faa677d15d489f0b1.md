# Original Graph moves pair returned IDs with the input order

The original Graph move operation awaits each message request in input order and appends each replacement ID. The C++ receiver expects the same ordering and checks the ID/header counts before assigning IDs by index. A failure exits the original loop before its aggregate success callback; the scoped operation has no compensating move for an already completed prefix. Fixed accepted code later uses batching and selects resync fallback on a count mismatch. The imported batch response ordering and live partial-failure behavior were not validated.

Scope: Graph move result and Exchange listener contract.
