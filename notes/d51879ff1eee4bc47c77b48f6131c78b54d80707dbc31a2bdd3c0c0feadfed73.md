# Completed filter tests miss active-search selection

For D324852 at revision 3db8992b23246ea57cc7d8b38630fe8c7e32ebae, the AI review reports that QuickFilterBarHelpers.set_filter_text waits for all messages to load before returning. Assertions made afterward therefore do not cover selection and message display while later search hits arrive. The proposed regression scenario selects a visible result, supplies later hits above it in ascending order, and checks message identity and display before completion. It also checks that the outermost endUpdateBatch flushes pending redraw work. These are coverage proposals, not confirmed regressions: the reported local experiment checked message identity and invalidation, but not message display after user input during an active body search. The task was cancelled without recorded feedback.

Scope: Quick-filter active-search tests.
