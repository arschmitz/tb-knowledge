# Panorama folder counts retain server and pending-count semantics

With Panorama compiled and enabled, non-server count access refreshes folderInfo counts before adding pending counts. Deep traversal still excludes virtual folders. The new database did not initialize the old folder cache, which explains this scoped refresh. Fixed code uses a startup preference and a FolderInfo-to-MessageDatabase bridge. The same landing adds SQL indexes and initial settings, while current cache_size setup runs after every connection open. No count/restart/performance test ran.

Scope: Panorama legacy count bridge.
