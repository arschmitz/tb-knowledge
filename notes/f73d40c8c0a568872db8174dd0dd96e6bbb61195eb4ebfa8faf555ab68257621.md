# CMS EOF flushes a missing final newline through the decoded MIME callback

After sending a nonempty decoded CMS buffer successfully, MimeCMS_eof emits CRLF when its last byte is not LF, except for an LFCR ending. A lone CR does not match that exception. The bytes go through the MIME output callback and line buffer after decoder Finish; they do not modify the original CMS input or prove signature validity. Existing EOF ordering flushes earlier buffered input before crypto_eof, so this callback can produce a new final line later. A negative callback result follows existing error cleanup. The original was backed out; accepted source retains the flush within a later allowed-part gate.

Scope: CMS decoded-output line completion.
