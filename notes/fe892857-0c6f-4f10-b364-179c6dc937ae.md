# ICS parser separates worker parsing from item conversion and recurrence completion

Scope: production privileged parser/service JS and a module worker; public
interfaces and xpcshell tests. CalICSCalendar caller path is
calendar/providers/ics/CalICSCalendar.sys.mjs:429–456. Every local body in
CalIcsParser.sys.mjs, CalICSService.sys.mjs and CalICSService.worker.mjs was read.
The bundled ICAL grammar/backend is a separate imported source scope.

Parser constructor 30–36 owns arrays for items, parentless items, unhandled
components and properties. The public interface says create a parser per input.
The body appends rather than resets arrays on repeated parseString, so reuse does
not automatically discard prior results. Getters 177–191 return shallow array
copies, retaining the actual item/component/property objects.

parseString 131–157 has two entry paths. Without a listener, calls actual
cal.icsService.parseICS, processes root synchronously and logs caught errors
without returning a result or throwing them to the caller. With a listener,
calls parseICSAsync with an internal root-component listener. A successful code
starts component conversion; failure passes the status and this parser to the
external listener. parseFromStream 167–175 reads available bytes via NetUtil,
detects charset using MailStringUtils, converts bytes to string, then calls
parseString. Full NetUtil and charset behavior remains external.

CalICSService.parseICSAsync, 590–604, creates a new module ChromeWorker per input.
onmessage wraps returned jCal data in actual ICAL.Component and calIcalComponent,
then calls listener.onParsingComplete with written Cr.OK value. onerror logs
serialized input/error and reports NS_ERROR_FAILURE with null root. Posts the
input string. No returned operation, cancel handle, explicit handler removal or
terminate-on-error appears. Worker 10–17 imports the bundled library, sets
ICAL.design.strict=false, parses message data, posts result and closes itself
on success. A parse throw occurs before its explicit self.close; native worker
error lifetime remains unresolved. Worker completion is not yet item conversion.

processIcalComponent 42–129 accepts VCALENDAR root or walks VCALENDAR children
of an outer root. Retains top-level properties except VERSION/PRODID. Detects
Google Calendar product string and submits every subcomponent to parserState.
The state owns pending count, normal items, UID→recurring-parent map, recurrence
exceptions, unknown components and timezone warnings.

submit 263–320 converts VEVENT/ VTODO into actual CalEvent/CalTodo and attaches
the component; Google events call description repair. Checks event start/end or
task entry/due timezone. VTIMEZONE is omitted as a standalone extra component;
unknown components are retained. Recurrence-ID items enter exception list;
ordinary items enter main array, and only those with recurrenceInfo enter UID
parent map. With an async listener, each conversion is dispatched to the current
thread; otherwise runs directly. threadCount is a pending-conversion count,
not evidence of one native thread per item. No try/finally decrements on a
conversion throw; dispatched exceptions can leave join waiting.

join/checkCompletion 328–344 invokes join only when pending count reaches zero.
Join callback 78–128 attaches exceptions to found parent. Without one, creates
event/task master with same ID, DTSTART=recurrenceId, X-MOZ-FAKED-MASTER=1,
and new recurrence info; adds explicit recurrence date and records the original
parentless item, then installs exception. Appends results and calls external
listener with NS_OK. No promise resolves here; completion is that callback.
Join function is not cleared after call. There is no general once guard.

Actual caller ICS onParsingComplete ignores rc and adopts parser items without
awaiting returned promises before ending batch/loading/unlocking. Thus error
status, parser result accumulation and provider completion are separate contracts.
See the checked download/parse record for this caller; changing parser callbacks
can affect cache refill, imports and view notifications.

Direct tests: test_ics_parser.js:19–43 checks preserved property and unknown
component; 45–64 checks async BOGUS failure status and unsupported root emptiness;
66–100 checks fake master flag/date, recurrence occurrence and parentless identity;
102–139 checks two asynchronously converted tasks/dates; 145–221 checks sorted
serialization lines and stream round trips. test_timezone at 141–143 is an empty
TODO, not timezone-warning coverage. These checks do not establish every task
exception, callback-once, parser-reuse or cancellation branch.
