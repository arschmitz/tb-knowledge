# S/MIME detection reads the protocol parameter instead of its position

Entry2170 checks multipart/signed separately from EnigmailMime.getProtocol(contentType), avoiding the old requirement that protocol immediately follow the MIME type. Fixed getProtocol delegates to getParameter, which uses the parsed parameter map and returns an empty string when absent. The changed Boolean gate uses RegExp.test after a reviewer request; the author deferred the broader 36-site search refactor, so this does not establish that all sites changed. The full new dual-signed fixture and test were read. The historical test checks the body text, an S/MIME mismatch/notok icon and absence of an encrypted-ok icon; it does not establish a valid signature. The fixed test later expects no signed icon for mismatch, so that later icon behavior must not be attributed to the original landing. Reviewer-requested debug logs are absent from the landed test. Missing Bug 1878664 comments7/8 prevent a complete audit. No cryptographic verification, message render, test or linked predecessor source was executed/read beyond this scope.

Scope: OpenPGP and S/MIME MIME detection.
