# The OAuth override default permits customization but does not opt every account in

Turning experimental.mail.ews.overrideOAuth.enabled on exposes customization by default. OAuth2Module still requires customDetails.useCustomDetails before it selects the override path; otherwise it uses registered provider details. Unknown providers also require an issuer and scopes. UI visibility and a true default therefore do not prove that every provider or redirect flow authenticates. Later generic OAuth and Boolean-override handling are separate changes.

Scope: OAuth preference, account configuration and module initialization.
