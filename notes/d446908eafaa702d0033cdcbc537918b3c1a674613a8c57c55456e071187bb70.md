# First-run offline tests need their own policy state

The new offline-first-run fixture initializes InAppNotifications with forceOffline=true while policy acceptance is still absent. It directly expects empty notifications, empty seeds and a scheduled update timer. The other offline fixture sets policy acceptance to the current version before initialization. This isolates two startup states without treating an empty cache as permission to show bundled appeals. forceOffline bypasses automation suppression, not policy readiness. Existing cache-selection lessons cover the general gate; this finding adds the exact fixture and first-initialization contract. No startup or network run was performed.

Scope: Notification startup tests.
