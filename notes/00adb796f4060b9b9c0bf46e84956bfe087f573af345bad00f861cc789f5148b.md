# Exchange message channels fetch to the offline store before display

The original EWS channel in 605 fetched MIME directly; the fixed shared Exchange channel first checks HasMsgOffline. A stored message streams directly from the local store. An unstored message is fetched into that store, then read from it. MsgFetcher starts one message at a time, discards a failed output, and on success finishes the message before setting storeToken, offlineMessageSize and Offline. It does not set messageSize, which should already come from server synchronization. It stops the whole queued operation on an error. This explains why later message display depends on both the database header and local-store metadata. Current code explicitly leaves local-copy policy and tee streaming as TODOs; no cache-policy behavior beyond this source is claimed.

Scope: exchange.
