# EWS retry coordination retains an error token across the owner request loop

The initial EWS sender keeps an optional line token across retries. One failed runner holds it while handling early failure or waiting for a response backoff; other failed runners await its shared release future and retry without automatically becoming owners. Dropping the token releases the line, including when an error leaves the owner scope. The initial code sends before acquiring and is not a mutex around all network requests. Fixed accepted protocol_shared later adds a pre-send busy wait and uses an external line-token crate. Release signals completion of the owner scope, not proof that every request or authentication attempt succeeds.

Scope: rust-protocol-error-recovery.
