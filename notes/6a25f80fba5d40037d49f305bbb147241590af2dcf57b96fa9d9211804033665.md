# Keep global filter definitions separate from per-window controls

The available report explains that a global QuickFilterManager definition can already exist when a new tab or window binds its UI before the Experiment adds that window’s control. The landed guards skip absent nodes during binding and reflection. In post-processing, the model is updated before the missing-node guard, so presentation absence does not discard the new filter state. A reporter suggests calling bindUI later; this study did not execute that recovery. The accepted review describes temporary Experiment support while a public API is missing, not a stable API or a general guarantee for DOM patching. Existing source knowledge covers the three guards. Partial historical evidence: Bug 1885525comments2/3 unavailable; no new runtime validation.
