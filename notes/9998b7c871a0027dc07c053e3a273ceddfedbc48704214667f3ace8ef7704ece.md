# Omitting the compose-close prompt flag stops checking the save prompt

In close_compose_window, an omitted aShouldPrompt uses BrowserTestUtils.closeWindow and a tick. It does not assert that a save prompt appears. Explicit true installs a promiseAlertDialog handler before cmd_close; false closes through the command without that handler. Bug 1850192 removed the false argument from the reply-identity test when identity changes began marking the draft dirty. That adjustment relaxes the prompt expectation. It does not test the reported customized-From save prompt or save-and-reopen persistence. This helper contract is present in both the landing revision and the fixed accepted comparison. When testing that regression, choose a helper path that observes the prompt and separately check persisted identity. This is scoped test guidance from source, not a claim that the historical reviewer demanded a new test or a general ban on optional Boolean parameters.

Scope: compose-test-contracts.
