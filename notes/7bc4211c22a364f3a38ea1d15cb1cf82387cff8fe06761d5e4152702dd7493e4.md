# Appearance retained folder-open persistence after rejecting its removal

The Appearance work initially proposed storing folder flags only when the user changed them. Later in Bug 1829737, the author explicitly abandons that plan: DBViewWrapper relies on writing thread/sort/view state when opening a folder, and the attempted removal caused rendering problems in the author’s investigation. The adopted scope instead exposes defaults and provides separate all-folder or chosen-folder application. The assigned source and current commitViewState write the three persisted fields; current static tests separately keep an already-accessed folder unchanged when only the defaults change. Preserve the rejected strategy and the adopted scope as distinct historical decisions. This is not a general rule that folder-open persistence can never change, a new DBViewWrapper source audit or a reproduced rendering failure. Existing code/persistence lessons are reused; this note adds the explicit change-of-plan rationale. Partial historical evidence: Bug comments9/10/12/35 unavailable; no new runtime validation.

Scope: Historical Appearance design decision.
