# Check FCC conversion with an independent native expectation

Current checkComposeHeaders first asserts exactly one compose window, then reads its gMsgCompose.compFields. For each truthy expected MV3 FCC ID it splits the account ID from the path, finds the incoming server, and builds the expected URI from server.rootFolder.URI. Its comment explicitly avoids getFolder because that function is under test. It also checks nocopy:// for disabled FCC and an empty native fcc for reset. The IDL exposes fcc and fcc2 as AString; their C++ setters store the corresponding header strings. Supported test pattern: derive a conversion expectation independently from the helper being tested. This test checks compose state, not delivery or whether a sent copy actually exists.

Scope: mail/components/extensions.
