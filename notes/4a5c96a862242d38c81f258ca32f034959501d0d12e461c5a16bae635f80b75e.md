# The folder first-new header contract is nullable in the fixed accepted source

The July 2025 documentation patch described firstNewMessage as throwing when no new message exists. At fixed accepted revision 0b93f0f7a926ed94c8a0646f18b6734ec7cc0f6d, the IDL says null and GetFirstNewMessage initializes a null output, returns NS_OK for no database or no first-new key, and suppresses a failed header lookup. The database firstNew key itself remains nsMsgKey_None for an empty list. Keep the API level and revision explicit. No runtime test was run.

Scope: mailnews folder/database API.
