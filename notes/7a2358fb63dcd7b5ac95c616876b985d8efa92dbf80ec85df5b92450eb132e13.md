# Match the VerifyLogon comment to its actual EWS endpoint-URI return

Fixed C++ adapter still says there is no good non-null _retval value, while forwarding the caller output pointer to CheckConnectivity. Fixed EWS Rust bridge obtains client.url(), creates SafeUri, starts the asynchronous check and returns Ok(uri.into()). A focused comment correction should describe that endpoint return and later listener result. The comment is stale; this study does not claim the C++ path actually leaves the outparam unset. Other Exchange protocol implementations are not audited here.

Scope: EWS connectivity result/return and ConfigVerifier contract.
