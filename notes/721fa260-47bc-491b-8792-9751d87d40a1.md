# Keep runtime null checks at public message database interfaces

In D209891, one reviewer proposed MOZ_ASSERT for null arguments that seemed impossible. Another reviewer said public interfaces should keep NS_ENSURE_ARG_POINTER so bad callers get a runtime error, and the author avoided changing unknown call contracts in a cleanup. The accepted DeleteHeader implementation uses NS_ENSURE_ARG_POINTER(msg). The review also removed old checks after ordinary Mozilla new, which is infallible in this environment; those allocation checks did not serve the same caller-validation role. Preserve the distinction when cleaning legacy C++.

Scope: Message database review practice.
