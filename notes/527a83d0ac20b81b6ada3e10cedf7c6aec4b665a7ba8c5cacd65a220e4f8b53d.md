# Scrolling uses the immediate row-fill path without removing deferred index updates

The scroll handler passes true to the visible-row helper; ordinary calls keep fillImmediately=false. All visible-row insertion paths carry that flag to _addRowAtIndex. Assigning row.index still schedules a frame, and the immediate fill cancels that pending callback before filling the row. This scopes the exception to new rows added for scrolling. Existing coalesced-index and subclass-cancellation lessons still apply. The author expected better scrolling, but the reviewer deferred ESR 140 uplift pending profiling; no measured improvement is available.

Scope: Tree-view visible-row scheduling.
