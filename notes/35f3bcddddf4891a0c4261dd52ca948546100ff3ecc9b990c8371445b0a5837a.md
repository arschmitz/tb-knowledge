# Let the Windows application picker control its resize behavior

The Windows handler-picker subdialog no longer receives resizable=no. Its closing callback still accepts params.handlerApp, adds that handler, and rebuilds the menu. The non-Windows file-picker route remains separate. For this dialog call site, do not restore a fixed-size feature merely to match another picker. The source proves the removed restriction, not that every long application name, zoom level or native window size was visually checked. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Application picker dialog scope.
