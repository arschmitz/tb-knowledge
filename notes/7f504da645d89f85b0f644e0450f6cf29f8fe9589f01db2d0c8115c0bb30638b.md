# Keep new-folder dialog enablement tied to name and parent selection

Current newFolderDialog registers the input handler and reevaluates acceptance after folder selection. doEnabling disables the button for an empty name, no selected parent or an existing same-name child. This is newer than the landing-era input-only closure. Keep the named handler and both inputs when changing dialog state; dialog accept invokes the async callback without awaiting it, so closing the dialog is not completion of metadata inheritance. These are fixed accepted source and test-code observations. Full Bugzilla and historical review timeline/inline discussion remain pending.
