# The shared extension account fixture resolves readiness through one async contract

createAccount is async for all protocol branches after EWS introduced synchronization work. Its EWS branch awaits the folder readiness condition before returning the account, while immediate branches still resolve through the same promise contract. The changed callers await creation before using server/account state, and the extension message handler becomes async before adding the identity and returning the key. The EWS default wrapper returns that promise. This is ordered fixture setup across these xpcshell tests; it does not authorize parallel test steps or prove a test pass. Shared server startup and folder-order assumptions remain bounded dependencies.

Scope: WebExtension xpcshell fixture completion.
