# The no-sync-token fixture both hides sync-collection support and rejects that report

The new CalDAV fixture switch has two effects: it omits sync-collection from supported-report-set and returns HTTP400 for an attempted sync-collection report. The browser test disables the switch before creating a cached calendar, then reuses alarm and server-change scenarios and waits for pending sync to end. Accepted provider code selects WebDAV sync only when that report is supported; otherwise it builds a Depth1 etag PROPFIND. The test has no direct HTTP400 or request-count assertion, so the safeguard is not an independently verified rejection scenario. Cleanup restores the switch after its retained 1000 ms delay. No browser test or real-server synchronization ran.

Scope: Calendar CalDAV legacy-sync browser fixture.
