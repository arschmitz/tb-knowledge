# Search startup, observer readiness and extension setup have separate completion boundaries

The port changes comm consumers to an imported SearchService without merging their completion contracts. Delayed startup calls init without awaiting it. The shared extension readiness getter resolves for an initialized service or waits for init-complete; the getter does not start initialization. Default-provider setup awaits that readiness, while its manifest handler deliberately does not await the whole registration task. openWebSearch returns init/default lookup and dispatches an external URI request, not browser-navigation completion. The upstream service implementation and runtime outcomes remain unverified.

Scope: Thunderbird search-service consumer initialization.
