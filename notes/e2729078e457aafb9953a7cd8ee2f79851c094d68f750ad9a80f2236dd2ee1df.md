# Address Book forced-color styling pairs the content preference with state tokens

Fresh full11-file416-line human preference/CSS/markup patch read. These Address Book/shared form/tree/list components switch their color-override branches from prefers-contrast to forced-colors, use system Canvas/CanvasText/SelectedItem state colors, and add browser.display.document_color_use=0 to enable in-content high-contrast overrides on Mac/Linux as described by the author/reviewer. The code is a coordinated local component change, not a declaration that contrast preference and forced-color mode are globally interchangeable. Fixed default remains0 and Address Book imports the shared list-container and token sheets. The fixed list root keeps separate forced/non-forced token branches and a Canvas border, but later source has changed indicator/hover rules; the exact historical foreground/dimensions are not asserted as unchanged current code. Current shared common.css also retains distinct forced-color accent tokens. No tests change in this patch, and the author reports no automated coverage. Main Bug comment1 remains unavailable; this is public source-only knowledge with zero full-audit credit. No native high-contrast or accessibility test ran.

Scope: Address Book forced-color preference and stylesheet scope.
