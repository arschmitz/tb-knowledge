# Keep message-update event coverage tied to its actual notification routes

The old/new message property event was built on a folder notification service to avoid registering a database listener on every folder. This patch deliberately reports junk changes from the UI and SetJunkScoreForMessages filter route. Other direct database writers are not proven covered: the author describes their parsing-only role as current understanding and proposes centralized junk updates as later work. Preserve the explicit route limit when consuming this event; a new oldProperties bag is not a complete database before-image. Static source and historical review evidence only; no new runtime validation.

Scope: extension message updates.
