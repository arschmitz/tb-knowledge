# The original threaded rebuild notifies after construction but does not expose completion through sortBy

The owned threaded rebuild first clears its row map and reports removal, then awaits conversation selection. It constructs rows in a user-blocking scheduler task and yields every 250 rows when that API exists, with a direct async callback for the test environment. Final row-count addition follows construction. The original sortBy invokes this async helper without returning or awaiting it, so that caller's return does not mean rows are ready. The fixed accepted adapter later uses a shared awaited date sort; the private rebuild is a historical phase. No responsiveness or ordering race was reproduced.

Scope: Panorama threaded row rebuild completion.
