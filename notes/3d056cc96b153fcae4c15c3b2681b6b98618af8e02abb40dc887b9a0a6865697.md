# Handle nullable aggregate-header allocation at the parser callers

In the corrected September2024 parser reland, GetNextHeaderInAggregate can return nullptr. Both To and Cc branches in ParseHeaders detect that result and return NS_ERROR_OUT_OF_MEMORY before using the header. The initial helper-only guard left callers able to continue; the review explicitly required propagation. This is a historical parser contract. The fixed accepted checkout instead uses value objects and caller-owned aggregate strings; do not copy an obsolete allocation API into new code. No new failure-injection or crash test ran.

Scope: Mail header allocation error propagation.
