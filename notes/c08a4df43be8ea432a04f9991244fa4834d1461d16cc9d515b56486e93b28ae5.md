# Single-folder Exchange APIs keep fallback child and message arrays separate

DeleteFolder and EmptyFolder now accept one target folderId through XPIDL. EmptyFolder still carries separate subfolderIds and messageIds for an older-server fallback. EWS wraps the single target in a one-element internal vector for normal operations but can use multiple child IDs in the fallback. The shared EraseFolder trait remains, so its proposed removal was not adopted. The IDL’s fallback descriptions still say folderIds, a removed parameter name; they should identify the single target and the separate child/message arrays. This is an API/data-role distinction, not a global rule against vectors or proof that a server recursively deleted anything.

Scope: mailnews/protocols/exchange.
