# Retry short synchronous writes using the returned byte count

Entry2185 adds SyncWriteAll because one output-stream Write may consume only part of a message. The helper keeps writing, decreases count by the actual n bytes and advances data by n; it returns a Write error immediately. The fixed implementation retains this loop. This supports short positive writes, but the helper has no explicit successful-zero-progress check, and no new helper test or stream execution was performed.

Scope: Local message batch storage.
