# Require a message for every assertion

Every assertion must have a non-empty message that states the expected behavior.
This rule applies to all assertion writing, including examples and local
experiments, and every review, self-review, verification, and repair flow.
Check the actual assertion API and message argument, including shared helpers.
Report missing or empty messages within review scope, including other authors'
patches. A nearby comment or test name does not replace the assertion message.
Keep unrelated assertions outside the requested change unchanged.

## Authority and scope

On October 19, 2026, the user requested: "The knowledge repo and review flows of
all sorts as well as any writing should enforce that all assertions have a message".
This is deliberate instruction authority, not an automatically learned convention.
Automatic learning must not change this rule.

The existing requirement to include "should" when writing or self-reviewing test
messages still applies. Do not report the absence of "should" alone as a defect
in another author's patch. A missing message is a separate review finding.
This supplements the [comment-writing guide](81596887-76aa-4804-932a-d01b73042690.md)
and [code-style guide](08ac54d5-331d-4ab5-bc8f-6120318565a3.md).

## Validation and limits

The rule is supplied directly through shared and local agent instructions,
standalone workflow style references, and console turn instructions. Focused
console tests passed for initial and steered turns with retrieval disabled.
These instructions require the check; they are not a static assertion linter.
A running console backend must load the changed modules to supply the new text.
