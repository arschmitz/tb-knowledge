# The unreferenced-related ZIP task uses attachment size as a content proxy

The first browser task asserts two attachment names, a size of 22 for each empty ZIP, and a false isEmpty result. It does not compare full payload bytes or invoke Open/Save. AttachmentInfo.isEmpty can return size<1 when sizeResolved is already true, so the nonempty assertion need not perform a new attachment fetch. Keep the test comment’s explicit size-as-proxy limit when describing this coverage. Static inspection only; required primary context remains partial.

Scope: Attachment browser regression coverage.
