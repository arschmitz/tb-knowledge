# A missing IMAP UNSEEN count skips the delta block while preserving summary work

The original guard records numUnread != -1 before replacing an absent server UNSEEN value with the cached unread count. It gates pending-unread delta and new-mail state updates, while preserving later summary/count work. The accepted protocol uses NOOP for the selected folder and its mailbox-spec builder writes -1 for that case; named-mailbox STATUS data supplies the unseen count. Later accepted folder code also defers unselected-folder biff until flags synchronize, which is a separate phase. This source contract explains why a missing-count whole-function early return would be wrong; it does not prove that all repeated notifications or concurrent-session races are fixed.

Scope: IMAP folder-status count and biff state.
