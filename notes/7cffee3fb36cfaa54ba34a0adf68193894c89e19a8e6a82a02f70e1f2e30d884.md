# Missing HTTP security info preserves the original request failure

When the channel security-info getter has a null output, getter_addrefs reports Err(NS_OK). The request code treats that as absent security info and returns the original failed-request status. It only constructs TransportSecurityFailure when security info exists and the NSS error service classifies its error code. Keep the getter outcome separate from the original connection failure; NS_OK here does not mean the HTTP request succeeded. Static call-site inspection only; no transport or NSS runtime test ran.

Scope: Rust HTTP transport error classification.
