# The classless-folder fixture changes after the mock-server move

The original RemoteFolder constructor assigns a fifth argument with IPF.Note default. Its classless test passes null, and the fake server omits FolderClass for a falsey value. The test waits for callbacks and checks the complete created-ID sequence, but its deep assertion has no message. At the accepted revision the test imports RemoteFolder from MockServer; that constructor has four parameters and no folderClass assignment, while the test still passes a fifth null and EwsServer still checks folder.folderClass. Keep the original default-versus-null scenario separate from this later fixture drift. A current fifth null argument does not establish a configurable folder class. No runtime failure or server compatibility result is reproduced.

Scope: EWS folder-class fixture constructor and assertion phases.
