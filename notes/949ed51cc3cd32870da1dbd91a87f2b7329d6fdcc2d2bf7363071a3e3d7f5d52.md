# Describe canonical IMAP paths separately from server delimiters

The possibleImapMailbox interface accepts a canonical path that always uses slash separators, plus the actual server hierarchy delimiter. The current implementation discovers or creates folders, converts the canonical path into an online name, and reports whether the folder is new. Its caller uses that new-folder result for ACL discovery. Manual documentation proposal for this interface: state the input representation, the separate server value, side effects and the return meaning. A boolean method name that sounds like validation is not proof of a pure predicate. The inspected mailbox tests cover discovery and Unicode renaming; they do not establish a matrix of non-slash server delimiters.

Scope: mailnews/imap.
