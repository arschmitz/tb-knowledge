# Correct the historical scope of QR export ASCII identity filtering

Correction to lesson 7493ed9cd6bf7f109fc988957bb5032a1a350fc6c75ae768a4b9fd6964f9d840: entry1084, commit d407a7880a9bd663ec4a6e8113aae4da5e9a4840, adds the ASCII email predicate to identities serialized by QRExport.getAccountData. The ASCII guard on account.defaultIdentity in getEligibleAccounts already exists in the direct parent 473cfca5e2b71e3b3d9e833441a9f4f45c2bd5f2, lines86–90. This landing extends filtering to the identity list, including secondary identities; it does not introduce the default-account eligibility guard. At accepted revision0b93f0f7a926ed94c8a0646f18b6734ec7cc0f6d both guards remain. The correction changes the historical attribution, not the current combined behavior. Display names remain serialized. The predicate is not a complete email syntax validator. Exact parent source, the full two-file landing diff, and accepted source windows were read. No tests or Android import were run. The old immutable record is preserved; this is a source-fact correction, not a change to deliberate guidance.

Scope: mail/modules/QRExport.sys.mjs.
