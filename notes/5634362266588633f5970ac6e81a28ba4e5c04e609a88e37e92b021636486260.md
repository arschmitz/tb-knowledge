# Select Panorama through build support and startup registration, including test startup

Entry 2113 separates building Panorama from using it: MOZ_PANORAMA controls build inclusion and mail.panorama.enabled selects the database. Its MailGlue factory overrides the msgDBService contract; xpcshell duplicates the override because it does not run MailGlue. Entry 2115 starts the database during account-manager initialization, changes startup to synchronous nsresult and removes the explicit startup await from tests. The fixed accepted account manager owns registration and startup under the compiled flag and startup preference; current test head triggers that same owner by accessing MailServices.accounts after preparing preferences and the database. Use that startup path when testing this integration rather than copying an obsolete MailGlue shim or calling startup twice. Startup now rejects an already-open connection. Existing shared knowledge covers singleton accessors and the stale promise comment. No startup, build-flag matrix, migration, failure or shutdown test ran. Full discussion is pending.

Scope: Panorama database service registration.
