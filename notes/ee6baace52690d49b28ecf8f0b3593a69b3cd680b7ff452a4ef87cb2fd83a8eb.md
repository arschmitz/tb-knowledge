# Selected-mailbox getters have different ownership contracts

The public Git diff for 2169 adds a mutex around selected-mailbox replacement, reset and selected reads/copies. The header explicitly limits researched protection to fSelectedMailboxName, not all parser members. A locked raw-pointer getter still returns a borrowed pointer after the local guard ends. Fixed source explicitly restricts that raw getter to the IMAP thread and also provides an nsACString overload that copies while locked; nsImapProtocol::GetSelectedMailboxName uses that owned-copy overload before creating the returned C string. CreateCurrentMailboxSpec takes the selected pointer under a short guard and uses it later in the same method; its complete thread/lifetime preconditions and every caller were not audited. These public source facts do not prove a new race, all-parser thread safety or a universal lock pattern. Restricted Bug 1954407 and D241857 were unavailable, so no discussion acceptance is inferred, no private scenario is reproduced, and full-audit credit is zero. No thread sanitizer, IMAP or native test ran.

Scope: IMAP selected-mailbox ownership.
