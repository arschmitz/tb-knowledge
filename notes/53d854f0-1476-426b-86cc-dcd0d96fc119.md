# Calendar HTTP preparation and certificate exception callbacks retain actual owners and receivers

Production privileged JavaScript. All local bodies of prepHttpChannel,
sendHttpRequest, InterfaceRequestor_getInterface, BadCertHandler and
checkBadCertStatus were read, calProviderUtils.sys.mjs:44–309.
Native HTTP/principal/certificate dialog receivers are separate scopes.

prepHttpChannel chooses origin userContextId from Calendar auth containerMap:
force-new auth uses a fresh UUID, otherwise an actual calendar interface with
capabilities.username.supported=true supplies username. Existing channel skips
this selection unless force-new flag branch is taken; selected attributes do not
recreate an existing channel. Creates a content principal for a new channel,
sets Accept XML/UTF-8 headers, bypasses cache, installs supplied callbacks.
Stream upload seeks an nsISeekableStream to start; string input becomes UTF-8
string stream; setUploadStream receives content type and unknown length.
Returns prepared channel without opening. sendHttpRequest initializes loader
observer and calls asyncOpen; it has no completion promise or catch.

This differs from ICS's main download/upload channel, which uses system principal
at 324–331,586–593. ICS's ETag PROPFIND fallback uses prepHttpChannel at 1202–1214.
Do not apply the container-isolation claim to every calendar request merely
because the helper exists. The actual call's arguments and principal decide it.
test_multiple_usernames is a possible additional test link from symbol discovery;
its whole assertion/body-to-helper connection was not verified in this pass.

InterfaceRequestor_getInterface first calls the actual receiver QueryInterface.
If it throws, nsIAuthPrompt2 lazily owns cal.auth.Prompt(this); prompt provider or
nsIPrompt returns a new window prompter; otherwise rethrows. Lifetime is tied to
receiver/calAuthPrompt; no release/reset method appears in this helper.

checkBadCertStatus uses NSS error classification and ignores classification throws
for non-certificate codes. For bad cert with securityInfo, creates BadCertHandler
and calls notifyCertProblem with transport security info and originalURI.
Handler owns calendar and one-shot zero-delay timer. Static reported Map records
host:port and suppresses another opening within five seconds.

Timer callback opens actual chrome://pippki/content/exceptionDialog.xhtml with
securityInfo/location and exceptionAdded=false. Registers domwindowclosed observer;
only exact returned dialog subject removes observer and resolves deferred promise.
After close, an added exception records telemetry with protocol/port/error and
refreshes calendar when allowed, then removes host:port from Map. No finally
guarantees observer/Map cleanup if opening, wait continuation, telemetry or refresh
throws. Owner/callback identities and removal condition are observed. Whole native
window close, certificate override and telemetry behavior are not inferred solely
from these names. No direct runtime certificate-dialog test was established here.
