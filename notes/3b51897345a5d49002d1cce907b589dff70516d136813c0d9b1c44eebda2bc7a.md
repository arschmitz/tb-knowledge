# A loaded about:addons page is separate from a loaded extension options context

The historical getContexts test first waited for about:addons through a new tab helper, then separately waited for the extension options-loaded message before checking its TAB context. The accepted later test avoids pre-opening the manager because its comment reports overlapping initial and options loads. It also includes the options documentId. The helper closes only after a successful callback, so it is not evidence of cleanup on rejection. The URL assertion alone does not prove focus. No test ran.

Scope: extensions/runtime-getContexts-options-test.
