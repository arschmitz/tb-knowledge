# Keep IMAP folder storage paths separate from summary database paths

CreateFileForDB retains .msf on its output. CreateClientSubfolderInfo and RenameClient clone/strip that suffix into a separate folderPath for AddSubfolderWithPath while passing dbFile to OpenDBFromFile. Proposed scoped naming rule: use folderPath and dbFile/dbPath according to these roles, and keep declarations and definitions aligned. The old misleading dbPath parameter is historical, not a naming precedent for new code. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: IMAP folder versus database path naming.
