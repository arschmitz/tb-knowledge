# Header-only message reads stop at the separator but finish through the stream listener

messages.getHeaders requests bodyFormat none, returns the first header block and selects raw or decoded conversion without inventing a missing Content-Type. The processor still uses the MIME header parser. In the normal streaming branch, a three-character carry detects a separator across chunks. The listener stores only new header bytes, requests cancellation and keeps consuming later chunks. onStopRequest resolves the message even with an abort status after the header boundary was found; onDataAvailable does not resolve it. Cancellation failure is caught, and attached-message extraction follows a separate parent-message path. The new tests compare complete header dictionaries in three decoding modes. They do not force split boundaries, prove cancellation support or measure speed.

Scope: mail/extensions/messages/headers.
