# The PKCE fixture consumes state challenges and authorization codes once

The owned fixture replaces its authorization-code Set with single-use maps. A challenge is recorded under state, consumed when a code is created, then consumed again by code during token exchange. The token branch checks for a verifier and compares the resulting S256 challenge. Both production and fixture call CryptoUtils.sha256Base64, so this checks integration agreement rather than independent hash correctness. The test issuers now require PKCE; non-PKCE fixture coverage is no longer provided. Refresh-token handling is a separate branch, and no test ran.

Scope: OAuth2 test fixture PKCE state and code contract.
