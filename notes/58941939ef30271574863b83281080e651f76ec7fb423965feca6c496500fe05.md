# Exchange service comments still describe removed parameters and obsolete private declarations

The current FetchMessage declaration has only uri and streamListener, but its comment says the query is ignored unless aConvert is true. Conversion is now chosen by the channel spec. The same header still declares GetMessageContent and DownloadMessage, while the inspected full service implementation has no definitions for those old paths. Scoped documentation/cleanup recommendation: align this header with the real channel route before teaching callers to pass nonexistent parameters. No link or compiler failure was reproduced. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.
