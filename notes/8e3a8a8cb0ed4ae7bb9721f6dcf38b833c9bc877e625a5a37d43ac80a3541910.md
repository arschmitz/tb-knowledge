# Compaction documentation must preserve late-failure and listener-lifetime limits

MboxCompactor.h says any error leaves the mbox untouched and uses .temp-compact in its walkthrough. Current path setup uses .compact-temp, and a failed final install can leave the original moved aside for recovery. The IDL still says the listener is released after onCompactionComplete even though the implementation must call onFinalSummary afterward and the higher-level comments now name that final boundary. Scoped documentation recommendation: update these statements to the actual phase, path and recovery limits; do not replace them with an unverified universal rollback guarantee. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mbox compaction phase documentation limits.
