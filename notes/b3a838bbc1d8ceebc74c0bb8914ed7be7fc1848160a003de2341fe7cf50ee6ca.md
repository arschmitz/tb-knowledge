# Route Exchange file-copy startup failure through the operation completion owner

Accepted CopyFileMessage calls handler->OnCopyCompleted when StartCopyingNextMessage fails. The public handler method completes the whole operation and routes listener and dequeue work through the global copy service. Existing corrected knowledge covers that shared queue owner. Keep the startup-failure route when changing this entry point; beginning the operation does not prove that an asynchronous callback will finish a failed start. Other callback-time early returns are separate untested failure routes. This is a scoped manual recommendation from static source. No copy, failure, queue, runtime, build or lint test ran. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange copy completion and dequeue.
