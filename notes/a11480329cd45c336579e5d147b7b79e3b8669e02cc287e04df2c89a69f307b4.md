# Await notification test cleanup before replacing retry state

Proposed test cleanup change: await clear() at the start of test_progressiveRetry and restore the original _fallbackIntervals after using short intervals. The current clear helper yields before clearing state; this test invokes it without await, then changes getExpirationTime, _fallbackIntervals and _schedule. The inspected global cleanup awaits clear but does not restore _fallbackIntervals. This is a static ordering and isolation concern, not a reproduced intermittent failure. Inspect later tasks before choosing the smallest repair. The current reset helper clears failure count, update history and a pending timer; it does not restore the replaced interval array. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.
