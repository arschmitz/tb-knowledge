# Route XMPP CDATA through the same text-node path as ordinary text

XMPPParser guards both ontext and oncdata after a SAX parser error and passes both to characters. characters appends text to the current XML node; addText joins adjacent TextNode content. getXML escapes text when serializing, while the debug convertToString is deliberately unencoded. CDATA content therefore stays text rather than becoming nested XML. Do not confuse the debug form with the encoded XML boundary or infer an entire rendering-security audit from this parser change. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: XMPP CDATA text handling.
