# The calendar reconstruction fixture loads registry preferences before its task

The new separately registered browser manifest defines three storage calendars, their default/composite/color fields and a sort preference containing only two IDs. The task checks restored objects and visible list state instead of creating its calendars itself. It also checks order repair and default selection. Many new individual assertions omit message arguments, including the per-property helper and the added disabled-button check in the older task. Those missing diagnostics remain a source-quality limit; no runtime result is inferred.

Scope: Calendar browser startup fixture and diagnostics.
