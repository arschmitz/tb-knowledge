# Calendar password prompts serve concurrent requests

Calendar password prompts serve concurrent requests. The old 60-second record was shared by a provider, so one request's `PREVIOUS_FAILED` could remove a replacement login supplied to another. The fix records `{key, password}` by request `loadInfo` in a `WeakMap`, because an auth retry may use a new channel but keeps that load info. It removes only the same password that this request received and the server rejected. Tests cover two requests and a saved replacement. https://phabricator.services.mozilla.com/D319397 and https://github.com/thunderbird/thunderbird-desktop/commit/2fdf9b286f5e4ff85e373defa4413f0e50b83340

Scope: calendar.
