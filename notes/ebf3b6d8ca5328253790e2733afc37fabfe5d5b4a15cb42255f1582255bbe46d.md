# Document destructured option properties and their actual object types

668 corrects the callback parameter to options.updateAttachmentsDisplayFn and open to a required BrowsingContext object, not an optional integer browsingContextId. Current constructor documentation also marks options.message optional and types it nsIMsgDBHdr. The current open implementation reads browsingContext.topChromeWindow, and its menu caller passes aboutMessage.browsingContext. Proposed manual documentation rule: trace the destructured property path and the actual consumer before approving a type, optional marker or parameter rename. Type-first JSDoc punctuation itself is lint scope and is not a new manual rule.

Scope: Attachment API documentation contracts.
