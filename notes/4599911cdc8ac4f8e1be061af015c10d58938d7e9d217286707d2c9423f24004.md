# Compute QR OAuth usage separately for incoming and outgoing servers

1029 adds getAccountOAuthUsage returning independent incoming and outgoing booleans; its unit test covers password-only, each mixed direction and OAuth on both. The accepted helper now also falls back to the default outgoing server when the identity has no smtpServerKey, matching getAccountData's current resolution. The UI must reason about both servers an account exports. The default-server refinement is current context, not a later bug fully studied here.

Scope: QR export server authentication matrix.
