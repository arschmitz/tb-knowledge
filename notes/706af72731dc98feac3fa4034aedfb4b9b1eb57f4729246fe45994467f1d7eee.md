# Treat attachment save as a browsing-context and cancellation contract

The current save method accepts a BrowsingContext, passes it to the native file picker, sanitizes the default filename, tolerates an unset last-directory preference and returns null on cancellation. After a successful save it dispatches attachmentSaved and returns the path. Save failure offers a new picker attempt. Keep these distinct outcomes when replacing the removed native saveAttachment entrypoint. No file picker was run. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mail attachment saving.
