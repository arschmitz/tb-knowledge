# Gecko promise-worker controller owns pending jobs, reply values, transfers and termination

Full privileged controller module483 lines read. BasePromiseWorker:115–174 stores
URL/options/main-thread functions, inherited exception decoders and per-instance
deferred job Map/counter. _worker:193–304 lazily creates actual ChromeWorker,
records launch time and installs onerror/onmessage closures retaining controller.
No worker exists until first post. onerror prevents default, rejects all current
jobs and clears Map/closure references. It does not itself terminate/delete worker.

post:323–425 waits for promised args/transfers, unwraps actual Meta objects,
allocates ThreadToWorker-N ID and posts {fun,args,id}. It then retains deferred,
closure and ID until reply. Numeric posting errors become Components.Exception;
other posting errors rethrow before retaining a job. A caller-supplied closure
holds objects alive until response/error/termination; args with delayed promises
can change request-post ordering relative to call ordering.

onmessage:232–300 routes reverse calls through actual _functions map; a returned
promise rejection sends fail, and Meta sends data/transfers. A synchronous main
function throw occurs before Promise.resolve wraps its result; that route has
no surrounding catch in this body. Reverse callback error settlement therefore
needs its own test rather than inference from the declared async-capable API.
For normal reply ID, ok resolves the envelope and fail rejects WorkerError, then
deletes job. Missing both fields deletes job without settling it; unexpected ID
throws. These are explicit protocol-invalid boundaries, not ordinary success.

post catches serialized WorkerError through actual decoder and ErrorEvent into
Error, returns reply.ok and optionally accumulates nonnegative worker duration
in last argument's outExecutionDuration. Returning reply.ok means completed worker
dispatch, not unrelated provider/cache/UI operation completion. terminate:433–456
terminates native worker, deletes pointer if successful, rejects all pending jobs
with worker-terminated Error and clears Map. A later post lazily starts a new worker.
If native terminate throws, logging occurs before Map cleanup; pointer remains.

Direct test_Promise tasks check simple/no/promised/delayed/rejected args, buffer
detachment plus exact result bytes, Meta transfers, error message, two pending
job rejections on terminate, new worker identity and bidirectional callback data.
Cleanup directly asserts Map size0. It does not directly verify native thread
destruction, synchronous reverse-call throws or every malformed protocol case.
ESM test checks module worker bounce. Both ran PASS in the recorded older build.
Thunderbird DNS.lookup is an actual consumer of post('execute'), not a same-name link.
