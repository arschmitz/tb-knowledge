# storeObserver subscription ownership and Calendar disconnect limits

All local bodies in `store.mjs` and the full `test_state_store.js` were read.
The store injects a root reducer and listener middleware; it disables Redux
developer tools. Imported Redux implementation is a separate file role and scope.

`storeObserver`, lines 35–133, returns a class extending the supplied class.
Its constructor forwards arguments, retains selectors, and subscribes an arrow
closure that reads the instance. Thus the store subscription can retain the
instance regardless of whether its DOM node is connected. `applyInitialState`
starts the first comparison after the subclass is ready. `#stateChange` reads
each selector, skips strict identity equality, caches a changed value before
calling the subclass hook, and supplies name/old/new values. A hook can throw;
there is no per-selector catch in this body.

The base hook throws until overridden. `selectValue(fieldName, ...args)` receives
an array even when no extra arguments are supplied, so `if (!args)` is never the
normal no-argument branch; it calls the selector on current state. Do not infer
cached-value retrieval from that branch's comment alone. `dispatch` forwards an
action but does not return `store.dispatch`'s value. `dispose` calls the retained
unsubscribe callback. There is no constructor re-subscription on DOM reconnect,
automatic disconnected callback, or local guard around repeated disposal.

The actual Calendar mixin extends `storeObserver(superClass)`,
`calendar-event-dialog-source-mixin.mjs:109–188`, and passes a selector closed
over its fixed session key. Its `disconnectedCallback`, 211–218, disconnects
the route controller and clears route state. That method does not call `dispose`.
The read create/edit class and positioned-dialog base likewise do not show a
dispose call. Closing and route clearing are therefore not proven subscription
release paths. Reused dialogs can intentionally retain their subscription for
their owning window; removal, window destruction, and final release need an
owner-specific lifetime check. This is not a measured leak report.

Direct test checks: `test_rootReducer` checks injection availability; `test_store`
checks the initial store interface/state; `test_storeObserver` constructs an
actual subclass, verifies base argument forwarding, initial and changed hook
arguments/call counts, and selector values. It invokes `dispose` at the end but
does not dispatch afterward to assert absence of callbacks. It does not directly
test Calendar disconnect, reconnect, argument-bearing selectors, unchanged
identity suppression, thrown hooks, or object collection.

This adds the store ownership that remained unresolved in the earlier
[listener note](9926c9e6-c286-41ca-814d-2942d230a1c2.md). The route-controller and
window-resize listener have separate owners and release mechanisms.
