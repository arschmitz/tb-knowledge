# forceOffline controls the first notification initialization in automation

Fresh full five-file patch and every changed test hunk read. InAppNotifications.init(forceOffline) suppresses bundled defaults in automation unless explicitly forced, inside the existing loadFromCache and empty-notification/no-cache gates. Its early _jsonFile return means forceOffline affects first initialization, not reinitialization. The dedicated offline fixture calls init(true); the ordinary fixture keeps init(). Marionette defaults disable the feature separately. Fixed source adds readyToUpdate and skipCleanup behavior already covered by existing focused lessons. Full review history includes acceptance and later criticism. Broader MailGlue bypass, calling init(true) in the ordinary file, and relocating the misleading no-builtins test were proposed later; this landing does not apply those alternatives. The suggested optional-default JSDoc syntax is also absent from the landing and fixed signature. Human unfamiliarity, assumptions about moved tests and later uplift/failure reports are preserved, without claiming runtime verification.

Scope: In-app notification offline test initialization.
