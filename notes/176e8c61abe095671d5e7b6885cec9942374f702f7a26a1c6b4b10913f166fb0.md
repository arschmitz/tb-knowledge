# Keep the local UTF-8 path conversion separate from URL escaping

The 1960372 repair gets the server local path through nsIFile.GetPath, checks the result and converts UTF-16 to UTF-8 with CopyUTF16toUTF8. The Windows branch adds the expected leading slash and normalizes backslashes; the folder component is unescaped, converted to a filesystem path and appended as UTF-8. The checked mailbox service/URL consumers then perform directory URL escaping separately. Removing the old native-path helper avoids a Windows codepage prefix being mixed with a UTF-8 folder suffix in this path. This is the exact mailbox conversion chain, not a universal encoding rule. Bug comments6/19 are unavailable; no Windows Unicode filesystem or runtime test ran.

Scope: Mailbox path encoding layers.
