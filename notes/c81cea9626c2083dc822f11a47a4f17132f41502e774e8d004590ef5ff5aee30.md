# The renamed Exchange copy handlers keep callback-driven queue advancement

The cross-server caller starts ExchangeMessageCopyHandler and reports an immediate setup failure separately. EndCopy passes buffered data to message creation; OnCreateFinished reports failure, or on a successful move deletes the source before advancing the queue. Folder creation uses retained-self lambdas, then copies messages and advances through MessageCopyListener; empty folders advance directly. The accepted message callback has later failure/header guards distinct from the original rename. These selected paths do not establish all-error rollback or complete folder-move cleanup.

Scope: Exchange message and folder copy handler sequencing.
