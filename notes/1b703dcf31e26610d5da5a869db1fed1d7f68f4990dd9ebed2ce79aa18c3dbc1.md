# Attachment modification completes after copy, original deletion and any IMAP refresh

The JS modification path awaits stripped data, replacement copy, original deletion and finally the IMAP-only refresh. Its key-change observer runs in setMessageKey during copy; that event is earlier than the whole operation promise. The extension test now awaits deleteAttachments before getFull with its original extension ID and checking the deleted attachment payload, while skipping IMAP/NNTP. Copy/delete/refresh callbacks reject on unsuccessful status. Temporary-file removal follows copy success, so this is not a rollback or cleanup-on-all-errors guarantee. No message, server or test operation ran.

Scope: AttachmentInfo replacement-message completion.
