# DisableUpdateSettings adds a separate visibility preference for updater controls

This landing adds a true-by-default mail.update_settings.enabled preference and a Boolean DisableUpdateSettings policy whose true branch calls setAndLockPref with false. General settings uses the preference or the packaged-app condition to add hidden-via-pref to the updater header and fieldset; this path is separate from the existing appUpdate permission/automatic-update-lock branch. The stylesheet hides that class with display:none!important, and the new browser test directly checks both containers when the pref is false, skipping if updater UI is not built. The written policy vectors separately expect default true/unlocked and false/locked values. These scoped source/test facts do not establish backend update behavior, live-toggle handling, computed rendering or a native policy/test result; the upstream helper implementations are not fully paired.

Scope: mail/components/enterprisepolicies.
