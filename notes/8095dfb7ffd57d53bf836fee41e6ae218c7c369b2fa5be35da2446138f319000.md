# Bound a single mbox message with a tolerant recorded-size limit

Current nsMsgDBFolder::GetMsgInputStream chooses the larger of messageSize and offlineMessageSize, adds a 10 percent margin, and ensures at least 512 bytes before passing the limit to the store. Mbox storage supplies that limit to MboxMsgInputStream; maildir explicitly ignores it and reads the per-message file. This is a corruption safety limit rather than an exact message length. Preserve the backend distinction; the uint32_t margin arithmetic and corrupted-size extremes were not independently tested. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Single-message mbox safety limit.
