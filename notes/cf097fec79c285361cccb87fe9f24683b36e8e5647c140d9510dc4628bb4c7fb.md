# Enterprise policy documentation metadata and example choices are separate from runtime policy input

The new documentation YAML supplies per-policy prose, affected preferences and GPO/Intune/plist/JSON examples for an external documentation generator. Its policies are named mapping entries, even though README calls them a list. The documented pipe-separated alternatives describe choices and are not a single loadable configuration. The notification example uses flattened InAppNotification_Enabled names, whereas the actual runtime schema accepts a nested InAppNotification object with DonationEnabled, SurveyEnabled, MessageEnabled and Disabled. The consumer maps SurveyEnabled to blog_enabled and inverts Disabled for enabled. Preserve that metadata/example/runtime boundary when using or fixing these docs. No generator rendering, every-policy schema validation, YAML parsing or native policy test was run; published-site behavior and complete backend correctness remain unverified.

Scope: enterprise policy documentation source and schema boundary.
