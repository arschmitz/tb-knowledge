# The compaction reland closes the working DB on both callback outcomes

Relative to the original Part 2 entry 2028, reland 2063 moves ForceClosed out of a success-only block and does not use its return to replace the compaction status. OnCompactionComplete updates expunged bytes and compress-commits only on success, then closes and drops the working DB before rename work or error return. This prevents retaining that working handle during failed compaction cleanup. The fixed accepted callback keeps unconditional close and also attempts to close a live DB another actor reopened before Windows renames. Existing lessons cover copied DB files and recovery phases. The backout reported test failures, but no specific cause or passing retry is established here. No failure experiment/build/runtime run.

Scope: mailnews folder compaction DB lifecycle.
