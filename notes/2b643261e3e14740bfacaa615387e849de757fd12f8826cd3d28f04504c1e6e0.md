# Historical NTLM validation permits retry without proving operation success

The owned EWS client tries NTLM renewal before prompting. After user RETRY it refetches credentials and validates them before retrying the original operation. Validation classifies401 as invalid and any other HTTP status as valid; Continue means retry the operation, not that the operation succeeded or a cookie was observed. Silent failure bypasses the handler. The accepted implementation later moves authentication to the shared sender and Necko. These are static historical boundaries, with no executed authentication or concurrency claim.

Scope: Owned EWS authentication retry boundary.
