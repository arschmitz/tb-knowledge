# Put the optional marker on the intended HTTP scheme character

The 1960271 patch changes http?s to https? in AttachmentInfo.isAllowedURL. The former allows https and the misspelled htts but rejects plain http; the latter permits http and https. The surrounding URL.canParse check remains a separate gate. Fixed accepted code later narrows HTTP(S) attachment URLs to feed-message enclosures and separately handles UNC and EWS schemes. This historical regular-expression repair does not authorize every current HTTP attachment. A seven-case ECMAScript matrix checked only the two expressions; no Thunderbird attachment or network operation ran.

Scope: Scoped completion and input contracts.
