# Secure-message telemetry now waits for crypto processing completion

Entry 2039 keeps pending data by message URI across reloads, flushes before switching messages, and resets a 500 ms timer whenever security data arrives. It exposes MsgSecurityTelemetryProcessed with a skipped flag for tests. Frozen source has replaced that probe/timer/read-only counting with secureMailLoaded recording from smimeprocessed and openpgpprocessed. S/MIME dispatch waits for MsgLoaded and all expected signature callbacks, and prevents a second dispatch for the same processing cycle. The current test registers SecureMailLoaded before selecting secure messages and MsgLoaded for plain messages. Use the current completion signal when adding tests; the old timer, skipped event and unread-only metric are historical contracts. Later landing chronology is not covered here. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.
