# Keep folderless summary validity separate from physical-store validation

The current nsMailDatabase validity path treats no owning folder as valid to avoid deleting a summary opened from a message URL, and treats a virtual folder as having no storage. Physical folders defer to the message store. Preserve those exceptions when changing direct-file opening; lack of a folder does not prove the .msf file was physically checked or that all operations on its headers have an owning folder. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Folderless and virtual summary validation.
