# Check the caller gate after adding OAuth scope persistence

674 makes setRefreshToken update httpRealm independently of the password string and persists module scope to server preferences when a preference root exists. Its historical fetch caller still invokes the helper only when the refresh token string changes. This separates the helper fix from the caller condition that can prevent scope-only updates from reaching it. The fixed accepted caller invokes the helper for a token change or a scope change, then updates _scope; current storage avoids no-op writes and updates matching subset logins. Proposed manual review rule: trace the caller gate as well as the persistence helper when adding a new reason to save state. The current scope-only contract is also recorded in the adjacent batch. No scope-only runtime test ran.

Scope: OAuth token and realm persistence.
