# Cache lookup failure and zero-delay scheduling have separate updater contracts

The read-only cache callback checks its result before reading the entry. A non-NS_OK result resolves0 and returns; successful lookup uses entry?.expirationTime. Remaining-time calculation maps missing/no-expiration values to 0. Initialization uses zero to fetch, but successful post-fetch scheduling uses defaultInterval when the computed delay is zero. Keep those consumers separate to avoid assuming a zero delay always triggers an immediate request. Existing selected timing tests stub the expiration function; they do not directly assert the real cache callback branch. No cache or RCWN-mode test ran.

Scope: In-app notification cache expiration and scheduling.
