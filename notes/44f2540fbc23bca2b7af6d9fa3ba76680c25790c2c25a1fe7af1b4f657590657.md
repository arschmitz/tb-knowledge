# Wayland popup readiness includes the final resize as well as document load

For a Wayland popup, or when the diagnostic preference is enabled, triggerAction waits for browserLoaded and contentReadyAndResized.promise before openPopup. The ordinary contentReady promise resolves on any BrowserResized message; the newer promise resolves only when data.detail is delayed. Those are separate lifecycle states. Manual promise naming proposal in this family: name the event condition the promise guarantees and keep the load and final-size waits explicit. The actual toolbar button must be present and enabled, and the window is focused first. No Wayland runtime or platform diagnosis was reproduced. destroy rejects browserLoaded but the inspected code does not settle contentReadyAndResized, so close-before-final-resize remains a lifecycle question rather than a proved fix.

Scope: extension-popup-final-resize.
