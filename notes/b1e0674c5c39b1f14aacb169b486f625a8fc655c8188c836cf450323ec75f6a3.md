# Match message-header field names to the header they hold

The property listener constructor accepts msgHdr but stores it in a consistently misspelled mshHdr field. The callback uses the same field, so this is not an observed identity-matching failure. Proposed local naming cleanup: keep the field spelling aligned with msgHdr when modifying this listener, rather than copying that transposition into related code. This is a readability proposal based on the actual parameter and value. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Folder property listener field naming.
