# Worktree purpose and build-cache retention

A clean source worktree can still contain useful ignored build output. The fixed daily-build and dependency-update worktrees retain private build data. They are separate from disposable patch and Try task workspaces. A stopped process or an old source revision alone does not establish that the build output is disposable.

## Evidence

At the cited baseline, `commands/graph/daily-build.mjs` says: "Keep this fixed pair and its private output so the next build is incremental." `desktop/README.md` describes the dependency updater as retaining "one reusable worktree pair" for each source pair. `commands/graph/build.mjs` says: "Configure files, generated headers and compiler objects stay in their worktree." Shared installed-binary snapshots therefore do not replace all private incremental build data.

An uncommitted console change adds owner, purpose and retention descriptions to the worktree inventory. Registered build-cache layouts receive distinct daily-build and dependency-update names. Task labels use validated task ownership where available. Missing ownership remains explicit, and saved process IDs do not claim current work. The manager, checkout choices and graph tooltips use these descriptions.

Both the commit header and context menu use the same worktree picker. Background build caches remain unavailable for manual checkout, with a visible explanation. A manual target uses the existing confirmation and checkout API. The default checkout remains unchanged when another worktree is selected.

## Validation and limits

The final scoped checks cover 41 tests across manual worktrees, browser checkout flows, graph worktree visibility, the commit dialog and build behavior. Browser checks change actual disposable Git worktree heads through both pickers and verify that default source and cached build output remain unchanged. Additional inventory checks cover both repository sides, misleading folder names, task ownership and configured Review ownership. ESLint and independent source review passed. The live console restarted and returned distinct names and retention reasons for both existing caches; its served HTML included the header picker. Existing cache directories remained present. No timing benchmark or new native Thunderbird build ran. The change is local working source; verify its committed form before relying on a later checkout.
