# Warn on unsupported secret-key features without changing keys during startup

An imported secret key can advertise AEAD or v5 support that Thunderbird cannot use, leading correspondents to send incompatible encrypted mail or keys. Bug 1874715 first considered rewriting or rejecting keys, but the landed path warns instead: RNP startup scans existing secret keys and logs a warning, while import returns fingerprints for a user warning. Automatic repair was deferred because the RNP query API existed but a suitable fix API did not, and changing an existing key would require an unexpected unlock prompt. Current RNP code still uses this warning path. The bug discussion records packaging concerns with custom RNP APIs on systems that use a global library.

Scope: OpenPGP key compatibility.
