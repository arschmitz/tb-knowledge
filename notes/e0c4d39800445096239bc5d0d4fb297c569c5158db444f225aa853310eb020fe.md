# Discarding a Gloda database must invalidate both pending-commit maps

The pending map by folder/key and the map by Gloda ID represent the same queued commit. The historical discard path deleted only the first, leaving _commitCallback to dereference stale headers through the second. The fix obtains the ID before deleting both entries. Fixed compaction additionally retains a limbo queue; repair/deletion drops these commits, and later callback guards are separate changes. Reuse the existing compaction lesson for that evolution. No runtime or new regression test ran.

Scope: Gloda pending commit invariants.
