# Keep a sender key ID separate from recipient email parsing

The encryption path accepts a hexadecimal 0x sender key ID without parsing it as an email address. Ordinary senders and to/bcc lists use stripEmail, and email addresses are wrapped for the backend. Current recipient handling rejects a 0x key ID explicitly. Do not apply the sender exception to recipients. Optional review cleanup to remove old quote handling was deferred in the 2024 patch, and an attempted synchronous compose-call cleanup was restored after failures. Current source no longer has that quote workaround; the original deferral is not a permanent syntax rule.

Scope: OpenPGP encryption input contracts.
