# Scope macOS attachment drag deduplication to the requested destination

The current macOS drag workaround remembers attachment.lastSavedPath and returns when the requested destination path is repeated, before createUnique and saveToFile. Other platforms do not use this guard. The comment reports grouped native transfer requests as the reason; no native request count or repeated-drag behavior was measured. This path check is not a general attachment-content deduplication rule. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mail attachment drag.
