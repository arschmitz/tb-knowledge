# Test notification eligibility before priority selection

587 routes cached/load/update/request paths through _updateNotificationManager, which supplies getNotifications eligible results to NotificationManager. The regression fixture has a future notification with severity 1 and a current notification with severity 5; the current item must be emitted, and a spy checks the filtered manager input. This adds the ordering rationale to the earlier filtered-list lesson: an ineligible higher-priority item must not suppress an eligible lower-priority item. No notification runtime test was run.

Scope: In-app notification eligibility and selection.
