# Closing a database view releases its tree adapters after empty-row notification

nsMsgDBView.Close clears the model keys, flags and levels before notifying both tree adapters about removed rows. It then nulls both tree references and releases database listeners. That preserves the row-count callback contract while ending adapter ownership at close instead of waiting for destruction. The exact cycle and retained UI size remain attributed historical reasoning; no heap/leak test ran. This is not a blanket claim that nulling any reference cures a leak.

Scope: Message-view tree ownership.
