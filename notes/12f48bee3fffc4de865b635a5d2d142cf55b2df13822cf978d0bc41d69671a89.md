# Shared view commands pass local message keys into a protocol-specific hook

The shared view now collects messageKeys for every folder and delegates protocol work to HandleViewCommand after its local state changes. The Exchange override resolves those local keys through headers to protocol IDs; IMAP keeps its own flag/keyword behavior. The names describe shared local inputs rather than an IMAP-only UID array. The main view supplies a null copy listener and ignores the hook result, so this call is not remote completion or unchanged synchronous error propagation. The default base hook does nothing. This is a scoped API/name contract, not proof every junk/filter route uses it. No view/protocol test ran.

Scope: View protocol delegation and local-key naming.
