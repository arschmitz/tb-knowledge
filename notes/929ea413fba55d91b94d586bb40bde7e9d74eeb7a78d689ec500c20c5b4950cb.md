# Gloda query-test extractors need unique stable comparison keys

queryExpect maps expected results by extractor output. QueryExpectationListener deletes a matched key and rejects an unexpected result, while completion rejects any remaining key. Duplicate expected extractor keys collapse in the map, so the documented uniqueness condition matters. Recommend choosing identity keys that remain unique for the query scope rather than a convenient display label. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
