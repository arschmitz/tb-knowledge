# Arm picker waits before triggering their controls

The shared picker harness sets the date/select popup promise before clicking or calling showPicker, waits for hiding, and then checks content state. It waits for a non-about:blank page and focus first. Recommend retaining this ordering for these popup tests. The current harness still uses bounded delays in other steps, so this finding does not claim the test is fully event-driven. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check was run.

Scope: mail/base/test.
