# Mailbox message key zero bypasses the folder database search for an EML file

Current nsMailboxUrl::GetMsgHdrForKey returns NS_OK immediately for key zero, after validating the output pointer and file path. Its comment says this appears to be an .eml file and avoids scanning all folders for a matching database. nsMailboxProtocol uses the same key-zero convention to open the file socket. This is a scoped fast path, not a benchmark or proof that key zero identifies every external-message format. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mailbox EML header lookup fast path.
