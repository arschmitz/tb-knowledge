# Do not infer populated string outputs from a file-header success result

The current nsMsgFileHdr charset, effectiveCharset and accountKey getters return NS_OK without assigning their output references, while the corresponding setters return NS_ERROR_NOT_IMPLEMENTED. Preserve this limitation when interpreting a file-backed message header. Recommend an explicit output-state test before changing these stubs; the source alone does not prove how every caller initializes its string. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: external file message headers.
