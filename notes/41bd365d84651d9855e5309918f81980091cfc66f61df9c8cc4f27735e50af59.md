# Message selection rechecks indices after thread expansion and limits callback arguments

The message-index finder can expand an elided thread, shifting later indices. setSelectedMessages records the row count, collects speculative indices and returns them only if the count is unchanged; otherwise it re-queries every requested header. Its explicit map callback preserves the finder receiver and forwards only the header, so the array index cannot become aForceFind. That flag controls persistent filter relaxation and is separate from the wrapper’s hardcoded native expansion argument. The dedicated regression checks 17 listed versus 22 total messages, derives five unlisted IDs and compares the exact selected-ID set after selecting those plus the first/last listed messages. It does not test deletion or prove general reentrant stability.

Scope: extensions/mailTabs.
