# Do not invent an extension message ID for an EML compose source

Current compose relatedMessageId documentation states that the value is undefined for an original message opened from file, as well as unrelated compose cases. The 715 change corrects this description. This complements the EML mailto actor guard: a standalone file can compose successfully without a database-backed message ID. Only schema and actor behavior were checked here; relatedMessageId construction and permission enforcement were not traced.

Scope: mail/components/extensions.
