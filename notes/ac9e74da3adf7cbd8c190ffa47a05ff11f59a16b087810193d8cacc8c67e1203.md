# The outgoing-security baseline assertion reads the incoming control

In test_adjustSSLToPort, the first assertion under Outgoing testing reads incomingConnectionSecurity.value but says the outgoing socket should not be SSL. It checks the already exercised incoming control instead of the outgoing baseline. The later outgoing465/587 assertions use outgoingConnectionSecurity correctly. The mismatched baseline remains in accepted source. Change that receiver when repairing this test and keep the message tied to the actual expected control state; this is an assertion-scope diagnostic, not an executed test failure or a missing-should-only finding.

Scope: Account Hub manual-config assertion receiver accuracy.
