# Category layout must complete before dialog positioning

For Bug 2084433 at revision 24ae8c26d87e424b3f98e49153604460e4ede65b, the report says route readiness waits for translated category controls, and PositionedDialog.prepareLayout() measures chip capacity while initial opening remains hidden. This ordering supports positioning from the rendered category layout. The report says disabling the layout hook caused pre-position assertions to fail, then restoring it passed regression and verification runs. This is reported local validation of this dialog change, not independent proof or a rule for every dialog.

Scope: Calendar dialog layout readiness.
