# A lazy-dialog absence assertion does not test a disabled preference route

The disabled-preference test still only asserts zero #calendarDialog elements at test startup. Because creation is lazy even when the preference is enabled, that assertion alone does not exercise disabled-preference routing. A focused proposed test should attempt an event open with the preference false and verify the legacy dialog route plus no new dialog. This is a static coverage gap in that named test, not proof the fallback is broken or that no other tests cover it. No runtime/build/lint or native dialog/accessibility check ran.

Scope: Calendar lazy dialog integration and preference coverage.
