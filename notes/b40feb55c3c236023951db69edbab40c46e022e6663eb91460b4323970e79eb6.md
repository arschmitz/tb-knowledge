# Wait for injected script completion before inspecting extension content

In the MV3 content-script tests, the background API stage and actual script execution are separate signals. Entry 2058 adds named browser.test messages at the end of injected code/files, waits for them before checkContent, then releases the waiting background script. This addresses the author-reported case where startup manifest injection exceeded the helper’s 500 ms wait. The fixed accepted source keeps this pattern in consolidated contentScripts/register tests; the old _mv3 path is absent. CSS-only cases and negative injection checks still have timing limits. The commit identifies D239869 as precedent, but its discussion and this patch’s external context remain pending. Static source/test inspection only; no reproduced intermittent or runtime pass.

Scope: mail/extensions content-script browser tests.
