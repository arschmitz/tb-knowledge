# Thread-safe reference counting does not protect mutable stream state

MboxMsgOutputStream already had thread-safe support macros; entry 1630 adds a mutex to its state operations because a blocking stream can be called from other threads. Current StartPos, envelope setup, status, Write, Flush, Close and Finish use that lock. Preserve the stream-state locking boundary separately from reference-count safety. This is source inspection only; no concurrent writer/close experiment was run. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Mbox output stream state locking.
