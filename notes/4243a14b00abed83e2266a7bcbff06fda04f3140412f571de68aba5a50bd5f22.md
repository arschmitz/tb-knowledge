# Move-action log migration was narrower than the later Fluent logger

The original fix sends move logging to moved-message-log with named id/folder arguments while copy logging still uses logCopyStr from properties. Accepted source later uses Fluent for both. The values are the message identifier and target folder URI; the Fluent comment describing id as the author is inconsistent with that producer. LogRuleHit and LogRuleHitFail share the generic logger, so action-description text alone does not prove success. No log rendering or filter execution was run.

Scope: Filter action log localization.
