# Keep bootstrap storage initialization separate from loading XPCOM

At the accepted revision gBootstrap has constinit storage, but InitXPCOMGlue still resolves the executable path, obtains a bootstrap object, checks the result, assigns it, and starts logging. Normal shutdown logs termination before reset. The 2024 runtime annotation is older syntax for this storage. Do not infer that constant initialization loads XPCOM or removes the runtime failure paths. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/app/nsMailApp.cpp.
