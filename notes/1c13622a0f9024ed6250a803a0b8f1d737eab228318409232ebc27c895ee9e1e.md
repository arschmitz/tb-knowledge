# Lando merge destination names are separate from revision-pinning source branches

The follow-up explicitly defines lando-repo as the destination and selects it by merge behavior. The fixed accepted kind separately selects staging or production destination names, while the pinning transform obtains its source branch from the action and deliberately reads version and Gecko configuration from the production source repository even for staging. Do not substitute a destination label, task project, source branch, symbolic Gecko ref or exact Gecko revision for one another. Current repository names are later Git-era values, not claims about the original Mercurial worker. No merge task, network-backed transform or staging write was executed.

Scope: Thunderbird release merge automation.
