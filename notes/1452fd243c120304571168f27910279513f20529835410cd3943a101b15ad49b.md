# ForAccount does not check the OAuth preference-migration result

ForAccount calls MigrateOAuthDetailsIfNecessary without checking its nsresult and then returns the outcome of opening the username-specific branch. The migration first writes and deletes the legacy useCustomDetails flag, then transfers five string settings one at a time with early error returns. This order is not an all-or-nothing transfer; lookup success does not prove the full migration completed. The accepted source keeps the ignored result and the transfer order, although it changes the old-branch/flag error guards. This is a static completion/error contract finding. No profile mutation, injected failure or authorization outcome was tested.

Scope: Exchange OAuth settings.
