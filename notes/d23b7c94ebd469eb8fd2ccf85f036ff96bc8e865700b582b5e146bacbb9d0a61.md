# Recipient pillification resolves autocomplete before save and send consume pill addresses

This landing resolves the selected-or-first final autocomplete value before creating a row-input pill or updating an edited pill. The actual save/send callers await pillifyRecipients before preparing the message, and recipient extraction consumes the resulting pill.fullAddress values. The new path reads the controller completion value without reentering handleEnter, while blur handling keeps its separate handler path. The added test checks a new To input and keyboard draft save with three local matches; selected nonzero results, existing-pill edits, actual sending and native provider behavior were not run or directly covered.

Scope: Compose recipient completion ordering.
