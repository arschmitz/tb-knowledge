# Check store-token API values against actual stored message boundaries

Current test_msgHdrProperties asserts token "0" for the first message, derives the second offset from the From line, messageSize and separator, and confirms each token points at From -. It then tests attribute/string-property writes in both directions and lazy migration from msgOffset. The fixed From-line length is an explicit fixture assumption. These assertions establish a meaningful byte-to-header test contract, not a generic test for all storage backends. No xpcshell task was run.

Scope: mailnews/base/test.
