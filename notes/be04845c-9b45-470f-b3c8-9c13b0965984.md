# Storage item queries join SQL selection with recurring maps and occurrence filters

## Directly observed trigger and consumers

`CalStorageCalendar.getItems` decodes bit flags into event/todo, occurrence,
invitation, offline and completed-state filters. Disabled calendars or a request
for neither item type return an empty stream. Other requests reach the cached
item model, which ensures its recurring maps, then forwards chunks from the base
model. The base queries events first, adjusts the remaining count, then queries
todos when requested. The outer stream is bounded by the requested count.

Event/todo query producers await `startupPromise`, which is resolved immediately
in xpcshell but comes from `MailGlue.afterStartUp` during ordinary application
startup. They first select nonrecurring parents by SQL range/calendar/offline
filters. Row consumers reconstruct items, expand/filter them, and enqueue arrays.
They then iterate recurring parent and offline flag maps, expand matching items,
and close their streams. They yield the event loop after more than 15 ms of
processing. This is conditional scheduling, not an arbitrary test wait.
Evidence: [calendar/providers/storage/CalStorageItemModel.sys.mjs:37–47](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L37-L47), [calendar/providers/storage/CalStorageItemModel.sys.mjs:152–242](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L152-L242),
[calendar/providers/storage/CalStorageItemModel.sys.mjs:252–353](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L252-L353), and [calendar/providers/storage/CalStorageStatements.sys.mjs:336–414](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageStatements.sys.mjs#L336-L414).

The event SQL compares floating dates with supplied timezone offsets and other
dates with native timestamps. It excludes recurrence-bearing rows and exceptions
from this first phase. Recurring selection uses separate SQL and later maps.
The todo phase also filters completed state on expanded results. Offline flag
priority differs when multiple offline request bits are combined: events choose
DELETED before CREATED; todos choose CREATED before DELETED. That is the explicit
branch order, not a statement that callers normally combine these flags.

`#expandOccurrences` uses the parent's actual recurrence object when occurrences
are requested. Otherwise it checks the parent range. It filters invitations by
an invited attendee with `NEEDS-ACTION` and applies an optional final predicate.
The returned value is an array, including an empty array when nothing matches.
Evidence: [calendar/providers/storage/CalStorageItemModel.sys.mjs:355–384](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L355-L384).

## Errors, cancellation and completion

Nonrecurring SQL errors are caught/logged before recurring selection. The database
wrapper separately catches row-consumer errors, so a finished query does not mean
every conversion or enqueue succeeded. The cached wrapper treats an error with
cause `db-shutdown` as an empty/ended stream and rethrows other errors. No native
pending-statement cancellation handle is propagated from the database wrapper.
A closed output stream is a different event from native statement completion.

## Direct tests and limits

`doPropertiesTest` creates and modifies recurring event/todo occurrences, refreshes
queries, then creates a second calendar with the same ID to bypass existing
caches. It directly compares occurrence counts and category/property values after
reload. Named event/todo tests use this helper. The later cache tests directly
check changed exception data is not hidden by parent caching.
