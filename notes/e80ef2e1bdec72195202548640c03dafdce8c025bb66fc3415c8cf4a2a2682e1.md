# The first Exchange manual-config landing adds an empty subview scaffold

The original Exchange-settings landing adds a custom-element module, empty form and state-map entry. setState and captureState are empty, and no service-URL field or changed test is present. Its templateId follows email.mjs's lazy module-loading path. Accepted source later supplies URL input, validation, focus, copied capture and a microsoft route; that later behavior must stay separate from the initial scaffold. The original nextStep spelling also differs from the accepted state key. No UI or account setup ran.

Scope: Account Hub Exchange manual configuration phases.
