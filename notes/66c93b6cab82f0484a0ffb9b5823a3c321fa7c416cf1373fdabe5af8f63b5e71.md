# Separate junk-score updates from actions and wait for action callbacks

The folder API separates setting a numeric junk score/origin/percentage from acting on messages already classified. performActionsOnJunkMsgs can mark read or move/delete without setting the score; its unit test deliberately keeps an empty score during action-only cases. The JS wrapper waits for the junk callback before starting good-message actions and rejects with Error on a failed callback. Empty/no-action branches notify success synchronously. The copy listener forwards later completion, but the selected native CopyMessages/DeleteMessages calls do not store their immediate return in rv, so this inspection does not establish delivery of every failure to the callback. The read-state preference here is the manual-mark preference; automatic-classification preference rules remain separate. Part 1does not remove the view duplicate until a later patch. No test ran.

Scope: Junk score/action separation and completion.
