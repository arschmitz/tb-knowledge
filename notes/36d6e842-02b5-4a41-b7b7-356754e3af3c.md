# Gecko application entry, startup stages, and profile cleanup

## Application entry

Firefox's `do_main()` selects application data from `XUL_APP_FILE` or a first `-app` argument, otherwise it uses compiled application data. The xpcshell command takes a separate test-shell entry. After setting platform-specific bootstrap information and checking the browser command line, the ordinary application path calls `gBootstrap->XRE_main()`.

The executable also has a separate `contentproc` path that calls child-process initialization. A content process is a separate process used for application content. Do not assume a helper process runs the same application startup as the parent.

## Shared runtime stages

`XREMain::XRE_main()` loads or copies application data, sets runtime directories, and establishes platform and crash-reporting work. It calls `XRE_mainInit()` and `XRE_mainStartup()` in sequence. Either can return an error or request an early exit.

Only after those stages succeed does it allocate `ScopedXPCOMStartup` and initialize the component runtime. It passes `aInitJSContext=false`: the source says `XRE_mainRun()` needs to initialize the JavaScript context after reading user preferences. It then calls `XRE_mainRun()`.

Corrupt or incomplete application resources have explicit crash paths. Do not turn those results into ordinary successful startup in a wrapper.

## Shutdown order

After the run stage, the remote service is shut down before a possible restart launch. The source explains that otherwise the new process could send its launch request to the old process.

`mScopedXPCOM` is cleared before unlocking the profile. The profile lock must remain held while the component runtime shuts down. The order is stated by the source and is visible in the function body.

## Engine and application selection

The root `moz.build` includes the selected `app.mozbuild`; otherwise it includes `toolkit/toolkit.mozbuild`. The toolkit file visits core layers including networking, components, scripts, storage, parsing, graphics, documents, widgets, editing, layout, and navigation. It also includes toolkit, services, and test harnesses under their conditions.

The build file selects the shared Rust library only when `MOZ_OVERRIDE_GKRUST` is false. This connects to Thunderbird's separate Rust override. Accessibility, sandbox, tests, and remote automation have their own conditions; a literal directory list does not prove they are enabled.

This note covers the top-level sequence. It does not claim a complete review of every branch inside each startup stage or every platform entry point.
