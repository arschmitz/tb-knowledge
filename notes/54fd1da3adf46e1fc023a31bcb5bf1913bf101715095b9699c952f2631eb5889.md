# The virtual-folder command port keeps failure notifications as wait outcomes

The original command port changes the message-tab and message-window actions while retaining waits for both DeleteOrMoveMsgCompleted and DeleteOrMoveMsgFailed. The exact historical promiseFolderEvent receiver resolves on a matching event, so either event can fulfill Promise.any. That wait ending does not itself assert successful deletion; the display checks follow separately. Fixed accepted source later uses performDelete with only Completed versus a rejecting timeout. Keep those completion phases distinct.

Scope: Virtual-folder deletion command and event phases.
