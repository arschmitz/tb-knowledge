# CardDAV availability probes use provider metadata, not user grants

The two account-creation branches query OAuth2Providers.getHostnameDetails with carddav instead of creating and initializing OAuth2Module. A truthy result means configured hostname/activity metadata exists. It does not show that the user granted a scope or that CardDAV authentication will succeed. The existing-account comment about a scope being granted overstates this check. Keep provider lookup separate from session initialization, which also handles issuer/client and token/object state. Actual CardDAV discovery remains a later call.

Scope: Account creation CardDAV discovery.
