# Reply-to-list send completion and compose-window closure need separate waits

The test arms domWindowClosed before sending, waits for aftersend and checks address collection, then awaits the natural close. It no longer force-closes a window while remaining send or prompt work can use that context. Account association also precedes creating the folder that emits UI notifications. The Bug attributes the following returnReceipt failure to unfinished earlier work, but retains a later associated failure. No browser test ran.

Scope: Compose test completion and lifetime.
