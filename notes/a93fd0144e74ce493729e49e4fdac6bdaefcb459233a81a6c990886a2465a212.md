# Keep decoded message content distinct from raw MIME content

getFull defaults decodeHeaders and decodeContent to true. Raw content uses binarystring/nodecode and preserves folding; decoded content uses unicode/decode. convertMessagePart exposes body only for non-attachment text parts, while rawBody covers the parser content of all parts. Raw headers remain arrays and the API has a synthetic outer message/rfc822 envelope. These values are a MIME tree representation, not proof of exact original file bytes. The fixtures cover different encodings, missing content types, attachments and an encoded comma; the test does not cover every independent option combination. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/raw-decoded-contract.
