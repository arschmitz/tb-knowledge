# Current EWS erase checks zipped response pairs without a local count gate

The owned dedicated folder-delete path extracts a response through single_response_or_error. Accepted generic DoEraseFolder instead zips folder IDs with response messages and checks each resulting pair. This loop has no local cardinality check and returns success after an empty pair sequence. ErrorItemNotFound is tolerated only for checked responses; other checked errors propagate. This describes the helper's control flow. Upstream parser and request guarantees were not proved, and no malformed response was replayed.

Scope: EWS erase response validation.
