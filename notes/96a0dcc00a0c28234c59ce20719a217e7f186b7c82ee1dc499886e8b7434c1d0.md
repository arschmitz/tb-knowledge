# Await AddonInstaller status before branching on it

Accepted AddonInstaller.install awaits isInstalled, and Account Hub setAddon awaits both isInstalled and isDisabled. The first predicate requires the requested ID, a matching version and an active add-on; the second tests existence and inactivity. Their addon && expressions can return an absent add-on value as well as booleans, so consumers use truthiness. Do not replace these awaited branches with checks on a Promise or assume a strict boolean return from their JSDoc. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/accountcreation.
