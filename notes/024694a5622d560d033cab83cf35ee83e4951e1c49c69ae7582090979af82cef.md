# Extension message setup promises must name the protocol completion they wait for

The initial browser helper returned Promise.resolve after local addMessageBatch. The follow-up waits for mailTestUtils.updateFolderAndNotify, which registers a listener before updateFolder and calls back only for FolderLoaded on the requested URI. Fake IMAP injection instead returns PromiseUrlListener: it resolves on NS_OK and rejects other URL stop results. Awaiting either helper is meaningful because its event contract is explicit. The follow-up was motivated by intermittent-test investigation, but no runtime check here proves a general cure. Keep browser and xpcshell wrappers scoped to their own helper implementation.

Scope: Extension browser message setup.
