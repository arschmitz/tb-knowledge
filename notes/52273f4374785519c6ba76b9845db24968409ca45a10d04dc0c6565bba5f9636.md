# Do not carry the old POP3 abort stream contract into the current sink

The 2048 patch removes the explicit stream Close in IncorporateAbort; its backout restores that close and returns the close result. The frozen sink has evolved again: it calls DiscardNewMessage with the folder and output stream, clears the stream member and returns NS_OK. Thus the historical backout is not current evidence that this sink must call Close itself or return its status. Recheck the current pluggable-store disposal contract before changing abort cleanup. The store implementations and an abort were not executed here. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: POP3 sink abort API evolution.
