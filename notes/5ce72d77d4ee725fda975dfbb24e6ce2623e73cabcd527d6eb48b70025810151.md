# Download completion and early-start failure have different cleanup evidence

Accepted OnStopRunningUrl clears mDownloadInProgress and the partial-message list before delegating. DownloadMessagesForOffline sets the in-progress flag before obtaining the server, and has early error returns afterward. Static inspection therefore supports normal callback cleanup, not a guarantee that every start failure resets the flag. The view also returns header-collection status rather than the folder download call’s result. No failure-injection runtime ran. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
