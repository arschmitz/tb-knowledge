# Summary repair and below-threshold database compression use different lifecycle points

The patch removes an immediate compress commit after folder.updateFolder in the summary-rebuild path and changes the backend auto-compaction event from kLargeCommit to kCompressCommit when the threshold is not exceeded and mDatabase exists. Accepted repair code still closes/backs up the database before updating, while protocol-specific rebuild state remains distinct. This chooses a lifecycle point and commit mode; it proves no completed asynchronous parse, universal database compression or measured disk-space recovery. No repair or compaction test ran.

Scope: folder-database-maintenance.
