# Reject null recipient objects while mapping empty optional names to None

Current outgoing ThinVec entries are Option<RefPtr<msgIAddressObject>>. A null entry returns NS_ERROR_NULL_POINTER through collect<Result<Vec<_>,nsresult>>; it is not silently filtered out despite the old comment wording. An empty display name becomes None because it is optional. Keep malformed required objects distinct from optional empty fields when translating XPCOM data into Rust.

Scope: rust/protocol_shared/src.
