# nsMsgProgress::CloseProgressDialog behavior in mailnews/base/src/nsMsgProgress.cpp

Marks progress closed and broadcasts STOP, with failure when forceClose is true and success otherwise. It does not close a DOM window directly; sendProgress.js closes its window upon STOP. New listeners later see STOP with NS_OK regardless of this original status.

## State read

- forceClose

## State changed

- m_closeProgress=true; OnStateChange caches flags/status

## Calls and triggers

- Calls this->OnStateChange. MessageSend._updateCopyStatus unregisters itself then closeProgressDialog(false) after successful retry at411-413.
- sendProgress.js listener closes window at28-51.

## Result and consumers

Return is OnStateChange's NS_OK; it does not certify that the operation succeeded.

## Errors

forceClose changes event status to NS_ERROR_FAILURE; listener return statuses are discarded downstream.

## Async completion

Synchronous broadcast; receiver may abort work and close UI. No waiting for transport shutdown.

## Ownership and cleanup

Does not clear listener array; unload unregisters dialog listener.
