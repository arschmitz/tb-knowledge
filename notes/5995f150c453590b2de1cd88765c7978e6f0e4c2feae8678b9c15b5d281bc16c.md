# UNAVAILABLE state stops the IMAP bad-password retry path

The response parser treats UNAVAILABLE as an alert and records fServerUnavailable. After failed authentication, TryToLogon checks that flag before marking a method failed, selecting another method or reaching the new-password prompt. In the original landing the flag was set only inside the nonempty/nonduplicate alert branch; fixed source sets it before duplicate-display suppression for nonempty text. Constructor and StartTLS reset clear it, but no per-attempt lifecycle or popup runtime guarantee is claimed. Related1602375 was read; primary803994 lacks comment17 and the assigned review is unread. This is source-only knowledge with zero full-audit credit.

Scope: IMAP response and authentication state.
