# Separate filter warning removal from filter safety and enablement

History830 was described as shadow/redeclare cleanup, but also removed the permanent-decryption alert and its Fluent string. The full D222239 discussion explicitly requested that change. The author agreed to remove the alert while retaining the unenabled implementation for later investigation and maintenance. The final code keeps folder validation and the distinct MoveDecrypt/CopyDecrypt actions. This establishes an intentional interaction change, not proof that permanent decryption is safe or that filters were enabled. Later thoughts about enabling filters and replacing nested searchBlankLine callbacks remained suggestions, not applied changes. This supersedes the earlier source-only note whose review context was still unread. No filter or encryption runtime was tested.
