# Treat disabled Windows notification server as a temporary historical workaround

In May 2024, setting alerts.useSystemBackend and alerts.useSystemBackend.windows.notificationserver.enabled to false removed a 10-second delay when a user clicked a Windows notification. It let the notification dismiss and open the message, but did not bring Thunderbird to the foreground. Bug discussion traced the delay to notification-server handoff and a timeout while passing foreground permission to the application. The later Bug 1863798 fix (commit 4427b61a578) adds notification-windowsTag handling in MessengerContentHandler and removes these disabling prefs. Follow that newer code; do not present the May preference as current guidance.

Scope: Windows notifications.
