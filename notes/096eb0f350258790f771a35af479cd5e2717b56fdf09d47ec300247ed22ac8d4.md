# Notification replacement tests must check object identity as well as count

The notification manager holds one active element and replaces it with a new element when a new notification arrives. The initial 779 tests check one child plus Assert.notStrictEqual for replacement, and the current browser test retains both checks. A child count alone cannot detect stale content or reuse of the old notification. The manager now waits for scheduler activity before constructing the new element. Manual test naming and assertion proposal in this family: distinguish show-and-hide from replacement in test_showAndHideNotification and test_showNotificationReplaces, and state which identity must change. These inspected tests are source evidence, not a passing browser run.

Scope: notification-replacement.
