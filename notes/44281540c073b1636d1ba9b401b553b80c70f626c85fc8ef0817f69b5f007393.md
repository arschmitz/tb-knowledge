# The renamed Exchange message listeners retain header references and count successful reads

ExchangeSimpleMessageListener clones the array of RefPtr header values and passes those retained header references before returned IDs/fallback state; it does not clone the message objects. ExchangeMessageFetchListener adds a data callback's byte count only after that callback succeeds, and passes the cumulative count to stop. These adapter contracts remain across the rename. MarkMessagesRead separately captures its headers/IDs and updates local state in its success callback; the client start return is not that callback's completion. No runtime or all-caller guarantee is claimed.

Scope: Exchange listener adapter ownership and byte-count contract.
