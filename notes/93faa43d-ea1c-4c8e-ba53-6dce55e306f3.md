# Name a notification update as a method when it has side effects

The notification controller uses `updateNotifications()` and `getNotifications()` as methods. In [D210183](https://phabricator.services.mozilla.com/D210183), a reviewer asked if these should be property accessors. The author explained that later updates would have more side effects and that a property would hide them. The reviewer accepted the patch. Current `updateNotifications()` persists data and updates the display manager, which supports that narrow choice.

## Evidence

The May 2024 code in commit `2d5264d9efb68bed69df0fe77154bcc067fe27a8` writes a `JSONFile` and calls `saveSoon()`. The review reply says, "Both of these are going to get more side effects and hiding them as a property seems dangerous." The current method also calls `_updateNotificationManager()`.

## Validation and limits

I read the landed code and browser review. This is a rule for operations with meaningful side effects in this component, not a ban on getters and setters across Thunderbird. No tests ran for this study.
