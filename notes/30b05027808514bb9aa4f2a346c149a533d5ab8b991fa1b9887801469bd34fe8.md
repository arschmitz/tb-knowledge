# Message loading flags and standalone commands follow the current message completion events

Current-channel headers set msgLoading before MsgLoading. Current top-level document completion clears msgLoading, sets msgLoaded and emits MsgLoaded after attachment work; external resources may still load. The standalone message window updates GetMessages and other commands from MsgLoaded, and extension open waits for that completion or an already-loaded state. Recreated about:message views reload for loading or loaded state. The old URL listener remains for error redirects; no runtime behavior or full listener removal is proved.

Scope: about-message-load-event-order.
