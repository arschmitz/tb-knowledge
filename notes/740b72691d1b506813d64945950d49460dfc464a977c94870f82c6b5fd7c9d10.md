# Separate file-copy completion from imported-header availability

messages.import waits for copyFileMessageOperation and then importOperation. One confirms copy service success; the other supplies the matching destination header after database/server work. The listener is installed before copying, matches folder URI and the known key or Message-ID, and resolves a cached header. Manual promise naming proposal: name the completion phase so a successful transport callback is not mistaken for a usable API message result. The two waits and names are the actual accepted implementation. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/import-completion.
