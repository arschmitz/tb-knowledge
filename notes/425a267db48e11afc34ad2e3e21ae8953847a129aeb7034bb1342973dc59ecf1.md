# The send-format helpers wait at the next-send boundary after assertions

Both helpers compute the next wall-clock second immediately after send_later, check the selected message and then await only the remaining interval before returning. Their actual loop callers await the whole helper, so that boundary belongs to the ordered next-send scenario rather than a fixed post-selection pause. The source comments tie this to date sorting by seconds. This scoped lint-excepted timing choice is not a general arbitrary-delay rule, a measured performance result or proof of a race cure; underlying native sorting and test runtime were not exercised.

Scope: Composition test send ordering and timing.
