# Custom-element registration and child-browser readiness are separate MessagePane waits

Accepted about3Pane first awaits customElements.whenDefined("message-pane"), obtains the element, registers count/selection events and later awaits messagePane.isReady(). isReady waits for the single and multi-message documents when incomplete or still about:blank. For this initialization path, element definition alone does not guarantee child document APIs exist. It is a scoped wait pattern, not a guarantee that every future browser navigation is complete. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
