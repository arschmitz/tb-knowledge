# Text and HTML export tests tolerate platform line endings

test_saveAs.js removes CR characters from both actual and expected text only in its .txt and .html checks. The .eml check retains the original substrings. A generated body without any line ending had hidden the mismatch on Unix; adding a realistic CRLF body exposed it. Keep this assertion tolerance scoped to platform-formatted export. It does not establish byte-for-byte serialization correctness or justify stripping newlines from production messages. No export test or native platform comparison ran.

Scope: Message export tests.
