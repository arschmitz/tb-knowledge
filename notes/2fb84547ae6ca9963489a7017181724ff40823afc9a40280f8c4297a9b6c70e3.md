# The Exchange trash preference updates an existing destination and its flags

The server validates a nonempty trash path under its root, clears the previous Trash flag, stores the path and flags the new destination. Empty input leaves the preference unchanged. Folder creation uses that saved path to reconcile the new folder flag, or adopts an already distinguished Trash folder when no path exists. The UI writes its hidden persisted path while updating the real picker. Later folder lookup delegates to the server path; the original folder helper searched flags. This ordered update is not a transaction and does not prove every error leaves prior state intact. Static source only.

Scope: Exchange trash preference and folder state.
