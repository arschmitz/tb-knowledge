# The two-step EWS fetch still defaults optional message metadata

The two-step EWS sync requests explicit metadata through GetItem, but created/updated message arguments still use defaults when optional size, read, flag or preview values are absent. Missing IDs or a missing fetched entry fail separately. The comment about data integrity explains the request strategy; it is not a check that every requested field exists. This is a static boundary, not evidence that a new omission occurred or that the fallback values caused a live failure.

Scope: EWS message synchronization metadata.
