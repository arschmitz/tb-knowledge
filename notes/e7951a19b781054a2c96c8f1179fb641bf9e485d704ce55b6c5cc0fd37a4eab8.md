# Mbox repair writes beside the original and replaces it only when changed

The wrapper checks space for the original size plus one MiB before starting a ChromeWorker. The worker creates a unique .tmp sibling, appends converted chunks, replaces the input only when a bare CR changed, and otherwise removes the temporary file. This is the normal success-path lifecycle. The worker has no finally around all I/O, so the inspected code does not establish temporary-file cleanup after every error. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mbox repair temporary file and space guard.
