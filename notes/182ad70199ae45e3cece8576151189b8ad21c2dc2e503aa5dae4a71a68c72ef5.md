# Panorama deletion wrappers currently ignore legacy options and dispatch after row deletion

The inspected DeleteMessages wrapper calls RemoveMessage for each key and returns at the first failure. DeleteMessage and DeleteHeader delegate to it. Their comments explicitly leave instigator, commit and notify options ignored, so callers cannot infer those legacy behaviors from their signatures. RemoveMessage deletes named properties and the message row before it dispatches the removed Message and old flags. The per-folder adapter checks membership and forwards a null instigator. Current source deliberately retains cached data and records unresolved deletion-payload TODOs; the written listener test is separate evidence. No transaction atomicity, cache expiry guarantee, deletion test or callback execution was validated. The added MOZ_ASSERT has no message.

Scope: Panorama delete compatibility boundary.
