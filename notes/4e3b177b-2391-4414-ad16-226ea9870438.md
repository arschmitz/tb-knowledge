# Keep extension Quick Filter state and visible controls in sync

`browser.mailTabs.setQuickFilter()` must update the Quick Filter Bar input and controls as well as the message query. When a user is typing in a nonempty, focused search input, `SearchBar.overrideSearchTerm()` refuses to replace that text. The extension path retains the prior search term in that case.

## Evidence

The [bug report](https://bugzilla.mozilla.org/show_bug.cgi?id=1873860) describes an extension that filtered messages while leaving the search input empty after the move from a XUL textbox to an HTML input in shadow DOM. Commits `1980cfa31c417f178e7dc2d71494ecce20c42864`, `b8e4f3b809b51d06380ecafa13f76d089c0ff1b9`, and `5e38d1096942583a40f7087a0c8f9c8bb10d0541` changed the API path and added extension and widget tests. In [D208612](https://phabricator.services.mozilla.com/D208612), the author explained that the focus restriction prevents changing the field while the user types. [D208613](https://phabricator.services.mozilla.com/D208613) records that a failed Try run led to moving the extension test into the existing `browser_ext_quickFilter.js` file.

## Validation and limits

I inspected the landed diffs, current related source, Bugzilla, and the three public reviews on October 6, 2026. I did not run the tests. The rule concerns this extension API and search widget, not every focused input.
