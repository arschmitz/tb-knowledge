# Removing messenger content accessibility also blocks native Storybook skin URLs

Bug 2067321 removed `contentaccessible=yes` from the messenger package. The native chrome registry checks the package flag for skin URLs too. This explains blocked `chrome://messenger/skin/layout.css` and `chrome://messenger/skin/shared/tb-banner.css` loads from the HTTP Storybook page. It does not explain every stylesheet error.

## Evidence

- Commit `05d87b739d82f3ef3163f325f05129a500c65bbf`, September 1, 2026, by Geoff Lankow, reviewed by tobyp: <https://phabricator.services.mozilla.com/D322014>. The commit says: "Also removes the contentaccessible flag on chrome://messenger/content."
- In `mail/base/jar.mn`, the registration changes from `% content messenger %content/messenger/ contentaccessible=yes` to `% content messenger %content/messenger/`.
- In Gecko's `chrome/nsChromeRegistry.cpp`, `AllowContentToAccess` gets the URL host, reads that package's flags, and sets `*aResult = !!(flags & CONTENT_ACCESSIBLE);`. It does not limit this check to the content provider.
- `tb-banner.mjs` creates a link to `chrome://messenger/skin/shared/tb-banner.css`. `variables.css` imports `chrome://messenger/skin/layout.css`. A JavaScript module resolver does not rewrite these runtime links or nested CSS imports.
- Bug 2077553 records another CSS regression from this removal, with a last-good build on August 31 and first-bad build on September 1. That report concerns the old Calendar description editor, not a Storybook regression test: <https://bugzilla.mozilla.org/show_bug.cgi?id=2077553#c6>.

## Validation and limits

A native xpcshell 161.0a1 probe used a content principal for `http://localhost:5703/iframe.html`, `allowContentToAccess`, and `checkLoadURIWithPrincipal` with `ALLOW_CHROME`. Both messenger skin URLs were inaccessible and returned `NS_ERROR_DOM_BAD_URI`.

Registering `content messenger ./ contentaccessible=yes` after startup in a separate disposable xpcshell process made both URLs accessible and allowed. The manifest changed only that process. An earlier attempt using the startup `-r` option did not change the effective registration and was inconclusive.

`chrome://global/skin/global.css` was accessible and allowed in both successful probe configurations. Any reported error for that URL needs separate investigation. This experiment proves the native permission gate. It does not render a CSS document or establish a full Storybook runtime regression range. No Thunderbird source or running application was changed. Serving mapped Storybook resources over HTTP is a possible fix; this note does not authorize restoring broad content access.
