# Use the real notification element and payload setter in Storybook

The accepted Storybook story imports the actual notification element and icon stylesheet, supplies the templates expected by that element, selects in-app-notification and passes the scenario through setNotificationData. Its setData option can leave the fixture without a payload. Use the real component, required templates and production setter in nearby stories so the scenario exercises the same input contract. Existing knowledge already covers pre-connection storage and replay. This is a scoped manual recommendation from static source. No Storybook, runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending.

Scope: In-app notification Storybook behavior.
