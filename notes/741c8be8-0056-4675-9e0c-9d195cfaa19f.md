# CalDAV delete conflicts and older call arguments affect remote and cached item state

CalDavCalendar.deleteItem:824–826 calls current doDeleteItem(item,ignoreEtag,fromInbox,uri).
doDeleteItem:838–941 validates ID, chooses explicit/calendar/inbox URI, rejects
deleting the collection itself, and uses cached ETag unless ignored. DeleteResponse
accepts HTTP200/204/404. Normal successful calendar deletion clears href/itemInfo;
cached mode resolves null and lets the cache wrapper delete local storage;
uncached mode awaits memory delete. Inbox mode returns null without removing the
main calendar item. onError reports/notifications and rejects a status-bearing
Components.Exception. Actual returned values can be null or backing delete result,
despite Promise<void> documentation.

A conflict triggers HEAD. HEAD404 notifies success and returns null without normal
index cleanup. HEAD5xx rejects unavailable. For another nonzero status, it fetches
local item and asks cal.provider.promptOverwrite; consent retries with ignoreEtag,
decline returns null. The actual CalCachedCalendar.deleteItem:987–1037 treats any
provider fulfillment as success and deletes cached item plus metadata. Consequently
decline can remove the cached item while remote deletion was declined. This effect
is supported by both bodies and was reached in a controlled exact-body probe:
DELETE conflict→HEAD200→one declined prompt→one cache and metadata deletion;
provider itemInfo remained. Real server/UI behavior was not run in that probe.

Separate older call sites have argument mismatches. promptOverwrite:525 calls
doDeleteItem(aItem,aListener,true,false,null), so the listener object becomes
ignoreEtag and true becomes fromInbox; fifth argument is ignored. doModifyItem:776
and processItipReply:2328 call five arguments ending in null/delUri, but fourth
argument true becomes uri and the intended fifth URI is ignored. Passing true
into the URI role can fail in real channel setup; exact native exception/recovery
remains unresolved. These are current call expressions, not assumed matches.
The current retry at921 and public delete at825 use the four-argument contract.

Direct test_caldav_requests.js:702–735 asserts method DELETE, If-Match and accepted
404. It does not check provider conflict prompts, facade deletion or old inbox
call positions. Common provider deletion helper checks ordinary removal/observers;
it executes this normal path, not every conflict branch. The controlled probe
also reached promptOverwrite and recorded the five argument positions.
No product pass is assigned to those uncovered branches. See the existing
[facade mutation record](136d02e0-8196-4513-b49a-d763668afe02.md).
