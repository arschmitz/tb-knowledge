# Use shared password-dialog strings with the platform-specific message form

Accepted QR authorization and password viewing request password-os-auth-dialog-message plus the macosx suffix on macOS, and the common caption. Both await Fluent messages before calling the OS keystore. Scoped pattern: reuse this established message/caption pair and platform branch when changing these consumers. The source comments identify a macOS string-format constraint; no native dialog or paired API contract was verified here. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
