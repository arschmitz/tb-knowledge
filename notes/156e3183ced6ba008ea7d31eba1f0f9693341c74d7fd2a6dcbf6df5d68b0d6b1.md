# File-message copy completion and IMAP folder refresh are separate awaited stages

MailUtils.copyFileMessageAsync resolves without a result after successful copy completion and rejects for an unsuccessful callback status. It copies with Read flags, no replacement and no draft/template mode. updateFolderAsync separately waits for an IMAP URL listener and returns immediately for other folder types. The file-drop callers await each file in order, catch each failure as a warning and still request one final refresh; they are not atomic imports. The extension import path only starts updateFolder in its successful copy callback and also waits for its existing message-added promise. The native final append branch keeps automatic refresh only for draft append. Callback delivery for native no-URL update branches remains untested; the helper is not proof that every destination settles.

Scope: front-end file-message import completion.
