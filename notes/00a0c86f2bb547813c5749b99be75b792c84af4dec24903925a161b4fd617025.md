# Wait for a copied message before closing its source window

In browser_replyMultipartCharset.js, the intermittent fix waits until the destination folder contains one message after invoking the copy menu and before closing the source window. Menu closure alone does not prove the copy finished. For this test, keep the folder-state wait before later selection and reply steps. A separate 500 ms wait still exists; this fix does not prove that all timing races or arbitrary delays were removed. The test was read, not run. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.

Scope: mail / test.
