# Calendar dialog reload checks bracket asynchronous event retrieval

The fixed CalendarDialog loader checks queued reload state before and after awaiting calendar.getItem. setCalendarEvent updates calendar/event attributes and recurrence selection, while the caller gates this dialog on event view mode and a preference. These checks are newer than the original loading patch, whose successful response path lacked the same reload mechanism. Preserve the current state machine when changing the provider lookup; do not label the historical response limitation a current defect. Named browser assertions were read statically; no dialog or provider race ran. The original review retained attributes as observable component state after a method-only design challenge; it did not settle every missing/bad-data error branch. The initial task covered existing-event data routing, not every dialog field.
