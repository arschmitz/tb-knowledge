# Notification documentation must state the scheduler’s actual time unit

Entry 1504 and current docs call mail.inappnotifications.refreshInterval a value in seconds. Current updater uses that integer directly as the timeout delay, with fallback 21600000, and no seconds-to-milliseconds conversion at this boundary. Record this as a static documentation/unit discrepancy. Proposed rule for this scheduler: document milliseconds and distinguish preference fallback delay from the HTTP cache’s remaining time. No scheduling experiment or runtime repair was made. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: In-app notification update units.
