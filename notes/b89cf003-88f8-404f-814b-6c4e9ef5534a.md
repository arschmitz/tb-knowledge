# BMO update authentication needs the API key header

For the BMO REST endpoint, send the saved API key in `X-Bugzilla-API-Key`.
Do not rely on an `api_key` field in the JSON update body. A browser login
uses a separate cookie session from the console's Node.js HTTP requests.

## Evidence

On 2026-11-04, two PUT requests to the invalid target `/rest/bug/0` used
the same saved key. The body-only key returned HTTP 401, error code 410:
"You must log in before using this part of Bugzilla." The header key with
an empty JSON body returned HTTP 400, code 100: "You must enter a valid bug
number!" The second request passed the login gate. Neither request could
change a real bug because bug ID 0 is invalid.

[BMO authentication documentation](https://bmo.readthedocs.io/en/latest/api/core/v1/general.html#authentication)
specifies the header and says to send one authentication method per request.
A successful public bug read alone does not prove authentication. The live
header check also received the authenticated-only `update_token` field;
the token value was not logged.

At console base revision `a3b6d210a3c09a66524e59a620cdeb2fc0f602f3`,
`lib/bugzilla.mjs` put the key in the write body. The local repair puts the
current configured key in a shared header helper for all Bugzilla request
families and removes query/body credentials. This repair was uncommitted
when this note was recorded.

The write-deadline helper also wrapped explicit authentication failures as
uncertain outcomes. [HTTP 401 semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.2)
state that the request was not applied. Preserve completed 401/403 rejection
details. Keep lost replies, cancellation after sending, and 5xx responses
uncertain, with no automatic write retry.

## Validation and limits

61 focused API, authentication, and deadline tests passed. Two check-in action
tests also passed. ESLint passed for the four changed files. An independent
checker approved the evidence and source changes.

The changed source client completed an authenticated live read. No real bug
was updated during validation. A running backend must load the changed module
before its next write can use the fix. This observation applies to BMO on the
stated date; do not assume the same behavior for every Bugzilla installation.
