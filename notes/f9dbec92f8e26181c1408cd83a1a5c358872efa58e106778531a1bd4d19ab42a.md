# Avoid a destination refresh during same-folder attachment replacement

The accepted move/copy handler says attachment deletion replaces a message with a modified copy in the same folder. Refreshing while deletion is in progress can re-add the original header and confuse IMAP pseudo-header key mapping. It therefore updates the destination only if a source URI differs from the destination URI; the delete operation supplies the later refresh. This is a current follow-up to the original 1055 unconditional refresh. Preserve the phase and URI predicate, not just the general instruction to refresh after every operation. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/attachment-delete-refresh.
