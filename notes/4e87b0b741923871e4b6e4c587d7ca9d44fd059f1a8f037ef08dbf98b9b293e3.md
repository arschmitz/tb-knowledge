# Empty category selections still need initial rendering

For Bug 2084433 at revision 24ae8c26d87e424b3f98e49153604460e4ede65b, the AI report identifies a case where reusing an empty selector result prevented newly loaded edit choices from rendering. The reported fix explicitly renders those choices before edit readiness completes. Apply this lesson to category initialization when selector identity can remain unchanged despite newly available choices; it does not establish a general rule against stable selector results. The named regression test is reported, but source inspection and independent execution are not supplied.

Scope: Calendar event category rendering.
