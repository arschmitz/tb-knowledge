# Folder-selection assertions need a named row and expected state in their messages

The virtual-folder test adds row-count, row-name, checkbox-state, chosen-count and saved-URI assertions without message arguments. For example, its scalar equality calls provide only actual/expected and its checkbox calls provide only the condition. Comments dividing initial and changed selection do not supply assertion messages. Add nonempty expected-behavior messages when editing these checks, such as "The first source folder should be unchecked after the click." and "The virtual folder should search second, third and fourth." Keep the actual row/folder and expected state visible so failures inside nested dialog callbacks identify the failed behavior. This is a scoped diagnostic review finding about missing arguments, not a defect based only on the absence of should.

Scope: mail/folder-selection/tests.
