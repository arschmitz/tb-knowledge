# Click-handler diagnostics add tab IDs without changing completion rules

The owned patch adds both stored and incoming tab IDs to the existing multiple-tab failure message. It changes diagnostics only. Exact accepted UpdateTabPromise still resets its log on about:blank, requires a nonblank URL plus loading and complete states, and removes its onUpdated listener only when those conditions are met. Consumers create the promise before the tab action and verify the returned tab ID and URL. A failure report can identify which two IDs mixed, but the patch does not filter stale events or establish the cause of the intermittent failure. No test ran.

Scope: WebExtension click-handler test diagnostics.
