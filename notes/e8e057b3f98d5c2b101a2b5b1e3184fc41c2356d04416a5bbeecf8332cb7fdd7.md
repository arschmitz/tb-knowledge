# The IMAP append SEARCH fallback stops forwarding the zero end marker

The search iterator returns zero when no next match exists. The original append fallback checked a message-key sentinel; this patch instead tests the UID directly before SetAppendMsgUid, so zero is no longer forwarded. The Expunge consumer already treats zero as no deleted match. This per-iterator end marker is separate from the original global ImapUid_None value and later zero-sentinel policy. No append, search or expunge was run.

Scope: IMAP append UID fallback sentinel.
