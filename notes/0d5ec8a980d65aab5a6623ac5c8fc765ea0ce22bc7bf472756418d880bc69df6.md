# Keep name-sort documentation aligned with the current comparator

The folder schema says name sorting is case-insensitive. The original landing explicitly used sensitivity:"base" with prettyName.localeCompare, while the fixed current code uses localizedName.localeCompare without that option. Recommend focused mixed-case and localized-name tests and a documentation check; do not infer a proven ordering bug from a locale-sensitive comparator alone. This is a current source-versus-description concern, not evidence of review approval for a new sorting rule. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: extension folder sorting.
