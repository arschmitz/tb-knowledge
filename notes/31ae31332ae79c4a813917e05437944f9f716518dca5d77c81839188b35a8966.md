# CardDAV tests wait separately for dialog closure and initial sync

The owned CardDAV task registers its dialog unload wait before clicking accept. It registers the directory-sync observer before opening the dialog, then awaits the dialog callback, unload and sync before checking prefs, saved logins and the selected book row. These are separate completion states. The shared dialog helper in this landing uses the harness open promise plus a timer turn; the fixed accepted helper later waits for load instead. The removed local helper's URL, overlay and stylesheet assertions are not present as direct assertions in the replacement. No equivalence of external harness checks or successful intermittent-test repair is proved. Required Bug 1978879 comment 58 remains unavailable, so this source-only partial has zero full-audit credit.

Scope: Thunderbird address-book browser tests.
