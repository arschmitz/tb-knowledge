# Await each attachment save-as picker in sequence

The current saveAs handler iterates attachments and awaits info.save(top.browsingContext) for each one. This preserves one picker at a time and lets the saved-directory preference from one operation guide the next. Scope this ordering to user-facing save-as dialogs; it does not imply that independent background writes must be serial. The outer handler itself starts the async helper without awaiting it. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mail attachment saving.
