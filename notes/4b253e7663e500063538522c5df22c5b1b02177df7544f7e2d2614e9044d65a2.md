# The initial certificate probe and exception action are separate from later confirmation UI

The initial probe sends protocol greeting/capability/quit commands to collect TLS security information; it does not authenticate the mail account or add an exception just by fetching. Its Add Exception action immediately calls rememberValidityOverride, with the permanence preference controlling duration. Accepted current code instead opens exceptionDialog and updates UI after exceptionAdded. Keep those phases separate when describing tests or security UI. Initial EWS is skipped and STARTTLS has only configuration coverage. The required removed review body keeps full-audit credit zero; no probe, override or test ran.

Scope: Historical account-settings certificate action boundary.
