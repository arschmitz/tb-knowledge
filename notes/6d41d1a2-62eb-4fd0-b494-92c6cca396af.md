# Windows initial setup launch and test coverage

The Commands desktop setup uses MozillaBuild 4 or newer with `-no-start -defterm -c`. The batch file preserves the runner exit code across its pause. The prerequisite installer uses PowerShell `Start-Process` with `-Verb RunAs -Wait -PassThru`, terminating errors, and the installer exit code. Its path passes through an environment variable rather than PowerShell source.

## Evidence

This is an uncommitted working-tree observation, not an accepted convention. The source baseline is `592cd39cc9e8edabb55c097df86732f4601f97ad`; several setup files were already untracked. The launcher flags match Firefox `mach.ps1` for MozillaBuild >=4.0. Microsoft documents the process options at https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1 .

The native release helper test list now includes `test/desktop-setup.test.mjs`. A separate Windows setup workflow runs helper and Electron tests. Browser fixtures supply an isolated fake `start-shell.bat` because terminal planning checks the file before simulated setup execution.

## Validation and limits

On macOS, 24 setup tests passed and one Windows-only batch execution test was skipped. After fixture changes, all three Electron setup tests passed again. Scoped ESLint passed and both workflow YAML files parsed. An independent source and before/after review passed. Native Windows batch execution, administrator prompts, MozillaBuild installation, a full bootstrap/build, and a Windows Thunderbird window remain unverified. CI is configured but has not run for these local changes.
