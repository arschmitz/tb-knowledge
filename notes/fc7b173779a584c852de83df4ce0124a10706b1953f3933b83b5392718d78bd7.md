# Graph calendar discovery uses manager initialization before explicit registry persistence

This landing returns manager-initialized Graph calendars backed by provider BaseClass properties instead of a standalone in-memory metadata class. The manager assigns id/URI, while name and readOnly use the property store. Explicit registration separately writes registry type/URI and flushes preferences; the startup path reads those values to reconstruct calendars. Initialization can already write changed nontransient properties once an id exists, so it is not a side-effect-free discovery object. The added test asserts the registry type after registration, not restart recovery or event-data caching. Item operations are still unimplemented in the original class, and later fixed memory/sync behavior is a separate phase. No profile restart, Graph server request or test was run.

Scope: Graph calendar discovery and registration.
