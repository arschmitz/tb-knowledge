# Crypto address normalization is not shell escaping

getCryptParams strips a parsed display name and wraps the sender address in angle brackets, or preserves an explicit hexadecimal key ID. RNP uses args.sender as a key identifier. The 2024 cleanup removed quote-to-backslash replacement in this data value. Manual boundary proposal: normalize address/key data for its actual consumer and avoid adding command-line escaping to values passed through these library APIs. This does not establish a general escaping policy for subprocess arguments. Current stripEmail catches parser errors and can return an empty list, so the outer catch is not proof that every malformed address becomes a thrown error.

Scope: openpgp.
