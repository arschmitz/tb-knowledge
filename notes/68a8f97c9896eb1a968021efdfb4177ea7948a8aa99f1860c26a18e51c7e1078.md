# EWS same-server moves use explicit version fallback and ordered remote IDs

The original MoveItem path is selected for moves between folders with the same incoming-server object. Its Rust request omits ReturnNewItemIds through Exchange2010 and requests it for later versions; the callback receives an explicit sync-required flag rather than inferring fallback from ID-array length. The fixed shared Exchange path now covers same-server copies too. For returned IDs, the folder consumer checks lengths and maps headers by input order; legacy fallback starts a destination sync. Current EWS orchestration returns new IDs with a separate RequiresResync value. This is a checked implementation/caller contract, not proof of server ordering, complete metadata preservation or real old-server compatibility.

Scope: Exchange EWS same-server message copy/move.
