# Keep favicon page identity, icon location and image data separate

The accepted MailUtils helper stores only for http(s) page identities. A data icon can be stored directly; otherwise a cached favicon stops the fetch branch, and an uncached icon is fetched into a data URI before Places storage. The feed path discovers or downloads an icon and inserts the feed page in history before storage. Its comment still names the older Places API, so the rationale is historical and was not independently revalidated against paired Gecko. Keep pageURI, iconURI and dataURL roles distinct when porting API calls. Adjacent entries 987, 993 and 996 own completion, retrieval and wait changes; those are not duplicated here.

Scope: mail/favicons/dataflow.
