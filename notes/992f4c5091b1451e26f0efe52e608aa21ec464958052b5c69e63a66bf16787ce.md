# Mail selection events are independent of the displayed message

The mailTabs UI listener now listens for select on the about:3pane window and reads getActualSelectedMessages when a database view exists. It no longer derives selection notification from the loaded message URI. Keep selection ownership independent of message-pane visibility; a hidden pane still has a selected-message list. This is the inspected extension event contract, not a claim that all selections load a message. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: MailTabs selection event boundary.
