# Compose result delivery keeps a shared listener-failure state

At the fixed accepted revision, waitForOperationAndHandleResults uses one msgOperationException variable for the operation and its sequential listener loop. If per-listener message conversion or awaited onSuccess throws, the catch stores that exception; later matching listeners skip the success branch and receive onFailure. A rejected onFailure has no local catch in this loop. Do not read the window-lifetime race fix as a guarantee that listener failures are isolated. The four-extension regression covers successful sendNow details before and after background termination; it does not inject these failure paths. This is a conditional local source contract, not a reproduced failure or a claim that add-on script exceptions necessarily reject fire.async.

Scope: extensions/compose.
