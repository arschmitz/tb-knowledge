# Collect one Calendar refresh before publishing its rows

740 replaces incremental addItems calls with collecting stream chunks through Array.fromAsync, flattening them and adding the resulting items once. This supports a single sort and selection restoration for the refreshed range. The fixed accepted source additionally rejects a refresh cancelled while awaiting results and rechecks hidden state before publishing; those are later refinements, not changes attributed to 740. Materializing all results is different from merely increasing a stream queue and can still retain the full result in memory.

Scope: Calendar refresh publication.
