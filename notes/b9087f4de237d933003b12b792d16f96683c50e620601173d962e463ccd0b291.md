# EWS version fallback distinguishes stored errors from future server responses

For the checked EWS handler, no stored value or invalid JSON selects Exchange2007_SP1. An unknown identifier already stored for the endpoint instead errors. An unknown identifier received from the server caps to Exchange2013_SP1, while an absent/empty response identifier leaves the known value unchanged. The in-memory version changes before fallible preference persistence. D252323 accepts endpoint-only keys as reasonable for now; it does not prove every account behind an endpoint uses one version or that the legacy-ID symptom is fixed. Exact test equality avoids treating Exchange2013 as a match for Exchange2013_SP1. Static source/test inspection only.

Scope: EWS version request and persistence boundary.
