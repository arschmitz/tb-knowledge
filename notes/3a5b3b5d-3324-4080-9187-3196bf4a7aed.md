always-fail.html explicitly describes a harness check, calls testFailed with an expected-failure message, then calls finishTest. Its generated wrapper points to this file through the shared mochi-single route. The generated manifest marks the wrapper fail-if=true. ## Expected-failure contract

The sentinel says it deliberately fails to test the harness. The manifest sets `fail-if = ["true"]`. The inspected SimpleTest branch reports an unexpected pass when `expected == "fail"` and no failure was recorded. Test-runner interpretation of the manifest and its assignment to `SimpleTest.expected` remain outside this pass.

**Scope limit:** Source intent and expected-failure wiring are observed. Manifest interpretation by the test runner and an actual runtime pass were not verified. This sentinel does not directly assert every forwarding, duplicate-completion, asynchronous cleanup or preference-restoration detail.
