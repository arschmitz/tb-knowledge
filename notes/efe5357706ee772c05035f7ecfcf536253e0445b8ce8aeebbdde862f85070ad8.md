# A copied MIME header has child allocations that need typed cleanup

mime_new copies an input header before allocating the object. Its accepted allocation-failure path calls PR_Free(hdrs), while MimeHeaders_copy can allocate all_headers and heads and MimeHeaders_free frees both before the outer structure. Recommend the complete header cleanup routine for that copied owner when changing this failure path. This is a static residual cleanup concern; the input header is not the owner being freed, and no out-of-memory leak was reproduced. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/mime/src.
