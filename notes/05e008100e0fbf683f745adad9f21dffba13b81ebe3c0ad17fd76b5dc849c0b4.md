# Password retry tests wait for stored login contents after protocol completion

The six SMTP/IMAP/POP3/NNTP result blocks add an awaited stored-login condition after protocol or message progress: exactly one login and the new expected password. The following username/count/password assertions remain separate; the predicate alone does not check the username. PromiseUrlListener resolves successful URL completion and has no login-storage condition. Current tests express the same checks with async searchLoginsAsync, while the owned patch used synchronous findLogins. Preserve both completion boundaries when changing these fixtures rather than treating a protocol callback as the saved credential. The 18 final field assertions lack messages; a local review repair should state each expected field with should. Source expresses these test conditions without proving timing or helper/runtime outcomes.

Scope: Mailnews password retry tests.
