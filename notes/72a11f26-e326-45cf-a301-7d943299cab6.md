# Write XPIDL method summaries and parameter descriptions as complete documentation

For touched XPIDL methods, put a blank line after the short method summary before longer detail so readers and generated documentation can separate them. Start @param descriptions with a capital letter and end sentences with punctuation. D203799 reviewer explicitly called both conventions out on nsIMsgOutgoingServerService.idl. The accepted 2024 file still has mixed older wording and punctuation, so this is a justified review/style rule to apply to new or changed documentation, not a claim that every historical line already conforms.
