# Object-based OAuth registration overwrites built-in and scheme privileges before freezing

The landing replaces positional registration arguments with an IssuerDetails object and updates the real extension caller to pass named fields, including issuerIdentifier. Registration copies the object, then overrides builtIn and useSchemeRedirect to false before freezing it. The registration test deliberately supplies builtIn:true and expects false; this checks stored details, not a login flow. Fixed accepted storage later removes schemeRedirect instead. The review's object-ordering suggestion is adopted in this API, not a global rule for function arguments.

Scope: OAuth extension provider details.
