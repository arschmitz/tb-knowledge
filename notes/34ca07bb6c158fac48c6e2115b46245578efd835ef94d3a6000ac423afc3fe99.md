# Check rejection cleanup at the GPGME-to-RNP byte boundary

Proposal for deArmorTypedArray and encryptAndOrSign: release each successfully created native handle on success and rejection, and restore the caller's args.encrypt value when signing or dearmoring rejects. The historical helper throws before its destroy calls; the caller restores args.encrypt only after signing/dearmoring. Failed output-buffer extraction leaves a null result, so define how that failure reaches the caller. Do not infer a runtime leak, corruption or exploit from this static gap. Preserve byte arrays at the backend boundary and check the native output ownership contract before changing copies. Minimum test coverage: native input/output creation failure, dearmor rejection, failed buffer extraction, signing rejection and successful combined signing/encryption; assertions should state cleanup, restored state and expected error/result. No failure test or native crypto test ran.
