# Document byte counts and callback sequence in POP sink interfaces

The accepted nsIPop3Sink describes the begin/write/complete sequence but does not document incorporateWrite length units. The native implementation constructs a byte string using block and length; parser HandleLine status is not propagated by every write path. Keep units and lifecycle order explicit in documentation for this interface, rather than naming an argument length without its unit or claiming all parsing failures propagate. The current POP command tests distinguish TOP/RETR behavior; they do not by themselves prove LF-only header regression coverage. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: POP interface documentation and byte units.
