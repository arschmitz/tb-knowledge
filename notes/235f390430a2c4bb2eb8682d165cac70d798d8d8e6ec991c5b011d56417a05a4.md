# Use shell expansion that matches the build variable’s actual type

build-libotr declares LDFLAGS as a scalar string but stores configure arguments in arrays. Its Windows and Linux linker calls intentionally split ${LDFLAGS}, with a narrow SC2086 exemption, instead of using ${LDFLAGS[@]}. For this script, preserve the scalar-versus-array distinction. This does not recommend unquoted arbitrary input or establish that paths with spaces survive scalar flag splitting. This is static source evidence. No runtime, build or live accessibility validation was run. Full bug and review discussion remains pending.

Scope: Libotr scalar and array shell arguments.
