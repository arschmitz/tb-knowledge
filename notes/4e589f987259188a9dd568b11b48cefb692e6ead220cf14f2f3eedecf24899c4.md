# The temporary treescript bridge exposes the first action payload as merge-info

The June 2025 treescript adaptation takes the first action name and payload, assigns that payload to worker.merge-info, and lets revision pinning mutate its replacements. This is a shared dictionary alias in the inspected Python source, not a deep copy. The preceding landoscript follow-up reads the action payload directly; the fixed accepted pinning code again reads it directly and has no create_merge_info bridge. Preserve these stages when porting the payload consumer. The old one-key assertion has no message and does not check for an empty action list; current code also assumes a nonempty first action. Upstream action resolution and worker execution remain untested dependencies.

Scope: Thunderbird release merge automation.
