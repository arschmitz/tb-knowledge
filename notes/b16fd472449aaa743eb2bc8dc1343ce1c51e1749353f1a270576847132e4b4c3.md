# Custom column identity and its normalized CSS hook are different namespaces

Accepted makeCustomColumnCell lowercases column.id to produce the dashed <name>-column class and dataset.columnName; persisted columnStates and the DB handler still use the original column.id. Later lookup/removal normalizes the CSS hook the same way. A scoped naming recommendation is to retain that conversion boundary rather than rename persisted IDs to match CSS presentation. This study does not establish a universal character rule or collision guarantee for extension IDs. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
