# Keep form-picker fixtures with the widget tests that use their controls

The landing moves formContent HTML and EML fixtures into the widget test files directory and changes unrelated drag/drop input to sampleContent. Current form-picker tests use that widget-local HTTP document and read the matching EML from disk. The HTML contains native date/select/datalist/details controls. Keep these control fixtures distinct from generic message drag fixtures; this is a scoped fixture-ownership recommendation rather than a global files-directory rule. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Form-picker fixture ownership.
