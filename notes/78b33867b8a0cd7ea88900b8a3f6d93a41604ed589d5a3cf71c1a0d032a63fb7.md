# Recheck the active buffer preference consumer after the Panorama adapter changed

Entry 2113 namespaces mail.bufferRows as mail.panorama.bufferRows and updates the five cache-test helpers together. Those historical tests deliberately fill buffered ranges from both ends and check insertion/removal among cached and empty slots. At the fixed accepted revision the named LiveViewDataAdapter and TreeDataAdapter production files contain no mail.panorama.bufferRows string, while one test write remains. The current adapter asynchronously counts/selects messages after sorting and derives from the common tree adapter. A test setting alone is not proof that a preference still controls production behavior. This is an exact presence check in the three named files; it does not claim all runtime preference access is known. The surviving setting needs a scoped test-purpose check before changing it. No preference behavior, cache-performance, rendering, runtime or accessibility test ran. Full discussion is pending.

Scope: Panorama adapter preference and test scope.
