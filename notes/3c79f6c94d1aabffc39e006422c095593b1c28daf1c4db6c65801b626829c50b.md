# The removed threaded-deletion guard checked a result still set to NS_OK

The preimage initializes rv to NS_OK, calls GetThreadContainingIndex without assigning its result, and then checks rv with NS_ENSURE_SUCCESS. That check reads the unchanged success value. The patch removes this dead check; it does not fix an uninitialized rv read. The new expanded-root path separately assigns and checks the result of base RemoveByIndex. This is exact historical source evidence, without a reproduced failure or a claim that all helper results are handled.

Scope: Threaded DB view deletion result handling.
