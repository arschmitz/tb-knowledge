# Match browser test names and registration to the local family

Manual naming proposal for these mail/calendar browser tests: retain browser_ followed by a concise feature name and .js, such as browser_messageBodyAs.js or browser_threadTreeSelection.js. New descriptive task names in the selection and calendar drag families use test plus a CamelCase behavior, such as testSelectionRestoredOnContextClose or testMonthViewDragEventItem. Existing body-mode tasks use test_email_menubar and similar underscore forms; do not claim the whole tree is already uniform. In the split mail/base browser manifests, register a new test beside its alphabetical neighbors as the manifest instructs. Moving a test to menus or widgets also moves its manifest and support-file context.

Scope: test-naming.
