# Filtered calendar reads recheck visibility before committing items

After collecting iterator results, the filtered-view mixin first checks whether the iterator was invalidated, then checks disabled/composite visibility before addItems. Iterator cleanup still runs when the new visibility check skips results. The ICS cache-toggle regression compares one month cell with the new calendar ID after a one-second late-arrival window; it does not force every provider race or directly check manager membership. No cache change or browser test ran.

Scope: Calendar filtered-view asynchronous item commit.
