# Folder-ID callers must handle missing0 before deliberate insertion

This migration makes lookup return a numeric folder ID, with0 meaning no match. Insertion deliberately fails on a duplicate rather than acting as get-or-create. A caller that wants creation must handle0 first. The historical JS root getter used ??, which keeps0 and skips insertRoot; accepted current code uses ||. POP3 nondeferred rootMsgFolder reaches that inherited getter. Current CreateNewDB also looks up before inserting only for 0. Preserve this exact numeric-sentinel contract when choosing a fallback; it is not a global rule favoring one JavaScript operator. The normal folder bridge rejects0/missing rows. Static source only; no new profile, build or test run.

Scope: Panorama numeric folder identity and incoming-server creation.
