# Distinguish idle database retention from the open-count budget

Idle cleanup closes a database only when its last-use time is old and its size is strictly below mail.db.keep_open_size. The separate maximum-count pass can still close a large database. It sorts by log10(size) multiplied by lastUseTime and removes the lowest score, so the policy is size-biased rather than strict least-recently-used order. Do not describe a database above the threshold as permanently exempt. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Message database retention policy.
