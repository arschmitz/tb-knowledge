# Trace account-config assertion messages through their wrappers

The owned test adds incoming and outgoing password checks but labels both as incoming server username. The historical assert_equal_config wrapper builds a field message, while its assert_equal helper omits that message from Assert.equal. The fixed accepted helper now passes a generated message directly, but the two password labels still identify the wrong field. A focused repair should pass the expected behavior to the actual assertion API and name the incoming or outgoing password. For example: Incoming password should equal the supplied password. This is a proposed diagnostic correction under the current writing rules, not a source implementation change or a finding based only on the word should.

Scope: Account creation test diagnostics.
