# After an extension wakeup, validate the tab through the tracker rather than its browser

Bug 1893831 showed the first menus.onClicked event after a Manifest V3 background restart failed. A mail3pane tab can have no linkedBrowser when no message is selected, so copying the upstream browser-tab check through linkedBrowser was invalid in Thunderbird. The accepted listener converts the native tab before wakeup, checks tabTracker.getTab after wakeup to detect a closed tab, and passes nativeTab.linkedBrowser (which may be null) as pending browser for fire.sync. Preserve the clicked tab identity across asynchronous wakeup and allow Thunderbird tabs with no message browser.

Scope: WebExtension menus.

Paths:

- `mail/components/extensions/parent/ext-menus.js`
