# Current empty discovery bypasses the sync-selection step

Historically the two inline discovery paths chose found/success when either address-book or calendar length was nonzero, otherwise not-found/info on the sync page. Current #fetchSyncAccounts instead routes both-empty results directly to emailAddedSuccessSubview, and routes any discovered resources to emailSyncAccountsSubview. Proposed scoped cases: both empty, only address books, only calendars and both types; a fulfilled empty result is separate from a thrown discovery error. This is a current state-branch comparison, not later chronological coverage. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: account hub discovery states.
