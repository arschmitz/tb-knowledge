# Use separate pending promises for open, select and close events

The landing creates both TabOpen and TabSelect waits before triggering a foreground open; accepted browser_tabSwitch additionally uses tabClosePromise and tabSelectPromise for the corresponding helpers. Scoped syntax/naming recommendation: name each pending wait by the event it observes and register all expected waits before the action. The historical patch briefly reused tabOpenPromise for switch/close, so favor accepted current names. This does not prescribe a global promise suffix for unrelated values. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: tab test synchronization.
