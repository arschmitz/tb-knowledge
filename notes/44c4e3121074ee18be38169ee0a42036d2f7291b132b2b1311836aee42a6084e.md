# The checkbox preference helper loses its message through an extra argument

The fixed Thunderbird testCheckboxes helper calls is with actual checked, expected checked, wantedValue and then the intended message. The separately pinned Gecko browser-test harness declares is(a,b,name), so wantedValue occupies the message argument and the fourth string is ignored. That string also omits not for the unchecked expectation. This is a static caller/signature and expected-behavior diagnostic defect, distinct from merely omitting should. Check arity and the actual Boolean expectation before copying this helper. No test was run; the Gecko signature is identified separately and is not claimed to be the fixed comm parent.

Scope: Preference assertion diagnostics.
