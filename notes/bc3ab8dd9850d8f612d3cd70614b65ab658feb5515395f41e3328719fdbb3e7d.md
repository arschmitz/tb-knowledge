# Search Messages drag data has separate message, URL and file-provider roles

ThreadPaneOnDragStart writes message URI, source URL, file-promise URL/provider and destination filename flavors per selected message. Its comments distinguish Windows file-URL fetches, Linux single/multiple-message handling and the macOS flavor provider. text/plain remains because the provider cannot obtain text/x-moz-message in this path. The calendar test builds a DataTransfer directly and checks event title/body after a drop; entry 2033 removes its claim to mimic the retired shared handler. This synthetic test does not exercise OS drag-to-filesystem behavior. Preserve data roles and platform coverage limits when removing a flavor. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.
