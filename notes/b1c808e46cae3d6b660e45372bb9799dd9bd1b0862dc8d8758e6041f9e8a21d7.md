# Updated OS-auth callers no longer pass a preference name to LoginHelper

The inspected password manager, privacy pane and QR export callers use getOSAuthEnabled() without a preference-name argument. The privacy setter passes only the checkbox Boolean to setOSAuthEnabled. The original port also adds an explicit signon.management.page.os-auth.locked.enabled false default. Current callers separately preserve primary-password and authorization paths; the accepted token.hasPassword check is a later difference from the original empty-password probe. Existing capability guidance remains separate. LoginHelper implementation, OS prompts and the unavailable Bug 4/full review were not read; this source-only API migration is not proof of platform support or successful authentication.

Scope: Saved-password helper API migration.
