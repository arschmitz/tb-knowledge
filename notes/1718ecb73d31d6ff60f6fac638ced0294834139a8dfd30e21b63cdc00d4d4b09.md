# External-key text normalization does not establish key validity

The current key helper strips a leading lowercase0x, removes ASCII spaces and uppercases the text. For40characters it keeps the last16; for 64 it keeps the first16. The HTML pattern separately constrains allowed hexadecimal/grouped input shapes, and the later completion caller separately requires a matching public-key user email before saving. These are distinct source checks, not proof that a string names a valid external secret key or that every fingerprint form works. The historical changed test types one valid16hex ID and does not directly exercise invalid input/fingerprint cases. Main Bug comment1 is unavailable and review remains unread; zero full-audit credit and no key/crypto/test run.

Scope: External-key text and identity boundaries.
