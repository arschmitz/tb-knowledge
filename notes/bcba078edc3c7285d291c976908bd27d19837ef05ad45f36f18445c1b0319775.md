# Custom-keyword tests distinguish valid-token survival from legacy add/remove state

The mixed-token test catches store rejection and directly checks that the valid keyword reached fake-server state; it does not directly assert malformed-token absence or overall operation success. The legacy test separately adds &aok- and removes a preloaded normalized &Aok-, then deep-compares the two state booleans. The helper waits for its URL listener. These direct assertions cover selected fake-server outcomes, not all punctuation, offline playback or provider interoperability.

Scope: IMAP custom-keyword fake-server test coverage.
