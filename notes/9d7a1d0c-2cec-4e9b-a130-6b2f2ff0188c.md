# Startup migration must preserve a server login preference

The former one-time mail.startup.enabledMailCheckOnce migration forced defaultServer.loginAtStartUp to true when the main window loaded, including for profiles that deliberately disabled it. The accepted fix removed that override and removed a legacy wizard helper that also enabled loginAtStartUp and downloadOnBiff. The wizard still selects a default account if needed. New account configuration has its own loginAtStartup: true default. When changing startup behavior, keep account selection separate from changing a stored server preference.

Scope: Account startup behavior.

Paths:

- `mail/base/content/messenger.js`
- `mailnews/base/prefs/content/AccountWizard.js`
- `mail/components/accountcreation/modules/AccountConfig.sys.mjs`
