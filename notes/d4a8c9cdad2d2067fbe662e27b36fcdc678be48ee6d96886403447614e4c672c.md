# The credentials-confirmation assertion message names the wrong username source

The changed test message calls the displayed username a result returned from autodiscovery, while its expected value remains emailUser.email. The original confirmation view is populated with username: stateData.email. This assertion therefore checks the submitted email, not a distinct returned username. Its value check and the null-config repair are separate from this misleading diagnostic wording.

Scope: Account Hub redirect-confirmation test diagnostics.
