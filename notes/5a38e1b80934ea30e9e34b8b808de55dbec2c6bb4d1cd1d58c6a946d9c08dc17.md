# Panorama compatibility tests bind real folder identity to fixture data

The new 2072 xpcshell test changes the SQLite root name to server1, asserts the created local account key and adds matching child folders before opening a per-folder DB. It checks scalar header fields, deep key arrays, flag persistence, forward/reverse enumerators and markAllRead’s changed-key result. This validates intended compatibility surfaces, not every legacy database method. Fixed tests also check cross-folder header rejection and folder identity. Keep account/fixture IDs aligned and check the actual caller/API version: current LiveView takes numeric folder IDs, replacing the old null-folder-object guards. Historical missing assertion messages are not defects by themselves. No test run occurred.

Scope: mailnews Panorama xpcshell compatibility tests.
