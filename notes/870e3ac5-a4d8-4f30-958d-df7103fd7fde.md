# Changing a thread child also invalidates the surviving root display

Deleting a child elsewhere must notify the view about the surviving root or dummy group row, even when that row remains in place. Check threaded, grouped and search/virtual-folder views. nsMsgViewNotificationCode::changed uses a positive count of 1 for one changed row; actual deletion notifications are separate. The regression test in 264 observes reply/group counts in another tab, with expanded/collapsed and cross-folder variants. Current source retains root invalidation and has later recovery improvements. Do not freeze the old corrupt-root behavior.

Scope: message DB view.
