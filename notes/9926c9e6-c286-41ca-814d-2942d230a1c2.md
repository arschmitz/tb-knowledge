# Calendar dialog listener ownership and a narrower dismissal contract

This adds inherited listener ownership to the [checked Save chain](353cc2f9-95b3-4347-ac57-c5ba2d03804f.md) and narrows its statement about native dismissal.

`PositionedDialog.show()` registers `#debounceResize` on the actual `window` for resize. The arrow callback uses this dialog, clears an earlier timer, and schedules `#update()` after 100 milliseconds. The timer keeps work pending until it runs or is cleared.

`PositionedDialog.close()` clears the trigger, clears the pending timer, removes the same resize callback from the same window, then calls the inherited close method. This is a checked registration/removal pair with a stable callback identity. It is separate from Save and cancel listeners registered on the dialog's own nodes.

The source mixin's `disconnectedCallback()` calls its inherited disconnect hook when present, disconnects its route controller, clears route-start state, and clears route data. The read `PositionedDialog` file has no disconnect cleanup method. Removal without the close path therefore needs a separate lifetime check; this note does not assert a demonstrated leak.

Correction: the earlier broad sentence that closing and native dismissal are blocked while Save is pending should be read narrowly. The checked JavaScript overrides ignore calls to `close()` and `requestClose()` while pending. `handleEvent()` calls `close()` for cancel. Native Escape, close-watcher default actions, and every inherited cancellation path were not fully traced or run. They are not proven blocked by these overrides alone.

Test relationship: the Create Save browser test directly checks keyboard Save, closing after success, and restored focus. That does not itself prove every pending native-dismissal path or listener release after a disconnected element. Those test links remain unresolved.
