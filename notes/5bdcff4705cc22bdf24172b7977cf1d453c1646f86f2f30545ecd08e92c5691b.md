# WebExtension attachment names follow header precedence and explicit fallbacks

The accepted emitter first reads filename from Content-Disposition, then name from fullContentType if the first result is empty. The 1910 landing used structured contentType.get("name"); that is historical, not the current extraction. Forwarded message/rfc822 parts receive ForwardedMessage.eml when no name is found. Deleted-attachment placeholders return their name even when it is empty. Keep these MIME cases separate when changing filename parsing. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: WebExtension MIME filename precedence.
