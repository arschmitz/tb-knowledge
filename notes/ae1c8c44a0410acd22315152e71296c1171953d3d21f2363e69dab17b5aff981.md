# Offline fetch uses a reversed key stack to preserve sequential input order

The fetcher copies input keys in reverse, reads LastElement and pops the key after its fetch completes. This preserves caller order while using a stack. It resets output stream and byte count before starting the next message, and continues only after successful storage/header updates. Failure stops the remaining queue and reaches the completion callback. The channel still passes a one-key list. This source does not establish parallel fetching, rollback of already stored earlier messages or full cancellation. No offline download ran.

Scope: Multi-message Exchange offline fetch queue and per-message state.
