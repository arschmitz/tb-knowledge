# Header values and raw serialization use UTF-8 types separately from field names

IHeaderBlock uses AUTF8String for unfolded values and whole-block serialization, while name(index) remains ACString. This preserves a type distinction at the XPCOM boundary without turning field values into blindly RFC2047-decoded text. The IDL documents possible UTF-8 field data; it does not itself implement field-name validation or supply non-ASCII tests. Keep these exact interface choices scoped to header data rather than treating every byte string as interchangeable.

Scope: message-header-xpcom-interface.
