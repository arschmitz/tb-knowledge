# Panorama folderDB and messageDB name service facades rather than row collections

The renamed folderDB/messageDB attributes expose nsIFolderDatabase/nsIMessageDatabase interfaces covering both primary and property tables. Their generated C++ getters return addrefed interfaces; separate concrete native helpers borrow database references. The shared JS fixture reads those named properties after account-manager service setup and clears its references in cleanup. This API rename changes callers and documentation, not stored schema or test expectations. Local variables called folders/messages do not imply the old public property names remain, and this is not a project-wide suffix rule. No interface, schema, cleanup or test execution ran.

Scope: Panorama public facade names and native receiver contracts.
