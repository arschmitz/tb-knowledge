# A terminal SMTP retry failure resets retry state for the next message

A first transient MAIL/RCPT response reconnects and returns with isRetry true. On the terminal reporting path, the added reset clears that flag so a later unrelated message can take its own retry branch. The fake MAIL handler always returns 451 and the regression asserts two attempts for each message; it catches listener rejection and does not assert the exact final error code. No SMTP run or failure reproduction occurred.

Scope: SMTP MAIL/RCPT 4xx retry lifecycle.
