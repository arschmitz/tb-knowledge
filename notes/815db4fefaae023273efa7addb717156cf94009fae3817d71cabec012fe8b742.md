# Append-copy state keeps the UID while key consumers remain explicit conversion boundaries

The owned append-state change stores ImapUid and marks temporary UID-to-nsMsgKey casts at undo/listener and offline-store boundaries. The fixed setter still casts for AddDstKey and SetMessageKey; the later completion path instead attempts MsgKeyFromUid before offline insertion. Preserve the typed stored value, the key-requiring consumers and the source phase separately. ImapUid is still an unsigned-long alias, and its documentation acknowledges that XPCOM does not simply prevent numeric casts. This landing and its review do not establish compiler-enforced UID/key separation or a migrated database.

Scope: IMAP append copy state.
