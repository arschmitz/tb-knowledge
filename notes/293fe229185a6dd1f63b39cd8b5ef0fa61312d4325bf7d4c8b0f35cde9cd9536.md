# Translate calendar promise rejection into an explicit failure status

The iTIP promise rejection paths use e.result || Cr.NS_ERROR_FAILURE before onOperationComplete. An exception without a native result must not accidentally report a successful zero status. The accepted collision-resolution modify path retains the same boundary. Preserve operation type, result and error detail when adapting promise-based calendar methods to the listener API. This study read a representative current path and all historical changed rejection branches; it did not run calendar operations.

Scope: calendar/base/modules.
