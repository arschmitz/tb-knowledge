# Pane locks follow the selected layout's resize axis and grid span

This landing chooses message-splitter lock targets with the layout. Classic view uses vertical resizing and locks only threadPane because folderPane spans the thread, splitter and message rows. Wide keeps both upper panes locked vertically; Vertical locks both on the horizontal axis. The actual splitter maps these directions to height/width and removes locks that no longer match the target set or axis. The added regression test directly checks Classic pane geometry through restored size, window changes, collapse/expand and a drag; it does not establish all-layout, keyboard or platform rendering behavior. Later accepted test preference handling uses pushPrefEnv/popPrefEnv and is a separate phase. The lesson is a scoped grid/consumer contract, not a general rule to lock or unlock every full-height element.

Scope: Three-pane layout and splitter geometry.
