# Keep disabled optional values in the draft

The Bug 2061214 implementation report describes Save preparation that omits disabled optional rows from the saved event without removing their draft values. Disabled rows also do not block Save through validation. This lets users turn a row off and back on without losing input. Apply this behavior to the calendar create/edit Save work described in the report, rather than treating it as a general Thunderbird convention. The report says an intentional mutation that included disabled rows triggered two exclusion assertion failures. These are AI-reported implementation and test results; the later verification did not confirm matching runtime binaries.

Scope: Calendar event Save optional rows.
