# Keep notification payload, DOM, class and file names as separate conventions

The notification boundary preserves backend CTA and URL keys, translates them to lowercase cta/url and dashed data-id attributes, uses dashed in-app-notification-* classes/tags, and uses InAppNotification class names. Its component modules use dashed filenames, while template IDs and include files retain inAppNotification... camel forms and browser tests use browser_inAppNotification*. For this component family, follow the convention of each boundary and preserve public payload spelling; do not mechanically convert every name to one casing. Generic class/tag naming rules already have shared evidence. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Notification boundary naming.
