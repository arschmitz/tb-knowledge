# Panorama message insertion uses existing references as a provisional thread graph

MessageDatabase::AddMessage resolves the first reference as threadId and the last as threadParent by looking for existing Message-Ids. It sets a zero threadId to the new row key in SQL and in the cache before notifying listeners. The code marks this as an unsustainable hack that assumes parents already exist. FindByMessageId returns zero both for no match and for statement errors, and duplicate Message-Ids have undefined selection behavior. Do not treat this path as complete out-of-order thread reconstruction or error discrimination. Static source only; no database or threading test ran.

Scope: panorama.
