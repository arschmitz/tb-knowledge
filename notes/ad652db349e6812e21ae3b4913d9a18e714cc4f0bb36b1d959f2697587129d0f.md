# Recent folder selection, ordering and limits are separate query stages

Entry 1303 filters candidates before sorting and applies a positive limit at the end. The accepted extension query now prepares lastUsed/lastUsedAsDestination date criteria, filters, chooses an explicit sort, and resolves limit -1 through mail.folder_widget.max_recent only for a recent query. Preserve those stages when changing this API; filtering non-recent folders does not imply recent ordering. The old recent field is now deprecated in favor of lastUsed and sort. This is scoped current API guidance; no performance measurement, limit test or boundary-date test was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Extension folder query stages.
