# Qualify compose file drops before showing the attachment overlay

The directory fix accepts an nsIFile only when isFile() succeeds. The accepted external drag branch shows the overlay only when getValidAttachments returns entries; it no longer has the historical empty-list else assignment to dropEffect. The regression checks that a directory produces no shown overlay, no drop and no attachment. Positive tests wait for show after the showing and animation phases. Preserve the difference between candidate filtering, overlay state and actual attachment creation. The 500 ms negative wait is the inspected test choice, not a proposed general testing rule. No drag test was executed.

Scope: mail/compose/drop-qualification.
