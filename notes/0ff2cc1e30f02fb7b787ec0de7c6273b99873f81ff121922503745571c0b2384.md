# Incomplete Exchange custom-OAuth fields leave the advanced configuration without overrides

The capture path first clears copied OAuth settings and only creates custom details when OAuth2 is selected, default mode is unchecked and both tenant/application inputs have values. Empty custom inputs therefore avoid the old nonemptystring exception and leave no custom details for the backend helper to apply. The added test takes the advanced route with those inputs empty and checks actual override/app/tenant property names rather than an oauthSettings bag. These are source and negative-assertion contracts; native property exposure, account creation, authentication and service acceptance were not executed or established.

Scope: Exchange capture guard, advanced action and backend override receiver.
