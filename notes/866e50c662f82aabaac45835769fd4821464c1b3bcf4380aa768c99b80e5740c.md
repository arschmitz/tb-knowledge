# Missing header newlines warn and continue instead of aborting ParseHeaders

ParseHeaders keeps the empty-buffer success case, but a nonempty header block without terminal CR/LF now warns and calls MsgLogToConsole4 before continuing its bounded scan. The helper logs a mailnews script-console message. A later accepted test executes a long no-linebreak header followed by a blank line, without directly asserting parser state, byte position or an injected database failure. Keep that limited test scope separate from a crash or index-corruption proof.

Scope: Local mailbox header-parser continuation.
