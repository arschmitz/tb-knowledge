# Undo availability follows the main window transaction manager

SetupUndoRedoCommand chooses the current tabmail window or the most recent mail:3pane window. It returns false when a standalone .eml has no main window, queries messenger.canUndo/canRedo and transaction type, and updates the corresponding menu label. The removed canUndoDeleteOnServer capability no longer gates this path. Removing that capability does not make every operation undoable; the transaction stack still determines availability. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
