# Notification sound playback is separate from notification policy and preview policy

MailNotificationManager.playSound uses the supplied branch type and URL to choose the system event or a file-based custom sound. The method does not check the sound-enabled Boolean or Do Not Disturb state. New-mail notification handling checks those conditions before calling it; chat applies its own sound/focus conditions, and both Settings previews call it directly. Thus the later new-mail DND guard is not a global mute for all callers. Current custom Audio ownership is extracted to NotificationSounds; that later structure is separate from this historical move. Tests inspect MockSound records or automation-ended Audio src, not actual audible output. No sound or UI test ran.

Scope: mail and chat notification sound.
