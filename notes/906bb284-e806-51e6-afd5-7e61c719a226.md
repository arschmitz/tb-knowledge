# nsMsgProgress::OnStateChange behavior in mailnews/base/src/nsMsgProgress.cpp

Caches every flags/status pair, then visits weak listeners in forward order. Dead references are removed. Live listeners receive the original progress/request/flags/status. Firefox iterator checks current array length and adjusts positions on removal; listeners appended during callbacks can be visited in this broadcast. This is not a snapshot dispatch.

## State read

- mListenerInfoList; callback arguments

## State changed

- m_pendingStateFlags; m_pendingStateValue; dead entries removed

- Native compose listener can unregister and abort at3350-3382; dialog listener closes its window at28-51.

## Result and consumers

NS_OK after synchronous callback loop; registered callback return codes discarded. UI completion notification is distinct from transport promise completion.

## Errors

Dead listener is cleaned up, not reported as error.

## Async completion

## Ownership and cleanup

Each weak referent is held by temporary nsCOMPtr while callback runs. Loop owns no persistent strong listener reference.
