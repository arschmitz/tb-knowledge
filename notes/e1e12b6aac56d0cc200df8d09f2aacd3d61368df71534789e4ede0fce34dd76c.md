# Biff traversal updates deadlines in place and keeps shared-target retries due

The owned biff refactor appends new server entries and sorts in SetupNextBiff, replacing removal/reinsertion during PerformBiff traversal with in-place deadline updates. A call-local targetFolders list suppresses repeated destination folders within that pass. A first due server advances its deadline even if busy or unable to prompt; a later due server sharing that target keeps its old deadline for a later pass. This does not track completion of asynchronous downloads. Additions are deduplicated and removal deletes matching entries, but removal still does not reset the next timer. Empty scheduling does not itself cancel a timer, and timer-creation failure warns while returning NS_OK. The checked preference caller ignores add/remove failures before saving DoBiff. No timer, reentrancy or network test ran.

Scope: mailnews/base/biff-scheduler.
