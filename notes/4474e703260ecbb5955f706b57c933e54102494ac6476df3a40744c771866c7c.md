# Keep the transitional UID assumption inside named IMAP helpers

At the fixed accepted revision, UidsFromHdrs and UidFromHdr still read messageKey. UidsFromMsgKeys clones validated keys, and MsgKeysFromUids rejects zero before cloning the values. Named helper functions state the TODO for future separation. A caller must not infer that independent UID storage is already implemented from these names. Prefer these conversion boundaries to spreading the temporary key-equals-UID assumption through new IMAP callers. Header/single-value helpers use assertions while array helpers return errors; those contracts are not interchangeable.

Scope: mailnews/imap/src.
