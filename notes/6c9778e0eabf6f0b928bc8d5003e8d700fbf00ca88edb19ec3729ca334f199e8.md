# Alarm loading excludes failed calendars so an empty reminder dialog can close

The alarm service counts an unresolved calendar as loading only when its currentStatus is a success code. The dialog closes when its alarm list is empty and the service is no longer loading. The comment-only change explains why failed network calendars are excluded; it does not introduce that behavior. The accepted getter also has a later guard for an unregistered calendar, which is a separate phase.

Scope: calendar-alarm-loading-close-contract.
