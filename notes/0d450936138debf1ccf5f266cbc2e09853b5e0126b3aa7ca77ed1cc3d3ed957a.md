# Historical exact-count stream copy rejects EOF before the requested byte count

The historical SyncCopyStreamN copies exactly the requested uint32_t byte count, limits each read to the remaining count and rejects zero-byte input before completion. It delegates complete writes to SyncWriteAll. Errors can leave already-written output and the API returns no partial byte count. The fixed accepted source no longer contains this helper; its SyncCopyStream contract instead copies to EOF and reports bytes copied. Keep those phases and contracts separate. No IO or test ran.

Scope: Mailnews synchronous stream utility contracts.
