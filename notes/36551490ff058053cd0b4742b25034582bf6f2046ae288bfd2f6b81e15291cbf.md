# A single mbox message requires a separator even when the read starts past EOF

Entry 1287 makes the initial parser state require a From separator. Seeking past a file’s end can yield EOF rather than an I/O error, so accepting empty initial input would hide a corrupt token. The accepted parser treats missing initial From data as malformed, while its post-message state accepts EOF. Keep these two parser states distinct. This is a scoped parser contract; no malformed file or seek was executed and discussion remains pending.

Scope: Mbox initial separator validation.
