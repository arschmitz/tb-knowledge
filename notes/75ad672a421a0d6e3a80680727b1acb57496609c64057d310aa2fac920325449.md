# Thundermail OAuth keeps production and staging issuers separate with PKCE

Thundermail production and stage hosts map to separate issuers/endpoints while sharing OIDC scopes and the desktop client ID. Both enable PKCE, the proof-key flow whose consumer creates an S256 challenge and submits the verifier during authorization-code exchange. OAuth2Module uses issuer-specific oauth:// login origin and scope realm. Current extra external-browser/issuerIdentifier settings are later source context, not part of the assigned patch. No live login, token, endpoint or protocol-capability validation.

Scope: oauth-thundermail-provider.
