# Check state mutation before returning from an offline-copy guard

The crash fix checks that the copy-destination list is nonempty before removing index zero and returns NS_ERROR_UNEXPECTED otherwise. Accepted ClearOperation clears m_operation before this guard, while persisting the bitmask happens afterwards. Therefore failure can already change in-memory state; it is not an atomic unchanged-state return. The inspected replay helper ignores the ClearOperation result. The earlier multiple-copy uncertainty remains separate and is not fixed by the bounds guard. Review mutation order and caller error handling with the guard. No startup crash or replay runtime was reproduced and no new focused test landed here.

Scope: mailnews/db/offline-copy-guard.
