# S/MIME CSR keys are generated directly in the NSS store

The account end-to-end encryption pane calls nsICertGen to generate a certificate signing request. The C++ code asks the internal NSS slot for a permanent, sensitive private key, builds and signs the request, and returns text for the selected file. The user later imports a matching certificate; NSS can match it to that stored private key. Bug 1581796 rejected temporary WebCrypto and shell/OpenSSL routes for this workflow because they complicate private key storage. Current code retains this design. Review S/MIME CSR changes for where the private key persists, not only for the request text.

Scope: S/MIME certificate requests.
