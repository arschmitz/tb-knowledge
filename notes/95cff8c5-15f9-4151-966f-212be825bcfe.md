# Storage offline journal methods preserve created records and turn remote deletions into flags

## Directly observed state transitions

`getItemOfflineFlag(null)` resolves null. For an item, the offline model chooses
its event or todo statement, binds this calendar ID and item ID, then reads
`offline_journal`; a falsey value is normalized to null.
`setOfflineJournalFlag` chooses the matching UPDATE statement and binds
`flag || null`. UPDATE failure is logged and swallowed. Neither method updates
the recurring flag caches itself.
Evidence: [calendar/providers/storage/CalStorageCalendar.sys.mjs:429–432](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L429-L432), [calendar/providers/storage/CalStorageOfflineModel.sys.mjs:19–48](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageOfflineModel.sys.mjs#L19-L48), and
[calendar/providers/storage/CalStorageStatements.sys.mjs:645–655](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageStatements.sys.mjs#L645-L655).

`addOfflineItem` writes CREATED. `modifyOfflineItem` leaves CREATED or DELETED
unchanged; otherwise it writes MODIFIED. It sends operation success after this
choice. `deleteOfflineItem` physically deletes a CREATED record, turns MODIFIED
into DELETED, leaves an already DELETED record unchanged, or writes DELETED when
no old flag exists. It sends `onDeleteItem` after the choice. `resetItemOfflineFlag`
writes null. These methods distinguish a pending upload from a deletion of an
item that previously existed remotely.
Evidence: [calendar/providers/storage/CalStorageCalendar.sys.mjs:437–480](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L437-L480) and [calendar/providers/storage/CalStorageItemModel.sys.mjs:1368–1382](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L1368-L1382).

The physical deletion request removes item and extra rows; the ordinary modified/
deleted flag requests change only matching event/todo rows. They resolve without
returning an item. The swallowed writer error means method settlement alone does
not establish that the flag was saved. No cancellation interface appears in these
methods. Connection and statement ownership is held by their shared model base.

## Validation and test classification

The new live recurring-cache probe directly checked CREATED persistence and a
reopened offline-created query. It executes the actual `addOfflineItem`, offline
model and SQL UPDATE. It does not directly test MODIFIED/DELETED transitions,
remote upload playback, or writer failures. The saved wipe-preservation test
covers CREATED state retained in a reopened cache. The existing CalDAV playback
records are separate provider evidence and are not promoted to a direct test of
every local transition.
