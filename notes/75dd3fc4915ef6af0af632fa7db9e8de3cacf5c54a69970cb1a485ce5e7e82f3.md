# Next-UID tracking changes type while the folder cache keeps signed casts

The tracking patch passes ImapUid through the STATUS comparison and SetServerCounts instead of signed temporaries. Folder cache persistence still uses GetCachedInt32 with a pointer cast and SetCachedInt32 with a value cast. The original missing sentinel is ImapUid_None; accepted later code uses zero. This is a bounded type and serialization boundary, not a cache format migration or demonstrated full-range round trip. No tests change.

Scope: IMAP next-UID tracking and cache boundary.
