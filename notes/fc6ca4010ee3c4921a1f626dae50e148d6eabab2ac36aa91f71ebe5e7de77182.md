# CardDAV discovery logs and rethrows request rejection before its response fallback

This logging landing changes ordinary native connection rejection to Connection error and wraps discovery tryURL in a warning-and-rethrow catch. HTTP207 plus parsed XML remains the success condition. A rejection is logged and rethrown, so it does not become the null response used for normal discovery fallback. The accepted source retains warning plus rethrow despite the reviewer concern; later OAuth-origin and redirected-URL handling is a separate phase. This is static control-flow evidence, not a request or retry result.

Scope: CardDAV address-book discovery errors.
