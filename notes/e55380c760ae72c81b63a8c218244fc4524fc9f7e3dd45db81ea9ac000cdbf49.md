# Store compaction delegates database coordination to its listener

The store API documents an operation decoupled from folder/database details, with the folder used to locate the data. The mbox store gets the file path and starts MboxCompactor, while FolderCompactor owns the database work through callbacks. Scoped architecture recommendation: keep the file compactor and database coordinator separate rather than adding folder-view mutations to the low-level scan. This is the inspected separation, not an independently validated concurrency guarantee. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mbox store and database compaction boundary.
