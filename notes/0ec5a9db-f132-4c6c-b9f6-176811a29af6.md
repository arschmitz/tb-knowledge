# Filter cached notifications before giving them to the display manager

The initial notification storage keeps a complete feed. The display manager must receive only eligible items. In May 2024, one update path sent the raw feed to `NotificationManager`, so a future notification could appear early. Commit `d7197770e21fcfd0164dcc5038f5d46688fa3564` routed manager updates through `_updateNotificationManager()` and `getNotifications()`.

## Evidence

Bug [1909633](https://bugzilla.mozilla.org/show_bug.cgi?id=1909633) describes the unfiltered handoff. [D217746](https://phabricator.services.mozilla.com/D217746) accepted the fix. Its test supplies a future item with higher priority and a current item with lower priority, then checks that the current item is chosen. The current source still uses `_updateNotificationManager()` for the handoff.

## Validation and limits

I read the original May code, later fix, test, Bugzilla report, and browser review. I did not run the test. Eligibility rules have grown since 2024; use the current `NotificationFilter` rather than the first date-only filter.
