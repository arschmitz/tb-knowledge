# Set calendar title properties through the unescaped text-value contract

The historical export change puts title directly into NAME and X-WR-CALNAME serialized property lines. The accepted current property factory trims and parses serialized ICS text; the text-property value setter instead accepts an unescaped value. Proposed repair for this exporter: create each named property and assign the original title through value, then serialize it. Keep filesystem filename cleanup separate from the semantic calendar title. Minimum test coverage: a plain title, comma/semicolon/backslash, newline, trailing spaces and an empty calendar. The retained export test checks a plain NAME title and real event/HTML data; it does not establish these special-title cases. No parser, exporter or file-picker test ran, and no data corruption or injection result is claimed. Main review asks about empty selection and metadata compatibility, but does not review serialized-title escaping. Both reviewers accept the patch; this proposed repair is separate from that approval.

Scope: calendar/import-export.
