# Archive options change future destinations, so test an archive action

Commit `ee9b4849ecc4be69a7f5e1cde9a3569665b0db16` added `archiveRecreateInbox`. With folder structure preserved, the default stops at Inbox. When this option is true, the archive path includes Inbox. Changing the option affects later archives; it does not move old archived messages.

## Evidence

Bug [697706](https://bugzilla.mozilla.org/show_bug.cgi?id=697706) described the missing Inbox level. In [D208350](https://phabricator.services.mozilla.com/D208350), a reviewer requested a test that archives a message and checks for the Inbox folder. The accepted patch added monthly and yearly destination checks in `browser_messageCommandsArchive.js`, in addition to the settings dialog tests. The review also requested that new text move from DTD/properties to a Fluent `.ftl` file; the landed option string is `recreate-inbox` in `am-archiveoptions.ftl`.

## Validation and limits

I inspected the landed code, behavior test, Bugzilla report, and review discussion. I did not run the browser test. The Fluent request supports new strings in this area; it does not prove that every old string in Thunderbird uses Fluent.
