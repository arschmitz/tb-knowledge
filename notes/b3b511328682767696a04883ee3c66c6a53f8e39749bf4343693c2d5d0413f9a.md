# Retry a Sent-folder copy when no progress object exists

762 fixes a TypeError by checking this._sendProgress?.processCanceledByUser. It creates a replacement progress dialog only when an existing dialog was cancelled and the preference enables it; absence of a progress object does not prevent retrying the copy itself. Newer accepted code moves the same guard into _prepareFccRetry. Progress presentation is optional state, while the copy retry is the operation. No failing copy was injected.

Scope: Compose copy retry progress.
