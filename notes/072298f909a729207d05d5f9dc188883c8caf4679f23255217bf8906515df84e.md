# Lossy raw-string helpers still require a valid terminated buffer

parse_utf8_lossy and parse_utf16_lossy scan raw memory until a NUL and only then decode lossily. They have no length parameter or null-pointer check. Callers must supply a readable, valid terminated buffer for that scan; lossy decoding handles encoding, not pointer validity. The checked removal observer passes topic/data into these helpers, and its manual-testing comment is not a proof for every XPCOM string origin. No invalid-pointer or unterminated-input test ran.

Scope: Rust mailnews_string_glue unsafe input contract.
