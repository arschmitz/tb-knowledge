# Read-only CardDAV full resync still reaches two public write guards

After the Internal-method rewrite, fetchAllFromServer still uses public super.deleteCards for missing remote cards and public super.modifyCard for changed existing cards. Both public methods reject _readOnly. The deletion throws before the write; the modification error is caught and logged by the vCard parse branch. New cards use the internal bulk path. Sync-v2 can call this full resync after HTTP 400, while the inspected read-only and expired-token tests are separate tasks. This supports a focused check of read-only full resync with changed/deleted cards, not a claim that all sync fails or that this study reproduced a failure.

Scope: Thunderbird CardDAV read-only full-resync boundary.
