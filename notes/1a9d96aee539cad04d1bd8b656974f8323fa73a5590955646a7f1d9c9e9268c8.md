# X-Mozilla-Status2 contributes only the upper flag bits

The accepted parser reads exactly eight characters for X-Mozilla-Status2 and merges only flags2 & 0xFFFF0000. X-Mozilla-Status uses four characters and handles priority bits separately. This preserves the separate roles of the two stored headers instead of allowing Status2 low bits to overwrite Status1 behavior. Header length is a release-path condition; MsgIsHex is only asserted in the checked code. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
