# Database read updates do not replace IMAP server flag commands

The checked KillSubthread filter path separately calls MarkKilled, MarkRead and StoreImapFlags. Quick-search MarkAllRead similarly updates local keys and then sends Seen flags after successful local iteration. Keep local summary state and remote IMAP state as distinct responsibilities. A local key-based API migration is not proof that a server flag command became unnecessary. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
