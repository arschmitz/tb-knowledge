# Tie the add-on success notice to the successful branch

The current install-addon handler catches an installation error and shows an error notice, then reaches the success notice after the catch. A scoped review recommendation is to put success reporting on a success-only path and preserve loading cleanup for both outcomes. This describes the inspected control flow, not a reproduced double-notice UI failure or the cause of the historical configuration-test failure. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account Hub install result reporting.
