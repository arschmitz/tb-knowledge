# Attachment rewrite output is normalized before replacement copy

Successful stripAttachments stream completion joins the byte-string chunks and normalizes existing CRLF, lone CR and lone LF to CRLF before resolving. The caller awaits that rewritten data before copying the replacement into the original folder, then deletes the original and updates the folder. This is whole-message output normalization for this path, not a global rule to rewrite every custom fixture body or a proof of binary-content preservation/atomic replacement. No message or server operation ran.

Scope: Attachment delete/detach MIME replacement.
