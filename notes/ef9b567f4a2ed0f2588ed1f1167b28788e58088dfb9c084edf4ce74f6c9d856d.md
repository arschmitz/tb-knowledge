# The EWS XPCOM bridge owns arguments beyond the synchronous call

At the accepted bridge, ChangeReadStatus maps to Rust change_read_status and copies the borrowed ThinVec into the detached async operation. The task outlives the method scope, so retaining an owned value matters at this boundary. For this bridge, keep the generated C++ spelling, IDL lowerCamelCase method and Rust snake_case method mapping explicit; use the argument ownership required by the task. This is a scoped ownership and naming recommendation, not a project-wide rename rule. No Rust build or lifetime test was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: EWS XPCOM argument ownership.
