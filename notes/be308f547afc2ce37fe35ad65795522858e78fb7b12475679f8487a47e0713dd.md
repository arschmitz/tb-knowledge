# FetchMimePart reuses internal channel URIs and the registered message service

FetchMimePart expects x-moz-ews or x-moz-graph, asserts that expectation, returns the input URL and calls FetchMessage directly. The service is registered for internal and message schemes, and FetchMessage opens an I/O-service channel with the system principal. The assertion is a debug check, not release-mode URL validation. Keep message URL conversion at GetUrlForUri and avoid converting an already internal part URL again. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange part service boundary.
