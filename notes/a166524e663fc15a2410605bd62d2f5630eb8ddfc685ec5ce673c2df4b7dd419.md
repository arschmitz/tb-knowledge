# Calendar extraction accepts failed request status after non-empty text, not only abort status

Both completion callbacks reject only when the request status is unsuccessful and the captured content is empty. They do not check specifically for NS_BINDING_ABORTED. The listeners keep the first non-empty text chunk, and accepted completion then feeds the item description or extraction parser. Non-empty text does not establish message completeness or why the request failed; the patch adds no direct regression test.

Scope: Calendar email extraction and drag/drop.
