# Give a combined notification-order test a distinct scenario name

Current test code uses test_sortByStartAt for both a start-date-only fixture and a fixture that combines severity, start date and percent chance. A scoped naming improvement is to name the combined precedence scenario explicitly so failures identify the contract being checked. This is a proposed manual test convention; duplicate function display names in add_task are not proof that either test is unregistered. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: In-app notification test scenario naming.
