# Separate native form completion from exposing untouched errors

The original name/email fix evaluates both fields independently and requires both for completion. Fixed accepted auto form preserves that completion condition but exposes aria-invalid only when showErrors is true or the individual input was touched. It emits config-updated with detail.completed and hides manual configuration until complete. Current tests distinguish an invalid untouched name from a touched invalid email. Preserve completion and presentation as separate states; historical clearing of domain/username is not the current config shape. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Account Hub auto-form validation states.
