# ClearFlag closes a database it opens without taking ownership of a caller’s open database

1358 records whether the folder database was already open before flag lookup/change and closes it at the normal end only when it was not. Accepted ClearFlag retains that pattern, with an early locked-folder no-op. The normal-success ownership contract matters when updating folder flags; early error returns mean this is not a general guarantee that every failure closes the database. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
