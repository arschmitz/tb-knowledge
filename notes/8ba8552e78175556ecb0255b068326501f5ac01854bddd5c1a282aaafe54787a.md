# Nested view-update batches and unchanged selections avoid redundant UI work

The thread-tree shim counts nested beginUpdateBatch/endUpdateBatch calls. While the count is nonzero, it suppresses invalidation, scrolling and row-count callbacks. Selection restoration uses that batch while native lookup can expand threads. The current code also compares row count and selection indices before firing a select event, because a redundant event can reload the already displayed message. Keep batching balanced and distinguish notification suppression from message selection itself. The 2024 boolean batch flag is superseded.

Scope: message-list.
