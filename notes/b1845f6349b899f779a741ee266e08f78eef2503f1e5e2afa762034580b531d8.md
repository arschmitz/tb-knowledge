# Parser header buffer inline capacity rationale

In D232987, linked to commit 71579e92d447, reviewer BenC requested mozilla::Vector<char> instead of mozilla::Vector<char, 1024> for m_headers in nsParseMailbox.h. The stated reason was that expected header blocks exceed 1KB, so the inline buffer would enlarge each parser object with little benefit. This is a scoped review decision for this buffer, not a general rule against inline capacity. The approximate 16KB header size is the reviewer's estimate, not a measured result in this evidence. The captured inline shows the replacement, but no runtime or memory measurement is supplied. The proposed parser using a single read-only memory chunk was a future wish, not an implemented change.

Scope: mailnews/local parser.
