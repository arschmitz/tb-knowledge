# Keep failed credentials with their channel

A D319397 review reported a race when `mSuppliedPasswords` was shared across authentication channels and keyed only by origin, realm, and username. Because `PREVIOUS_FAILED` describes one channel's earlier prompt, another channel could replace the stored entry before failure handling and have its credential deleted. The proposed channel-scoped state and two-channel test were review recommendations; runtime tests were not run in the record. Recheck the current source before applying them.

Scope: Calendar authentication.

This is a workflow or historical planning observation.
