# The legacy EWS empty-folder path lacks completion when there are no messages

In the owned and fixed accepted implementation, the pre-Exchange2010 branch deletes any listed subfolders, then delegates completion to delete_messages only when message_ids is nonempty. If that list is empty after successful folder deletion, or both lists were empty, the function ends without calling the operation listener. The C++ success callback therefore has no completion trigger from this path for local reconciliation or URL stop. A scoped repair should explicitly complete the no-message success case while preserving the earlier error return. There is also a documentation mismatch: emptyFolder IDL promises useLegacyFallback=true for the workaround, but delegated message deletion sends No/false. The current C++ callback ignores that argument. These are static branch/contract findings; no old-server failure was reproduced.

Scope: rust/ews/empty-folder.
