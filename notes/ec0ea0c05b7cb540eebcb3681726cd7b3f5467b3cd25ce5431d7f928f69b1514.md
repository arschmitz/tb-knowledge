# Current EWS deletion treats an already missing remote item as retry recovery

The accepted delete operation handles ErrorItemNotFound as success with a warning because an earlier attempt can delete the server message without deleting the local database entry. Other per-item errors still become Processing errors. This scoped source contract prevents forcing a zombie local message on retry; it is not a rule to ignore arbitrary delete failures. Its operation is later context for the 1275 dependency API, with no service or retry execution in this study. This is source and test inspection only.
