# Attachment drag file promises return before the asynchronous save finishes

The message attachment drag setup registers application/x-moz-file-promise and its provider. Selected attachment-list items and the attachment-name drag handler feed this setup. The provider accepts that flavor, creates a unique destination file, sets the nsIFile out parameter, and calls saveToFile without awaiting it. In 3963, the macOS branch that removed the promise flavor was deleted; the patch did not add tests or wait for saved content. The fixed accepted AttachmentInfo.saveToFile separately awaits its download, but the provider callback still returns before that promise settles. Its current second parameter is isTmp, so do not infer a historical URL argument contract from the provider call alone. A later current destination-path guard is covered by the linked deduplication lesson. Native Cocoa flavor handling is a bounded unpaired dependency, and no macOS drag success or duplicate count was measured. Required primary discussion has missing human comments, so this is source-only knowledge with zero full-audit credit.

Scope: mail/attachments/drag.
