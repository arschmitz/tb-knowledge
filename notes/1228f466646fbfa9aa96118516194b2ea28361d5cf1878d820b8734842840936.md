# Special-use Trash flags should not replace an already selected Trash folder

Current SetBoxFlags applies Trash to a special-use folder only with the MoveToTrash delete model and when no folder is already flagged Trash. DiscoveryDone later reconciles the raw preference and discovered candidates, after its unverified-folder processing. Preserve these separate initial flagging and later reconciliation roles. This is not proof that every server returns only one special-use Trash folder or that the picker icon updates immediately; the author reported UI refresh issues but their causes were not read. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: IMAP Trash flag reconciliation.
