# A new MailStream header request after Close returns an error

The HeaderBlock documentation mentions an after-Close call, but Close clears mStream and EnsureHeaderInBuffer rejects that null pointer before checking the cached-header flag. A new HeaderBlock call after close therefore returns NS_ERROR_NOT_INITIALIZED. The inspected EWS consumer requests headers before close. HeaderAfterReading drains the stream; it does not explicitly test Close. This is a static boundary/documentation finding, not a reproduced caller failure.

Scope: MailStream close and cached-header API wording.
