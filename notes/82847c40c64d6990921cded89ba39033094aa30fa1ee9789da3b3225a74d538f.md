# Keep current EWS and RSS types aligned across extension conversion and schema

The current converter treats imap, pop3, nntp, rss and ews as native types. Unknown provider types receive the extension: prefix, and smart mailboxes are excluded. Historical 636 temporarily excluded EWS and omitted RSS from the native set. Entry 651 restores RSS in the converter and both manifest-version schema choices, preventing a built-in RSS account from appearing as extension:rss. The current getMailAccounts filter excludes im; its nearby preliminary-EWS exclusion comment is stale. Check conversion, schema and executable filtering together. Entry 651 added no RSS API test and points to Bug 1912394 for later test work, which remains unread. No API runtime test ran.

Scope: mail/components/extensions.
