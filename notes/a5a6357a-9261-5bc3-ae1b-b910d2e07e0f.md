# nsMsgProgress::OpenProgressDialog behavior in mailnews/base/src/nsMsgProgress.cpp

Rejects a null URL, creates an argument array containing this progress interface then compose parameters, gets Firefox's WindowWatcher service, and opens a chrome dependent centered _blank window. The native method returns the OpenWindow status, not the new window. sendProgress.js reads the two arguments and registers its UI listener after DOMContentLoaded.

- dialogURL, parentDOMWindow, parameters

## State changed

## Calls and triggers

- MessageSend._prepareFccRetry creates a replacement progress object and opens the same dialog at428-448.
- WindowWatcher::Service()->OpenWindow is an interface boundary; Firefox IDL specifies nsIArray argument expansion. Concrete window-creation body not traced.

## Result and consumers

nsresult from OpenWindow means that call returned; dialog DOM loading and message send completion occur separately.

## Errors

Null URL rejected by NS_ENSURE_ARG_POINTER. Service lookup and AppendElement results are not checked here; OpenWindow failure propagates.

## Async completion

Does not return a promise or wait for dialog load/send. DOMContentLoaded later initializes sendProgress.js.

## Ownership and cleanup

Local smart pointers own array, service and returned window references during the call; dialog keeps window.arguments[0]. Dialog unload unregisters its listener.
