# The EWS certificate check probes the HTTPS host root

In the owned EWS extension and fixed accepted source, Fetch Certificate sends an HTTPS GET to the selected hostname and port with path /. Both XHR load and error callbacks pass channel status and securityInfo to the shared certificate display. This is a TLS probe; it does not authenticate or send SOAP to the configured EWS endpoint. The outgoing pane passes the actual server type and uses443 for an omitted HTTPS port. Enabled incoming/outgoing EWS tests check success, hostname and View Certificate state through shared helpers; they do not assert the configured EWS URL or redirect chain. The accepted logger default uses mail.certificate-check.loglevel. Current classification and confirmation UI have later changes. Four relevant current checkButtons scalar assertions omit diagnostic messages, and the type JSDoc omits ews despite its branch. These are scoped static findings, not a runtime or global style claim.

Scope: Account settings certificate check.
