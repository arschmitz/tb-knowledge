# Limit headless drag exclusions to Linux and keep other address book coverage

GTK provides no nsIDragService in Linux headless mode because there is no display. The address book test checks MOZ_HEADLESS and platform before requesting the service; it only skips its drag-to-recipient block when the service is unavailable. browser.ini skips two whole drag-dependent tests only on headless Linux. D209789 review caught a condition that might have disabled all Linux drag coverage and accepted the narrower expression. Keep non-drag assertions running, and keep Windows/macOS and headed Linux drag coverage unless their own evidence shows a failure. Bug 1806870 remains open, so this is a test accommodation for an upstream platform limit.

Scope: headless address book tests.

Paths:

- `mail/components/addrbook/test/browser/browser_contact_sidebar.js`
- `mail/components/addrbook/test/browser/browser.ini`
