# Maildir move-path lookup and clone results are separate failure boundaries

Fresh full maildir patch read, including every changed Clone site. The reported move-path change checks GetFilePath before dereferencing folderPath and checks Clone before using toPath; other selected clone calls now propagate failure too. These are nsresult checks, relying on the successful-outparam contract, not explicit checks against every possible null success result or validation of every Append/Exists call. The needed historical filter caller only falls back to MoveIncorporatedMessage after success with !msgMoved and records a failed shortcut as failure. The exact fixed maildir blob no longer contains MoveNewlyDownloadedMessage; no later removal patch is claimed audited. Needed current scan/finish paths were read separately. BeginScan retains checked Clone, while the later rewritten FinishNewMessage uses EnsureSubDir and has a separate unchecked clone in its already-moved branch. That current example does not establish reversal of the error-checking preference or prove every path is protected.

Scope: Maildir file-path error boundaries.
