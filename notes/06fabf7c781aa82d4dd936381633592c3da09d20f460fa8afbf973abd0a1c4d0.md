# The notification-action prototype used placeholder IDs with a real mark-read callback

The fresh entry 2129 source implements action1 by marking the captured message read and consumes action2 without opening it. It supplies actions only for one new message; ordinary body clicks still display that captured message. The reviewer's mark_read/ignore naming question was explicitly nonblocking and those identifiers were not applied. The parser accepts known configured names in preference order and ignores unknown names. Added tests directly inspect action arrays/order and wait for mark-read state; Do Nothing does not independently assert no opening or unchanged read state. Fixed0b93 has later semantic IDs, validity functions and callback API, which are separate comparison context. Main Bug 410338 comments5–9/14/17 remain unavailable: this is a source-supported partial lesson with zero audit credit. No notification, macOS support or test run occurred.

Scope: New mail notification prototype action boundary.
