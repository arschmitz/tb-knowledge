# Resolve the owning database before flagging a cross-folder message

MarkThreadRead resolves GetDBForHeader for each header before querying and changing that message key in its owning database. A key alone does not identify a message across folders. Keep the owner lookup with the key when working on cross-folder thread state; do not substitute a view index, RFC Message-ID or one fixed database. The IDL contains older compression wording, so this note relies only on its folder-local identity and the actual current owner lookup. Static source and test inspection only. Complete Bugzilla and historical review timeline/inline context remains pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
