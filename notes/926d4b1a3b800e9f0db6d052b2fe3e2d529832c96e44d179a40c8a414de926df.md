# Unset preferences match neither pref_true nor pref_false

The pref_true branch defaults missing boolean preferences to false, while pref_false defaults them to true. Therefore an absent preference rejects both explicit-state requirements during normal filtering. The current tests verify that the absent test preference has neither a user nor a default value before asserting rejection. Preserve this asymmetric default pair if unset must remain distinct from explicit false; this is a scoped source contract. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source landing alone does not establish reviewer approval.

Scope: Notification preference tri-state defaults.
