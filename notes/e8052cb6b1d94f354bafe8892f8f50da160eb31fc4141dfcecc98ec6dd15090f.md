# Replace the old notification type class when the type changes

The container observes type and removes in-app-notification-${oldValue} before adding the new class. The base template carries only the neutral container class; the donation design is a type-specific modifier. Blog styling supplies its own icon, colors and content padding. Keep the remove/add transition when adding notification types so a reused element does not retain the previous theme. The current code synthesizes a class even for an unknown or removed type; this mechanism alone does not validate backend types or supply a styled fallback. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Notification type and class lifecycle.
