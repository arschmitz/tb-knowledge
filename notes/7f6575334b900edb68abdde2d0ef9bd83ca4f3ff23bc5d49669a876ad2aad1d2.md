# Match progress-listener registrations to the actual callback lifecycle

In the checked Thunderbird patch, messageProgressListener subscribes with NOTIFY_STATE_REQUEST and then requires a current nsIMailChannel with STATE_START. Printing and the link test subscribe with NOTIFY_STATE_WINDOW for their completion callbacks; the test also needs location events for hash navigation. D252222 explicitly rejected a STATE_IS_WINDOW registration value. The final message registration differs from the earlier WINDOW/NETWORK proposals in the Bug. Check the final source and callback together. No paired Gecko implementation or live event trace was inspected.

Scope: Thunderbird browser progress event contracts.
