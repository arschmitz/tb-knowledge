# API comments must describe ownership, identity, insertion and notification

Manual documentation proposal for nsIMsgDatabase header APIs: say whether the return is detached or live, who assigns its key, what a collision does, whether insertion happens now and whether listeners are notified. These details are not formatting rules. Check comments against the signature and implementation during later API changes. The current no-argument createNewHdr still contains the old note about a given key; that note belongs to legacy specific-key behavior and cannot prove the automatic-key method returns an existing header.

Scope: message-database.
