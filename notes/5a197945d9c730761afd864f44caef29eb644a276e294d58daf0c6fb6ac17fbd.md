# Follow the current attachment modification order instead of the retired deleter

The historical AttachmentDeleter changes forced an IMAP update between replacement copy and original deletion. That native deleter is now gone. Current AttachmentInfo strips content, copies the replacement, deletes the original and then updates an IMAP folder. Its listeners reject failed delete/update completion. Preserve that accepted order and await the helper boundary; do not teach the historical intermediate update as the current sequence. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Attachment modification lifecycle.
