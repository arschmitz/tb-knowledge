# Keep composition and message-display header preferences independent

The complete available D224213 review first opposes blanket removal of compose-header display, then considers merging preferences with migration. The author explains that this would also change composition choices; final acceptance retains two preferences because composition and message display have distinct meanings. Actual source keeps comma-separated mail.compose.other.header distinct from space-separated mailnews.headers.extraExpandedHeaders, and limits compose-only headers to outgoing folder ancestry with view-all override. This is the accepted bounded design rationale, not a rule that preferences can never migrate. Assigned main Bug 1802793 remains incomplete because comment1 is unavailable; this addition earns no complete audit credit. No live display test ran.

Scope: Custom message header preference compatibility.
