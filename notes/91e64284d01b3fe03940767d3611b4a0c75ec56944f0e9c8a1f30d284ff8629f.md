# The surviving credential-strip helper is not an unconditional URL sanitizer

The deleted InsertUsernameIntoUrl used URI parsing to add a username. The accepted StripUsernamePassword instead extracts optional output values and returns a sliced URL only when a parsed username is located; failures fall through to the original trimmed string. Its comment promises a URL without credentials more broadly than this fallback. Scoped documentation and test proposal: make the unchanged-on-failure behavior explicit, including malformed or password-only forms, before relying on this legacy helper. No credential-handling failure or caller exploit was reproduced, and its external dialog consumers were not audited. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: compose URL helper contract.
