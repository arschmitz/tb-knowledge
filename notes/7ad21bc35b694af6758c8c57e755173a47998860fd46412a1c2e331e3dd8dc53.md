# The extracted filter body query separates disabled state, custom-term errors and optional custom actions

The extraction returns false for disabled filters, true at the first body-requiring term/action, and propagates custom-term lookup/property errors while tolerating an uninitialized custom action. It is not entirely behavior-neutral to the old IMAP loop. The historical getter dereferences customTerm after NS_OK even when the registry has no object; current code later adds a null continue guard. Existing registry-miss knowledge is reused. This is an exact phase/nullable-result boundary, not a reproduced crash or blanket error suppression rule. No test ran.

Scope: Single-filter body requirement extraction.
