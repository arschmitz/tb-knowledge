# IMAP deletion helpers still use a transitional UID-to-key identity mapping

This corrects the earlier note 5bea928548f298bd9a453b2419842896e41cb634de3fb739eb1cb8ba520c95ab. At the fixed accepted revision, deletion notifications parse server UIDs, call MsgKeysFromUids and delete the returned message-store and database keys. The helper currently rejects UID zero and clones the remaining values; its TODO says independent UID/key lookup is a future step. The 2024 public independent-UID API was later removed. Preserve the named conversion boundary, but do not treat that helper name or the earlier note as proof that independent UID storage is already implemented. No network deletion or database test ran.

Scope: imap.
