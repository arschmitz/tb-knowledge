# OAuth custom details keep enable state separate from object presence

Incoming and outgoing OAuth initialization accept one optional IOAuth2CustomDetails object. A non-null object does not itself enable overrides: the JS entry checks the experimental preference and useCustomDetails. The IDL explains why the explicit flag travels with configuration across language boundaries and centralizes backing-setting logic. Protocol-specific native setters and the read-only normalized interface have different roles. This establishes the inspected configuration contract, not successful login, every caller path or a general rule against nullable APIs. No authentication or cross-language runtime test ran.

Scope: OAuth cross-language configuration.
