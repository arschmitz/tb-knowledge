# Subscription child enumeration does not preserve arbitrary insertion order

The inspected AddChildNode loop uses Compare to place siblings in reverse name order, and GetChildURIs walks from lastChild through prevSibling. This returns the reverse of the stored sibling order, not arbitrary arrival order. The new comment claiming insertion order is therefore too broad for unsorted arrivals. No real server, hostinfo output or runtime ordering experiment was run.

Scope: Subscription tree.
