# Filter extension-popup waits by the chrome document URI

The content-menu popup scenarios register the window-open wait before openDialog and filter the returned window by chrome://messenger/content/extensionPopup.xhtml. After that window is selected, they focus it and wait separately for non-about:blank browser content. The shared awaitBrowserLoaded helper checks the owner document, inner load state and caller URL predicate. A window-open event alone does not identify the popup or establish inner-page readiness. The owned change adds wait conditions; it does not directly assert maximization or dimensions. This is a scoped test-source pattern, with no reproduced intermittent result.

Scope: WebExtension browser tests.
