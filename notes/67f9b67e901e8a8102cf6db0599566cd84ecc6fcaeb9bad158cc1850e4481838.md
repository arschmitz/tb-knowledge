# A staged OAuth return-shape conversion must be read across both landings

Entry 1476 makes provider-test expectations use named object fields while getHostnameDetails still returns a tuple in that intermediate landing; 1477 changes the implementation and callers to the object. The accepted source and tests agree on the object shape. Treat the two exact changes as a source-consistency sequence; this note does not assert that the intermediate state ran in CI, caused a reported failure or was a rejected review request. For this API change, recommend updating callers, implementation and assertions as one verified boundary. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: OAuth tuple-to-object staging.
