# Compaction completion is abortable while the final summary is the reporting phase

OnCompactionComplete runs after preparing the new mbox and moving the original aside, but before installing the new store. A listener failure can still request rollback. OnFinalSummary runs afterward and its return value is ignored. The IDL says to keep non-instant GUI work until the final summary so the database/store commit interval stays short. Scoped manual API recommendation: preserve the distinct callback names, status-only commit signature and final status/size reporting signature; do not treat Complete as the final observer notification. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mbox compaction callback phases and naming.
