# Check observer state if the live permissions dialog is initialized again

init explicitly supports reusing an open permissions dialog: when _type is set, it calls uninit before adding the perm-changed observer again. uninit sets _observerRemoved to true; the exact file query shows no reset to false after the initial field declaration. A later uninit therefore skips its removal branch in that repeated-init sequence. Proposed scoped test: initialize the same manager twice, then tear it down and verify observer cleanup. Confirm a real repeated-init caller before attributing a user-visible leak. This is a current static lifetime concern, not a failure caused by deleting initWithParams. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: Permissions dialog observer lifetime.
