# Keep metric definitions with their component and verify generated names at consumers

Current configure registers mail/components/compose/metrics.yaml, cloudfile, addrbook and calendar/metrics.yaml in addition to general mail metrics. Definitions use snake_case such as compose_format, generated JS uses Glean.compose.composeFormat, and C++ uses its generated namespace. Proposed manual naming rule: place new metrics in the existing component definition file and use generated accessors rather than hand-normalizing them. Label values are separate contract strings; HTML/PlainText/PascalCase compose labels persist despite a2024 snake_case suggestion.

Scope: telemetry-schema.
