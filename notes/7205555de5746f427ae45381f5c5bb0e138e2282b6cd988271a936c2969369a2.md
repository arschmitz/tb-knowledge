# The EWS folder assertion passes strict options in its description argument

The edited EWS folder payload assertion calls window.assertDeepEqual(expected, folders, { strict: true }). The injected helper takes description third and options fourth, so this call uses the default non-strict object-key policy. Expected field values and array lengths are still checked; unexpected object keys are not rejected by that intended flag. A local repair should pass a nonempty expected-behavior message containing should third, then the strict options fourth. This issue is present in both the owned revision and fixed accepted call, independent of the changed localized display values.

Scope: Extension test assertion contracts.
