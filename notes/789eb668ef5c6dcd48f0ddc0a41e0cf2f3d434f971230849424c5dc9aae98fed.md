# Removing the offline-sync IDL keeps listener interfaces and direct C++ kickoff methods

The interface-removal landing deletes nsIImapOfflineSync and its XPIDL build entry, then makes Init and ProcessNextOperation direct C++ methods. The sync object still implements three listener interfaces and retains refcounting. ProcessNextOperation stays virtual because the original downloader class overrides it. Concrete service callers initialize the object, query nsISupports where needed and invoke the kickoff method directly. The accepted component table still registers the offline-sync contract. The later downloader class split is a separate phase. This evidence does not prove ABI compatibility, remote completion or a clean build.

Scope: mailnews/imap.
