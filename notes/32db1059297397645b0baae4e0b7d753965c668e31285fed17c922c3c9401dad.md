# Stream Exchange copy data through a channel listener rather than promising a synchronous buffer

Entry 1088 implements single-message CopyMessage by converting the URI, constructing a channel and opening it asynchronously with the supplied stream listener. Accepted FetchMessage retains the AsyncOpen boundary. CopyMessages for multiple messages remains NS_ERROR_NOT_IMPLEMENTED. The title says load into memory, but the implemented API streams data to a consumer; it does not return an in-memory message buffer or establish complete multi-message copy support. This note is based on source inspection. Tests were not run, and full review discussion remains pending.

Scope: mailnews/protocols/ews.
