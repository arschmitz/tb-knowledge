# The notification disconnect path removes keydown from a different receiver

At the frozen accepted revision, #showNotification registers keydown on document. #hideNotification removes that document listener. disconnectedCallback instead calls window.removeEventListener for keydown. The receiver is part of listener identity, so that window removal call does not remove the registration made on document. This is a scoped static mismatch in the current notification manager. It does not establish a reproduced keyboard failure or attribute the issue to historical entry 806, which adds backend clear handling. The historical new tests exercise clear-event removal while detached or unloading; they do not exercise this later document keydown registration. A disconnect-after-display keyboard scenario was not run. This record describes source behavior and a validation limit; it creates no new coding rule.

Scope: Notification manager keyboard listener receiver.
