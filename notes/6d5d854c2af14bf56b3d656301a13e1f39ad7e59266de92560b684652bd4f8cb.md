# The IMAP high-water checks use the live maximum message key

The two doMoves checks compare folder-info highWater with Math.max of the current folder messageKey values after awaited copy/update steps. They replace fixed expected values 6 and 11. The helper's explicit comment still assumes UIDs are used as message keys and names the separate migration, so this is a test expectation change rather than a general UID/key equivalence contract. Both modified Assert.equal calls still omit their message argument. Add a non-empty expected-behavior message when repairing those assertions. The inspected scenarios retain messages; no empty-folder or runtime behavior was tested here.
