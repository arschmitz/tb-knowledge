# DNS TXT records and strings inside each record are separate cases

Commit `67c20582122129e4bc650c6c963c35d9a3984dff` bounded a TXT string read to its declared length. Without that bound, reading a reply with several records could run into the next record and fail. Commit `b67b7f1045dcbc9d13ed86d6ba3819aac928c4a1` later walked all length-prefixed strings inside each TXT record. The later record shape uses a string array.

## Evidence

Bug [1571076](https://bugzilla.mozilla.org/show_bug.cgi?id=1571076) reported malformed UTF-8 from a TXT query. Bug [1583053](https://bugzilla.mozilla.org/show_bug.cgi?id=1583053) was reopened when the team distinguished multiple records from multiple strings within one record. [D209966](https://phabricator.services.mozilla.com/D209966) records the first fix and a lack of automated DNS tests. [D210189](https://phabricator.services.mozilla.com/D210189) records a failed Windows approach because ctypes arrays have no `map()` method; the landed follow-up uses `Array.from` after a cast based on `dwStringCount`.

## Validation and limits

I compared both commits with the current parser and read both bugs and browser reviews. I did not perform a live DNS query or run a Windows test.
