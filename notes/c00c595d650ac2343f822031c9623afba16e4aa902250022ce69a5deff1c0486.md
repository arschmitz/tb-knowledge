# Parser moves must release source streams before deleting Maildir data

The fixed MoveIncorporatedMessage drops inputStream after writing the destination and before deleting the source. Its comment names the Windows Maildir sharing violation that an open handle would cause. The code also updates the forward/reply pointer to the new live destination header before source cleanup. These are checked current refinements beyond the historical store-API rename; the rename alone did not prove their behavior. Destination attachment failure and committed-source deletion have separate paths. No filter move or Windows file deletion ran.

Scope: Parser move lifetime.
