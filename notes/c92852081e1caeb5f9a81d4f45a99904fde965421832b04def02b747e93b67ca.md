# Extension OAuth overrides select a domain key per hostname without replacing built-in registration maps

The landing separates extension issuers and hostname keys from built-ins. For each hostname suffix it tries a matching username-domain key before an unrestricted extension key, then falls back to built-in lookup only after extension lookup returns no match. Registration checks every normalized key before storing any and unregister removes only that issuer’s extension keys. The actual unrestricted branch also accepts a username with no email-like domain, so the new helper comment’s automatic built-in fallback sentence is too broad. Unit cases assert selected-domain fallback and restoration; no live OAuth or UI behavior was run.

Scope: OAuth provider extension registration and username-domain lookup.
