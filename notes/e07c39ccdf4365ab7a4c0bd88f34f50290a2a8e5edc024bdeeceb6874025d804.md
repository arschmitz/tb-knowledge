# The EWS update fast path must return the existing header before success

In the historical header-returning EWS callback, a message without an offline body still needs its existing database header returned. The patch adds existingHdr.forget(hdr) before the fast path returns NS_OK, matching the other successful branch. Rust's caller needs that returned header to populate fields and commit through the listener callbacks. The later accepted Exchange callback instead takes header fields as inputs and returns status; preserve that separate API phase. This is static ownership/caller evidence, not a reproduced sync warning.

Scope: Historical EWS message sync.
