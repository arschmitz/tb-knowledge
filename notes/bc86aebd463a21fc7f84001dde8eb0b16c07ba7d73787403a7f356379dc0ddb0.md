# Folder copy preconditions differ from the copy-service empty-list path

The folder copyMessages IDL documents a nonempty message array and directs JS callers to MailServices.copy.copyMessages. That service handles an empty array by notifying success and returning before folder copying. The checked local-folder receiver instead returns NS_ERROR_INVALID_ARG for empty headers. The same method name therefore does not establish the same caller contract. This patch adds only documentation; the source checks are static and do not prove all protocol behavior.

Scope: Message copy service versus folder receiver contract.
