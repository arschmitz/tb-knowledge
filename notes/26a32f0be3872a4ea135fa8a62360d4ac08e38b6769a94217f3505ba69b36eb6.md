# OpenPGP consumes prepared headers through the compose-security interface

MimeMessage passes the prepared top-level header string through nsIMsgComposeSecure rather than asking OpenPGP to rebuild a chosen field subset. Current protected serialization requests getHeaderString(true), which clones the Map and drops Bcc/Resent-Bcc; the separate recipient list still includes Bcc. OpenPGP rejects a missing prepared string and consumes it in its MIME writer. The current exclusion/unobtrusive branches are later phases beyond this initial interface patch. This is source data flow, not proof of standard compliance, S/MIME adoption or a crypto test result.

Scope: Compose MIME prepared-header boundary.
