# Match XMPP property JSDoc and optional parameters to the actual receiver

In the XMPP documentation patch, review replaces getter @returns with @type/@readonly and asks for optional parameter/default documentation. The final code applies property types, but keeps mixed null-union spelling and documents some defaults in prose rather than the exact proposed bracket syntax. Check the real constructor and builder: aLocalName is required, aQName defaults to it, attributes default to an object, and truthy attributes are copied. TextNode innerText is raw text while getXML escapes it. The tentative claim that optional arguments are implicitly nullable is not established as a general rule. No lint or test ran.

Scope: XMPP XML API documentation.
