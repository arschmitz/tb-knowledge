# Discarding an offline copy clears the database link without rewriting an untrusted mbox offset

Entry 1285 adds DiscardOfflineMsg. The accepted implementation skips the mbox DeleteMessages path because it could rewrite headers at a corrupt storeToken, and instead leaves the bytes for later compaction. Other stores receive a best-effort deletion whose failure is ignored. This is a scoped corruption-recovery decision; it does not guarantee immediate physical removal or successful compaction. No damaged mailbox or Maildir deletion was exercised, and discussion is pending.

Scope: Offline message corruption recovery.
