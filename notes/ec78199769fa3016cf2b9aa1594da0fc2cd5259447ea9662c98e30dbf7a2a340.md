# Choose Exchange hard deletion through the current delete model

The original EWS deletion landing only implemented aDeleteStorage. The current shared ExchangeFolder dispatcher hard-deletes when explicitly forced, when any ancestor is Trash, or for PERMANENTLY_DELETE. Otherwise it moves messages to the configured Trash folder through the same-server copy/move path. The current delete-model test covers the default Trash, a custom Trash and permanent deletion. Do not reuse the historical unsupported-soft-delete behavior as current architecture. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Exchange delete-model routing.
