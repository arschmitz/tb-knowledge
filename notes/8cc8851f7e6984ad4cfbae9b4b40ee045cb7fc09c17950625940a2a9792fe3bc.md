# Mailnews console helpers keep filenames as byte strings and error text as Unicode

The nsIScriptError migration changes MsgLogToConsole4 declaration, definition, historical macros and call sites together. Current error text remains nsAString while the filename is nsCString; Init no longer receives the old sourceLine argument. Newer current callers use nsDependentCString(__FILE__) rather than the owned nsCString copy in the 2024 patch. Manual C++ review proposal for this API: follow the receiving string type and lifetime when choosing a wrapper; do not convert a filename to UTF-16 merely because the diagnostic text is Unicode. This is a specific console boundary, not a repository-wide mandate for one nsString class. POP warning code and console macros from the historical patch are retired in the fixed source.

Scope: mailnews.
