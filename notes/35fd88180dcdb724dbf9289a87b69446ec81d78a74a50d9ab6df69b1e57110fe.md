# The CardDAV href index is a per-sync UID and etag snapshot

_getCardsByHref creates a fresh map from remote href to a UID/etag object. Its documentation says the map does not update when cards change and must not be stored for later use. Full-fetch comparison consumes the snapshot by removing seen hrefs and materializes remaining UID cards for deletion; sync-v2 uses the same index for lookup and etag comparison. The original helper tests property presence, while fixed accepted code later normalizes and filters usable hrefs. Keep this snapshot separate from a live card object and from the underlying SQLite property cache.

Scope: Thunderbird CardDAV reconciliation cache.
