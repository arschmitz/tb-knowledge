# Account Hub success text uses discovery provenance instead of a fixed ISPDB label

The owned mapper distinguishes Exchange, guessing and XML disk/provider/database sources, with a neutral title for unmapped values. It runs after the found-config view is initialized. Accepted code later keeps a generic success title and moves source text into a description. Source/subSource metadata drives the message; displaying a success class does not establish server authentication or the truth of a remote provider response.

Scope: Account Hub config provenance.
