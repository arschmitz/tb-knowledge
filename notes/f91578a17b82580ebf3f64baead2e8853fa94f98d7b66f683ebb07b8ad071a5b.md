# Keep Account Hub state keys separate from DOM and template IDs

The controller uses keys such as incomingConfigSubview for its state table, emailIncomingConfigSubview for a DOM ID, and email-manual-incoming-form for template loading. #initUI reads templateId through that table. Use each name at its actual boundary when adding a step; matching visible words does not make the identifiers interchangeable. This is a scoped naming and state-machine recommendation, not a requirement to rename every older state. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account Hub controller state naming.
