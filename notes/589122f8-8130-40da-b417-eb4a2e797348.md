# Preserve extension browsing context group when creating content tabs

The runtime.getContexts port passes initialBrowsingContextGroupId into a Thunderbird content-tab browser before it loads, so extension pages can join the same browsing context group. The browser test checks background contexts, a content tab and navigation, popup, background iframe, history.pushState, and an options page embedded in about:addons. A reload gets a new contextId while history.pushState keeps it. The test also checks expected -1 IDs for the background page. It was adapted from a Mozilla-central test; its landed version has commented-out multi-window/incognito sections and one self-comparison for an iframe windowId, so those cases are not proved by this patch.

Scope: WebExtension runtime contexts.
