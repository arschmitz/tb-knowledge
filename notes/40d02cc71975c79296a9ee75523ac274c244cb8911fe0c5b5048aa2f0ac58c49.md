# Success footer actions distinguish closing the Hub from starting another account

The accepted success state uses explicit Fluent IDs for Finish and Add new account. Forward dispatches a bubbling request-close then awaits reset; the custom action awaits reset without the close event. Reset awaits initialization of the auto form before clearing configuration and rebuilding the footer. Preserve the action distinction in this flow instead of using the same closure path for both labels. This is scoped behavior; generic module-before-element initialization is already covered by shared knowledge. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Account success footer action ownership.
