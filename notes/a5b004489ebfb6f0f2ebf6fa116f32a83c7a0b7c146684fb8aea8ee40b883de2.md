# Notification contrast overrides follow the variant theme rules

The accepted in-app notification CSS puts the prefers-contrast:more override inside the blog/message/security/donation variant group after ordinary light/dark token assignments. It uses Canvas/CanvasText for content, ButtonFace/ButtonText/ButtonBorder for controls, Highlight/HighlightText for active states and removes the illustration. Scoped CSS recommendation in this stylesheet: apply contrast tokens at the scope that wins the variant cascade. This query is prefers-contrast:more; it is not proof that every forced-colors or OS high-contrast combination is covered. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: in-app notification contrast cascade.
