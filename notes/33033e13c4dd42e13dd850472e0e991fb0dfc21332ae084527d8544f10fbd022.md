# The original CardDAV batch addition waits after clearing its read-only override

The first batching landing collects only new cards and uses bulkAddCards when the collection has more than 25 entries. It starts that promise inside the synchronous read-only override region, clears the override in finally and then awaits the promise. Holding the flag across await would conflict with the stated write-access constraint. This is the historical caller contract, not a preferred global override pattern. Fixed accepted code uses sync-only internal write methods and awaits bulkAddCardsInternal directly; the public SQLite entry still rejects read-only writes. No threshold or performance test is added by this landing.

Scope: Thunderbird CardDAV sync batching.
