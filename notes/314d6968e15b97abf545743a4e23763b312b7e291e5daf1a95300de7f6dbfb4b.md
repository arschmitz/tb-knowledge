# Clear calIDateTime date-only mode before timed alarm comparisons

The 1954358 repair compares an ongoing item against now after converting its start/end calIDateTime values into the alarm comparison timezone. It clears isDate on those values so all-day values participate as date-times rather than whole-day values. The actual calIDateTime interface says date-only mode returns zero for hour/minute/second and disallows setting those fields. This is a calIDateTime contract, not ordinary JavaScript Date behavior. Fixed code later supports absent task dates and fires if either end or start is still future; that later predicate differs from the original start<=now<=end test. No timezone or alarm runtime test ran.

Scope: Scoped state and notification contracts.
