# The initial Account Hub option change reads selected state after cloning and keeps the cache fallback

The initial 5002 change reads each cloned option's selected property after appending the clone, instead of reading its selected attribute. It leaves the !selected cache restore unchanged. The cache has two local writers: the host value setter and native-change handler. The four-case comment does not create a cache-exists guard; if no selected option is detected, the setter is called even when the cache is initially undefined. A later exact backout restores the attribute read, while fixed accepted source uses the property again with separate mutation-update logic. These phases do not prove native option selection behavior, an integration cure or a reproduced test failure.

Scope: AccountHubSelect option reconstruction and cache lifetime.
