# Exchange channel URI identity avoids fragment-only message selection

Entry 1483 changes the selected message identifier into channel URL path state because DocShell can treat fragment changes as same-document navigation. The accepted header documents channel URLs with a path key and message URIs with a fragment key, plus the reason for that distinction. ExchangeService converts the header message URI into the folder/channel form. Preserve the two URI roles instead of copying a message fragment into an arbitrary browsing channel. This is a scoped URI contract, not a general ban on fragments. No DocShell navigation or repeated-message display test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange channel versus message URI.
