# Successful file-to-EWS copy needs queue completion as well as listener completion

The historical 1485 implementation forwards OnStopCopy but leaves a TODO to notify the copy service to unblock its queue. The accepted ExchangeMessageCopyHandler::NotifyCompletion notifies the service instead of directly calling OnStopCopy. The service clears a completed/failed request, calls OnStopCopy before removing it, and schedules the next copy. These are separate completion owners. Preserve both when completing this copy flow; one user listener callback is not evidence that queued operations can advance. Bug 1931599 is linked source context and remains unread. No copy queue, multiple-message copy or failure-completion test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange copy queue completion.
