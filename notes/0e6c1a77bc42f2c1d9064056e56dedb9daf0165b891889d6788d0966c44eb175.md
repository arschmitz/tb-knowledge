# Read documented notification cache retention against both feed and offline IDs

The original docs say interactedWith and seeds are limited to IDs currently returned by the server. Current updateNotifications retains the union of feed and bundled default IDs and skips cleanup for temporary offline fallback data. Those later contracts already have shared lessons. Proposed documentation check for this component: state the fallback/union exception in the cache section instead of repeating the historical feed-only rule.
