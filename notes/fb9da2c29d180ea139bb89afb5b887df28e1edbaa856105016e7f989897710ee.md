# The return-to-compose report question loses an unused result channel

Part 2 removes the report's return-to-compose question and changes its IDL result to void. The inspected native compose caller ignored the old report out-value, and MessageSend.fail had already stopped assigning it after part1. The native method still returns its XPCOM call status; that is separate from the removed reported decision. Compose failure-state notification continues using its own rv. Other window-restoration paths remain outside this narrow result-removal claim, and no dialog or focus result was observed.

Scope: Thunderbird send-report question removal.
