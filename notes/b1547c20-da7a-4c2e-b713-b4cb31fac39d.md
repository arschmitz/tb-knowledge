# IDL import APIs use lower camel case names and direct return values when simplified

In D211685 the reviewer requested lowercase names for changed IDL methods and welcomed removal of multiple out parameters. The accepted patch changed GetDefaultLocation(out location, out found, out userVerify) to nsIFile getDefaultLocation(), with callers checking the returned location. Current IDL retains this form. This supports a scoped review rule for touched import IDL APIs: prefer lower camel case method names and a direct return value when extra out values carry no required behavior.
