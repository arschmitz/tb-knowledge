# Check runtime cell types rather than relying on a string return annotation

Accepted getText returns the stored value directly despite its string return annotation; LiveView stores unread and flagged booleans. Current assertions compare those cells with string literals using Assert.equal, which alone does not establish strict runtime string identity. A scoped review recommendation is to make this boundary type explicit and use a strict type assertion if string output is required. No test failure is claimed. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Tree adapter cell return types.
