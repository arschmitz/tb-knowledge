# The remote-content refactor changes the no-header mailbox fallback

After the earlier ShouldLoad guards, the former helper preserved a mailbox-specific path even when no DB header resolved; its message-header decision rejects null. The new caller instead accepts any missing GetPotentialMsgHdr result and no longer makes that scheme distinction. The accepted code retains this difference. The new tests use stored folder messages and do not directly cover a null DB header or external-file mailbox path. This is a bounded static branch change, with no claim of a demonstrated load, exploit or runtime failure.

Scope: Mail remote-content policy null-header fallback.
