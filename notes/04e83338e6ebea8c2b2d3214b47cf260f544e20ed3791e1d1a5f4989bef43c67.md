# Keep hovered links in a separate status-bar text channel

The checked status feedback change gives hovered URLs their own urlText label. setOverLink writes that label while showStatusString continues to update statusText, so the two producers do not overwrite the same visible field. When the status bar is hidden, the hover code still uses statusbar-display. The direct browser test checks URL text and expanded state on hover, then clearing/collapse on unhover. It does not inject background updates during hover or establish a five-second display guarantee, security outcome or assistive-technology result. The separate labels are a scoped implementation choice, not a universal UI layout rule.

Scope: Hovered URL and activity status channels.
