# An invalid stored junk-target account is an absent target, not a fatal GetSpamFolderURI error

Entry 1516 reports that a removed/corrupt junk target broke New Subfolder and Rename. The code now handles GetServer failure by clearing the in-memory ActionTargetAccount and returning NS_OK; it does not persistently repair the account preference here. Other lookup errors still propagate. Empty initial output lets current callers avoid attempting a move. Treat this as a narrow stale-account recovery path; the reported UI breakage was not reproduced. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: Junk target recovery.
