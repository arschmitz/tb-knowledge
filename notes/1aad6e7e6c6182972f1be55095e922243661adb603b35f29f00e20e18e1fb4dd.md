# Failed RNP signature-handle retrieval returns a bad result so callers reach cleanup

When rnp_op_verify_signature_get_handle returns nonzero, getVerifyDetails sets exitCode=-1, adds BAD_SIGNATURE, logs the native status and resolves false instead of throwing. The inline caller relies on statusFlags; the detached caller also reads the Boolean. Both then reach their existing input/operation destruction code for this resolved failure. This handles one native failure, not every throw in the helper or every native resource/crypto outcome. No signature or cleanup test ran.

Scope: OpenPGP signature verification failure propagation.
