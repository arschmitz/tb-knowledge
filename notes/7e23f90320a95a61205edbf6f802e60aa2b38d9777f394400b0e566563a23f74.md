# Treat trash_folder_name as a server-relative path with explicit encoding boundaries

Despite its legacy name, the Trash preference and picker use a path such as INBOX/Deleted or [Gmail]/Trash. The current explicit-preference comparison converts a non-UTF8 server path from modified UTF-7 to UTF-8 before comparing; the picker converts its Unicode path for a non-UTF8 server. FolderPathInServer returns the URI path without the leading slash after URL unescaping. A scoped naming/documentation recommendation is to call new local variables Path and state the encoding at conversion boundaries. No non-ASCII path round trip was executed, and all possible URI producer encodings were not traced. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: IMAP Trash path naming and encoding.
