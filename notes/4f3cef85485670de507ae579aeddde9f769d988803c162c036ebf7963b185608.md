# Keep Panorama compile-time and runtime activation distinct

The initial folder database build was gated directly on NIGHTLY_BUILD. Current mailnews/moz.build uses MOZ_PANORAMA, and the accepted docs describe the separate mail.panorama.enabled runtime preference. The test manifest enables that preference. The documentation labels Panorama as under development and states its goal is a global folder/message database with legacy-interface migration. These are the checked snapshot and documented direction, not a claim that every planned step is complete or every build has Panorama. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama activation and direction.
