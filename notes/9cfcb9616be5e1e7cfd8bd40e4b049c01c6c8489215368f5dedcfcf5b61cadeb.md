# The legacy EWS EmptyFolder branch has no success notification for an empty message list

For a server version before Exchange2010, EmptyFolder may call the child-delete operation’s do_operation directly. That method returns a result; the separate handle_operation wrapper performs listener success delivery. The fallback then invokes delete_messages only when message_ids is nonempty. If there are no message IDs and child deletion succeeds or is unnecessary, the visible fallback branch returns without notifying success. The native EmptyTrash caller performs local cleanup in its success callback, so task acceptance alone does not establish that cleanup. This unchanged conditional path appears in both the original-post and fixed accepted source. No old-server execution, user-visible hang or cause attributed to the single-ID patch is claimed.

Scope: rust/ews_xpcom.
