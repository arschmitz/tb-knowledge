# Pass a config copy when a form may edit state before the user accepts it

Current #setCurrentConfigForSubview passes a deep AccountConfig.copy to the step. Its comment gives the specific reason: edits made in incoming configuration must not change the config-found view when the user goes back. The controller owns when its accepted config changes. Preserve that boundary in new state-machine work. The historical captureState sometimes returned a live mutable object; the newer accepted copy rule is the better guide for editing transitions.

Scope: Account Hub state acceptance boundary.
