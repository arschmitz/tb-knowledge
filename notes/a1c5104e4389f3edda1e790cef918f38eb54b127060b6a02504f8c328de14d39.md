# Current EWS erase tolerates a remote folder that is already absent

The historical 1487 Rust request expects one response and reports non-success classes without a local success callback. The accepted erase operation handles ErrorItemNotFound as a successful absence condition so a stale local folder can be removed, while other failures remain errors. This is later accepted-source refinement, not proof of the historical failure cause or full coverage of the introducing bug. Preserve the distinction between remote absence and other service errors in this erase operation. No test, build or runtime operation was run.
