# Calendar warning receiver changes remain separate from detector result control flow

Modules use their own warn method with the calendar.loglevel option, while selected plain scripts call console.warn. Those logging calls do not replace explicit control flow: the CalDAV detector separately throws cancellation/auth/certificate or detection errors, a dangling identity lookup returns null, an invalid mode returns unchanged, and a successful backup warns with its file path. The new preference/receiver choice is not a promise that every warning aborts or that output was observed.

Scope: Calendar module and UI warning paths.
