# Linux tray service errors are logged on the worker thread

The patch replaces the tray service convenience spawn call with an owned std::thread::spawn closure. When mail.biff.show_tray_icon_always is true, the worker runs service.run_without_dbus_name and logs a returned Err instead of using the prior convenience method. The allocated handler still retains the service handle. Fixed accepted source preserves this result match. This establishes the service-returned error boundary; it does not establish that std::thread::spawn panics or every worker failure are caught. No D-Bus failure or startup runtime test ran. One Bugzilla comment is unavailable, so this source-only finding has no full-audit credit.

Scope: Linux tray service failure handling.
