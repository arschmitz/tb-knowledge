# The file-message focus fallback resolves after requesting focus

When activation has not arrived, the new helper timer calls win.focus and resolves immediately. Promise.race can therefore finish through that timer without observing activate; clearing the timer and yielding a tick is not a final active-window assertion. Its Assert.report calls only print diagnostics. The flowed-reply caller still awaits its own promiseFocus afterward and keeps the source message window open until draft inspection ends. This is a completion boundary, not a reproduced focus failure.

Scope: Shared message-window helper completion.
