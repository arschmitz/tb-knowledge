# The folder selection test helper has a message and default-scope gap

selectFolder adds Assert.notEqual(row, null) without an assertion message. Give that guard a nonempty expected-behavior message, such as "The requested folder row should exist before selection." Its JSDoc also says the default selects the All Folders view. The actual null-mode lookup uses activeModes in order; All wins in these tasks because they place it first. Describe that caller dependency when reusing the helper. The following click waits only until selectedRow equals the requested row, so that wait does not establish full view readiness. These are scoped diagnostics and comment-contract findings. They do not change the current source or establish a runtime failure.

Scope: Folder tree test helper review.
