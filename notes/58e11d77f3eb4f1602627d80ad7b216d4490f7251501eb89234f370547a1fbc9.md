# The EWS creation extraction adds assertions without expected-state messages

The owned extraction adds nine MOZ_ASSERT calls without a message: one offline-copy argument check, one source-kind check and seven new creation-handler checks. Examples include the destination-folder precondition and the detached-header state. Under the current user-directed assertion-message rule, these need nonempty messages that state the expected state. This is a scoped source-review finding. Historical accepted calls do not establish an exception or a runtime failure. The matching detached-header assertion also remains in the fixed accepted source.

Scope: Exchange C++ assertion diagnostics in the 4924 landing.
