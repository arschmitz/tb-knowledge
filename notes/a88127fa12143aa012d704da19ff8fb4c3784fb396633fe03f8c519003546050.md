# Mbox stream entry points lock before shared-state checks

The accepted MboxMsgInputStream methods guard Read, Available, StreamStatus, Close, Continue and metadata getters with mLock before reading or changing shared parser/stream state. The historical fixes reported a ThreadSanitizer race, but this study did not run that diagnostic. Keep the lock across the relevant state check and operation; do not infer that locking only the output-buffer copy covers the full stream contract. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/base/src.
