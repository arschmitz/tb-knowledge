# Review-backed syntax: write JSDoc on public component interfaces, use accurate `@param`/`@returns` types, and update it when names or behavior change (D298

Review-backed syntax: write JSDoc on public component interfaces, use accurate `@param`/`@returns` types, and update it when names or behavior change (D298632, D297345, D306242). Use complete sentences and periods in explanatory comments, and keep them within the local line width (D304012). Name variables for the state they represent rather than a broad or opposite state (D293024, D317699). Name tests and assertions for observable behavior; use an assertion message that says what should happen. Use complete Fluent IDs in literals or a nearby comment so dynamic IDs stay searchable (D306242, D304559). A changed Fluent value or attribute needs a new ID and usually migration; keep punctuation in translated strings rather than CSS (D299482, D304921, D312939). Prefer existing CSS tokens and font-relative sizing where UI text must scale, but do not claim a blanket `rem` mandate: the sample adds many `px` values too (D295950, D308989).
