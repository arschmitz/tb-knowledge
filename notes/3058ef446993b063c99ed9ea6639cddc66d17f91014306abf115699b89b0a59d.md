# Map attachment part notation from discovered MIME structure

Ordinary multipart paths can contain .1. without crossing an attached message. The accepted processor first finds a real parent message, enumerates nested attachments, builds a mapping from their exposed part numbers to jsmime dollar notation, and rewrites a requested part only when that mapping contains it. Parser pruning separately removes the messages API root level. Keep those two conversions distinct. The unusual multipart fixture exercises IDs, raw/full messages, files and two attached-message levels; its new test explicitly skips IMAP. The dollar syntax in the getAttachmentFile schema is a scoped parser feature, not a general rewrite rule for every partName.

Scope: mail/extensions/messages-part-names.
