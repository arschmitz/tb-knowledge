# Manual Account Hub errors combine native validity, text and accessible associations

Current incoming/outgoing templates use persistent label-for relationships and decorative error/success images with empty alt. Their getters set custom validity, aria-invalid and aria-describedby to the matching error text, and reset those associations on valid input. accountHubForms.css shows error text for native-invalid or aria-invalid states. A scoped recommendation is to keep these signals together when adding a field; color or an icon alone does not describe the error. Speech, contrast, focus announcements and zoom remain untested. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/accountcreation.
