# Encoded attachment-name coverage checks the returned attachment list

The encoded-name regression fixture supplies a split RFC2047 Content-Type name, attachment disposition without a filename, and application/octet-stream content. Its task skips IMAP and directly checks one attachment at partName 1.1 named Rechnung 2025-1056119.pdf through listAttachments. The current getAttachmentFile path shares the custom MIME emitter and passes attachmentPart.name to the File constructor, but this task does not directly check the returned File name or a saved disk filename. Keep that test boundary explicit when claiming coverage for the reported API. The four new browser.test.assertEq calls lack message arguments, so add messages such as "The attachment name should be decoded from the Content-Type parameter." A task name about encoded attachment names would also identify the actual fixture more clearly than the current text-as-attachment name.

Scope: mail/extensions/messages/tests.
