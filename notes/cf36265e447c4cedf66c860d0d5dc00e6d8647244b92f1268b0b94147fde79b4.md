# File-copy completion checks the header separator state before commit

EndCopy marks a non-write-failed copy unsuccessful when its parser is still reading headers, then attempts to discard an existing destination stream even before a destination key exists. The parser leaves header state on the empty separator; this is not full successful-header validation. Direct tests check final counts for valid and incomplete inputs on Berkeley and Maildir stores. The cleanup branch returns NS_OK and ignores discard status, so neither a particular rejection nor universal rollback is established. Required Bug discussion has recorded missing, truncated and unviewed scope; support is public Git/code only and full-audit credit stays zero.

Scope: Local message-file copy integrity and discard handling.
