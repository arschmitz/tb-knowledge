# Copy undo deletes new headers and redo uses preserved source headers

ExchangeCopyMoveTransaction keeps original source headers separately from the latest operation headers. For a copy, undo hard-deletes the destination current set and redo copies the original source set; for a move, operations use the current set and the completion listener replaces it with new headers. Folder success registers the transaction after local result headers exist. Method success is not remote completion, and the selected legacy fallback does not establish a populated result-header set. No copy/undo/redo test ran.

Scope: Exchange same-server copy undo and redo.
