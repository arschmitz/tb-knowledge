# Treat the QR view-password preference as an actual control-state boundary

1187 uses pref.privacy.disable_button.view_passwords to hide the QR passwords section, uncheck its checkbox and disable it. Accepted code and the current test retain all three checks; hiding alone would leave the checked value available to the form. This UI preference does not appear as a separate check inside requestAuthorizationToIncludePasswords, so this source does not establish a universal ban on all direct QRExport calls. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/preferences.
