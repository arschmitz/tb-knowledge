# The MV3 folder-info test waits for the target folder and expected state

The test registers a listener before its mutation and accepts only the InfoTest folder with the requested new-message or unread count. It removes that listener after a match. The checked event producer batches per-folder changed fields and the API bridge delivers them asynchronously, so this wait is narrower than consuming the next event. This is static test/producer evidence, not an observed flake cure.

Scope: Folders extension API asynchronous event test.
