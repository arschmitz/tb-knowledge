# Vector header storage remains a borrowed byte buffer

nsParseMailMessageState now uses mozilla::Vector<char> and checks fallible append. HeaderData values and GetAllHeaders point into that storage; GetAllHeaders does not transfer ownership or add a terminator. Keep consumers within the buffer lifetime and use explicit lengths. The existing bounded-header-slice lesson covers pointer/length safety; this note adds the owning-container and external borrow boundary. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
