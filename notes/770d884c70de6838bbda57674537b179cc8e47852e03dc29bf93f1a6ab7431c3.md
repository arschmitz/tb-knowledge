# The extension tracker defers both creation and activation to keep their order

Current ext-mail defers emitCreated to a resolved promise because the tab index is not final at TabOpen. It also defers emitActivated from TabSelect so activation does not precede creation. ext-tabs forwards those tracker events through its persistent event registrar. Preserve both event timing boundaries when changing tabmail; native synchronous dispatch order alone does not settle extension delivery timing. No event loop or extension runtime was executed. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: extension tab event ordering.
