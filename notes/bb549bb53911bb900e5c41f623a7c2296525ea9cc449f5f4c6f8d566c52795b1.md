# Moving a contact creates a new UID before deleting the old UID

The contact panel creates the destination card with a new UID before deleting the original card. Contact notifications maintain global and per-book caches keyed by UID, so the old deletion must keep its own identity. The original patch used dropCard(card, true); the accepted code uses addCard(card, true). This is the checked contact-move and cache contract, not a guarantee for remote servers.

Scope: address-book/contact-move.
