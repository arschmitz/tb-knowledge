# Give EWS ID lookup failures a fallible response-processing boundary

Current sync_messages_for_folder requires an ID both when building fetched-message indexes and when processing Create or Update changes. A change whose ID cannot be found in the fetched map returns a Processing error containing that ID. This keeps an absent identifier distinct from an identifier whose data could not be fetched. Preserve this distinction and use fallible Result collection in the same adapter rather than silently dropping malformed message responses. Other item variants are determined by the current imported enum helpers, not by the old non-message skip branch. Imported helper implementations were not adopted as Thunderbird style rules. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: EWS response indexing and error syntax.
