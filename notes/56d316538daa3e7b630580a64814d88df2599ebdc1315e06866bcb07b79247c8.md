# Calendar module initialization and window startup completion remain separate contracts

The cal service aliases now load singleton module exports. CalCalendarManager imports the timezone module for its initialization side effect, and the timezone constructor sets up its zone/default-pref state. This replaces the removed service startup chain, while the Thunderbird window still sends calendar-startup-done and its window-opening consumer still waits for that topic. Module evaluation and window readiness remain distinct. This is static source evidence; startup, shutdown and native factory lookup were not run.

Scope: Calendar service initialization.
