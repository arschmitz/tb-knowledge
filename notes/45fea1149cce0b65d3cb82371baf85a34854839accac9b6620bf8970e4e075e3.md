# Make the mouse helper’s preventDefault return contract explicit for each event mode

The accepted helper records aWindow.synthesizeMouseEvent’s return value when a type is supplied. In the default mousedown/mouseup branch it does not assign either return value, so defaultPrevented remains false. Its public comment describes whether preventDefault was called without that distinction. Proposed focused check: cancel a specified mouse event and a default click sequence, then document the intended returned value for each mode. This is a static return-contract concern; neither cancellation experiment was run. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: mail event-helper return values.
