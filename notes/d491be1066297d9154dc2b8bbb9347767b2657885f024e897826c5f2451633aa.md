# Checkbox-tree arrows address adjacent DOM inputs

The row's ArrowUp/ArrowDown listener directly addresses previousElementSibling or nextElementSibling, queries input and optionally calls focus. It then calls preventDefault even when no target exists. It does not check hidden/uncheckable state, walk adapter indices or recreate Tab/twisty traversal. This supports a narrow description of the source path, not proof of focus movement at virtualized boundaries or native scrolling behavior. Later bubbling change handling and subtree aggregation are separate. The earlier broad shared arrow/ARIA lesson remains provisional.

Scope: Checkbox tree row keyboard handling.
