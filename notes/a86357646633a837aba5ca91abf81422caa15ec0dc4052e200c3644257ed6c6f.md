# Account Hub invalid state includes accessibility attributes

At the accepted revision, the auto form sets aria-invalid on each input using native validity plus whether errors should be exposed or the input has been touched. That distinguishes validation state from when the UI exposes an error. For this form, keep aria-invalid and the visible error policy aligned instead of toggling an error class alone. This is a source-supported recommendation; screen-reader announcements, focus movement and actual accessible names were not inspected in a running UI. Full bug and review discussion remains pending.

Scope: Account Hub form accessibility.
