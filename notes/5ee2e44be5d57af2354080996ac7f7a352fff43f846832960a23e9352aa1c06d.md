# The filter-plugin lock guard applies to POP and local folders without acquiring a lock

CallFilterPlugins first sets filtersRun false and resolves the junk plugin. It then rejects a held folder lock only for pop3 or none; other server types continue to the existing junk/trait/filter gates. GetLocked only reads the semaphore holder, so the new comment does not accurately describe acquiring or ensuring a lock. The IMAP consumer calls the plugins before deciding whether to emit its immediate biff notification. This is bounded ordering, not proof that all junk notifications disappear or that broader locking was redesigned. Required primary2/3/4/8/9 remain unavailable, so the source publication carries zero full-audit credit.

Scope: Mail filter-plugin lock and notification ordering.
