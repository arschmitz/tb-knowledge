# Calendar model documentation separates immutable items from editable clones

The accepted item-model document describes VEVENT/VTODO items sharing CalItemBase, with immutable objects edited through clones. The checked implementation throws before mutating an immutable item, marks immutability after finalizing the base, and resets mImmutable on the clone destination. The same document distinguishes recurrence parents from displayed occurrences and names attendee/alarm components. Use it as a scoped architecture entry point; it is not proof of every provider or recurrence behavior, and the missing required discussion keeps this landing a zero-credit partial.

Scope: Calendar source architecture documentation.
