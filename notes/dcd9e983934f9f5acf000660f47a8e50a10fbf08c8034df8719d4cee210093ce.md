# An empty mbox can start a new line without ending in a newline

Historical CheckStartingOnNewLine at revision049b42b91d0c12d6287ee3a798b9bc6d58778cc4 sets onNewLine true for an empty file and for a nonempty file whose final byte is LF. The predicate means a new message can start on a line boundary; it does not mean the file literally ends with a newline. That empty-file distinction supports the local onNewLine name rather than the review’s endsWithNewline suggestion. The checker was later removed from the fixed accepted store, so this is a dated example of naming the actual Boolean contract, not a current API, a global naming rule, or a reason to reverse a general style preference. Complete assigned review and exact original source checked; no performance or write test ran.

Scope: Historical mbox append-boundary predicate.
