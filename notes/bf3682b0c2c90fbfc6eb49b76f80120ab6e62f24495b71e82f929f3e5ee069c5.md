# Alert hooks reserve duplicate-suppression state before asynchronous work

In the owned alertHook change, onAlert and onCertError add their cookie immediately after the duplicate guard. This reserves the state before onCertError awaits localization. The deferred promise removes the cookie when resolved; silent and test-suppressed ordinary alerts resolve it before returning. Notification completion or the five-second timer also requests release. This is a suppression window, not ownership of a visible notification or a wall-clock lock. The owned key uses hostPort and category; accepted source uses serverKey and category, not message text. Ordinary notification-backend failure returns false and the checked MailSession caller can fall back to a modal prompt. The certificate interface is void, so its C++ dispatcher does not await the async JavaScript hook. The owned observer callback and accepted callback API are separate phases. Static source proves ordering and return contracts; no alert or localization timing test ran.

Scope: mail/activity/alertHook.
