# The POP command watchdog stops at the first data event rather than guarding a whole reply

The watchdog starts after _send sends a command on an open socket. _onData yields once, then clears it before checking whether a complete line arrived; even a partial payload ends this guard until another send. _onOpen does not arm it for the initial greeting. Describe this as a sent-command first-data watchdog, not continuous coverage of a multiline response or all connection inactivity. The ten-second preference margin is source intent, not verified native race prevention. No timer or POP run occurred.

Scope: POP timer trigger and cancellation scope.
