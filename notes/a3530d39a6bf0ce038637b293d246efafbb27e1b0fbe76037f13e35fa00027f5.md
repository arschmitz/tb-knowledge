# Thundermail sequential downloads still buffer complete pieces

The multipart download loop processes pieces in part order, but each piece first collects decrypted chunks, allocates a complete piece buffer and unzips it. Its async stream start callback enqueues the result rather than producing it through a demand-driven pull callback. The save fallback also materializes the complete output stream as a Blob. This source supports the sequence and buffering stages, not the numerical peak-memory estimates in the comment or a hard bound on queued data. File-picker and Blob save paths remain separate contracts.

Scope: Thundermail generated multipart download and save fallback.
