# The first-run Escape guard is separate from Account Hub close and minimize requests

The modal suppresses Escape keydown only while the controller's cached isFirstRun is true. Its cancel listener still gates reset failure; separate header events request close or toggle minimization. The success forward action sends request-close, so finishing setup is distinct from dismissing it with Escape. The owned creation test asserts the dialog stays open after Escape and later waits for close after Finish. The accepted code preserves this separation through #handleKeyDown. This comm source does not establish that every cancel event is caused by Escape, that all programmatic closes are blocked, or that native keyboard/minimize behavior was executed.

Scope: Account Hub first-run Escape and completion controls.
