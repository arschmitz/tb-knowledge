# Address-book public writes retain read-only checks while server sync uses Internal methods

The read-only overhaul keeps guards in public addCard, modifyCard, deleteCards and bulkAddCards, and moves their work into Internal variants. Their local documentation reserves direct Internal calls for subclasses applying server sync. CardDAV's converted sync paths call those methods directly instead of setting a mutable override across async work. The public bulk wrapper remains async and returns the internal promise, preserving promise rejection for a read-only call. These names state a caller contract; JavaScript does not make them private or enforce permission by the name alone. The separate full-resync remainder still needs guarded-call checks.

Scope: Thunderbird address-book write-access contract.
