# Keep EWS sending separate from the Sent-folder copy

The EWS CreateItem request uses SendOnly and no saved_item_folder_id because MessageSend owns the copy and includes private/local headers such as Bcc. Current send_message retains that contract. Turning it into SendAndSaveCopy can duplicate the copy or lose locally added header content. The current FCC test identifies sentitems by distinguished folder ID, not an English Sent name; setup and final assertions were read: no URI inferred from name before sending, one copied message, and read flag set. No test run was made.

Scope: rust/ews_xpcom/src/client.
