# Treat StartPos as invalid while the mbox output stream is in error state

At fixed revision0b93f0f7a926ed94c8a0646f18b6734ec7cc0f6d, MboxMsgOutputStream::StartPos is documented as undefined in error state. Its implementation locks mLock, asserts the stream is not eError and mStartPos is not-1, then returns the offset. The constructor uses-1 after Tell fails, but callers must not rely on-1 as a promised StartPos error return. The reviewed contract deliberately leaves that state invalid; this is a local API requirement, not a general sentinel or exception-style rule. Declaration and implementation were statically inspected; relevant full assigned discussion was read. No error-state or concurrent runtime experiment ran.

Scope: mailnews/base/src.
