# Thread scroll calculations need pre-expansion counts and invalid-index handling

viewNavigate may already expand a thread before the row widget runs. The accepted2024 fix combines that row-count delta with expandRowAtIndex and passes the thread start separately from the selected row. A later unthreaded-view regression showed threadIndex may be nsMsgViewIndex_None as well as0. Current code recognizes both sentinels. Test threaded/unthreaded views, nonfirst unread children and already-visible previous-unread navigation. The later test checks no unnecessary scroll; no runtime test was run here. The dummy scroll reset remains scoped to the documented APZ repeated-destination case.

Scope: mail/base.
