# Test repeated Account Settings refresh for accumulated load handlers

Current MsgAccountManager can call onLoad again on an existing tab. onLoad installs a new anonymous contentFrame load listener each time; its hasLoaded condition guards outer registration but does not guard that addEventListener. Proposed focused test: refresh the existing tab repeatedly, load a subpage and count saved-preference/change handlers and popup activations. The source supports a possible listener accumulation path, not an executed duplicate action or a regression caused by this landing. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: account settings listener proposal.
