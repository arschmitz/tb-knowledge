# Keep the raw XPCOM macro signature separate from the checked Rust method

The read-status review corrected an attempted change to both signatures. For this xpcom_method! bridge, keep the macro argument as *const ThinVec<nsCString> and the inner Rust method argument as &ThinVec<nsCString>. The reviewer explains that the wrapper checks the pointer before supplying the reference; the inspected final bridge confirms the signature split. This adds the review correction to the existing ownership lesson; the later detached task still needs owned arguments. The reviewer reported a successful local compile. This study did not read the macro implementation/generated wrapper or run a Rust build.
