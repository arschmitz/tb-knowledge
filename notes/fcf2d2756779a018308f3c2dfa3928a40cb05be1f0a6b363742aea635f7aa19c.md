# Test the intended predicate when filtering Storybook manifest members

The current analyzer filter uses !member.kind === "field", which compares a Boolean with a string and is false for the checked kind values. It therefore does not provide the apparent non-field exemption; the remaining privacy/static/name tests decide retention. Recommend making the non-field comparison explicit if that exemption is intended, then testing generated members. The Node table checks language semantics only; manifest generation was not run. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending.
