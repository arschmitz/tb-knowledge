# Make a widget receiver explicit in an add-on callback

The disabled-add-on update listener declares an object method that calls this.querySelector, although that listener object does not itself declare a widget reference. A scoped review recommendation is to preserve the widget receiver explicitly when a callback changes its controls, or verify the API receiver contract before relying on this. This is a static concern; callback binding and the update-available path were not exercised, and it is not a diagnosis of the historical EWS test backout. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account Hub add-on callback receiver.
