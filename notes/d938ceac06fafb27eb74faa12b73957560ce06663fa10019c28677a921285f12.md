# Exchange's empty-password lookup includes NTLM without adding a prompt

This landing widens ExchangeIncomingServer::GetPassword's empty-cache condition to passwordCleartext or NTLM. The checked GetPasswordWithoutUI implementation queries the password manager with the server's local store type, hostname and username; the final getter returns the cached value. A nonempty cache still skips that lookup. This is a stored-password retrieval boundary, separate from the shared provider's Necko-based NTLM handling. It does not demonstrate authentication success, renewal of every cached value or a universal provider policy. No login or password-manager test ran.

Scope: Exchange incoming authentication.
