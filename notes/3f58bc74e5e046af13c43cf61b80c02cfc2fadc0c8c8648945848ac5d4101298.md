# Keep drag rejection and selection changes consistent with modifier keys

Current _onDragStart refuses a grouped header and an unselected row while Ctrl or Shift is already pressed. It prevents the drag and restores correct focus before returning. The selected-row path still permits dragging the existing multi-selection. A modifier test calls lower-level mouse steps because synthesizeDragOver cannot emulate the already-held modifier correctly. Do not simplify the rejection condition from the unmodified 2024 selection fix alone. Keyboard, focus and actual platform drag behavior remain untested in this study.

Scope: mail/base/content.
