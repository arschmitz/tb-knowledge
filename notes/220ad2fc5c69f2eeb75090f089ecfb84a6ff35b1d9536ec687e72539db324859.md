# Large-mailbox trace points separate database reopen from compaction completion

The test adds distinct messages before closing and reopening the database, before and after deletion, and before and after compaction URL completion. Existing assertions check the serialized size/count, summary validity, final file size and retained message key. Those trace boundaries help locate a stalled or failing phase, but adding them does not prove a fix. Bugzilla corrects an initial diagnosis and distinguishes lock failures from an out-of-date summary. No large-file runtime test was executed.

Scope: Mbox intermittent diagnostics.
