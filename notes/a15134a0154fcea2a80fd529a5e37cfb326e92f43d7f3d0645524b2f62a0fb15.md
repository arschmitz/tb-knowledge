# Message header creation has a detached-to-live lifecycle

Current nsIMsgDatabase prefers addMsgHdr for one-step insertion. Legacy callers may create a detached header, fill its properties, then call attachHdr and use the returned live header. The legacy Mork implementation returns the same object from AttachHdr, but callers must follow the interface contract rather than assume every database backend does that. createNewHdr assigns a new key; createNewHdrWithSpecificMsgKey supports legacy server-assigned keys. addNewHdrToDB rejects an already inserted key and sends the addition notification only when notify is true. The current test fills a detached header and tracks the returned live key. Do not teach the 2024 single keyed createNewHdr signature as current.

Scope: message-database.
