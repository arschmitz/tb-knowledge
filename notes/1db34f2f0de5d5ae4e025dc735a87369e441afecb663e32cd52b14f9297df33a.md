# Libmime accepts an empty decoded header instead of keeping encoded input

When RFC1522 conversion is enabled, MimeHeaders_convert_header_value now assigns the decoded output even when it is empty. A Q-encoded empty header is an explicit empty-string case in the JavaScript table, so a nonempty guard would retain the old encoded input. The wrapper returns void and can also clear output if the converter service is absent; do not treat every empty result as a success code. Added JavaScript table vectors do not directly exercise the changed C++ assignment. No tests ran.

Scope: MIME decoded string versus absence.
