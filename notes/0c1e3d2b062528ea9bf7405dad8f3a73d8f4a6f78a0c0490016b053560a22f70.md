# The original outgoing promise settles at send-stop but does not expose its request to abort

The listener stores a request at send-start and settles its Promise after send-stop delivery processing, except for the explicit sendUnsent return. The original field _smtpRequest now holds that Promise while abort still checks its .value; the plain Promise has no value assigned by this scope. Accepted code instead retains the listener and forwards or queues cancel status. A delivery callback rejection can bypass later settlement, and FCC start/scheduled cleanup is not terminal copy proof. The stale start-resolution JSDoc needs the actual completion boundary. No cancellation, hang or cure was reproduced.

Scope: MessageSend outgoing completion and cancellation phases.
