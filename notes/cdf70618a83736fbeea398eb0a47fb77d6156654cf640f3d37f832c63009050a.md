# Exchange Trash detection starts with the folder being deleted from

This landing starts the Trash-flag search at this before walking parents. It therefore selects hard deletion for messages deleted directly from Trash even when deleteStorage is false, while explicit force and the permanent-delete model remain separate inputs. The added EWS and Graph tasks wait for the completed folder event and directly assert a local count change from one to zero; their three assertions have nonempty expected-result messages. Those checks do not assert remote request shape, nested Trash deletion or failure/undo behavior, and no test was run. The old ancestor-only comment is narrower than the actual inclusive traversal.

Scope: Exchange message deletion.
