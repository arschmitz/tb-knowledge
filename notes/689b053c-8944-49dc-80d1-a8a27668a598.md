# Serialize IMAP login on the incoming server without proxying to the main thread

Bug 1862111 describes simultaneous IMAP connection threads using an old password and causing multiple prompts or provider lockout. The accepted patch adds a monitor on nsImapIncomingServer and runs TryToLogon under it on the current connection thread. The sink proxy explicitly rejects RunLogonExclusive because a main-thread hop would break this boundary. Current code retains that design. Each connection may still need its own authentication; the lock prevents concurrent login attempts, not every later attempt.

Scope: IMAP authentication.
