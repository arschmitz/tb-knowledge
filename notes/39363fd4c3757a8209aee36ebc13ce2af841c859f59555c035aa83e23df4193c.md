# Mailbox display formatting can encode a name and optionally include its address

Current Mailbox borrows name and optional email_address, and its Display implementation encodes the name before rendering the address. The trait conversion rejects addressless parser entries, but the struct itself can represent a name only. The formatter comments justify UTF-8 unwrap from an ASCII encoding result and separately leave allocation failure unresolved. A scoped recommendation is to preserve the actual constructor and encoding invariants when changing ownership or unwraps; this study did not verify the external RFC or execute encoding. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
