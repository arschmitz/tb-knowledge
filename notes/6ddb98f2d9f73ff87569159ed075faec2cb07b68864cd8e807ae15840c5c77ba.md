# Thunderbird Calendar architecture, Redux, and transaction documentation

The dialog passes host callbacks to `saveCalendarEventCreate`/`saveCalendarEventEdit`; those call the existing host `doTransaction("add", ...)` or `doTransaction("modify", ...)`, preserving transaction history and scheduling. Provider observers flow through `CalCalendarManager` to `CalendarFilteredViewMixin`; `storeObserver` only changes dialog controls/state. [Task 2]

Scope: calendar.
