# A private sync-operation handler records why its listener implementation differs

The extracted EWS sync handler keeps its operation state and reactive callbacks in one implementation file. Its class comment explains the operation lifetime and why this local implementation uses listener derivation despite the lambda pattern elsewhere: callback/initiation code is together, the class is private to the file and reference counting holds the shared operation state. The comment explicitly leaves room to replace the design later. Treat this as a documented local exception, not a general preference for inheritance or the Handler suffix.
