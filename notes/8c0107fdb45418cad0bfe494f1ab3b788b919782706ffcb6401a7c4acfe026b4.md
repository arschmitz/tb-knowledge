# Feed display tests must wait for the nested article browser

A feed website load occurs in the message-pane browser inside the about:message browser. displayFeedMessage obtains getMessagePaneBrowser(), checks both readyState and the expected URI, and waits only if the article has not already loaded. This avoids waiting forever for an event that already happened. Summary mode uses messageLoadedIn instead. The test changes rss.show.summary through pushPrefEnv and clears thread selection between cases. Manual test proposal for this path: assert the actual article or summary document as well as the preference and checked item; do not treat outer-message loading as proof that an article is ready. The global menu case is skipped on macOS because that test cannot click the native menu bar.

Scope: feeds.
