# WebExtension account exposure and EWS fixture readiness are separate contracts

The account filter now admits ews and AccountManager.getType returns ews as a native type; both manifest-version schema choices list it. The dedicated xpcshell manifest selects a fake EWS fixture whose shared creation helper starts folder sync and waits for the final configured folder. This is account/folder exposure and fixture readiness, not complete EWS operation coverage or a live Exchange result. The stale getMailAccounts summary still mentions excluding EWS despite its filter. The added custom shape assertions place a strict-options object in the description slot, so they do not enable strict object-key checking and provide no proper expected-behavior message at those calls. No test ran.

Scope: WebExtension EWS account and folder test support.
