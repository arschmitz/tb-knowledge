# Nested link clicks use the owning anchor for navigation attributes

Entry 1468 fixes target handling when a click lands on a child inside a link. The accepted actor now obtains href and linkNode together from BrowserUtils.hrefAndLinkNodeForClickEvent, and canNavigate reads target from that owning link node. The fixture includes a span inside a target=_blank anchor, and the extension test expects a new tab for that link. In this navigation family, recommend pairing URL and target from the same owner instead of reading a target from the innermost event element. The later BrowserUtils helper is current context, not full coverage of its own introduction. No extension, mouse, keyboard, shadow-DOM or navigation test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Nested link owner attributes.
