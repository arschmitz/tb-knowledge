# NNTP certificate errors preserve request security context before completing the action

The NNTP request URI uses the configured server port. On the normal socket-error path, the client awaits security info, stores it as runningUri.failedSecInfo and reports a bad-certificate error before quitting and completing the action. _onClose awaits a separate promise resolved after that normal completion path. The shared transport listener reads the same failedSecInfo field for bad-certificate URL failures. Later accepted code adds a security-info guard and server-key argument; those were absent from the original extraction. Mail-session feedback forwards the report and does not add an exception. The checked source does not prove rejection cleanup, native delivery, certificate trust or a user-approved override. Required numbered Bug 1192098 comment 3 is unavailable; source publication has zero full-audit credit.
