# The Calendar telemetry switch task retains a shared expected-label dependency

The new telemetry test shares expectedTelemetryValue across tasks. checkTelemetry(label) adds a label, while checkTelemetry() only compares the whole current expected map. testSwitchTabs opens Calendar and Tasks and uses only the no-argument form. Closing and reopening tabs removes one UI-state dependency, but does not initialize the expected map for this task. If those openings initialize views when earlier tasks were skipped, the actual labels are absent from that map. This is a conditional static isolation concern; no isolated run or active CI failure was observed. The mainline ordered task sequence still populates those labels in earlier tasks.

Scope: Calendar telemetry browser-test isolation.
