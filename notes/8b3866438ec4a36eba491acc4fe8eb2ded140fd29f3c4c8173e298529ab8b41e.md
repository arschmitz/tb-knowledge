# Normalize tag colors at the API boundary when storage has other writers

In D235449, the author explains that other consumers can update native tag storage, so creation-side uppercase alone cannot ensure consistent API output. The assigned patch stops uppercasing the color argument before native creation and uppercases tags.list output plus tracker cache/event values. Fixed tags.get also uppercases its returned color. This is a scoped public tag-API value contract; it does not require every native stored value to be uppercase. The three summary histories separately explain why color is the final creation signal after optional ordinal. Native write-order/event mechanics reuse existing lessons. Static source only; the linked Try and runtime event delivery were not verified.

Scope: Extension message tag value boundary.
