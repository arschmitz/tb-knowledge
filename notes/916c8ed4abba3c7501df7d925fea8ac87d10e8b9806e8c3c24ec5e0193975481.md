# Separate token presence classification from token validity

The historical 1173 hasPassword helper matches login origin, username and scope/realm. It does not check expiry or perform a refresh request. The tests label both valid and rejected tokens by their storage layout, then separately verify Bearer access_token after a request. Accepted tests now check reasons such as invalid grant and no refresh token without this inventory. A stored-token count is not a count of tokens known to work. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/MailGlue.sys.mjs.
