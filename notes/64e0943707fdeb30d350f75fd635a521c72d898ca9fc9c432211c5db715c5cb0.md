# Saved-search create and edit buttons use distinct localization contracts

The historical saved-search dialog chooses an accept button key and label from separate create/edit dialog attributes. The patch fixes both JavaScript writes to accessKey on getButton("accept"). At the fixed revision those branches instead choose Fluent messages with their own label and .accesskey fields. The correct JavaScript property spelling does not rename a Fluent attribute or authorize one key for both modes. No live dialog or keyboard validation ran.

Scope: Saved-search properties accept-button initialization.
