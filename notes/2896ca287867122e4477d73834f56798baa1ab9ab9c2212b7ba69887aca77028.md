# Selected protocol state must be the configuration captured for the next step

The 1198 implementation finds an incoming configuration by matching configType, then tests incoming.type != configType before changing the selected model. For a valid match, that guard is false, so changing the displayed alternative does not replace the captured incoming configuration. The misspelled references inside the guarded block are separate static defects, not a demonstrated executed crash. The accepted source explicitly assigns the selected incoming object and captureState returns a copy. This is a source-traced historical/current contrast; the later repair chronology and exact user-visible failure were not fully studied or reproduced. Full bug and review discussion remains pending.

Scope: Account Hub selected configuration.
