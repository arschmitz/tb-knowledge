# Refresh move-transaction headers from each completed move

For the inspected Exchange move transaction, undo moves the current header set from the original destination back to the source; redo uses the original direction. The folder operation supplies its newHeaders to a completion listener, and that listener replaces the transaction current set. Later moves therefore use the completed operation headers instead of stale original objects. The listener retains the transaction until callback. Current copy support/shared registration are later phases than the initial move-only landing. This is a callback-state contract, not proof of failure recovery, reentry protection or legacy-fallback correctness. No undo/redo test ran.

Scope: Exchange same-server move undo and redo.
