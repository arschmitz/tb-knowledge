# Check the removed message payload when testing database deletion callbacks

The initial listener test directly checks only the removed header interface and key. Its remaining post-delete field checks still use headerAdded, so those assertions do not directly establish the removed callback payload. At the fixed accepted revision the same checks use headerRemoved and cover folder, message ID, date, author, subject and read flags; the removed keyword assertion remains a commented TODO. Deletion payload lifetime is a real contract: the initial implementation copies row fields before dispatch, while the fixed implementation deliberately leaves cached data available and records unresolved notification TODOs. No runtime test was run for this study. Existing execution of a path must not be described as a direct assertion of every payload field.

Scope: Panorama notification regression tests.
