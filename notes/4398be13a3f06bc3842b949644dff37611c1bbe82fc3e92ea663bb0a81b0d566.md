# Insert message keys, flags and levels as one view-row operation

The native DB view stores keys, flags and indentation levels in parallel arrays. InsertMsgHdrAt inserts all three at the same index. The unread-thread listing uses that helper for each visible unread header, so an extra m_levels append in ExpandByIndex gives levels a different length from the other arrays. Entry 679 removes that append. Current code retains the helper and the removed append is absent. The existing view test checks expand/collapse row counts and quick-search levels, but it is not a newly added test of the exact read-root/unread-child failure. Manual C++ review proposal in this view family: keep row-array changes together and check row count and levels after filtering or expansion. This augments the old cross-folder level lesson; it does not imply that every extra sort is redundant.

Scope: native-message-view.
