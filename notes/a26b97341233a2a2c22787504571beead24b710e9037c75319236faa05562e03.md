# Allow POP authentication fallback at the rejected mechanism stage

Current PLAIN and LOGIN handlers advance to _nextAuthMethod when the mechanism command or an intermediate username challenge fails, before sending the next stage credentials. The terminal response handler also tries the next supported method and handles exhaustion through verify-logon failure or the password prompt. Keep command rejection distinct from a final password failure when reviewing this state machine. The current PLAIN else branch still has a FIXME about reporting username failure before a username was sent. Existing preferred-order knowledge is reused; no server interoperability or credential-log safety test was run. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: POP authentication stage fallback.
