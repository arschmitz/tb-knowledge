# Keep smart tag lookup error handling tied to the target branch contract

In the scoped D234679 review, retaining a redundant mainline lookup catch solely to ease an ESR 128 backport was rejected; a128-specific top patch was requested and the author agreed. The final mainline getTagFolder uses nullable getChildNamed outside the creation try/catch, while creation errors are still caught. When reusing this change on another branch, check that branch’s actual lookup contract before carrying over or removing a catch. This is an accepted local mainline/backport decision, not a general ban on catches or proof every lookup error is swallowed. The current source and complete assigned public discussion were read; no ESR build or runtime test was run.

Scope: mail/modules.
