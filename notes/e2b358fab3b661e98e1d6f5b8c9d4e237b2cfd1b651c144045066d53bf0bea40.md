# Notification preview length is a word-boundary target with distinct confidence and error paths

Fresh full preview patch read. With show_preview enabled and nonempty preview, _getAlertBody awaits LanguageDetector.detectLanguage, uses the detected language only when confident, and otherwise passes undefined to Intl.Segmenter. It cuts before the first word-like segment with index strictly greater than preview_length, trims trailing whitespace and adds an ellipsis. This can exceed the target and leaves the preview whole if there is no later matching boundary; it is not a strict character cap. The language-detection proposal is implemented despite Not Done. Review explicitly accepts URL-splitting as a limitation. The second newline separates notification text sections and is not source-code blank-line guidance. Fixed source retains the mechanism. Low-confidence fallback is distinct from detector rejection: the fixed caller catches a body error, logs it, then skips the system alert when body is absent. Author Linux-impact expectation is not an enforced Linux-only code condition. No changed tests cover boundary/equality, URL, confidence or rejection cases; none ran.

Scope: New mail notification preview segmentation.
