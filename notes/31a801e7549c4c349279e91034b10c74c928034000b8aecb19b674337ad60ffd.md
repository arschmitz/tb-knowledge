# Treat extension message user intent as an explicit option

messages.move/copy default isUserAction to false. For regular folder-backed operations, copyMessages receives the available normal window’s msgWindow and isUserAction as allowUndo. A user action without that window still passes null. The external-message copyFileMessage branch receives the window but has no allowUndo argument; moving an external message is rejected. Keep these branch contracts separate. The tests inspect undo item counts rather than replaying undo. The option does not guarantee every backend operation can be restored. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: extension message user actions.
