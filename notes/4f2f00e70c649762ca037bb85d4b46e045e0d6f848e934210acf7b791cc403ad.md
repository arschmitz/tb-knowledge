# Skip unrelated credential identities before changing their data

The OAuth refresh-token loops first restrict logins by origin, then continue immediately for another username. Current getRefreshToken and setRefreshToken retain that shape before scope matching or password changes. Proposed scoped syntax rule: keep identity guards before credential mutation and use an early continue so the matching path is clear. It is a readable control-flow convention backed by these loops, not a claim that early returns are universally required.

Scope: OAuth credential-loop syntax.
