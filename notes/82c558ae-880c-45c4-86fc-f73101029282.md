# Serialize POP3 client runs at the shared server boundary

Bug 1847137 changed POP3 access from parallel to a class-wide queue in Pop3IncomingServer.withClient. Pop3Service and Pop3Channel both enter through this method. A queued client starts when the preceding Pop3Client reaches _actionDone and calls onFree. The older downloadMailFromServers callback chain does not serialize all client runs. The review moved the queue from client-local/polling logic to this common boundary. This guards accounts that can deliver into one Inbox. The code still uses this queue in the current checkout. This commit added no focused serial-access test, and no runtime test was run in this study.

Scope: POP3 connection lifecycle.
