# Account Hub checks activity-specific stored OAuth tokens before optional discovery

Entry 1459 replaces Google-specific granted-scope string checks with OAuth2Module initialization for carddav and caldav, followed by a stored refresh-token check. Current CardDAV discovery retains this pattern and awaits getRefreshToken; the historical method was synchronous at the landing. In this discovery path, recommend asking the token module for the actual activity rather than inferring authorization from the mail configuration scope string. A missing provider mapping or a missing sufficiently scoped stored token returns an empty resource list. Current CalDAV discovery has moved, so this note does not claim its current owner uses the same exact call sequence. No token-vault, provider authorization, network or discovery test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Account Hub activity-specific OAuth discovery.
