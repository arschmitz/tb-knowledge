# The IMAP discovery test checks closed databases across store and subscription variants

The current test_listClosesDB tasks run discovery with and without subscriptions, update Inbox, and require null cached databases for folder1, its three descendants and Trash. Setup varies subscription flags between mbox and maildir; the manifests run both. Setup still uses a 1000 ms delay because the comment reports shorter delays could race discovery. These are inspected assertions and a historical test comment, not a reproduced timing failure or proof every folder database is always closed. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: IMAP discovery database test.
