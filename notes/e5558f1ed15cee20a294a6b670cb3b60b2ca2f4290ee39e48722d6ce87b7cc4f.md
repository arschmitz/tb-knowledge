# EWS sync callbacks distinguish detached-header insertion from existing-header commits

Fresh full five-file diff read, including Rust/Cargo/IDL changes. The landing separates SaveNewHeader (AddNewHdrToDB) from CommitChanges (database commit), documents callback roles and uses NS_ERROR_ILLEGAL_VALUE for an existing EWS-ID create and NS_ERROR_NOT_AVAILABLE for a missing expected-existing lookup. The null-on-missing proposal was rebutted with the expected-existing caller contract and Rust getter binding rationale; no global get/find or exception rule follows. The later if(existingHeader) question remains Not Done, and the landing still branches on NS_SUCCEEDED(rv). The landing applies both true and false read/attachment values through dedicated methods. It sorts creates, updates/read changes and deletes before processing; fixed0b93 instead explicitly preserves server chronological order in the moved sync module. Current missing-update recovery calls on_message_created, whose C++ callback actually inserts AddMsgHdr. The old recovery branch creates a header then commits without an explicit SaveNewHeader in that branch; its detached-header recovery persistence was not exercised or independently proved. Do not claim that historical branch guarantees insertion.

Scope: EWS message synchronization callback contract.
