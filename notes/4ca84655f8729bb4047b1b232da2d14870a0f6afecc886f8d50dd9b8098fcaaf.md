# Keep the POP3 sink lifecycle explicit in interface documentation

The current nsIPop3Sink IDL describes beginMailDelivery followed by endMailDelivery or abortMailDelivery, and separate incorporateBegin/write/complete-or-abort calls for each message. beginMailDelivery now has a void IDL result; native failure can still throw through the binding. Its uidlDownload parameter comment remains unexplained. Recommend documenting that distinction when touching this interface; the old public downloadInProgress attribute is absent. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/local/public.
