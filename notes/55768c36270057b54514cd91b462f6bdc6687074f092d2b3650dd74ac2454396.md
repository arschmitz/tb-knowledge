# Thundermail multipart encryption restarts a key-derived sequence

The uploader creates one content key for a file and passes that key to each part upload. Each part starts a new encryption transformer with sequence zero. Its nonce base comes from the first 12 exported key bytes, and the record sequence is XORed into that base. The per-transformer salt is stored in the header but is absent from this nonce-base calculation. Consequently the inspected source supplies the same key-derived starting sequence for each part of that upload in both phases. This is an input-identity and arithmetic finding, not a demonstrated cryptographic failure or safety guarantee.

Scope: Thundermail generated multipart uploader and ECE transformer.
