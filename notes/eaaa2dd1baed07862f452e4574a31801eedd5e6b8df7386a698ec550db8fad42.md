# Keep ordered source priority distinct from fastest promise completion

Accepted discovery starts disk, ISP, database and MX work in parallel. promiseFirstSuccessful then awaits the started promises in priority order and aborts lower-priority work after an ordered winner succeeds. It is not Promise.any choosing the fastest response. Proposed manual comment rule for this helper: describe the ordering, cancellation and all-failed result explicitly whenever changing its concurrency contract. This note is based on source inspection. Tests were not run, and full review discussion remains pending.

Scope: mail/components/accountcreation.
