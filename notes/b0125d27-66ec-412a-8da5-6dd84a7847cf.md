# Give unified and tag folders stable public IDs separate from smart storage

The accepted folder API maps native smart-account folders to public unified://<type> with /unified/<type> and tag://<key> with /tag/<key>. It checks that resolved native folders are actually the expected unified or tag kind before returning them, rather than trusting an ID prefix alone. The hidden smart account is not exposed as an API parent. In Manifest V2, accountId remains an empty string for these virtual folders because the old schema required a string; Manifest V3 omits it. Keep public IDs independent of internal account layout and preserve versioned compatibility.

Scope: WebExtension folder API.

Paths:

- `mail/components/extensions/ExtensionAccounts.sys.mjs`
