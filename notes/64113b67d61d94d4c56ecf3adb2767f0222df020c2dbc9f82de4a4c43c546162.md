# Icon conversion serializes shared-canvas work before parallel blob-byte reads

The multi-image icon path reuses one canvas. It awaits each draw and PNG capture in sequence, then reads the captured blobs into byte buffers in parallel. ICO construction uses indexed offsets into those buffers. Keep the shared mutation step distinct from the later reads; this is the accepted local order, not a measured performance result or general concurrency rule.

Scope: content-tab-icon-shared-canvas-order.
