# Report encryption intent even when the current identity cannot encrypt

Entry 525 explicitly keeps enabled encryption in ComposeDetails after an identity change makes it invalid. Current source reads the actual button when present and falls back to gSendEncrypted only when removed. Capability and intent differ; silently reporting encryption off would misdescribe the composer. The comment says the invalid message will not send, but this study has not followed that send guard at runtime.

Scope: mail/components/extensions/parent.
