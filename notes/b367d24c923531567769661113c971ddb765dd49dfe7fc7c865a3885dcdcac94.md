# EWS fetch completion now feeds a store read instead of exposing remote bytes directly

Entry 1483 replaces the direct EWS network message channel with a storage-backed fetch/write/read design. The accepted ExchangeMessageChannel first checks HasMsgOffline, reads existing content from the store, or downloads through ExchangeFetchMsgsToOffline and only starts the store read on success. This separates remote fetch completion from the channel stream seen by consumers. Existing shared knowledge already covers the asynchronous copy boundary; this note describes the additional local-store handoff. No EWS, store, message display or MIME conversion operation was run. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange message store handoff.
