# The XUL store slice writes persistence in its reducer without observing external updates

The XUL store slice initializes from the stored document/element/attribute value. Its set reducer writes the payload through XULStoreUtils and returns that payload as Redux state. The wrapper maps aliases such as messenger to a document URL. This factory installs no observer for later external XUL-store writes. Tests directly check reducer persistence and dispatch results; the implementation is a scoped side-effecting reducer, not a recommendation that all Redux reducers persist data.

Scope: state/xul-store-slices.
