# Production reset helpers should describe the operation rather than their former test use

Entry 867 renames _testHelperResetFilterState to _resetFilterState because switching to a special view uses it in production. DBViewWrapper forces threading and clears search terms for special views; SwitchView routes the reset through cmd_resetQuickFilterBar. The command resets only when the filterer is visible. The helper clears the stored sticky bit, creates a new QuickFilterState, updates search and reflects UI state. Tests and the shared teardown helper use the same renamed operation. Manual naming proposal: remove test-only wording when a helper becomes production behavior, and document the actual reset scope. The changed tests update calls but do not add a direct special-view regression scenario.

Scope: quick-filter-production-reset.
