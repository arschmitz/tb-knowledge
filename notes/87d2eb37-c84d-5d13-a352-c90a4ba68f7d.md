# MsgAuthPrompt.#promptUsernameAndPasswordInternal behavior in mailnews/base/src/MsgAsyncPrompter.sys.mjs

Rejects session-only saving. Creates unchecked checkbox, computes origin/realm, and shows remember label only for permanent saving enabled for that origin. For each matching stored username, marks checkbox true and fills password only when caller did not supply one. It always opens the username/password dialog. Cancel, unchecked state or absent origin returns dialog result. Otherwise it enforces primary-password policy and, if allowed, creates and awaits adding a LoginInfo before returning result. It does not recheck canRememberLogin at the save branch; matched stored login can set checked even when label is hidden.

## State read

- Save mode and per-origin saving flag
- Caller username/password
- Stored matching login credentials
- Dialog ok and checkbox

## State changed

- Caller username/password during preload and accepted dialog
- Login store via addLoginAsync when save branch reached

## Calls and triggers

- Own #getRealmInfo; Services.logins.searchLoginsAsync/getLoginSavingEnabled/addLoginAsync; local nsIPrompt_promptUsernameAndPassword; lazy.enforcePrimaryPassword resolves mail/modules/PrimaryPassword.sys.mjs:13-33, which checks policy/token and may open password setup dialog.

## Result and consumers

Promise<Boolean> resolves after dialog and any awaited login write, consumed by synchronous wrapper. Declining primary-password setup still returns dialog ok without saving.

## Errors

Session mode rejects NS_ERROR_NOT_IMPLEMENTED. URI, search, UI, policy, LoginInfo or add failures reject; no local catch/rollback. Output credentials may already be changed before add rejection.

## Async completion

Search awaited before modal prompt; add awaited after acceptance. No cancellation object or timeout.

## Ownership and cleanup

Caller owns credential wrappers; local checkbox/new LoginInfo created per operation; login service persistence ownership external.
