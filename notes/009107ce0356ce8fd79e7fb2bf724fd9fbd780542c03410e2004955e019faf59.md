# Ignored-thread commands apply the selected-message change before returning

Historical 613 moves notification setup and the ignore-thread/subthread action out of requestAnimationFrame while leaving only view reset deferred. The 639 follow-up also makes the explicit view reset synchronous. Current code is newer: the state change and threadTree.reset are both synchronous. For a single-backed virtual folder, the command checks ignored state in its underlying real folder; multi-folder and grouped views are excluded by command enablement. Manual command review proposal for this path: do not defer actions that read the current selected messages merely to avoid a layout flush; separate the user action from optional rendering work. The current reset comment still documents missing backend notification. External bug reasoning remains pending, so no unobserved menu race or exact failure trigger is claimed.

Scope: message-list.
