# Keep the backed-out URI shortcut separate from the accepted selection fix

The original message pane returned early for the same URI. A later selected backout exactly restores the prior file and reports a memory leak, without an inspected diagnostic. Current displayMessage lacks that guard. The later accepted path instead compares thread selections before suppressing redundant selection notifications. The lesson is to trace the complete landing/backout/replacement chain; do not preserve the same-URI shortcut as current guidance or infer how it leaked. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Message display and selection lifecycle.
