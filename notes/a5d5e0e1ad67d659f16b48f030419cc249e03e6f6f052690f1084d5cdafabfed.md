# Carry the selected account configuration through verification and creation

In the 1956579 repair, the configuration widget returns a copy with the chosen incoming protocol. The controller fills and stores that captured object before continuing. Verification writes successful auth methods and usernames into the same completeConfig passed to account creation. The browser task checks the resulting account type, not only the selected radio style; its manual-config companion checks the protocol field but does not finish account creation. The review found an EWS username placeholder after initial protocol success and later reported success after another update. Those manual reports are attributed. The separate async backend handoff is not awaited by validateAndFinish, so its promise alone is not proof the account exists. No test or live authentication ran here.

Scope: Account setup and Settings state.
