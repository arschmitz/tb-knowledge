# Test granted OAuth permissions separately from authorization success

658 adds granular-scope scenarios for no grant, mail-only, non-mail and all grants. Its fake IMAP server now checks that the access token actually grants test_mail. A valid username and token string are insufficient when mail permission is absent. The historical success path copies the granted scope to incoming/outgoing configuration and checks its persisted login realm and server preferences. Current tests still assert authorization completion before accepting the expected mail-verification failure. No real provider grant or browser test was run.

Scope: Granular OAuth permission behavior.
