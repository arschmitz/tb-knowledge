# Account Hub header refresh derives close-button visibility from first-run state

Fixed AccountHubHeader.refresh assigns closeButton.hidden from isFirstRun(). The predicate can return false for enterprise mode, a valid account, an enabled calendar, a populated non-system address book or the startup suppression preference. The inspected tests assert a hidden button on first run and a visible button on a subsequent run. The earlier landing in entry 2927 only disabled the raw account-count check while first-time rollout was not enabled; that temporary exception does not establish current policy. The button sends request-close, and the modal consumer still gates closing on its own minimized/reset state. These are static source and assertion facts, not executed UI or keyboard validation.

Scope: Account Hub close-button lifecycle.
