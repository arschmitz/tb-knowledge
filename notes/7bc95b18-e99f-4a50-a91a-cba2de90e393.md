# Document the enabled algorithm that requires a legacy crypto provider

When enabled algorithms require an OpenSSL legacy provider, express the dependency directly instead of relying on a version condition for a different algorithm. Commit 267 always enables CRYPTO_BACKEND_OPENSSL3_LEGACY for the OpenSSL3 backend because IDEA, CAST5 and BLOWFISH remain enabled. The review requested the reason comment; current code keeps it and a source link. This does not imply every OpenSSL3 consumer needs the legacy provider.

Scope: RNP build.
