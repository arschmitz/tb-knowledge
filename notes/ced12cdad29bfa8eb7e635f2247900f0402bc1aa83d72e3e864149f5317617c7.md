# Proxy feature restriction and preference setter selection remain separate source paths

The callback retains the Locked feature restriction but always supplies PoliciesUtils.setDefaultPref to the comm proxy helper. That helper does not read Locked and calls its setter with name/value only. The current proxy test has no explicit Locked:true case. These are forwarding and test-scope facts; the separate Gecko setter and native locking behavior are unpaired and unexecuted, so no runtime lost-lock result is claimed.

Scope: Enterprise Proxy policy forwarding.
