# Change POP3 service return types when connection start becomes queued

The queue makes GetNewMail and CheckForNewMail start asynchronously, so Bug 1847137 changed both nsIPop3Service IDL methods from nsIURI returns to void. Pop3Service and Pop3IncomingServer stopped returning the immediate running URI in the same patch. When queueing an operation behind another connection, check interface return contracts and callers together. This is a scoped API lesson, not a general rule that asynchronous methods cannot return a URI.

Scope: POP3 service API.
