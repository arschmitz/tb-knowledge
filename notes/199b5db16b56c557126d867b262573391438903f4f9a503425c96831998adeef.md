# Keep a live Panorama collection separate from its message snapshots

The current documentation says LiveView stays updated but sends plain JS objects; CreateJSMessage allocates a fresh plain object and copies primitive fields, with a new Date for its timestamp. Do not expect an already obtained message snapshot to mutate like an XPCOM header. Preserve the documented listener/update route for collection changes.
