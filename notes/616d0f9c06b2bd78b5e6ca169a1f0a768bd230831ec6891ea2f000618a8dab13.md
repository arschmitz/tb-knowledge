# Linux descriptor pre-expansion runs after the fork-server hook

In the checked comm startup code, XP_LINUX gates a temporary F_DUPFD duplicate of descriptor0 with minimum256. The helper runs after the fork-server hook because the source says forking resets the table size; a stopping fork-server returns before it. A scoped handle owns the duplicate, and errors are intentionally ignored as an optional optimization. Preserve that caller order and lifetime when changing this code. Capacity512 and 30–50ms comments are rationale, not a fresh timing result or a guarantee for every process. The later missing-header follow-up is separate. No Linux startup or build ran.

Scope: Application startup.
