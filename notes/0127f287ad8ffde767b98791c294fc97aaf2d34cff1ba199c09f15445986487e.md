# AsyncChannelOpener narrows the wrapper to a buffered channel result

The original refactor replaces XpComFuture<T> with a channel-specific AsyncChannelOpener. Its poll installs the listener waker, starts AsyncOpen once and waits for final status before draining buffered bytes. Original success returns a clone of the original channel, which the original HTTP caller discards. The fixed accepted future can instead return the listener's replacement channel, and the current HTTP caller uses it for response metadata. That later redirect/retry handling is a separate phase. No streaming, cancellation or runtime request result was tested.

Scope: Rust XPCOM channel glue and HTTP request completion.
