# Allow feed icon output rather than broad source-image protocols

The feed-subscriptions fix adds data: images. Current FeedUtils returns favicon.dataURI.spec after storing and reading the favicon; the subscription tree awaits that result, caches it on the row and invalidates the row. Keep the CSP permission tied to the representation the icon consumer receives. This narrow chain does not prove that every icon in the project is always a data URL. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Feed subscription icon representation.
