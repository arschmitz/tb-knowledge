# Compare derived tag contents rather than newly allocated array identities

The current keywords handler allocates newKeywords and oldKeywords with split/filter, then compares them using !=. Distinct arrays compare unequal even if their valid tag contents match. Native notifications are guarded by raw keyword changes, so the narrow concern is a raw keyword change that leaves the visible tag list unchanged. Recommend a content comparison and a test with non-tag keywords; no redundant event was reproduced. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: extension message tags.
