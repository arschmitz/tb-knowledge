# Keep both declarations of the Rust authentication FFI boundary aligned

The initial C header declared incoming_server, uri and action, while the Rust exported function accepted incoming_server and action only. A compile/link or native call was not run, so no concrete corruption or crash is claimed. The accepted declarations now agree on incoming_server, action and ErrorBehavior. Compare argument count, order, types and enum representation on both sides of this native boundary rather than relying on the common symbol name. Pointer null checks only reject null; callers still must supply valid objects for the call lifetime. The stale header crate name mailnews_prompt_glue does not match actual mailnews_ui_glue and is documentation evidence, not a naming rule.

Scope: mailnews_ui_glue C++ and Rust interface.
