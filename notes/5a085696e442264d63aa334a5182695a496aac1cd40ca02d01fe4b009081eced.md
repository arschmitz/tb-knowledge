# Use conversion names that reflect ownership and cost instead of an ordinary getter

Historical D210712 suggested as_ for a header representation; the author chose to_auth_header_value because conversion was not free. That 2024 method name is historical. Current shared AuthenticationProvider uses a different auth_header_value operation and does not establish that prefix. Proposed scoped Rust naming rule: distinguish a borrowed view, allocating conversion and consuming conversion when the new API has those semantics. Do not infer a global get_/as_/to_ policy from this one review.

Scope: rust/ews_xpcom/src.
