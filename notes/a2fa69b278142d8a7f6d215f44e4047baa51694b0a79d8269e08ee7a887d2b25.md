# Custom database and searchable-header preferences use different separators

The accepted parser lowercases mailnews.customDBHeaders and parses its space-delimited names. It strips whitespace from mailnews.customHeaders and parses colon-delimited names, deduplicates the merged list and uses lowercase database property names. Received is accumulated separately when retained as a custom header. Keep these local preference grammars distinct instead of apply one generic split rule. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
