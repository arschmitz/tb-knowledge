# Buffer-compaction comments should state which byte count they compare

The current Drain stores Available before incrementing mCursor, then compares that saved pre-drain count with one quarter of mOutBuffer.Length. Its comment describes the proportion left unconsumed. Recommend reconciling the comment and intended threshold when changing this code; pre-drain available and post-drain remaining are different units of state. This is a scoped static clarity concern, not a measured performance or corruption failure. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
