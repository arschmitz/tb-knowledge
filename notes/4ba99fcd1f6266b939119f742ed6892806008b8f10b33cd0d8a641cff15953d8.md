# ProxyGetChildNamed checks its folder before dispatching the import runnable

Fresh complete child-proxy null-guard hunk and needed runnable/callers read. ProxyGetChildNamed now validates the folder before constructing a runnable that dereferences m_folder on the main thread; successful dispatch still returns the runnable's folder-operation result separately from dispatch status. It does not add an aChild-pointer guard or normalize every caller state. Fixed depth-increase caller treats failed child lookup as fatal and breaks; post-create lookup reports failure and gates import on result/newFolder. The bug attributes the crash to a null folder and explicitly reports no automated coverage, Daily/Beta verification or known reproduction. Review uplift feasibility is distinct from later Bug beta/ESR landing records. Neither establishes the crash circumstances or an executed test here. This is a scoped receiver precondition; it does not add all-output validation or establish the upstream reason a folder became null.

Scope: Mail import main-thread proxy receiver guards.
