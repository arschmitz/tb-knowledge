# Wait for each tag-keyword change before the next message mutation

The extension update path creates its Keywords listener before removing obsolete tags, awaits that listener, then creates and awaits the addition listener. Junk changes happen last because they can reload the displayed message. Preserve this completion order in this API. Awaiting the extension method must include the tag events; merely calling the underlying mutation is not the same completion boundary. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Message update tag and junk ordering.
