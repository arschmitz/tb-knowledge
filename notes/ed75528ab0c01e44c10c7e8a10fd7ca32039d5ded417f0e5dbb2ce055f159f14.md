# The EWS send migration routes a failed start callback through stop reporting

Before this migration, a failed start listener logged and returned from send_message. The new DoSendMessage returns that failure from do_operation before building CreateItem. Shared handling then uses the outgoing listener's explicit failure adapter, which calls OnSendStop with the retained server URI and error status. Thus rejecting the start still prevents a send request, while failure reporting follows the common stop path. A failed success callback remains a separate warning. This is source control-flow evidence; no send or callback-failure test ran.

Scope: EWS outgoing operation lifecycle.
