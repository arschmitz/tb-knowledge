# Notification action preferences feed a later per-message validity filter

Fresh full six-file244-line notification-action preferences patch and all changed test hunks read. For system alerts the dialog creates one checkbox per available action, initializes from enabled action IDs, hides the old time controls and saves checked IDs as a comma-separated preference on dialogaccept. For custom alerts it hides the action heading and saveActions returns without changing the action preference. The landing also moves the mark-as-read,delete default outside NIGHTLY_BUILD; the earlier Daily-only prototype default is a separate landing. Fixed manager lazily resolves localized titles, maps stored IDs to known action objects and ignores unknown names. Current definitions additionally include starred, spam and archive; these later capabilities are not attributed to the original two-action UI. When a system notification represents one message, the consumer filters enabled actions by isValidFor and dispatches a selected action against that message; multiple-message notifications do not receive this list. Checkbox selection is not a guarantee that every enabled action is shown for every message/platform.

Scope: Notification dialog preference and system alert consumer.
