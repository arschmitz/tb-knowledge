# Mbox discard success does not prove stream rollback succeeded

DiscardNewMessage closes either the matching current stream or an already-preempted old stream, ignores the Close result and returns NS_OK. MboxMsgOutputStream returns success for an already-closed stream, but an active rollback can fail while flushing, seeking or truncating. The store return therefore does not prove data rollback succeeded. Keep this completion limit separate from the stream-identity guard that preserves a newer write. The matching branch also logs a lookup value after map removal; the source order is recorded but that handle lifetime is unresolved. No rollback or logging test ran.

Scope: Mbox discard return and rollback completion.
