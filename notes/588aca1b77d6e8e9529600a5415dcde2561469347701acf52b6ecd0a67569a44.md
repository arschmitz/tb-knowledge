# Search-result deletion refreshes the XUL row count through an update batch

OnDeleteCompleted acts when m_deletingRows is set: it releases suppressed change notifications, clears that flag and begins/ends an XUL tree update batch. The changed source comment names row-count refresh plus invalidation as the reason; a plain mTree->Invalidate previously did only the old path. The JavaScript tree remains a separate consumer, and frozen code now invalidates its full row range. Preserve these consumer-specific refresh paths when changing deletion cleanup. The patch adds no regression test, and the actual tree/accessibility row count was not observed. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: Search Messages delete row-count refresh.
