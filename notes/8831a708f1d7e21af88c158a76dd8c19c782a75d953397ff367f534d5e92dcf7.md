# Unread-folder selection tests use folder-level read notifications

The selection scenarios call folder.markMessagesRead or markAllMessagesRead after changing folders. Their local comment explains why: moving selection can close the earlier folder database, so changing only a message header may not notify folder listeners. The tasks directly compare which ordered row URIs remain after the action, including selected rows, ancestors, unread siblings and compact mode. They do not directly assert DOM focus or multiple-selection behavior. Preserve the action that emits the folder notification when extending these scenarios; an arbitrary wait does not replace that action. This is the accepted test contract, not a fresh database or browser result. Required Bug and review gaps keep entry 4279 partial.

Scope: Unread folder test actions.
