# The account-removal test repair waits for both button state and dialog closure

The selected repair moves five callers to closeRemoveDialog. It registers the disabled-state mutation wait before the first click, waits until the button is enabled again, then registers dialogclose before the second click. This replaces each caller's immediate disabled assertion and button-only wait. The fixed accepted helper later uses direct success/failure checks and acceptDialog, so the mutation-wait sequence is a historical phase, not the enduring implementation or a general harness rule.

Scope: Account-removal browser test completion.
