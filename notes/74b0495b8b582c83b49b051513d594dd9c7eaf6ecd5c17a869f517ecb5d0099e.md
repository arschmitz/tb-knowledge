# Exchange status feedback has distinct historical window and current service lifetimes

The historical reland obtains window feedback before remote work and captures it in callbacks. Folder/account sync allow missing feedback, while hard delete checks the window but then assumes a feedback object. Accepted current code looks up the global Feedback service separately and checks it before reporting status; delete success and failure both report stop. Account error also continues its post-sync callback for remaining work. Keep those phases separate: status reset is not proof remote work succeeded or every early-start failure has cleanup. No UI or EWS test ran.

Scope: Exchange progress status and operation completion phases.
