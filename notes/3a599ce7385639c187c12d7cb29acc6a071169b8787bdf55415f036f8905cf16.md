# The new header-to-UID assertion has no explicit expected-result message

The added UidsFromHdrs body calls MOZ_ASSERT(key != nsMsgKey_None) without an explicit message. The same call remains in the inspected fixed implementation. Under the current user-directed assertion rule, this changed site needs a nonempty message stating that the message header should have a valid key. This scoped finding is separate from older formatter assertions, unchanged caller assertions and any runtime failure.

Scope: IMAP staged UID assertion review.
