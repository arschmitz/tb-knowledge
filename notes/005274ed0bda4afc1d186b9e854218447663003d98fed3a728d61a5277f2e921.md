# Preserve original and edited calendar items as separate comparison inputs

The summary dialog works on a clone stored in window.calendarItem. On accept, it passes args.calendarEvent as oldItem and the edited clone as newItem to onOk. Preserve that separation when adding dialog mutations; changing the original item early can destroy the comparison used to decide outgoing changes. The sender also strips user data from its own clone and restores DTSTAMP and LAST-MODIFIED after those mutations. These are source contracts, not executed scheduling validation.

Scope: calendar/base/content.
