# Distinguish the large-message abort report from the thrown failure

When the large-message confirmation is declined, the changed MessageSend path calls fail(NS_ERROR_ABORT), then throws a Components.Exception whose result is NS_ERROR_FAILURE. The reporting state and thrown exception therefore carry different results. The historical Now/SendUnsent report suppression changes to NS_ERROR_ABORT; fixed fail also suppresses its report for that result. This source observation does not prove that every later rejection consumer treats the decline as an abort or that no other alert can appear. Other delivery modes have separate report branches. Source only: Bug 783526 comment 14 is unavailable; reviews are unread. No runtime validation.

Scope: Compose cancellation result channels.
