# An IMAP-to-local move must let the destination delete the source only after copy success

An IMAP-to-local move must let the destination delete the source only after copy success. Passing `moveMessage=true` to the source service also let it delete before a failed local copy, losing mail. Another fix synchronizes IMAP flags before setting the new-message count and delays new-mail notice for unselected folders until local flags catch up with server state. Tests check cross-server failure and server/client message state. [move commit](https://github.com/thunderbird/thunderbird-desktop/commit/20298d0e6306), [biff commit](https://github.com/thunderbird/thunderbird-desktop/commit/0bc9cf3ace02).

Scope: mailnews.

This is a workflow or historical planning observation.
