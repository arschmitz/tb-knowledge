# Check POP plugin lock ownership after the open-window check is removed

The accepted CallFilterPlugins lock guard is scoped to pop3 and none servers, and initializes aFiltersRun to false. POP end-delivery releases its semaphore before calling plugins and then reconciles the new-message count for filtering effects. Keep delivery ownership and the no-plugin case distinct. The broader historical lock guard is not the accepted rule for every IMAP folder, and no compact-during-delivery race was reproduced. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: POP filtering lock and count boundary.
