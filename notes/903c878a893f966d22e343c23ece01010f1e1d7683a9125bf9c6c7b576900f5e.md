# Protocol-card styling consumes radio checked state and a separate recommended class

The initial story wraps each same-name radio and its visible title/body in a label. Its CSS uses input:checked for selected colors and shadow, while a recommended class separately shows the badge. The fixed accepted production form uses later identifiers and a literal default checked radio; its controller sets checked from the mapped protocol and reads the checked value. The same three localized body IDs remain in its template. This supports the explicit state/consumer contract only. The original Lit element-position checked interpolation is not paired with renderer internals, and no initial selection, native focus, accessible name, contrast or rendered-size result was tested.

Scope: Account Hub protocol cards.
