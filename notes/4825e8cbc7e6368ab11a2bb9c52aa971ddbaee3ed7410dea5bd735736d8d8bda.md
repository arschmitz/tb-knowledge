# Exchange request control has separate download and offline-read phases

Cancel, Suspend and Resume delegate when mReadRequest exists. During download they return NS_ERROR_NOT_AVAILABLE with explicit warnings because there is no underlying download request handle to control. GetStatus uses the read request only when mStatus is successful, otherwise its own status. Do not describe the channel as fully cancelable throughout its lifetime. The observed boolean/pending/status concerns are retained as unverified review questions in the batch ledger. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange request phases.
