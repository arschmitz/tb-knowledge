# Shutdown folder notifications must not overwrite persisted expansion state

The all-mode folder-add handler returns when accounts.shutdownInProgress before calling FolderTreeProperties.setIsExpanded. CleanupOnExit sets that flag before inspecting emptyTrashOnExit, and setIsExpanded changes the saved open list and schedules a save. Replacing the POP3 trash folder during exit therefore must not be treated as an interactive new-folder expansion. Manual lifecycle proposal for this handler: guard before the first persistent UI-state write, not only before DOM insertion. The source explains the reported failure and current ordering; this study did not execute a POP3 shutdown/restart test or establish the same requirement for every folder mode.

Scope: folder-pane-shutdown.
