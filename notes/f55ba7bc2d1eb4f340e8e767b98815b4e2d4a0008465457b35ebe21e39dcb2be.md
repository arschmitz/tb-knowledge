# Task refreshes reject stale job and iterator results before updating the view

The task-tree refresh marks cancellation before awaiting its stream reader. After collecting items it returns when cancelled or when the calendar’s pending-job entry belongs to a newer job; only the current job updates rows and emits refresh. The filtered-view mixin separately returns when invalidation has removed its iterator from the active set. These actual guards keep stale completion from publishing results. The browser test’s refresh event, count and membership assertions do not prove ordering, provider-wide cancellation or a runtime intermittent cure.

Scope: Calendar task refresh result ownership.
