# Extension getFull uses a message envelope around the parser MIME root

convertMessagePart exposes an outer message/rfc822 object even when the parser root is multipart or text. Most message headers move to that envelope; content-* headers stay on the inner MIME part. Decoded headers set the outer content-type to message/rfc822. Raw and decoded header paths are distinct. Failed decryption returns no nested parts, so traversal must not assume a body child exists. Keep parser representation and extension API representation separate when adding body extraction or tests. Scope: messages.getFull conversion. The converter, text/calendar fixture and historical test changes were inspected. No API runtime test ran.

Scope: WebExtension messages MIME.
