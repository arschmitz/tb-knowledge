# A custom port on one side does not directly block adjustment of the other

The final adjustment method first branches on isIncoming. Its incoming custom-port guard and return apply only to that side; the outgoing custom-port guard is reached separately. An incoming custom port therefore no longer directly causes the outgoing branch to return, addressing the review's cross-side guard concern. A side can still retain its own custom value or hit its own guard. The default isIncoming=false is explicit. Accepted source later adds empty/unknown-port handling and changes outgoing defaults, so those later rules are not attributed to this landing. This is source/test-code inspection, not a live account, TLS or connection result.

Scope: Account Hub manual-config side-specific port guards.
