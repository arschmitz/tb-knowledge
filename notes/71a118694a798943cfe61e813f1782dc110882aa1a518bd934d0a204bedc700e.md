# Keep raw and decoded message headers as separate API modes

The accepted getFull defaults decodeHeaders and decodeContent to true for compatibility. convertMessagePart chooses headers or rawHeaders from that option, then carries the same options through nested parts. Decoded root headers move non-content fields into an outer message/rfc822 envelope. Entry 979 describes the old always-decoded behavior; it is not the complete current API. Callers that require the exact encoded address syntax must select the raw mode. No extension runtime or paired binding execution was run.

Scope: mail/components/extensions.
