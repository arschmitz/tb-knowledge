# Keep post-copy cleanup after an XPConnect callback failure

MessageSend defers onStopCopy because the compose listener can release the send object and close its window before a promise resolves. The callback is guarded for nsIMsgCopyServiceListener; a non-zero result through XPConnect can throw, but cleanup still follows the catch. 1020 simplifies that warning to a message plus the caught error. Preserve the deferred lifecycle and cleanup order when changing this warning path. No compose-window race was reproduced.

Scope: MessageSend post-copy callback lifecycle.
