# IMAP offline append has separate returned and callback status channels

OfflineAppendFromFile uses a discard guard until store finalization succeeds. The inspected historical and fixed code still call OnStopRunningUrl with NS_OK after the copy loop, while returning the tracked rv from the function. Header publication also precedes finalization in this path. A caller must not treat that listener success alone as proof that bytes were committed. A proposed regression test should inject a write or finish failure and check both status channels and header/store state. Runtime impact and the listener consumer contract remain unproved; no failure was executed.

Scope: IMAP offline append status.
