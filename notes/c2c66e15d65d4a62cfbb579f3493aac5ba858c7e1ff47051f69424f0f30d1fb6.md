# IMAP service retrieval and flag-operation completion have separate result contracts

The migration uses a named Imap Service in typed nsCOMPtr bindings and removes old retrieval checks. StoreImapFlags explicitly starts rv at NS_OK; the online Add/SubtractMessageFlags call does not assign its result to rv, while the offline branch records operations in the database. Returning NS_OK here does not demonstrate successful network completion. The accepted source has later UID-conversion details, which are separate from this historical service migration. No runtime tests.

Scope: imap-service-and-operation-results.
