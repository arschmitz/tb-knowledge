# Derive date precedence from conditionals as well as comments

The accepted comment says Date falls back through Received before EnvDate. The implementation seeds datePRTime with m_EnvDate; if Date is absent and that value is nonzero, Received and Delivery-date do not replace it because they only fill zero. dateReceived separately follows Received, Delivery-date, then the Date-derived value. This is a narrow source/comment discrepancy. The dateless test has no Received header and does not resolve that precedence. No runtime behavior or review intent was invented.

Scope: Message parser date precedence documentation.
