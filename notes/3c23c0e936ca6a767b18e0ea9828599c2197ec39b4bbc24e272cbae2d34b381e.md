# Use a child folder to test missing string properties instead of a root error

Fresh full folder-cache patch and complete changed unit fixture read. Panorama bypasses the legacy cache in string reads/writes and deletion, with the historical FlushToFolderCache early success and key assertion. Non-Panorama retains the cache path and file-existence check. Missing time properties avoid opening the DB; general properties fall through to folder-info DB access, closing only a DB opened for the read. Setter DB/commit behavior remains separate; this patch does not remove every cache or promise all write errors are propagated. The fixed property reader/writer/deletion preserve startup-pref gating. Fixed FlushToFolderCache now asserts the non-Panorama contract rather than the historical early-success branch; WriteToFolderCache also rejects Panorama. These are later exact current differences, not a general rule against caches or proof every caller is safe. The old fixture used the server root with a broad Assert.throws. The changed fixture creates a real child folder and directly asserts empty string for a missing/case-mismatched property, plus Unicode and literal empty/null/0 strings. Needed historical and fixed local GetDBFolderInfoAndDB explicitly reject mIsServer with NS_ERROR_NULL_POINTER, supporting the review's wrong-failure-reason concern at this boundary. This does not reproduce the old test, prove all root getters are forbidden or replace each possible upstream error with a missing-value result.

Scope: Folder property fixture error versus missing value.
