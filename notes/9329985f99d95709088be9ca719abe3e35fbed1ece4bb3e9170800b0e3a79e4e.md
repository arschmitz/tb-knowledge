# The original Thundermail URL flow saves a token before configuration lookup

The original landing requires name, email and token URL parameters. It rejects an existing issuer-origin login with the same username, then saves the supplied token before FetchConfig.fromISP and config-view initialization. This method has no rollback around those later awaits. A matching login is not proof that an account exists. The fixed accepted handler/method instead takes only name and email and has no URL-token save block; its later OAuth flow must remain separate. No live token, endpoint or setup failure was tested.

Scope: Thundermail URL token persistence phases.
