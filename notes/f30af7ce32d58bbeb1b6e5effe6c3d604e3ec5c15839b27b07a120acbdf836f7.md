# Account retention edits now commit through the subdialog accept handler

The parent opens a retention subdialog with the incoming server. Its initialization fills controls; dialogaccept calls onSave, which writes the shared form values back to server.retentionSettings. The parent pane no longer writes retention settings in onSave. The old radio-change confirmation and cancel-to-retain-all fallback are removed; the shared UI now displays an inline warning for selected IMAP/POP3/EWS deletion policies. Its copied question text is static, while the subdialog has separate accept/cancel buttons. This does not pause existing purge work or prove deletion timing. Required discussion gaps remain and full-audit credit is zero.

Scope: Account retention dialog ownership and warning.
