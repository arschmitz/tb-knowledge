# Keep EWS identity lookup separate from generic property search

Proposal for this message-sync boundary: preserve the one-result remote-ID contract when factoring lookup helpers. The historical code searches the EWS ID before header creation. Review explains that database property metadata does not mark uniqueness and potential ID types are not all strings. A generic single-result string-property helper would hide those assumptions; the reviewer explicitly agrees to retain the EWS helper. EWS identity and local message key are different values. Current Exchange sync still checks remote identity before insertion and treats repeated create/delete changes as no-ops. The old successful-null callback and getter_addrefs Err(NS_OK) interpretation are boundary-specific; they do not define general Rust success handling. No replay, server or database test ran.

Scope: mailnews/protocols/exchange.
