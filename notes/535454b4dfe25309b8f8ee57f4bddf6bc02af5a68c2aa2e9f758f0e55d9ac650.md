# Name autocomplete result fields for their distinct API roles

Current local results store both value and label; value contains the serialized mailbox while label comes from _createLabel with optional address-book context. Scoped naming recommendation: keep these role names aligned with getValueAt/getLabelAt and call a display formatter a label formatter. The preference still has the legacy commentColumn name; that does not mean getCommentAt still returns the context. This is local API naming guidance, not a project-wide ban on the word comment. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: autocomplete naming.
