# The copy-move functional entry returns data so EWS junk can orchestrate the next step

The fallback adds a functional copy/move entry returning a Result with new IDs and resync information instead of immediately calling the operation listener. This lets the outer junk operation decide its success/fallback result, while a separate wrapper performs listener conversion. The original result is a Vec<String>/bool pair; accepted current code uses CopyMoveSuccess and RequiresResync. The purpose comment remains useful, but its pair/Boolean return wording is stale in current code. This is scoped Rust orchestration and documentation evidence, not a rule that every callback should become a functional method or a new build/test result.

Scope: Scoped Rust callback-free operation composition.
