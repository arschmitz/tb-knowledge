# Empty message selection clears both single and summary browsers

Entry 1513 clears both browser modes from either empty-selection entrypoint. Current displayMessage without a URI and displayMessages with an empty list still do that when the pane is not collapsed. Their helpers hide and clear the previous single/summary content, including conversation-view state where present. The early collapsed-pane return remains separate; do not promise immediate clearing in that branch from this patch. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: Message pane clearing.
