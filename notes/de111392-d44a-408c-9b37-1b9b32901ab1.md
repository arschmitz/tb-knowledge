# Let CardDAV population continue after Sync creates the address book

AddressBookStore.create starts CardDAV fetch after creating the book but does not await the remote population. In D205784 the reviewer suggested awaiting it; the author explained that a server failure or an hour-long fetch should not block syncing other items, and the suggestion was not applied. The rejected review request is an explicit behavior decision: Sync creates the book record, then remote content population proceeds separately and catches errors.

Scope: Thunderbird Sync task ordering.
