# The historical wizard passes a controller to the signal-based add-on installer

The abortable-removal patch changes AddonInstaller to accept an AbortSignal and use addEventListener on that value during direct installation. Account Hub passes controller.signal, but the historical wizard passes this._abortable, which it just set to an AbortController. Those are different caller contracts. The concern is limited to direct installation; an already-active matching add-on can return before that listener is used. Keep the historical wizard finding separate from the checked current Account Hub call. No installation or Owl-authentication result was reproduced.

Scope: Thunderbird account-creation add-on installation.
