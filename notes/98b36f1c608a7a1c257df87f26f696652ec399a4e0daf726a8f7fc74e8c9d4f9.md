# IMAP pending-removal byte accounting follows flag transitions

MarkPendingRemoval compares the requested mark with the existing nonempty pendingRemoval property before changing expungedBytes. A first mark adds the offline size, an unmark subtracts it and repeated same-state calls return without another delta. ApplyRetentionSettings can revisit the same offline headers, which explains the guard. The test directly checks these transition/repetition results; it does not test database failure or atomic flag/count persistence. Two new property assertions omit messages. No test or native IMAP operation ran.

Scope: IMAP offline retention.
