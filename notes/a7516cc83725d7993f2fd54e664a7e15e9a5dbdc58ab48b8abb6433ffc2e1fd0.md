# Distinguish the copy listener message key from a database header key

D229190 corrects a review concern that this SetMessageKey call mutates nsIMsgDBHdr.messageKey. In the checked historical path, CopyListener forwards to an nsIMsgSend-typed field, whose MessageSend setter assigns private _messageKey. The shared callback reports created-message identity; its name alone does not prove a database-key write. Keep the receiver and caller contract explicit before applying the concern from another protocol. Current Exchange still delivers keys to copy listeners, but the API is marked temporary. No copy, filter, send or runtime test ran.

Scope: Copy listener receiver and identity contract.
