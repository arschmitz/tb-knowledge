# Assert the invitation result instead of a constant completion marker

The landing removes Assert.ok(true, ran to completion) as four completion markers in the invitation tests. Current tests retain checks on real link counts/text, expanded Details state or iMIP bar readiness. Proposed local assertion guidance: use the relevant observable result rather than a constant true marker, while preserving awaited completion signals. This does not establish that every test needs extra assertions beyond its meaningful awaited condition. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: calendar test assertions.
