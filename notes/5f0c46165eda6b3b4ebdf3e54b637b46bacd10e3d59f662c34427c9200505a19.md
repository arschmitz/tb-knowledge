# Multiple To and Cc header aggregation must keep the owning buffer alive

Accepted FinalizeHeaders returns an empty value for no entries, reuses the single borrowed entry, or builds a caller-owned nsCString and returns a HeaderData pointer/length into it. The local aggregateToHeaders and aggregateCcHeaders stay alive through database assignment. Do not return a pointer into a lambda-local temporary or infer that HeaderData itself owns the aggregate string. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/local/src.
