# New-mail listener filtering remains separate from message collection

The internal messages-received event is collected per folder first. The API listener permits all folders when monitorAllFolders is true; by default it permits Inbox and normal folders while excluding special-use and virtual folders. It starts the message list before wakeup and then fires the converted folder and page. A current custom-listener test expects drafts only for the listener with true. These filters are API delivery policy, not the rule for adding a header to the pending batch. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: WebExtension new-mail folder policy.
