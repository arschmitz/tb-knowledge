# Trash discovery reads the raw preference before using a default

Current DiscoveryDone checks the raw trash_folder_name value because GetTrashFolderName can return the default Trash name even when no preference is stored. An explicit preference keeps matching folders and clears other Trash flags. Without one, a special-use Trash folder is preferred, with a default-name branch only when none is found; if no flagged folder is found the raw preference is cleared. Preserve the unset-versus-default distinction. The picker similarly avoids manufacturing a stored default while discovery is incomplete. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: IMAP Trash preference discovery.
