# Keep current CalDAV username fallback distinct from the old session-id token layout

The removed inventory distinguishes username, sessionId and calendar-ID layouts. Accepted CalDavCalendar instead creates its session with getProperty username or calendar.id. Current regression tests expect a new modern-origin token for old session-ID/Lightning-origin records and preserve the old record; they adapt the preserved legacy origin for the Rust login backend. This is the tested current expectation, not proof that the legacy credentials are used to authenticate or that migration ran on a real profile. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: calendar/providers/caldav.
