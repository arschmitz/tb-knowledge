# The new-mail regression setup does not consume replyToMsgHdr

The test passes replyToMsgHdr while creating a one-message set and says this forces a reply into Thread A. The actual wrapper and MessageInjection forward the set to makeMessages. Its propagation list accepts inReplyTo; it does not include replyToMsgHdr, and the first message is given null inReplyTo when the set lacks that property. The inspected historical and accepted generator segments match. The test's root counts and allowed spacing of 3 or 4 therefore do not directly establish the intended reply attachment or chronological movement. This is static coverage evidence, with no test execution or failure claim.

Scope: Threaded undo browser-test message injection.
