# Rebuild Gloda recipient arrays for each indexing pass

Gloda optimize builds fresh involves and recipients arrays and a fresh identity-seen map for each message pass. The junk/un-junk regression test directly checks two involved identities, one recipient and reuse of the message ID. The change also starts fresh toMe/fromMe temporary arrays, but current assignment to those fields is conditional, so it does not establish clearing of old now-empty fields or universal indexing idempotence. Repair Folder is a reported trigger, not the path directly asserted by this test. No indexing test ran.

Scope: Rebuild Gloda recipient arrays for each indexing pass.
