# Propose a concurrent-object test for the shared OAuth telemetry data

The fixed accepted constructor writes telemetryData.issuer, while telemetryData:{} is defined on OAuth2.prototype and no own telemetry object is created in that constructor. Assigning/deleting reason mutates that inherited object. Propose a test with overlapping objects for distinct issuers and prompt reasons, checking that one completion cannot overwrite or clear another object’s telemetry. This is a static shared-state concern only: no misattribution was reproduced, no runtime repair is claimed, and current builtIn gating is distinct from the historical provider-name gate. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: OAuth telemetry isolation.
