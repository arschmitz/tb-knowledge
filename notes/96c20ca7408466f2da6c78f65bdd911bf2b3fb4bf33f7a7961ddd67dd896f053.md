# The account default-identity observer still uses the old initializer signature

initIdentityValues now expects account and identity. The account page loads that shared implementation before am-main.js, but onDefaultIdentityChange still supplies only subject.QueryInterface(Ci.nsIMsgIdentity). That value is bound to account and leaves identity undefined. The same call remains at the fixed accepted revision. This is a static argument-contract mismatch in the notification path; the added POP add-identity visibility assertion does not exercise it, and no runtime failure was reproduced.

Scope: Account main page identity observer.
