# Preserve sibling reordering and server reparenting as separate operations

Current moveFolderWithin changes sibling order, with absent or 0 beforeId meaning the end. It saves a contiguous ordinal sequence starting at 1 and updates cached ordinals after each successful statement. moveFolderTo changes the parent and clears the moved folder ordinal. The interface reserves the sibling operation for UI display ordering. These operations do not themselves move mail folders on a server, and the inspected SaveOrdinals loop is not proof of atomic multi-row success. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama display order versus folder move.
