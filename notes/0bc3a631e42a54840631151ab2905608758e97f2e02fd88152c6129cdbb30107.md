# The m_levels top-row comment is one-based while insertion and tests use zero

The adjacent member comment still says Threading level of each row (1=top). The ordinary AddHdr path inserts a root with level zero, GetLevel exposes the stored level for threaded display, and the existing quick-search test explicitly expects its first row at zero. The comment therefore does not match that zero-based root contract. The width patch leaves this pre-existing comment unchanged. This is a narrow source-comment finding, not an instruction change or a claim of runtime failure.

Scope: Thunderbird native-view comment contract.
