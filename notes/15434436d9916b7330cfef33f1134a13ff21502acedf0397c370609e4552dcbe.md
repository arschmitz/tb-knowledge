# Write assertions as expected-state statements that read on failure

D214331 asks should-form descriptions so the same message works for success and failure. Historical/current tests state expected status-bar request counts rather than saying an event already succeeded. Proposed manual rule: name the object and expected result in assertion messages, often using should. This wording preference is beyond formatter/lint, not an enforced universal requirement.

Scope: mail/base/test.
