# Keep fetch limits distinct from HTTP upload lengths

Accepted HTTP upload setup converts the body length to i64 for SetUploadStream, while the safe Exchange fetch adapter explicitly rejects data longer than i32::MAX. Do not reuse one boundary limit for the other or claim that an i64 channel length proves unlimited native-string allocation. The representation/type differences are static; large allocation and overflow behavior were not tested. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Rust stream length boundaries.
