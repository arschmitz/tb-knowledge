# Preserve decryption behavior when replacing attachment parsing

Attachment extraction historically tries decryption. Switching to MimeTreeEmitter lost that behavior, leaving encrypted messages without listed attachments; entry300 restored getDecryptedMessage in both attachment-list and single-part paths. listAttachments and getAttachmentFile expose decrypted files and nested attached messages. getRaw/getFull have decrypt options, but this change did not add an original-encrypted-part option to attachment APIs. Current extraction keeps this contract.

Scope: extensions encrypted attachments.

- `mail/components/extensions/ExtensionMessages.sys.mjs`
