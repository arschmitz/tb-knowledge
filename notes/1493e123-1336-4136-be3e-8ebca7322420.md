# ICS serialization and file or HTTP write completion cross different boundaries

Production privileged JavaScript. Extends [ICS queue result limits](ce4bf3f0-4a84-48aa-b5b0-db7cc711eb56.md).
The file branch calls Gecko IOUtils. The HTTP branch calls native channel APIs.
Both source revisions are retained in the evidence scope; the native file branch
has its own focused record.

`#writeICS`, 459–471, requires URI, locks, awaits backup then #doWriteICS. Its
catch unlocks with MODIFICATION_FAILED but does not rethrow. #doWriteICS,
541–629, creates serializer, preserves unmapped components and all unmapped
properties except X-WR-CALNAME/TIMEZONE, writes current name/default timezone,
and awaits items directly from memory to avoid the provider's locked queue.
The memory query selects all types/completion states, unbounded.

Creates system-principal destination channel and asks hook.onBeforePut. A false
answer reports modification failure and unlocks; it does not overwrite. A true
answer enters the last-window-closing survival area, which delays application
exit while work remains, then calls async #writeSerializerToChannel without await.
The outer try cannot catch every later rejection from that async method.

Local file branch, 479–529, reads destination permissions if it exists, otherwise
uses 0600. Awaits IOUtils.createUniqueFile in the same parent, serializes to text,
then awaits IOUtils.writeUTF8(destination,text,{tmpPath}). This avoids direct
partial writes to the old file. On caught failure, reports error, unlocks failed,
and queues forced refresh. This branch does not explicitly remove the temporary
file or exit the survival area in its catch. Success lets file hook update its
timestamp, unlocks, sends onLoad and exits survival area. These are control-flow
facts; complete OS failure cleanup and application-exit impact need native checks.

Non-file branch sets notificationCallbacks, supplies serialized input to
nsIUploadChannel.setUploadStream and calls asyncOpen(this). It returns after
starting upload, before onStopRequest. onDataAvailable, 635–643, consumes and
discards response bytes. onStopRequest, 645–688, checks HTTP requestSucceeded
or non-HTTP request.status. Failure reports status and MODIFICATION_FAILED,
queues refresh, unlocks failed and exits survival area. Success invokes hook
onAfterPut; only its response callback unlocks, loads and exits. Missing ETag can
therefore add another HTTP request before this completion callback.

There is no promise resolving to remote acknowledgement from #doWriteICS itself.
Public mutation promises are completed through #unlock and have the function
resolver limit recorded separately. Changing write/observer order affects cached
callback settlement, scheduling consumers, view observers and pending queue tasks.
No explicit operation cancellation API appears in these writer bodies.

Direct tests: test_ics_offline_playback verifies fixture server text and cache
state for mutation/replay/conflict scenarios. Cached/uncached notification tasks
execute upload and wait for onLoad. browser_icsCacheToggleGhost.js:18–92 writes
a local ICS fixture, toggles cache and checks month view contains only the new
calendar ID; it executes local reads and owner replacement. It does not directly
exercise this provider's atomic write or failed temporary-file cleanup. Browser
test was read, not run in this pass. Native IOUtils tests cover generic temporary
write behavior, not the complete ICS caller error/exit path.
