# Keep tag keys, labels, internal URIs and extension IDs distinct

The accepted tag folder is created using tag.key, renamed to tag.tag, and stores the actual folder.URI. Current extension tests expose tag://custom:_tag for a key whose internal URI component can be hashed; the historical public-ID fixture used a hash. Follow the current public API representation and preserve key-versus-label meaning in variable names. This is not a guarantee that internal hashes are stable or that URI encoding can replace the folder system. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Tag folder representation names.
