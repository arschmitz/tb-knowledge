# Keep RawHdr input data separate from database header objects and caller policy

Entry 2103 introduces a native RawHdr data structure and noscript addMsgHdr input so callers need not use a detached Mork row to carry message data. The legacy backend creates a header, fills fields, attaches it and forwards notify to AddNewHdrToDB. Its comment assigns choices such as suppressing replyTo to callers. The fixed accepted local-folder caller applies a missing-Date fallback before AddMsgHdr, supporting that division of responsibility. Current references is an array and dateReceived is PRTime; the original string and seconds fields are historical and must not guide new callers. The initial Panorama implementation forwards fewer fields than the legacy backend and does not use notify in that method; current forwarding is wider. Backend parity for fields and notification suppression needs its own tests. The existing shared detached/live lifecycle lesson is reused rather than restated as a new rule. No native insertion, field-parity, error or notification test ran. Full discussion is pending.

Scope: Message database raw-header insertion.
