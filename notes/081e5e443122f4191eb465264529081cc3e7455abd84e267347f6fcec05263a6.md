# Exchange folder expansion supplies no follow-on message sync

The EWS PerformExpand typo patch changes only the comment spelling. Its continuation remains a no-op after SyncFolderList; Biff and GetNewMessages use other continuations that fetch messages. The accepted Exchange implementation retains this Expand behavior. Direct tests wait for a discovered folder, then perform separate message operations. Accepted SyncFolderList also invokes the continuation after an error, so the no-op NS_OK must not be read as proof of remote sync success. These are bounded static source facts, with no executed protocol or UI result.

Scope: Exchange incoming server folder discovery.
