# Corruption tests verify failure, invalidation, redownload and a later local-only read

The offline-download test deliberately offsets storeToken, explicitly fails if the bad stream succeeds, checks token, size and Offline metadata, then redownloads and performs a localOnly read. Keep these separate stages in this mbox test family so a successful network read alone cannot hide broken invalidation. This is scoped test guidance based on the existing source; the malformed-token test is limited to mbox and no test or corruption repair was run here. It differs from the already learned locked-store tests, which cover refusal to write while locked. Full Bugzilla and Phabricator discussion remains pending.

Scope: IMAP corruption recovery tests.
