# Offline stream listeners forward the real channel rather than the pump

OfflineMessageReadListener forwards start, data and stop using mChannel as the request argument. An nsIInputStreamPump supplies nsIRequest but does not supply nsIChannel; docshell consumers require a channel-like request. The wrapper is created by the accepted AsyncReadMessageFromStore helper. Preserve that identity substitution when moving the offline read path; returning only the pump to the display listener changes its available interfaces. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Offline stream channel identity.
