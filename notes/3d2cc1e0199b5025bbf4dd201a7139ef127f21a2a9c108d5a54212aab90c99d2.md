# Exchange copy listeners receive message keys for all created messages

Entry 1485 removes the draft-only guard around SetMessageKey. The accepted copy handler still sends the created message key whenever it has a copy listener, then handles non-draft source-file read state separately. Do not tie message identity delivery to draft saving alone in this copy listener family. The current source calls the message-key mechanism temporary; this note does not recommend extending that mechanism as a new general API. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange created-message key callback.
