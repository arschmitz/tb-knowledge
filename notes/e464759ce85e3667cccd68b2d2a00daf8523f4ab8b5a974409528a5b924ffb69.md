# Calendar ASSERT removal separates fatal input guards from continuing warnings

The old cal.ASSERT default failure logged and continued, while critical failure threw Components.Exception. Part 5 uses explicit Error guards for required auth values, preference inputs and abstract base construction, so formerly nonfatal checks can now stop the operation; ordinary Error also differs from the old critical exception/result-code contract. Other sites deliberately remain warnings, including attendee counts and the questioned ICS unlock branch, which still access following values. The unit helper adds an explicit one-item error instead of its message-less assertion. Async signatures and later conversions remain separate phases. No failure or test was executed.

Scope: Calendar assertion migration contracts.
