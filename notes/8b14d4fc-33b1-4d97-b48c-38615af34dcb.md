# Gecko worker-side dispatch serializes replies and needs explicit error forwarding

Full worker template275 lines and generator69 read. Generated worker module/script
are separate packaged products: worker/moz.build generates PromiseWorker.mjs/.js
from this template through generate_module/generate_script. Generator removes
script-only sections for module, keeps blank lines to preserve template line
numbers, converts export markers to exports.X for script or final PromiseWorker
ESM export. The generated files are not tracked source files to edit or claim
manually reviewed separately. The controller module is packaged by parent moz.build.

AbstractWorker:87–107 owns reverse pending jobs and WorkerToThread-N IDs.
callMainThread:126–141 saves resolve/reject before sending {id,fun,args}.
handleMessage:147–273 first routes matching reverse reply ID; it resolves/rejects
the whole envelope and deletes that job. Otherwise it measures optional duration,
awaits actual dispatch and posts {ok,id,durationMs}. Generic async dispatch calls
can overlap between message events; DNS's native execute is synchronous on one
worker thread, a distinct serialization reason.

Meta return can transfer buffers and close worker only after sending successful
reply. Built-in exceptions are serialized with name/message/location/module stack;
DOMException branch sends constructor name/message but not the DOMException's
specific name field, while controller decoder reads error.name. That name
preservation boundary is untested in the checked test pair. Custom toMsg errors
need matching controller ExceptionHandlers. Unknown errors are rethrown from
async handleMessage; falsey thrown values can take success branch because !exn
controls it. Reply-post/clone failures occur outside dispatch try/catch.

Test worker fixtures explicitly connect message listener and unhandledrejection
listener that throws error.reason, allowing parent onerror to reject jobs.
Thunderbird DNS.worker:550–569 connects only message listener in the checked
source. It does not add that explicit rejection-forwarding listener. Unknown
Error/reply serialization failure produces a rejected handler promise; actual
native worker-event propagation/pending DNS settlement remains a trace gap.
Do not certify that all DNS failures reject from the generic controller alone.

The [controller study](65c0191a-c28b-470a-8421-c9eb29a0a991.md) distinguishes accepted serialized errors,
unhandled events and termination. Direct generic error test uses the fixture's
extra listener and checks message; ESM test covers bounce only. Both passing
files do not verify DNS-specific unknown-error propagation or worker.close cleanup.
