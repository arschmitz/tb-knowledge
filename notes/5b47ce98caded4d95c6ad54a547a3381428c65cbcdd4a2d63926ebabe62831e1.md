# The force-close path remains a separate search-table lifetime question

At the accepted revision, ForceClosed releases and clears the main header/thread tables and Mork store, but does not explicitly clear m_mdbSearchResultsTables there; the new map is explicitly cleared in the destructor. HdrIsInCache can take its map-hit path without calling GetSearchResultsTable. This is a scoped static lifetime observation for a future check, not a proved dangling access or a requested repair. The inspected virtual-folder listener path and source do not establish a post-close call; no force-close race or reopened-database test was run. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source landing alone does not establish reviewer approval.

Scope: Search-table force-close validation.
