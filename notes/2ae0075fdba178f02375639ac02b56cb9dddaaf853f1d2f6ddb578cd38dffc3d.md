# Attachment display callbacks keep object identity separate from a DOM-list index

The producer stores the same AttachmentInfo object whose completion callback receives this after isEmpty assigns its size. The updater's index belongs to the DOM list, so the landing removes using that index to write currentAttachments. The DOM index remains useful for missing-item and first-item UI handling. Both inspected builders automatically await only file attachments, keeping link fetch user-initiated. These identity/order facts support the narrow change without reproducing a race or auditing later APIs.

Scope: Message-reader attachment size updates.
