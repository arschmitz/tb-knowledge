# Treat a LiveView message object as a snapshot

The adapter documentation says its plain Message fields are not live. Native add/remove callbacks construct a new JS object, while current flag changes reinitialize the row and invalidate relevant UI state. Do not retain a returned message object and assume its fields update in place. This is the inspected Panorama boundary; the native flag callback still notes that filter membership changes are not handled for hypothetical new filters. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Panorama message snapshots.
