# Handle hash changes when opening a flow in an existing about:import tab

D210600 review caught that restoring about:import needed a hash for each flow. The landed hash update then caused Bug 1904305: invoking Export while Import was open, or the reverse, changed the URL but did not switch the visible pane because no hashchange handler ran. The later fix tracks currentTab, handles hashchange, and resets the wizard for a new flow. browser_importTabChange.js tests Export, Address Book, Calendar, then Import in one tab. When URL state selects UI state, cover initial load, restored tab, and reuse of an already-open tab.

Scope: Import and export tab routing.
