# Notification CTA interaction precedes awaited opening and later selection cleanup

Accepted executeNotificationCTA rejects a stale notification ID, emits the interaction event, awaits NotificationOpener.openLink, records interaction duration and then clears its selected notification. For no-UI notifications the opener may wait for user activity and return when dismissed. Therefore the interaction event or fulfilled opener is not proof that a tab visibly opened. Preserve this ordering distinction when changing tests or telemetry. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
