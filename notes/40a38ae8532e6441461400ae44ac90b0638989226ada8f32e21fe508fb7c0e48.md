# SecurityDevices separates sequential module work from later policy completion reporting

The original SecurityDevices handler awaits deletions before additions, ignores deletion errors for repeated policies, and skips an addition when an installed module has the same library path. Its profile callback starts the async implementation and catches rejection without returning the promise. Later fixed accepted source returns the promise and notifies a policy-specific test observer; later tests wait for that observer before checking module names. Keep the original and later completion/reporting phases separate. These comm contracts do not establish native module loading, certificate trust, platform deployment or engine scheduling results.

Scope: Enterprise policy security-device lifecycle.
