# Let the shared search view rebuild when threading or grouping changes

Bug 1893793 moved SetViewFlags from nsMsgXFVirtualFolderDBView to its nsMsgSearchDBView base so cross-folder virtual and synthetic search views share the same transition logic. The code rebuilds only when the grouped or threaded bits change, then applies the flags through the base view. The wrapper no longer forces a second sort for a cross-folder virtual view. In search view changes, put the rebuild in the backend that owns its rows and avoid a redundant wrapper rebuild. This behavior remains in the current checkout; check each view type before generalizing.

Scope: Search message views.
