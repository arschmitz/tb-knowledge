# Check an updater preference port across the next upgrade transition

The historical Windows About-dialog update port added multi-session lockout preferences. The complete Thunderbird discussion first reports the preferences fix the problem, then reopens after a user still sees it on135.0b3. The author explains the preferences must already be written before the upgrade and asks specifically about b3→b4; a later author report says that transition applies the update. When validating this kind of preference integration, identify the starting version and the next-version transition. Merely installing the version containing the preference is not the same experiment. This is a scoped historical validation lesson from a preference-only comm patch and attributed reports, not a reproduced Windows updater result or a claim that current updater internals work the same way. Related toolkit Bug 1907127 still lacks comments2/10, so this partial finding adds no complete-audit credit and makes no full upstream source claim.

Scope: Historical update preference integration.
