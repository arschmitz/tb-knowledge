# OAuth provider flags select transports while the extension API exposes only external-browser opt-in

This landing selects external-loopback flow from the global preference and issuer useExternalBrowser flag, then custom-scheme flow from its separate preference and issuer flag, then internal fallback. The extension schema/caller expose only external-browser opt-in; registration forces useSchemeRedirect:false. Its schema describes an HTTP loopback endpoint constraint, while the registration test stores an HTTPS localhost endpoint and asserts fields/freezing rather than executing a flow. At the fixed accepted revision, the scheme branch instead uses schemeRedirect and canUseSchemeRedirect. Keep provider eligibility, declared endpoint constraints and actual flow validation separate.

Scope: OAuth provider eligibility and extension registration.
