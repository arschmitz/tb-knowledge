# Preserve the distinct return contracts of new and deprecated tag creation

In the messages API, tags.create accepts an omitted key and returns the native key for the new display name. It rejects duplicate display names and lowercases supplied keys before checking collisions. The deprecated createTag wrapper awaits creation without returning the key, preserving its undefined result. Preserve these two contracts when changing the shared implementation. This is an observed API pattern, not a new project-wide rule; the implementation and changed tests were read but not run. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.

Scope: mail / components.
