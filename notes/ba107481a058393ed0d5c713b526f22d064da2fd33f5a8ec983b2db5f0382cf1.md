# SMTP username migration preserves valid UTF-8 bytes and cannot restore old truncation

This landing changes SMTP username access to string preferences and adds a version 63 migration for the listed SMTP servers. The migration skips empty values and leaves bytes accepted by a strict UTF-8 decoder unchanged; rejected bytes are written through setStringPref. Its tests distinguish recoverable Latin-1 bytes, an already-lost euro sign and already-valid UTF-8, then force a second migration to compare stored bytes. This is a byte-validity heuristic, not a way to recover truncated characters or identify every originally intended username; no migration was executed here.

Scope: SMTP username preference migration.
