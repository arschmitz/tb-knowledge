# Dead-folder view teardown clears wrapper state without native loading callbacks

The original wrapper change passes its dead-folder state to an explicit loading-state method. When state changes, dead folders skip native start/end bookkeeping while the wrapper still updates its Boolean and notifies its listener. Native endFolderLoading otherwise invokes totals/cache work, and reparenting separately resets the future listener flag. Tests assert closed/not-loading/cache absence and recreated identity, but do not directly assert listener reattachment or a native callback count. The accepted close options API is a later phase.

Scope: DBViewWrapper deleted-folder loading state.
