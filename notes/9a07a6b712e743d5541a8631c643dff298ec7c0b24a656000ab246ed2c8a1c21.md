# Panorama named message properties preserve typed defaults and a separate keyword path

The named property table keys values by message ID and name. String reads start empty; uint32 reads start at 0. Replacing one named value preserves other names, and property enumeration has no promised order. The fixed header API routes keywords through dedicated message tags, while storeToken reaches named storage through typed database wrappers. The fixed test directly checks getter results, sorted names and SQL rows; reopen persistence and addon semantics were not tested here. The review accepted this as interim work and preferred explicit core schema plus a different future addon-data system. That proposed direction does not mean the table was removed.

Scope: Panorama message property storage.
