# Correct the Exchange copy completion method name and retain queue ownership

This corrects lesson 752ff0591d49537e15613350acc9c5d7a5e8139b6fbdeb53a8a6583a1f7b0d0b. The accepted handler method is ExchangeMessageCopyHandler::OnCopyCompleted, not ExchangeMessageCopyHandler::NotifyCompletion. It calls nsMsgCopyService::NotifyCompletion; that service owns OnStopCopy, clears the completed or failed request and calls DoNextCopy. Historical EwsFolder forwarded OnStopCopy while leaving queue notification as a TODO linked to Bug 1931599. The ownership lesson remains valid: completing a user listener alone does not establish that the global copy queue can advance. Preserve the service completion route without adding a second OnStopCopy call. This is a static source correction in the same component and path scope. No multiple-message copy, queue-failure, runtime or build test ran. Full Bugzilla and Phabricator discussion is pending.

Scope: Exchange copy queue completion.
