# Clear the notification timer handle before the scheduled fetch can reschedule

NotificationUpdater._schedule returns when a timer is already pending. Its callback clears _timeout before calling _fetch, allowing the next fetch or failure path to schedule another update. Preserve that order and the test-state reset that cancels any remaining timer. This is the specific guard introduced by the human follow-up, not a claim that overlapping in-flight requests are prevented. The timer tests were read without execution. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.

Scope: mail / components.
