# Multiple returned sections preserve primary source coverage

This provisional tb-tools implementation returns up to three distinct matching
sections from a source while counting its claim once. The change applies to
knowledge retrieval and evaluation. It records observed implementation behavior,
not a new shared instruction or accepted style rule.

## Evidence and behavior

Previously, retrieval kept only one matching section per physical source and one
winning section after copy grouping. A source could be selected while its main
contract or exception remained outside the returned context.

The draft retains up to eight distinct section candidates per claim, preserving
the original winning primary before the candidate cap. Primary sources receive
the same ranked selection opportunity under the context and claim limits. Search
then adds supplemental sections in rounds using only remaining space. Repeated
section IDs, identical text and overlapping ranges from the same source are
removed. Additional sections need their own text, heading, or semantic match;
record-wide symbol, title, or component metadata is insufficient on its own.

Each excerpt has its own JSON context entry and physical source reference. The
returned parent ID list stays unique, and extra sections do not increase claim
rank. Short aliases retain their physical source reference too. Stored source
records, section boundaries, UTF-16 offsets, section IDs and embeddings do not
change. Existing hard context limits and explicit scope checks still apply.

The evaluator reports returned-anchor coverage separately from parent-source
recall. It checks actual returned text, source identity, repository, revision,
path and offsets. Adjacent ranges can support a quote across a section boundary.
Missing text and separate copies cannot be joined to manufacture a quote. Gap
resolution reuses the same check. Scheduled review receives original and current
returned context separately from reviewer-only source excerpts.

## Measured choice and validation

An initial design reserved one third of context for supplemental sections. On the
pinned public corpus of 319 records and 29 questions, exact source-complete cases
fell from 19 to 15. Mean source recall fell from 0.7586 to 0.6034. This was a
regression, with no returned-anchor gain, so that allocation was rejected.

The final design selects fitting primary sources first. The same pinned comparison
retains 19 of 29 source-complete cases and mean source recall 0.7586 before and
after. All seven original-source anchor requirements remain absent from this
pinned corpus, so their returned-anchor coverage remains zero. The fixture was
not weakened or filled with expected-answer data.

- All 196 related knowledge, task-query and code-evidence tests passed.
- The dedicated multiple-section suite passed 10 of 10 cases. It checks source
  diversity, duplicate suppression, exact/semantic complements, source references,
  metadata-only exclusions, the original primary under alias competition, and
  all four fitting primary sources under a measured tight budget.
- A hash-checked pre-edit retrieval module failed five of the first eight new
  regression cases. The new implementation passes those cases. A focused checked
  contract-and-exception fixture improves returned-anchor coverage from zero to
  one while retaining the same parent-source recall.
- An independent assistant reviewed the final source changes and ran 62 checks.
  All passed. This remains assistant judgment, not proof of every behavior.
- ESLint and Git whitespace checks passed. No live learning or model calls ran.

The implementation remains an uncommitted draft beside other ongoing work. The
base commit alone does not contain it. These tests do not measure generated-answer
quality or full-library latency. A bounded candidate set and context budget can
still omit useful passages. Large full parent path lists remain a separate budget
limit. No general neighbor expansion or full-source scan is added.
