# Cached Sync data must not turn a deleted object back into a live record

The initial 2024 createRecord methods marked deleted only when neither a local object nor cached record data existed. Later Bug 1909424 reports that after local deletion the tracker noticed it, but cached data still existed, so createRecord sent a normal record instead of a deleted:true tombstone. The July fix introduced CachedStore.markDeleted and an immediate deleted-ID guard while cache removal runs. This demonstrates why forward-compatible caches need explicit deletion semantics and a deletion test with cached data. The current getAllIDs implementation should be checked separately before assuming all transitional deletion behavior is correct; the later fix has not been fully examined in this chronological pass.

Scope: Thunderbird Sync deletion.
