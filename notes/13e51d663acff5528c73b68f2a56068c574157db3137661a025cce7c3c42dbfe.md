# POP3 deletion and body retrieval use different new-message accounting

In the accepted UIDL handler, an already known message marked DELETE enters the delete queue without incrementing _newMessageTotal. A FETCH_BODY message increments the total and is retrieved; _messagesToDownload contains FETCH_BODY and TOO_BIG, not DELETE. Preserve that distinction when changing received-message status. The inspected filter tests exercise retrieval and deletion commands, but do not directly assert the displayed received-message count. This is static source and test-code inspection.
