# Reduced-motion panel navigation must skip the event wait and still finish

PanelMultiView creates its translateX transform and awaits transition events only under prefers-reduced-motion:no-preference. The no-animation path still checks whether the panel is open, hides the prior view, removes temporary size/outline state, cleans the phase and flushes layout before focusing the next view. Waiting outside the preference branch would wait for an animation that never starts. Manual asynchronous UI proposal here: gate the event-dependent wait together with the animation, while preserving the completion and focus path for both preferences. This adds JavaScript lifetime evidence to the existing reduced-motion CSS lesson. No reduced-motion navigation or focus test was run.

Scope: panel-navigation-accessibility.
