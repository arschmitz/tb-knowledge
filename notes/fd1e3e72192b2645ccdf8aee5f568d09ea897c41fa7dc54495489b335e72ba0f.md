# Panic avoidance and completed Exchange sync handling are different milestones

Entries 858–861 replace todo! for Delete and ReadFlagChange with explicit unsupported-operation logs. The first change was backed out for reported build bustage; the reland changes the format arguments and a follow-up formats one call. Logging kept those branches from deliberately panicking, but did not apply the server changes. Current code has moved to client/sync_messages_for_folder.rs and calls on_message_deleted and on_read_status_changed. The C++ listener resolves the Exchange ID into a database header. An already deleted message returns success; a missing header for a read update returns NS_MSG_MESSAGE_NOT_FOUND, which Rust tolerates. Other read-update errors propagate. Keep crash prevention, unsupported work and applied database changes separate when describing a fix. This is current context for the historical placeholder, not coverage of every later Exchange implementation commit.

Scope: exchange-sync-change-progress.
