# Review whether repeated scheduling can replace an uncleared timer handle

The fixed accepted folder pane _setCollapseTimer assigns a new timeout without clearing an old one in that method. _clearCollapseTimer only has the current handle. Repeated calls before a previous timeout fires could therefore leave an older callback untracked unless event ordering prevents it. This is an unresolved static timer concern, not a reproduced drag defect. Check repeated scheduling or document the event invariant before proposing a fix.

Scope: Folder pane collapse timer ownership.
