# UIDVALIDITY invalidation has a dedicated summary-reset boundary

This landing extracts HandleUidInvalidation from UpdateImapMailboxInfo when the stored UIDVALIDITY differs from the mailbox spec. The helper carries backup/transfer-info handling, summary DB recreation, UIDVALIDITY storage and MODSEQ/highest-UID reset; the caller separately requests every server UID using an empty prior list. It reobtains folder information and adds an early failure return, so extraction alone does not prove behavior equivalence under DB errors or notification reentry. The inspected normal path resets summary metadata and does not itself call DeleteStoreMessages; the broad comment is not proof that all offline message bytes are removed. No DB/protocol/filesystem test or broad IMAP redesign was performed.

Scope: IMAP mailbox UID invalidation.
