# Remove a retired importer across registration, build, strings and tests

The Windows Live Mail removal is a substantive human removal, despite its large diff. It deletes its settings implementation, component registration, build entries, locale strings and test/fixture family. Accepted registration/build/test manifests no longer include it, while other importers remain. A scoped removal checklist should follow each owned integration seam rather than delete only the main implementation. This does not establish removal of Outlook support or all Windows import capability. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Importer retirement boundaries.
