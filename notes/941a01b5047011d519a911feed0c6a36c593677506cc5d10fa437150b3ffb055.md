# Closing after a failed Calendar lookup does not settle an already awaited show promise

In the owned loader, a held show promise is created before the calendar/item lookups. Missing calendar, missing item or a non-event closes the dialog and returns without the successful resolver call. The base close method does not know that promise. Accepted Calendar close resets and replaces its promise field, but replacement alone does not resolve or reject an older promise already captured by show. The accepted missing-ID path separately rejects. This is a conditional static settlement gap; no hanging window or rejection was reproduced.

Scope: Calendar dialog loading failure settlement.
