# Calendar message drops share one asynchronous conversion boundary

The accepted event and task drop handlers construct CalEvent or CalTodo, await calendarItemFromMessage, and then open the corresponding editor. Conversion uses the header subject and mid: message ID, defaults dates/alarms and reads message text through a stream listener. Its stop handler tolerates a failed status only when it already has content. This describes the checked helper; not every dropped format or message-stream failure was tested. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: calendar/base/content.
