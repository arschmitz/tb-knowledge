# News and mail delivery callbacks require argument-order checks across interface changes

The historical 1367 NewsDeliveryListener call retains url, true, exitCode even though the new callback then expects isNewsDelivery first, and its news forwarding branch omits serverURI. Accepted code uses serverURI, exitCode, secInfo, errMsg, isNewsDelivery, and NewsDeliveryListener passes url, exitCode, null, null, true. This source comparison shows a dated argument-order hazard, not a reproduced news failure. When changing this callback, trace each protocol caller and forwarding branch together.
