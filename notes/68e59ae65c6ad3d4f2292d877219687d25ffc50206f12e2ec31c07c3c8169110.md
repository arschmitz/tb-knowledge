# ShortcutsOverlay moves startup calls into each window and requests current-global imports

The original port replaces the overlay load listener with explicit setupShortcuts calls in both window startup paths. Main-window startup calls it after opening the first tab; the standalone window uses its OnLoad handler. Production and test imports request { global: "current" }, and MOZ_SRC_FILES registers the content module. setupShortcuts starts async label setup without returning its promise, then installs the key listener, so its return does not mark completed labeling. The dialog test covers the exported open API, not all shortcut routes. The original local tabmail lookup and the later accepted three-pane/repeat handling are separate phases; the review explicitly withdraws its standalone-search fix claim. These local options do not prove the unpaired native module-loader implementation.

Scope: Thunderbird window-scoped shortcut module integration.
