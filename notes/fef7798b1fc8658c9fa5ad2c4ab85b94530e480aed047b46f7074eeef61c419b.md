# Inline Calendar error prompts keep caller windows and local title resources

Removing showError leaves its prompt-service behavior at each caller. Migration, import/export and snooze warnings pass their window; the iTIP callback passes null as the old default did. All four caller bundles include calendar/calendar.ftl for generic-error-title, while their existing branches choose the detailed message. Stream cleanup, the snooze true result and the iTIP failure return remain separate caller behavior. No prompt, localization or accessibility result was exercised.

Scope: Calendar error-prompt helper removal.
