# Translate a label before using its immediate shadow geometry

The category menulist must have its localized label before code reads/manipulates its shadow #label-box/#label. Current code uses l10n.formatValueSync for multiple/no categories then sets label; asynchronous setAttributes would not establish that ordering. This is a specific XUL geometry dependency, not a rule to make all Fluent translation synchronous. D214347 also explains the specific migration failure: setAttributes chose textContent on this special menulist and wiped children instead of assigning label. The author said IIRC, so retain that attribution; both child-preservation and immediate geometry matter.

Scope: calendar.
