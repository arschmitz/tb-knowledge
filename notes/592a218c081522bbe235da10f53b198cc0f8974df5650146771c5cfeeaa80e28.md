# Account Hub install controls keep DOM, event and Fluent names in their own forms

The template uses the native button addonInstall with type="button" and a separate addonInfo external information link. The widget emits dashed install-addon and config-updated event names; Fluent IDs use account-hub- prefixes. Scoped manual naming recommendation for this widget family: keep lowerCamel DOM IDs, dashed public event/Fluent names and UpperCamel class names aligned with their respective consumers. These are observed local forms, not an approved project-wide rule. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: Account Hub add-on control and event naming.
