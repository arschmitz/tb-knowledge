# Delete command routing follows focus and the specific UI surface

InitEditMessagesMenu sends folder-focused deletion to cmd_deleteFolder, handles message-count and all-deleted state for message views, and retains a text-box deletion fallback. Current header controls use cmd_shiftDeleteMessage/cmd_deleteMessage, while the multi-message handler still uses cmd_shiftDelete/cmd_delete. Scoped naming/API recommendation: follow the command namespace implemented by each surface; do not apply a blanket command-string rename based on one handler. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: message delete focus and command namespace.
