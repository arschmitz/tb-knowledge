# Describe the condition for undefined at the API entry point

The 715 cleanup moves vague return annotations into precise function descriptions: cloudFile getAccount/updateAccount describe a missing account, sessions.getTabValue describes a missing key for the given tab, and tabs.getCurrent describes a non-tab context. Their current parent implementations agree. cloudFile also returns undefined when the account belongs to another provider, which the short schema description does not state. Proposed review rule: document expected absence, invalid-ID errors, and ownership filtering separately instead of saying only that undefined may be returned.

Scope: mail/components/extensions.
