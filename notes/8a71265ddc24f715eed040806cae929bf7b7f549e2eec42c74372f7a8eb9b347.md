# Delete the draft object so its C++ members are destroyed

mime_bridge_create_draft_stream creates mime_draft_data with new and deletes it on the FAIL path. The class contains nsTArray, nsCOMPtr, nsString and nsCString members, so object destruction matters in addition to freeing the allocation. The URL and stream have their own PR_Free cleanup, while options use delete. Review this exact allocation family and header before changing cleanup. The fix is static evidence; broader MIME lifetime correctness and allocation failures were not tested. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.

Scope: mailnews / mime.
