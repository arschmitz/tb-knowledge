# Exchange IDL placement reflects a Rust boundary rather than a public extension API

The accepted exchange/src/moz.build keeps IExchangeClient and related IDL files inside src. Its comment says they must be exposed to interact with Rust but are not APIs intended for other components. OfflineStorage is instead exported by the common protocol build and common is included alongside Exchange. Scoped architecture and file-placement lesson: distinguish a generated language boundary from a public API merely because both use IDL or exported headers. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Protocol build and interop boundary.
