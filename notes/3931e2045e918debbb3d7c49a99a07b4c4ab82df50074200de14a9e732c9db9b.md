# Let the Account Hub parent own add-on installation and the result widget own its state

The widget emits the bubbling install-addon event and disables its install button. The email view awaits installation, then asks the widget to refresh add-on state. The widget fills addonAccountType on all exchange choices when an active matching add-on is found and gates continuation for the exchange choice. Discovery metadata, installation and visible state are separate steps; setAddon is asynchronous and the inspected callers do not await its refresh. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account Hub add-on ownership.
