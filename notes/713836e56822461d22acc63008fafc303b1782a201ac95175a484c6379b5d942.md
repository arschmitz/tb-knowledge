# Assert the primary-password prompt focus as well as visibility

The current expectPasswordPrompt callback checks that password1Textbox is visible and is doc.activeElement before entering text or clicking accept/cancel. This is a concrete keyboard-focus assertion in addition to the export result. Scoped accessibility recommendation: preserve that focus assertion when changing the challenge dialog. Static reading did not verify native focus, assistive-technology announcements, macOS OS-auth UI or keyboard execution. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
