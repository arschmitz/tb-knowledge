# Compose completion events carry details while their capture timing remains a separate phase

Successful onAfterSend and onAfterSave events include ComposeDetails beside mode and saved message copies. The original handlers collect details before waking an extension background, but still await a getter in sequential completion callbacks. Accepted later code captures tab and details synchronously while the compose window is valid and caches the result per extension before delivery. These are distinct timing phases. Failure payloads do not construct details, and permission guards still control identity/FCC fields and message copies. Direct tests check exact details around background termination; no runtime result is claimed.

Scope: Compose extension completion events.
