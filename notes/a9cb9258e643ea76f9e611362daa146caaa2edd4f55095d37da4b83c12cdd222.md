# Inline-image parsing changes channel content type only when a MIME part is requested

This landing adds the part_to_load condition before MimeInlineImage_parse_begin sets the channel content type from the image. It preserves the setter for a requested MIME part and enables the body-channel assertion expecting text/html. The owned image-parser blob equals the fixed accepted blob; the test keeps raw MIME headers separate from output channel metadata. This is a scoped guard and test-oracle fact, not proof of message rendering, all attachment channels or successful native conversion. Later attachment URL/type changes and the later test-driver signature are separate phases.

Scope: MIME inline-image channel metadata.
