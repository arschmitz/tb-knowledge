# Outlook contact fields no longer depend on nsIImportFieldMap

The field-map cleanup removed nsIImportFieldMap interfaces and parameters. Outlook BuildCard now calls its own SetFieldValue method for mapped MAPI properties, keeping contact-field assignment within the Outlook importer. The review says the old field-map path was otherwise unused after the CSV importer replacement, with uncertainty about whether the Outlook extension path worked before. Current source retains SetFieldValue. Check Outlook contact behavior through the surviving importer instead of restoring the retired shared field-map API.

Scope: Outlook contact import.
