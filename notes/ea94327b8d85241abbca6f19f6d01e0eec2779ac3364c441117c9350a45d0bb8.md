# Lazy-findbar state checks and command accesses have different creation effects

The wrapper creates its XUL child through the findbar getter. Find commands, open, the browser setter and Chat field passthroughs use that getter. By contrast hidden/browser getters and clear/close inspect an existing child without creating one; MessagePane uses those passive methods during view changes. A property access can therefore materialize the child even without a search-command method call. This is the explicit inspected interface, not full findbar parity or proof of zero startup cost.

Scope: LazyFindbar accessor and caller contract.
