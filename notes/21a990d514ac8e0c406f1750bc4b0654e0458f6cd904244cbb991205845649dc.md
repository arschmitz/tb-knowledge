# A successful priority account configuration wins over an Exchange discovery error

parallelAutoDiscovery waits for the priority search and Exchange discovery to settle. If the priority search succeeds, it returns that config despite an Exchange error, appending a successful Exchange alternative only when needed. When priority discovery fails, an Exchange rejection is thrown only if it has a user-facing Fluent title; other rejected outcomes return null. External abort and the earlier redirect-cancellation branch are separate paths. This is the inspected result-selection contract, not proof that every provider or password-prompt flow works.

Scope: Account discovery result and error precedence.
