# Graph batching sorts numeric response IDs and uses count-based move fallback

The landing groups operations into at most20, awaits blocks in order, sorts typed batch responses by numeric ID and retains successful item statuses. Move results choose fallback when returned ID count differs from input count. This is not full mapping validation: no ID completeness/uniqueness check is shown. The checked native message callback uses destination sync for fallback and indexed local updates otherwise; the folder callback instead requires one ID and ignores fallback. No general partial-result recovery or live move result is established.

Scope: Graph batch move result callbacks.
