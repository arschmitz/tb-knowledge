# Keep database output objects and status results separate

OpenDBFromFile returns immediately for NS_ERROR_FILE_NOT_FOUND, but otherwise transfers the database to the output even if Open reports another failure. It normalizes SUMMARY_MISSING only when aCreate is true, and attaches the folder only on success. The local copy caller intentionally uses an OUT_OF_DATE database to set summary validity. Do not discard every returned object solely because the status failed. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check was run.

Scope: mailnews/db/msgdb.
