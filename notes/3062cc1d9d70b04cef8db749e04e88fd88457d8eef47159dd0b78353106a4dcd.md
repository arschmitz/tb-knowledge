# Distinguish scheduled EWS work from successful remote completion

1108's XPCOM SaveMessage bridge reads the input synchronously, owns callbacks with RefPtr, and detaches a moz_task so the async operation outlives the call. Returning Ok only means that scheduling succeeded. The historical outer save_message reports OnStartCopy, maps the inner Result to a status, and calls OnStopCopy; it aborts early if OnStartCopy itself fails. Current CreateMessage keeps a detached task but uses a safe create listener and a different completion framework. Preserve the asynchronous completion contract without copying the retired callback architecture.

Scope: EWS file-save scheduling and completion.
