# Storage dates preserve foreign timezone definitions and distinguish missing date bindings from truthy row fields

## Existing evidence reused

The earlier shared lesson
[Handle a missing start date at recurrence display and storage boundaries](../records/6621c0992d912a6e5e5aba0d962187ed91abe6e3b441863172de115179263a48.json)
records accepted missing-date binding and scoped display behavior at its original
revision. This record keeps that evidence and adds the pinned storage helper,
row-read and ownership details. It does not replace or broaden the original
lesson into a rule for every date consumer.

## Directly observed binding and read contracts

`#setDateParamHelper` writes a present date's native microsecond value and a known
timezone ID. For a foreign timezone with an iCalendar component, it writes the
serialized definition. If a timezone has no available definition, it writes
`floating`. An absent date binds null for both date and timezone. Event all-day
flags use `item.startDate?.isDate`, so no start date is invented for the write.
Evidence: [calendar/providers/storage/CalStorageItemModel.sys.mjs:1052–1069](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L1052-L1069) and [calendar/providers/storage/CalStorageItemModel.sys.mjs:1112–1129](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L1112-L1129).

`newDateTime` creates a date, repairs an old oversized unsigned native-time value
above its stated threshold, rounds the repaired value to a whole second, and sets
`nativeTime`. If a timezone is supplied, it looks up the timezone and converts
the date when lookup succeeds. Failed lookup logs a warning and leaves the date
object as constructed/assigned. Without a timezone argument it sets floating.
Evidence: [calendar/providers/storage/calStorageHelpers.sys.mjs:104–128](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/calStorageHelpers.sys.mjs#L104-L128).

`getTimezone` stores foreign `BEGIN:VTIMEZONE` definitions in a module-level cache
keyed by the full definition string. The cache strongly retains created timezone
objects; this file has no eviction or shutdown cleanup. Ordinary IDs use the
actual Calendar timezone service. `textToDate` decodes U/Z/L prefixes, escapes for
explicit timezone text, and a D marker for a date-only value. Malformed input is
not validated as a whole record in this method.
Evidence: [calendar/providers/storage/calStorageHelpers.sys.mjs:34–91](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/calStorageHelpers.sys.mjs#L34-L91).

The common item-row reader uses truth checks before assigning several stored
values, including priority, recurrence ID, timestamps, and alarm acknowledgment.
A zero native timestamp fails those checks even though the date-binding helper
can write numeric zero. It restores LAST-MODIFIED last because other property
setters can change it. Evidence: [calendar/providers/storage/CalStorageItemModel.sys.mjs:394–433](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageItemModel.sys.mjs#L394-L433).
This is a source-observed branch distinction, not a tested universal epoch-date
failure. Exact caller/property defaults and all such values remain separate cases.

## Direct test and limits

`testNewDateTimeWithIcalTimezoneDef` uses a made-up VTIMEZONE and a fixed 2022
native timestamp. It directly checks the resulting year, zero-based month, day,
hour, minute, and second after conversion.
Evidence: [calendar/test/unit/test_calStorageHelpers.js:5–25](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/test/unit/test_calStorageHelpers.js#L5-L25).
It does not directly check malformed text, cache release, missing IDs, unsigned
pre-1970 repair, or zero-valued row fields.
