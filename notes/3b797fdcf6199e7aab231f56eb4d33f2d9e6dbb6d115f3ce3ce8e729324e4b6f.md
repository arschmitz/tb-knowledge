# Distinguish stable message keys from view indices and storage tokens

MailNewsTypes2 distinguishes a message key from the zero-based view index that can change when the view is reordered, and documents 0xffffffff as a missing-value placeholder. Current FolderCompactor preserves the database key while updating its store token. Therefore do not teach the old copied sentence that keys universally fail to survive folder compression; scope lifetime claims to the current store/database implementation. Keep key, view index and store token names distinct at API boundaries. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: MailNews message identity documentation.
