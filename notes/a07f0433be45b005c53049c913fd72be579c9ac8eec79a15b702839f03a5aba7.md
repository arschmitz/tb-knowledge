# Use shared parser fixtures for synchronous and asynchronous listener cases

The XMPP parser test stores input, output, isError and a description in TEST_DATA, then reuses those records for synchronous and successful asynchronous listener tests. The CDATA fixture expects escaped literal markup in the serialized output. Keep case descriptions specific to the parser behavior and use the same fixture when the sync and async contracts should agree. The separate async rejection case does not make all error fixtures part of the successful async loop, and no tests were run. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: XMPP parser test fixture naming.
