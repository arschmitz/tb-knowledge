# Keep Rust XPCOM unsafe blocks narrow and preserve buffer ownership

D210200 twice requested changes over unsafe byte-buffer handling. Earlier versions constructed a second owner or slice from raw memory held by a Vec, which the reviewer said was unsafe. The landed read_file allocates Vec<u8>, casts its pointer only for nsIInputStream::Read, then copies the actually read range with Vec::from(&read_sink[..bytes_read]). Its SAFETY comment states the Read pointer and length contract. Keep length conversion and result assembly outside unsafe blocks, and avoid multiple owners of the same allocation. Reviewer accepted after this change.

Scope: EWS Rust XPCOM bridge.
