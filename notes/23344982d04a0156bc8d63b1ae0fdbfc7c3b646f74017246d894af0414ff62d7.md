# Change both Calendar range endpoints through one invalidation

740 adds setDateRange so changing both boundaries does not invalidate twice. It compares both the instant and timezone ID, clones the arguments and makes stored dates immutable before invalidating once. These details matter when equal-looking dates have different zones or when a caller later mutates its date. The current JSDoc allows null, but the implementation dereferences both arguments and calls clone unconditionally. No null caller was found in the inspected scope. Proposed manual documentation rule: describe the actual accepted values rather than copying nullable annotations from individual setters.

Scope: Calendar filter date ownership.
