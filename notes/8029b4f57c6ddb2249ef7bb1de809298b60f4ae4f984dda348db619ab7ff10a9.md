# Application selection still creates and validates local handler objects

Removing getLocalHandlerApp does not remove local handler support. The current non-Windows picker checks returnOK, a selected file and _isValidHandlerExecutable before creating nsILocalHandlerApp, setting its display name/executable and adding it to possible handlers. The Windows path instead uses the app-picker dialog and validates params.handlerApp. Follow the platform-specific current selection path; neither path was run. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: mail attachment handlers.
