# Splitter tests wait on the frame-owned lock and explicit size changes

Entry2173 registers style/size and splitter-expanded waits before the mouse action, and waits on _mouseMoveBlocked using the fixture window requestAnimationFrame because the implementation releases that flag on its animation frame. The reviewer questioned waitForCondition, the author explained this match, and the reviewer explicitly accepted the scoped approach. Fixed code keeps the same frame-owned flag and condition/size waits. waitForMousemoveLock checks a two-second deadline between frames and logs an error on timeout; it does not reject or assert lock release, and a stalled animation frame is not independently time-bounded by this loop. Later geometry/event assertions remain separate. Existing MOUSE_DELAY and its lint exception do not establish a general arbitrary-delay rule. Local --verify and Daily/Beta claims are historical participant reports, not execution here. Bug 1820874 comments16/17/18 remain unavailable, so zero full-audit credit and no claim that the intermittent family was eliminated.
