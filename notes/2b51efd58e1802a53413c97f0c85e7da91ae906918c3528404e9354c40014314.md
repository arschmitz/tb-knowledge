# Compactor safety comments name the semaphore ownership condition

D237166 asks to replace a bare safe claim with the reason an unowned release is allowed. The author explains ReleaseSemaphore tolerates a different holder, and the fixed destructor comment names that behavior. Exact nsMsgDBFolder::ReleaseSemaphore clears state only when mSemaphoreHolder equals semHolder; another live holder takes a warning branch and is not cleared. This supports the destructor repeat-release explanation for this API. It is not a universal rule that releasing a lock without ownership is safe. The separate final-summary cleanup and recovery limits remain in existing f5e1062dea0c1b1709e9f9e65fb869528f5f99106e1e0eebbb74cb0fcdeb9315/8e3a8a8cb0ed4ae7bb9721f6dcf38b833c9bc877e625a5a37d43ac80a3541910. This accepted local comment example supports the deliberate reason-and-condition guidance without changing it. No runtime or concurrency experiment.
