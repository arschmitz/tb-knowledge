# Custom column guard precedes empty-view sort persistence

At revision a90a934a34c5c2707578df121e9905955ed4024d, nsMsgSearchDBView::Sort returns NS_OK before checking row count when !m_checkedCustomColumns && CustomColumnsInSortAndNotRegistered(). Thus the empty-view branch that stores sort type and order and calls SaveSortInfo is not reached under that condition. Account for this exception when reviewing sort persistence: a successful return alone does not prove that sort state was saved. The excerpt establishes control flow, but does not establish the guard's broader lifecycle or runtime behavior.

Scope: message search DB view.
