# Hidden-recipient retries retain a password for each candidate fingerprint

The first verification pass records candidate key fingerprints without prompting inside the native callback. After the native call returns, the code restores the default password provider and awaits candidate unlocking. Each successful unlock stores its password under that fingerprint. The retry callback looks up the password for the actual callback key. This supports distinct key passwords without an async prompt inside the synchronous native callback. The local map retains strings through the operation; tracker cleanup does not prove those strings are erased or that all native and error paths are safe.

Scope: OpenPGP hidden-recipient password retry.
