# Comm parameter registration now passes a schema class instead of mutating a shared mapping

The port defines CommParametersSchema as a GeckoParametersSchema subclass and passes that class plus get_defaults to extend_parameters_schema. The comm plugin calls register_parameters; the prior code updated an imported voluptuous mapping at import time. Existing tests expect complete inputs to pass and missing/extra fields to raise a broad Exception. The exact accepted schema/default proof objects are reused; library decoding behavior, paired Gecko implementation and a test run remain unverified. In the retained [D303298](https://phabricator.services.mozilla.com/D303298) discussion, a reviewer requests the original upstream bug and exact patch reference; this owned commit supplies1652123 and a specific upstream revision. That scoped request is not a repository-wide message rule.

Scope: Taskgraph parameter schema registration.
