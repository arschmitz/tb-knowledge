# Exchange discovery auth errors and ordinary-config success choose different UI paths

The original password-retry patch propagates a localized Exchange401 before deciding whether ordinary discovery found a config. It can therefore show its password step even with an ordinary result. The accepted later async-generator implementation instead returns a successful ordinary configuration, optionally enriched with Exchange, and only propagates a localized Exchange error when ordinary discovery failed. The view maps that error to AuthenticationRequiredError, requests discovery credentials if no password is retained, and otherwise reports the failure at the current step. No-result manual fallback and user cancellation are distinct. Current selected browser coverage clears the ordinary config URL before expecting the authentication step and ends at config selection, not account creation. Original/new state names and callback/generator signatures are separate phases. No real auth, prompt or test run occurred; primary discussion remains gapped.

Scope: Account Hub discovery credentials and fallback state.
