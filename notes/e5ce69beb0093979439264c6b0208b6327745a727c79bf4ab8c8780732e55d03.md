# Check renamed notification localization resources against their runtime registration

Proposal for the in-app notification resource boundary: after a module or Fluent filename changes, compare the registered resource ID, locale filename, markup ID and packaging mapping. The landed2024 diff creates in-app-notifications.ftl but requests messenger/inAppNotifications.ftl. An exact read of that camelCase path at the commit parent found no file. This establishes a static name mismatch; it does not establish the runtime/build effect or invalidate the recorded review acceptance. Current frozen code uses the camelCase resource as later context. This is a scoped proposed check, not a new user rule or a blanket filename convention.

Scope: mail/components/inappnotifications.
