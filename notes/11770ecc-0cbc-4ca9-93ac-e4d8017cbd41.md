# Compaction callbacks start after the initiating call returns

The store API guarantees that no listener callback runs before asyncCompact returns. An immediate startup error returns without callbacks; a successful start later invokes begin, retention queries, retained-message notices, completion, and final summary. The 2024 implementation lacked the separate final summary; current IDL and recovery work add it. Callers and tests must distinguish immediate method failure from later callback failure, and should not assume a completion callback fires for a failed startup.
