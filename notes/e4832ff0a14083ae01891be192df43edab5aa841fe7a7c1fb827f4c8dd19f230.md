# Read-state and unloaded message-pane readiness are separate test conditions

The test waits for message.isRead, then separately clears selection and waits for the pane to show about:blank. The original readiness check uses contentDocument.readyState; accepted later code checks that the pane is no longer loading and has the blank URI. The two explicit 500 ms workarounds remain scoped test exceptions with leak-related comments. Read state alone is not document unload, and a fixed delay is not a general loading guarantee. No leak or browser test ran.

Scope: message-read-browser-tests.
