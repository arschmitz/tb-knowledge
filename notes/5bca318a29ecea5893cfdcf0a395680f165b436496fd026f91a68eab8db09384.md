# Format notification URLs at both display and actual opening boundaries

NotificationManager now delegates actual opening to NotificationOpener, which formats notification.URL before routing externally or to a content tab. The visible container also formats its url attribute before assigning the anchor href; its browser test compares href with the formatted value. The original direct manager formatting moved owners. Retain both boundaries because visible-link state and opening are separate consumers; do not assume an already displayed URL replaces the backend URL passed to the opener. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Notification URL consumer boundaries.
