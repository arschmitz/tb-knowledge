# Lazy module values and registration imports have different loading roles

Entry 1493 moves Account Hub service/model access behind a lazy object and ES module getters. Current email controller still imports account-hub-step and account-hub-footer eagerly for registration side effects. Proposed component rule: use lazy property access for deferred values while retaining imports needed to register elements before use. This source pattern does not measure startup speed or require every import to be lazy. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: Account Hub module loading.
