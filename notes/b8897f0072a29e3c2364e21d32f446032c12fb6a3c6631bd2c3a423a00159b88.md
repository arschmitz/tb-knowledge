# Keep request stream data alive across the response channel lifetime

The current HTTP body setup copies data with SetByteStringData. Its SAFETY comment explains that the channel travels to Response but the request body does not, so ShareData could leave a dangling buffer and AdoptData could create two owners. This confirms the already captured fetch-adapter copying lesson in a distinct HTTP owner. Optimize only with an explicit lifetime/ownership design, not a local borrowed pointer. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: HTTP upload buffer lifetime.
