# Check tombstones in identifier enumeration as well as record reads

At the fixed accepted revision getCreateRecordData correctly checks _deleted.has(id), but getAllIDs checks _deleted.has(ids[k]) before assigning ids[k]. The result object initially has no value for that key. Thus the source does not support a claim that this test filters the deleted key k. AddressBookStore and ServerStore call super.getAllIDs before adding supported live objects, and itemExists also depends on getAllIDs. Record-read safety and enumeration safety are separate contracts. This is a verified source hazard, not a reproduced Sync failure or an authorized source fix. A focused pending-deletion enumeration test is still needed.

Scope: Sync identifier enumeration gap.
