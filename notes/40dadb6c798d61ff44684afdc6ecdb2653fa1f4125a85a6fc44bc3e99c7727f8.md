# Keep the QR primary-password challenge separate from the OS-auth branch

The 2024 QR authorization helper uses the old token DB/checkPassword/login(true) API. Accepted QR export and passwordManager now use an internal key token: if hasPassword is true they await logout then login and return isLoggedIn. Only the no-primary-password branch considers OS authentication, and disabled OS authentication returns true. Preserve the current branch/API rather than copying the older synchronous token calls. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/preferences.
