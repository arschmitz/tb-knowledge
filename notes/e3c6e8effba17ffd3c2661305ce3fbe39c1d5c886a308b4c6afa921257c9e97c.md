# The rejected-notification unit test checks external opener history

The rejected-wait task starts the async opener without keeping its returned promise, rejects the scheduler stub, waits one tick and 1,000 ms, then checks that the mock external URL history remains empty. Adjacent successful donation_tab tests expect an external URL in this unit setup. The production guard returns before both the external fallback and content-tab/focus branches, but these unit assertions directly observe only the external-history route. The called flag is set before await promise, so its message "promise is awaited" describes more than that one assertion proves. When extending this test, retaining and awaiting the opener promise would tie its final check to opener completion; registering stub restoration with harness cleanup would protect cleanup after an assertion fails. These are scoped test-review findings, not a reproduced focus failure or a general rule authorizing timer waits.

Scope: Notification opener regression-test boundary.
