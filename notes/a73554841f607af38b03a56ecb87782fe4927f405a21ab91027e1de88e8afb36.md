# Enumerate the personal dictionary through its own service

The owned dictionary dialog now reads mozIPersonalDictionary.wordList with hasMore/getNext, instead of calling the editor spellchecker until an empty-string sentinel. Add/remove operations still use the opener spellchecker. After rebuilding, it restores a bounded selection and inserts an empty placeholder when the list is empty for a documented old layout workaround. That placeholder is UI state, not a dictionary word. The historical bug comments and live keyboard/layout behavior were not verified. The Suite duplicate is excluded from style evidence. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/compose/personal-dictionary.
