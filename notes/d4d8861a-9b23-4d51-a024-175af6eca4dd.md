# CalDAV metadata connects remote paths and ETags to backing storage and item identity

CalDavCalendar:43–70 creates per-calendar itemInfo, href index, query queue and
discovery state. isCached:107–109 compares provider with superCalendar. Uncached
ensureTargetCalendar:111–124 creates memory storage, sets superCalendar, registers
a strong calDavObserver and enables relaxedMode. Cached offlineStorage:147–150
assigns injected storage and restores metadata. resetLog:152–164 batches deletion
of per-item metadata/index information; it is not a complete reset of every field.

offlineCachedProperties:166–182 names saved discovery/capability fields.
saveCalendarProperties:196–204 serializes them into calendar-properties metadata;
restore:205–216 only restores listed keys and migrates the legacy scheduling field.
setMetaData:228–239 stores ETag, decoded path and inbox flag separated by U+001A.
fetchCachedMetaData:280–321 restores these records into mItemInfoCache/mHrefIndex,
legacy ctag/token fields and provider properties. The webdav-sync-token branch
deletes the differently named sync-token key. ensureMetaData:245–278 streams stored
items and fills missing remote paths/metadata; finding missing information resets
ctag and proposed ctag. fetchCachedMetaData calls it without awaiting completion.

getItemLocationPath:465–476 uses stored location for known items. New paths replace
characters outside ASCII letters, digits, underscore, hyphen and dot with underscore
and add .ics. This preserves the item UID separately from its remote filename;
distinct UIDs can map to one filename (inferred collision risk, not universal failure).
makeUri:450–463 combines encoded path segments with collection/query parameters.
ensureDecodedPath/ensureEncodedPath:2228–2287 handle URL/path extraction, per-segment
decode with malformed escape fallback, and encoding. calendarUri:362–373 keeps
query parameters in mUriParams; the no-query branch does not explicitly clear old
parameters. Consumers of URI replacement need to consider that retained state.

addTargetCalendarItem:949–1098 derives UID from actual parsed first item, saves
relative location, inbox flag and ETag, and maps path→UID. A changed UID at an old
path launches deleteTargetCalendarItem without awaiting it. Index updates occur
before backing storage completion. deleteTargetCalendarItem:1105–1117 clears
indexes/metadata before awaiting delete; storage failure can leave them divergent.
isInbox:2289–2291 compares against full inbox URL; passing a path-only string into
that check is a separate boundary requiring receiver-specific validation.

Direct provider assertions: cached and uncached tests testPutSpecialCharactersInUID
retain retrieval under the original special-character UID after a valid upload.
The previously checked UID collision tests link server-changed UID/path behavior;
their installed run failed before provider assertions. No direct test was found
for retained URI query, mismatched metadata deletion key or unawaited rename cleanup.
