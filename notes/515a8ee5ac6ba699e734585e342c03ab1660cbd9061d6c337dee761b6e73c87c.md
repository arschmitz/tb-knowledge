# Namespace preference cleanup uses allocated slot capacity after consuming the filled prefix count

SetNamespaceFromPrefForHost queries numNamespaces, allocates that many zeroed pointer slots and receives a filled len from UnserializeNamespaces. It constructs namespaces over len, then frees prefixes over numNamespaces before freeing the array. The namespace constructor duplicates its prefix, so it retains independent storage. Keep consumed count and allocation cleanup bounds distinct. The historical Coverity report calls the len-to-capacity leak potential; no failed-allocation or sanitizer run reproduced it here.

Scope: IMAP namespace preference ownership.
