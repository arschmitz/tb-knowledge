# Exchange display downloads to the store before streaming from it

Current AsyncOpen checks HasMsgOffline. With no copy, it starts ExchangeFetchMsgsToOffline for one local key and captures RefPtr(this), the folder interface and an nsCOMPtr listener in its completion lambda. Only success calls HandleDownloadedMessages and StartMessageReadFromStore. This is a two-stage store-then-read path, not direct rendering of network chunks. The strong captures are an observed ownership pattern; they do not prove leak freedom or complete cancellation behavior. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange fetch-to-display lifecycle.
