# Unsuffixed store method names have different signatures before and after migration

The migration first adds database-free methods with a temporary2 suffix, moves callers, removes the old header-taking methods and then removes the suffix. A historical GetNewMsgOutputStream call therefore cannot be interpreted by its name alone: read its revision and signature. The current IDL takes a folder and returns a stream; finish returns the token for later retrieval. The inspected tests directly check readback, discard, one active write per folder and independent writes across folders. Those assertions do not cover every migrated caller or failure path. No store test or interface build ran.

Scope: Staged store API naming.
