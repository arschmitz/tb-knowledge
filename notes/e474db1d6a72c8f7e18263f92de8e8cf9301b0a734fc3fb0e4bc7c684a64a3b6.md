# Rust edition migration keeps raw-pointer caller contracts at Thunderbird FFI boundaries

The edition migration makes unsafe attributes and raw operations explicit without replacing the caller's validity guarantees. The authentication FFI function checks null pointers, then relies on valid objects for RefPtr conversion and the action output. The EWS constructor requires a valid iid and result allocation and requires checking nsresult before using the result. Observer decoding still requires null-terminated readable strings; its historical manual-testing comment is an assumption, not a validation step. Fixed accepted code moves the decoder and observer into shared crates while retaining those boundaries. No arbitrary-pointer safety or runtime result is claimed.

Scope: Rust FFI migration.
