# Column initialization tolerates a view with no concrete folder or DB view

Accepted addCustomColumn reads gFolder?.msgDatabase?.dBFolderInfo and conditionally calls gDBView?.addColumnHandler. Other column restoration code explicitly returns when no folder has loaded and handles a throwing folder database getter. These guards encode valid missing context during initialization or folderless views; optional chaining is not proof that a required handler was registered. A scoped recommendation is to distinguish valid absence from a broken initialized-view invariant. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
