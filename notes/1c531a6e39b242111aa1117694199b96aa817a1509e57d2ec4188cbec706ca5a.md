# Account actions belong to their selected account page and capability checks

The add-account control is a real HTML button in the outer sidebar header. Default and delete controls are on the selected account subpage, and their commands call the outer account manager. am-main disables the default button for the current default account, unsupported server type, missing identity or the locked default-account preference. Delete is gated by protocolInfo.canDelete. The removal helper clicks the child frame control and waits for the actual remove-account dialog. Manual UI and test proposal: when moving an action, move its capability state and test entry point with it; check the correct document and selected account. The current locked-delete-pref test no longer asserts that control, and separate concerns record that limit. This source pass does not establish that all administrator policies still gate every moved action.

Scope: account-settings-controls.
