# Keep Exchange soft delete distinct from permanent delete and current server-side moves

1543 historically routes a soft delete through the global copy service to Trash, then hard-deletes the source after copy completion. Accepted current HandleDeleteOperation also treats Trash ancestry and the permanent-delete model as hard delete; soft message delete now calls CopyItemsOnSameServer on the Trash folder with undo operation eDeleteMsg. Keep the historical mechanism separate from current behavior. The trash lookup explicitly checks for a null folder even after success; do not assume NS_OK means a folder exists. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange delete routing evolution.
