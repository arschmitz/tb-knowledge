# The OAuth token documentation sample does not match its initializer and completion contracts

The added sample lacks the closing parenthesis in its if condition and calls initFromHostname with two arguments, although the inspected historical and accepted method expects hostname, username and type in distinct positions. Its carddav argument is therefore the username, not the service type. The wrapper getAccessToken(listener) returns no promise; awaiting that call does not wait for the later success/failure callback. Keep the raw token work in the actual callback contract when using this example. These are static documentation/source findings, not a provider or runtime authentication result.
