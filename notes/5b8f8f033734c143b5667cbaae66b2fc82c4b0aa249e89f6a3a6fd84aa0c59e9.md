# Silent mail alerts still reach feedback listeners before visible fallback is suppressed

MailSession sends an alert to every feedback listener with the explicit silent flag and combines handled results. It then returns without its modal fallback when any listener handled it, silent is true, or test alerts are suppressed. alertHook adds an activity warning before its silent guard, so silent does not mean no feedback record. A visible backend exception returns false, allowing fallback. The historical interface change used nsIURI; the accepted API later uses serverKey for alertUser. Protocol callers must derive silence themselves. The initial JavaScript branches did not set silent true on the expected exception; accepted POP fixes that default/filter while NNTP still has a broader && catch filter. Do not infer all callers satisfy the intended contract or that the later server-key migration is complete. Mock tests cover explicit flag visibility, not protocol exception classification. No live notification or test ran.

Scope: mail-session and activity feedback alerts.
