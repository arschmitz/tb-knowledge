# Use typed state documentation rather than a string label for an object

The historical state table and form-data parameters are documented as String even though they are objects. Current incoming form defines ConfigFormState with AccountConfig config and boolean edited, then declares that return type for captureState. Proposed manual rule: document the fields and acceptance meaning of a form state object, and use string only for an actual ID or text. This strengthens manual API documentation beyond correct capitalization or formatting. The code was inspected; no type checker was run.

Scope: Account Hub state syntax and documentation.
