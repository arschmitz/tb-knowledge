# Check the actual default outgoing server before honoring a preference to reuse it

When useGlobalPreferredServer requests reuse, account creation suppresses the new-server branch only if a default server actually exists. Existing matching servers and the other creation flags have their own conditions. A preference to reuse a resource is not evidence that the resource exists. The outgoing service can return null when there are no servers, and can adopt the first server when no default key is set. Identity binding can remain on the global default path. Do not infer that the newly created server always gets an explicit identity.smtpServerKey.

Scope: mail/components/accountcreation.
