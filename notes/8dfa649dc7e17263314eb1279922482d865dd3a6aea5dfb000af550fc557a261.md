# ExchangeProtocolInfo keeps both protocol aliases and the stored EWS root keys

The renamed ExchangeProtocolInfo component still serves both ews and graph protocol-info contract IDs. The generic incoming-server consumer selects that service by appending its actual type to the contract prefix. The implementation retains the mail.root.ews-rel and mail.root.ews directory preferences. The class/file rename therefore does not authorize renaming those stored or protocol identifiers. These exact registration and consumer checks do not establish compiled ABI compatibility or live service behavior.

Scope: Exchange protocol-info rename and registration.
