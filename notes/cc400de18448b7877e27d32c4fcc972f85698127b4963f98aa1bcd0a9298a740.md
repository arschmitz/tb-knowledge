# Retrofit managed section lookup indexes without rebuilding completed caches

Current working-tree openKnowledgeStore creates the non-unique sections_record_id index with CREATE INDEX IF NOT EXISTS before checking the section version. This permits an already-completed version 1 cache to acquire the lookup index without forcing section/vector regeneration. An append-only read-only observation confirmed index_info contains record_id and EXPLAIN QUERY PLAN now reports SEARCH sections USING INDEX sections_record_id (record_id=?); the earlier observation reported SCAN sections. The inspected regression test creates multiple sections, keeps a completed version 1 cache, drops only the managed index, closes and reopens the store, and checks the restored non-unique index and indexed plan. It also asserts exact records/sections/search rows/vectors/settings, exact and semantic results, repository isolation and immutable evidence-file bytes are unchanged. This worker read the test but did not execute it. Runtime reports remain separate private evidence and do not support this shared lesson. Reusable proposal: add an idempotent managed index outside content-version rebuild gates, and validate old-cache preservation through the official open path. The scope is this lookup index and this current uncommitted implementation. It does not prove compact-metadata backfill, checkpoint latency, or whole-cache performance.

Scope: knowledge store schema maintenance.
