# Compaction separates store rewriting, folder database coordination, and batch UI

Bug 1890448 split compaction into nsIMsgPluggableStore.asyncCompact for message bytes, FolderCompactor for retention decisions and summary database updates, and BatchCompactor for folder sequencing, progress and completion. The current implementation keeps these layers. When changing compaction, place message copying and X-Mozilla header rewriting in the store layer, header/token updates in FolderCompactor, and window status in the batch layer. Check the boundary when a callback error occurs.

Scope: Folder compaction.
