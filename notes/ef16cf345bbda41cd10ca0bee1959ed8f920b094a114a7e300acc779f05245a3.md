# The offline proxy forwards at most one start notification and releases its channel at stop

mShouldStart becomes false before forwarding the first OnStartRequest, so subsequent starts return NS_OK without another destination call. OnStopRequest forwards the final status and then clears mChannel to break the held channel/listener relationship. This is a callback and ownership contract, not proof that every asynchronous failure path reaches stop. The existing discard-policy lesson owns the preference gate separately. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Offline proxy start and lifetime.
