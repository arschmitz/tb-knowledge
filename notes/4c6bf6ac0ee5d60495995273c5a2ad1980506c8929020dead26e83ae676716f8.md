# Folder preference read errors have different outcomes in auto-compaction and filter warnings

The migration makes GetPromptPurgeThreshold and GetWarnFilterChanged return the fallible Preferences::GetBool result directly. AutoCompact checks that result and returns before using prompt or scheduling an event. AlertFilterChanged instead initializes checkBox=false and ignores the getter result, so its local fallback remains at the caller. The separate purge-size helper uses an explicit 500MB value fallback and returns KiB. Preserve the exact caller contract when studying these similar-looking reads. No preference-failure or compaction/dialog execution ran.

Scope: Folder preference failure consumers.
