# Validate GPGME output bytes even after requesting binary format

Setting gpgme_set_armor(ctx,0) did not fully fix malformed signed+encrypted mail because user gpg.conf armor could still override it. Bug1898832 was reopened; the later fix checks the actual signedInner output and deArmors when needed before RNP encryption. Current RNP keeps this guard. The durable boundary is the bytes received, not the requested option. Reporter confirmation concerns the later fix, not proof the first landing was sufficient.

Scope: OpenPGP encoding boundary.
