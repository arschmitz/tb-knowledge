# Legacy folder population enumerates names before creating folder objects

The owned helper replaces separate mbox/maildir recursive walkers with direct child-name enumeration followed by lookup/addition of folder objects. Its messageStore argument is explicit. Existing folder status still carries the existing object, and AddSubfolder avoids appending that object twice. DB-derived names survive; filesystem name is a fallback. Mbox passes its deep flag, while the maildir legacy wrapper still forces true. Accepted0b93 later warns/continues for individual add/subtree failures instead of the original fail-fast behavior, and root-cache recreation now invalidates cached URL prefixes. Preserve these exact caller/error phases rather than claiming complete removal of legacy discovery. Tests are source assertions, not executed proof.

Scope: mailnews/protocols/common.
