# Thunderbird preferenceSlice to Gecko preference observer and Redux state

Both local factory bodies, reducers, selectors, and listener effects in
`preferenceSlice.mjs` were read. The full 244-line unit test was read. This is a
checked Thunderbird–Firefox relationship with both revisions above. The exact
Gecko target is `js/xpconnect/loader/XPCOMUtils.sys.mjs:176–277`.

`createPreferenceSlice`, lines 30–95, makes a slice named `prefs/<preference>`.
Its lazy initial state and reset reducer read `sliceScope.pref` and apply the
caller transform. Set and sync reducers transform their action payloads. A
selector returns the slice value. The Gecko getter retains raw preference values;
this factory applies the transform in Redux, so the write listener still receives
the original set payload.

The factory installs the Gecko preference callback. On a preference notification,
that callback dispatches only `sync(newValue)`. It then registers a store listener
matching set/reset. Set selects the current native preference type and writes the
raw payload with the matching typed setter. An undefined preference has type
invalid and takes the listener's error branch; creating a fallback getter does
not define a native preference. Reset clears the native user preference. Sync
does not match this write listener, which prevents this direct update path from
writing the same value back.

`createBoolPreferenceSlice`, 107–146, adds Boolean conversion and toggle/true/false
reducers plus a second listener. Toggle reads the original store state through
the selector before writing the opposite Boolean. SetTrue/SetFalse write the
explicit Boolean. The raw preference update flows back through Gecko's callback
and sync reducer. There is no local await for listener effects or preference
observer promises.

The owner is the module's store listener middleware, constructed at
`store.mjs:12–20`. Factories register listener definitions but do not expose the
returned unsubscribe/dispose handles. `sliceScope` and its getter stay reachable
from the reducers; the middleware retains effects. Exact imported Redux Toolkit
listener cancellation, error reporting, and slice replacement rules need their
own imported-code study. No production UI caller of these factories was found in
the checked `mail`, `calendar`, `chat`, and `mailnews` search outside Suite and
third-party code. Tests and the state-management example use them. This factory
chain must not be described as a verified user action in a production control.

Direct assertions in `test_state_preferenceSlice.js` check action objects,
transformed set/reset reducers, selectors, store injection, pref→store update,
an extra action that changes state but does not write the pref, raw `BAR` written
to the preference with transformed `bar` in the store, reset/fallback/user-value
removal, and all Boolean actions. The integration test uses actual preferences,
the actual store, and `TestUtils.waitForPrefChange`. Its helper is profile-only
`head_mailbase.js`; `xpcshell.toml:53` lists the test. `mail/base/moz.build:14–15`
includes the production modules as source resources.

Unverified cases include missing-native-type set, repeated factory creation for
the same preference, listener disposal, transform exceptions, all stored types,
locking, and a production control. The test file contains no passing-run evidence.
