# Thundermail restore completion does not establish that keys loaded

Both phases can resolve restore without proving that keys loaded. The storage helper returns early when no passphrase exists. Keychain.load catches its import/load error and returns false, but the restore caller ignores that value, calls store and sets its completion label. The validator then sets hasCorrectKeys after the restore call resolves. These exact paths distinguish promise settlement, successful loading and the displayed validation flag. The accepted typed passphrase-error and concurrent-restore changes are later behavior; they do not add a check of load's boolean result.

Scope: Thundermail generated keychain and session validator.
