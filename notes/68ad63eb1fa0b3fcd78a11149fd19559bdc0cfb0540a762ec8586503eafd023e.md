# Keep Account Manager DOM IDs and Fluent IDs in their own naming families

Current markup uses accountTreeCreateAccount for the DOM control and account-tree-add-account-button for its Fluent message. Subpages retain defaultAccount and deleteAccount DOM IDs with default-account-button and delete-account-button messages. Add-account menu messages use .label and .accesskey; the outer HTML button uses the message value as its text. Manual naming proposal in this feature: follow the existing DOM ID family for code lookups and the Fluent message family for translated text, and verify both bindings when moving controls. Shared CSS classes such as button-primary and icon-button keep their established names. This evidence does not justify a global dash-versus-camel rule or an automatic rename of legacy identifiers.

Scope: account-settings-naming.
