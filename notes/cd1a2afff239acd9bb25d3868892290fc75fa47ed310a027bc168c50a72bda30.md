# Account Hub slot tests keep scalar properties separate from visibility predicates

The slot tests pass tagName/id and their expected strings as separate Assert.strictEqual arguments, with one check per property. Text uses a scalar equality assertion, while hidden/shown predicates use Assert.ok. Each original assertion has an explicit should message. This keeps the actual property value in the scalar assertion instead of reducing it to a Boolean before the call. These are accepted forms in this browser test, not a project-wide requirement to use strict equality for every value. No test or failure-log experiment ran.

Scope: Account Hub browser assertion roles.
