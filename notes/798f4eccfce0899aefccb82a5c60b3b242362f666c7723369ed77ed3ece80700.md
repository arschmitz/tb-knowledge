# Removing explicit IMAP expansion calls leaves a conditional tree event path

The large-folder startup patch removes an explicit parent-folder performExpand call when adding a row, but keeps folderTree.expandRow(parentRow). The actual tree-listbox method emits a bubbling expanded event only when the row has both children and collapsed classes. The pane routes that event to _onExpanded, which can still request IMAP child discovery when subscriptions are ignored. The same guarded widget behavior exists in the owned and accepted phases. This proves removal of direct repeated calls, not that every programmatic expansion stops causing network work. No request-count or startup benchmark ran.

Scope: IMAP folder discovery and tree expansion.
