# Hidden-window removal requires separate policy for each windowless path

Entry 776 removes hidden DOM window dependencies across chat alerts, progress dialogs, sending and MAPI. Current chat alerts focus an existing main window or use WindowWatcher with a null parent and explicit chat tab arguments. Current shutdown requires a recent real window and returns failure when there is none. Current OpenProgressDialog delegates to WindowWatcher and accepts the parent it receives. MAPI initializes compose with null window and editor arguments. Current sending differs from the original patch: it now uses the most recent window and opens the progress dialog only if that window exists. Manual review proposal: name and document the actual parent and the no-window policy for each caller. Passing null is valid in some paths and an explicit failure in others; no universal fallback is established.

Scope: windowless-mail-lifecycle.
