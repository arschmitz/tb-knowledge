# Accepted native Panorama helpers borrow initialized singleton databases rather than retain per-object database references

The historical no-XPCOM patch gives several consumers RefPtrs to concrete database objects. Accepted Message and LiveView instead dereference DatabaseCore::sInstance in native helpers; these accessors do not create the core or extend its lifetime. Startup creates the database fields, and profile-before-change clears them and sInstance. Their valid use therefore requires the initialized service lifetime. GetInstanceForService is a separate owning-reference operation shared with component construction. This is an exact ownership boundary, not a global no-XPCOM rule or proof of thread-safe construction, shutdown-race safety or leak freedom. No execution tested those states.

Scope: Panorama native ownership and access lifetime.
