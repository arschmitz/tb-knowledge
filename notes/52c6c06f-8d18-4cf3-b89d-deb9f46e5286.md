# Folder lookup keeps weak URI identity and distinguishes detached folders

The component registration maps `@mozilla.org/mail/folder-lookup;1` to `FolderLookupService`. `MailUtils.getExistingFolder()` calls this service's `getFolderForURL()`; `getOrCreateFolder()` calls `getOrCreateFolderForURL()`. The similarly named helpers have different creation contracts.

The native cache maps exact URI strings to weak references. `GetExisting()` resolves a weak reference to a strong local result, removes an expired entry, and returns null if absent. `GetFolderForURL()` additionally requires a parent or requires the object itself to be its server's root folder. An error finding a root is treated as invalid. It returns null for invalid/detached folders. The IDL requires percent encoding, exact case, and no trailing slash except roots.

`CreateFolderAndCache()` requires the supplied parent URI to be cached, escapes the raw name in two stages so path separators become part of one folder name, and finds or creates the destination object by URI. A conflicting existing parent causes `NS_ERROR_INVALID_ARG`. Otherwise it assigns the supplied parent and returns the object. It does not create folder storage itself. The IDL parameter description calls the name URL-encoded; the implementation actually applies escaping, and tests pass raw slash/percent names. Keep that description/implementation difference visible.

`GetOrCreateFolderForURL()` reuses an existing object only if it has a server with a non-empty type. Otherwise `CreateDangling()` obtains the protocol-specific folder factory from the URI scheme, initializes a new object, and caches a weak reference. Actual factory type depends on registered scheme; unknown/disabled schemes fail through component creation. With Panorama enabled at startup, dangling creation is refused, while explicit `Cache()` is allowed only in that mode.

`EvictFolder()` removes an entry only if it still points to the same object, so deleting an old folder cannot evict a replacement at the same URI. `InvalidateCache()` empties only this lookup cache. `CreateRootFolderAndCache()` evicts entries whose URI begins with the root URI when that root is already cached; it uses a raw string-prefix comparison, not a path-segment test.

The checked deletion owner, `nsMsgDBFolder::RecursiveDelete()`, detaches descendants, deletes requested storage, and evicts successfully deleted folders. Real local Trash is retained for EmptyTrash reuse; virtual Trash is evicted. Native rename and other folder classes are only selected-section coverage here.

Direct test links: basic lookup checks root/Inbox identity, absent folder, creation, repeated lookup, deletion, trailing slash, and missing account. Unicode and slash/percent tasks check exact escaped URI. Replacement tasks retain a strong reference to the deleted object and check fresh identity, flag non-inheritance, rename descendants, Unified Trash, and eviction of an old object. Native behavior is not proved to pass by those test names. The static assertions were read; no test result is claimed.
