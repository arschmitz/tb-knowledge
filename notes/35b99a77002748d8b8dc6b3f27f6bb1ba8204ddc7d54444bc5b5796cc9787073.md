# The history button falls back to the hidden message browser without changing stored history

The popup and its selection handler first use tabmail.currentAboutMessage. For a 3-pane tab with a hidden message browser that getter returns null, so the handlers fall back to the inner message-browser window; a standalone message tab keeps its own window. The popup reverses getHistory().entries, but the actual method returns _history.slice(), preserving stored order. The fallback assumes the 3-pane messageBrowser exists and does not prove arbitrary tab or missing-browser handling. The unchanged class summary about adding a Calendar event/task does not describe these history handlers. No UI test ran.

Scope: Unified toolbar mail-history popup receivers.
