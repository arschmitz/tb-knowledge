# Native-only Panorama IDL listener methods keep IDL naming roles

In nsIMessageDatabase.idl, addMessageListener and removeMessageListener use lowerCamel names and a listener parameter even though [notxpcom] makes these native-only declarations. The historical1612 review explicitly requested camelCase/no a-for-argument naming, and both the landing and fixed declarations apply it despite the Not Done badge. The generated C++ implementation separately uses MessageDatabase::AddMessageListener(MessageListener* aListener) and RemoveMessageListener. Preserve the exact interface-versus-implementation roles when changing this family; this accepted local request is not a general ban on C++ a-prefixed parameters, a global IDL policy, or a change to deliberate user guidance. Exact declarations and complete assigned review inspected; no build or binding generation ran.

Scope: Panorama native-only IDL naming.
