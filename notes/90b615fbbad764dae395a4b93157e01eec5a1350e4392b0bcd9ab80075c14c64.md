# The original forwarded-text merge appends raw body bytes while accepted code stores separate pieces

The original continuation branch reuses the existing body/temp file for an unnamed, non-attached, non-HTML text part and opens the stream with PR_APPEND. Accepted code retains the routing guard but stores later pieces in appendedParts and reads/joins them after separate temporary files. Keep these phases distinct; the ASCII fixture does not establish general mixed-charset interoperability or every MIME type/disposition combination.

Scope: MIME inline-forward text continuation phases.
