# Keep browser-load Stop, search interruption and filter-run state distinct

Fresh complete19-file688-line removal patch read, including all changed production, IDL, UI, localization and test hunks. It deletes nsIMsgWindow.StopUrls/stopped and unused fields, routes toolbar/message-window Stop to the displayed browser, gives search sessions their own running state, uses shutdown state in offline/news paths, and deliberately removes on-demand filter stopping by disabling Run Now while work runs. Closing a running-filter dialog still prompts and then calls web-navigation STOP_ALL. These are distinct operation contracts, not proof Stop was globally unused or a substitute for all network cancellation. Fixed source still uses browser.stop for the main-window command and search-local m_searchRunning guards. Its filter dialog now tracks gRunningFilters, applies filters with a completion listener and ignores stale window callbacks; this is later refinement, not all implemented by2330. The original changed quit tests simulate running by setting disabled=true and prompt about shutdown; they do not exercise actual filter cancellation, browser/network Stop or offline-sync interruption. Current nsMsgWindow.cpp is a much smaller shell with later API removal. No runtime/build/lint/test or stop-operation experiment ran.

Scope: StopUrls removal and operation-scoped completion.
