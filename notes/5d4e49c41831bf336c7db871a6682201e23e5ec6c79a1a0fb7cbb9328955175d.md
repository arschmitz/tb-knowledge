# Protect copy notification processing from reentrant queue changes

NotifyCompletion records the original request count and rejects a found request whose index is beyond that boundary. After clearing an original request, it decrements the boundary before continuing; the comment says a completion listener can queue a new matching copy. FindRequest also skips pending-removal entries. Preserve these specific guards when editing the queue, and retain DoNextCopy after notification processing. This is static reentrant-callback protection, not proof from concurrent copies or listener failure injection. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mailnews/base/src.
