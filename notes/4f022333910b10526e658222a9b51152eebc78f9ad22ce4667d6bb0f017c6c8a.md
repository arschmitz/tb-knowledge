# OpenPGP recipient-list headings describe whether the displayed key is omitted

When myIdToSkipInList identifies the separately displayed decryption key, the extra-key heading uses openpgp-other-enc-additional-key-ids and the loop skips that key. Without that separate key, it uses openpgp-other-enc-all-key-ids. The Fluent text distinguishes "In addition" from the complete list. A missing or empty keyInfo.userId now omits the name label; it still shows the exact key/subkey IDs rather than using the list heading as a replacement name. The optional chain has a real absent-key contract. Keep the heading and per-key name roles separate when changing localization or row rendering. Text wrapping and accessible presentation remain untested. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: OpenPGP encryption recipient list labeling.
