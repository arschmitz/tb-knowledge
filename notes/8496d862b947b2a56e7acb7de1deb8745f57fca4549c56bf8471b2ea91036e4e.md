# Keep historical normalized Panorama child lookup separate from legacy lookup

The retired nsIFolder implementation normalized a name before an exact comparison, and its tests used composed and decomposed Unicode forms of the same child. Current legacy nsIMsgFolder lookup instead uses a case-insensitive UTF-8 comparator. Preserve the relevant interface boundary when reusing tests; neither one establishes a project-wide rule that all folder names use the same matching algorithm. The old Panorama Folder class is absent at the accepted endpoint. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Folder name matching history.
