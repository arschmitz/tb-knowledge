# Search Messages intercepts opening events before XUL tree toggles

The tree registers click and dblclick handlers in capture phase. A left double click opens messages only for a valid row whose cell is neither a cycler nor a twisty. The captured dblclick stops the tree widget’s editing/open-state handler. Enter stops immediate propagation before opening messages, so the tree keyboard handler does not toggle a thread. These are separate event boundaries. A generic bubbling double-click handler changes who handles the action. Modifier keys leave selection and delete-column actions to the ordinary multi-selection path. Keyboard, focus and accessible-tree effects remain untested. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: Search Messages tree input event boundaries.
