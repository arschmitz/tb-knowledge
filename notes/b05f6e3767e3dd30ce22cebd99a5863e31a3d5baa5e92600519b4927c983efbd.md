# The detached-window workaround delays the initial memory report

The fixed 500 ms wait is in setup before the first getWindows call, which minimizes memory before collecting reports. It does not add a readiness predicate or change assertNoDetachedWindows. The local timer exception and reviewer acceptance preserve an uncertain workaround; they do not prove a cache/GC cause or establish a general delay rule. Later report failures and historical local test reports remain separate from fresh execution.

Scope: Detached-window fixture timing and evidence limits.
