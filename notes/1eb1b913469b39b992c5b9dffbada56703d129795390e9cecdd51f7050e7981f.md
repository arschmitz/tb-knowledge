# Keep destination history separate from folder-opening history

The Recent Destinations review withdrew a proposal to use folder-viewing history for move/copy menus. Opening a folder marks it used, so those entries can displace actual destinations from the bounded menu. The accepted change keeps destination history and clarifies the label. At the fixed source revision the folder mode queries MRUTime, the destination menu queries MRMTime, and the extension sort API names lastUsed and lastUsedAsDestination separately. Preserve those consumer meanings when changing a recent list. The historical review mentions25 entries; current size comes from mail.folder_widget.max_recent, not a fixed count inferred here. This is a scoped source/review lesson, not a live recency or menu test.

Scope: Recent-folder consumer semantics.
