# Keep the POP empty-header signal within parser state semantics

EMPTY_MESSAGE_LINE accepts CR, LF or a zero byte. In ParseFolderLine, an empty signal finalizes headers only while the parser is in ParseHeadersState, then switches to ParseBodyState even after a parse error to stop accumulating headers. An empty signal with length zero does not add input bytes to m_position. It is a parser completion signal, not a stored extra blank line or a replacement for the POP line-reader protocol. Reuse the existing From-body/envelope guard lesson instead of combining those distinct boundaries. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: POP parser state and line length.
