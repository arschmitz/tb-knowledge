# WebGL postlude forwards completion and reports duplicate notification

Firefox repository `git:314d8065c5ad68c7e5c5f92d`, revision `1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b`. Scope: DOM Canvas WebGL conformance tests and the shared Mochitest harness. Languages in the cited files: JavaScript, HTML. File roles are listed in the metadata. No production WebGL implementation is claimed.

js-test-post asks shouldBeTrue to check successfullyParsed, appends completion text and count summary, and calls notifyFinishedToHarness. If no failures exist and runUntilFail parses truthy, it also schedules a 100 ms callback that increments runCount and navigates to the updated URL; notification still happens immediately in the same script. notifyFinishedToHarness records a failure on duplicate calls but does not return early. It sets window._didNotifyFinishedToHarness, calls the cached harness notifyFinished, and then invokes optional nonKhronosFrameworkNotifyDone.

## Completion and ownership

The target document owns the result DOM, duplicate-notification flag, and optional repeat timer. `notifyFinishedToHarness` calls the cached parent harness synchronously. That receiver calls the outer `SimpleTest.finish`. No returned promise represents completion of the whole test-cleanup sequence.

**Errors:** There is no local catch around result DOM access, harness callbacks, or completion. Duplicate notification is reported but can still call SimpleTest.finish again. The runUntilFail timer has no explicit cancellation in this code.

**Consumer:** mochi-single.notifyFinished calls outer parent.SimpleTest.finish and does not await a result. testPath is unused.

**Scope limit:** The body of shouldBeTrue and all target completion call sites were not fully traced in this pass.
