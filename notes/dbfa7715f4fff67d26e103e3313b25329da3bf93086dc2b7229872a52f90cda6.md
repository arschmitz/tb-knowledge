# Spam rename visibility changed separately from folder deletion

The historical fix removes the Junk-specific exception from cmd_renameFolder and removes junk from the context-menu rename shown list. Its separate deletion exception remains. The source comment explains that the localized Spam display name overrides a renamed folder name. Accepted later code reads online && canRename, with the base capability excluding SpecialUse folders. This is a scoped UI/capability change, not proof that every server or extension rename entry point is blocked. The changed test expectation checks menu visibility, not server state.

Scope: Folder-pane Spam rename eligibility.
