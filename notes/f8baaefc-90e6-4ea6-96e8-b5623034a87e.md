# Keep display-name cache invalidation tied to the values that affect rendering

The 2024 change stopped incrementing mail.displayname.version for the removed PreferDisplayName property but kept invalidation when DisplayName changes. Current AddrBookManager observes that version, clears its email-to-card cache, and notifies addrbook-displayname-changed; it also increments the version when global display preferences change. The message database view uses the version to reject cached sender and recipient names. A name display change needs both rendering logic and invalidation coverage or the UI may keep an old value.

Scope: Address display-name cache.

- `mailnews/addrbook/modules/AddrBookDirectory.sys.mjs`
