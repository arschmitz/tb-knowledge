# withNewUID selects contact identity, and each transfer caller chooses the policy

The dropCard removal places its storage behavior in addCard(card, withNewUID). The optional flag requests a fresh UID; the base retains the input UID when the flag is omitted or false. Drag/drop copy passes true, while drag move omits it. The contact panel keeps its separate new-UID-before-delete policy when changing books. Preserve that caller distinction instead of deriving identity from the word move alone. Existing CardDAV copy/move tests check changed versus retained UID and later destination metadata; synchronous local return does not establish remote completion.

Scope: Thunderbird address-book addCard API and transfer callers.
