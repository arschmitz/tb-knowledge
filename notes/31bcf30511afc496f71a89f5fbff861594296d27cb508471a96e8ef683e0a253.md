# Await a step action before advancing or handling its failure

The historical footer event handler starts #handleForwardAction and #initUI without awaiting them, although lazy imports and later discovery are asynchronous. Current forward handling awaits #handleForwardAction inside the try/catch, and the current action awaits configuration lookup and UI transitions. Keep async transition ownership explicit so the next step does not appear before its required action completes and a rejection reaches the intended notification handler. The later fixes were not fully rescanned or attributed to an unread review.

Scope: Account Hub asynchronous transitions.
