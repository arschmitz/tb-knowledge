# Retry attachment deletion at the failed operation rather than after every save

The attachment browser test waits for file existence and returns immediately. deleteAttachmentFile attempts IOUtils.remove up to three times, delays 250 ms only before a retry, requests retryReadonly, logs failures, and rethrows the final error. Its callers await deletion. Use this bounded test-cleanup pattern for the same locked-file concern; do not turn it into a general retry policy or hide permanent failures. The commit describes an intermittent file-lock fix attempt, not a reproduced root cause or a proven fix rate. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Attachment browser-test cleanup.
