# Exchange autodiscovery excludes specific legacy string-scope OAuth issuers

For legacy string scopes, getHostnameDetails returns undefined only when the normalized activity is exchange and the issuer belongs to the explicit exclusion set. Other string scopes remain compatible; object scopes use their activity keys. The actual autodiscovery caller initializes with imap, then performs the exchange eligibility check before requesting an access token. The new table tests metadata presence for 15 hostnames. It does not prove granted scopes, successful login or all-provider interoperability. Later extension registration is separate.

Scope: OAuth provider metadata and Exchange discovery.
