# Preference spelling cleanup was approved as a scoped compatibility exception

The threshold preference rename meets an explicit objection: old documentation can lead users to set a key that a one-time migration no longer reads. The author argues maintenance/searchability, and the reviewer later changes position because the setting already has UI. Approval remains optional/cosmetic and conditional on an early-cycle landing, no regressions and immediate backout for side effects. The review also retracts a request to rename old keys inside migration: those old names are required to copy existing values. The source implements versioned typed migration and coordinates consumers. This historical exception does not establish a general preference for renaming stored names. A later no-issues Try is a report, not an independently checked job.

Scope: Compaction preference compatibility review.
