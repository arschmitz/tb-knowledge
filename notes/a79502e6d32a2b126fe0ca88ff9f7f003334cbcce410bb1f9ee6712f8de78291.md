# A Gloda containsKey exception follows the missing-message path

The compaction worker initializes msgExistsLocally to false. If containsKey throws, the catch only logs, so the ID is queued for the same mark-as-deleted operation used for an absent key. That consumer clears the indexed location and sets deleted=1; it does not remove physical mail. The added healing test does not inject this exception. This is a conditional static finding, not a reproduced exception or observed loss.

Scope: Gloda compaction error handling.
