# Wait for search and view completion events in quick-filter tests

The 250 ms delay makes direct input assignment and immediate row assertions race the search. The accepted QuickFilterBarHelpers helper subscribes before dispatching input, then awaits autocomplete and all messages loaded. The extension browser test waits for dbViewWrapperListener.allMessagesLoaded before inspecting rows. The about:3pane listener tracks that state on view creation, destruction and loading. Use these observable states in quick-filter tests instead of arbitrary pauses.

Scope: Quick filter tests.
