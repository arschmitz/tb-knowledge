# Smiley matching uses escaped alternatives with word-character lookarounds

Fresh full one-file53-line smiley matcher patch read. getRegexp takes own keys from the theme icon map, keeps sort/reverse order, escapes each code with RegExp.escape, and puts alternatives in a noncapturing group between negative word-character lookarounds. The fixed source retains this exact form. These are word-character exclusions, not a requirement for literal whitespace on both sides or complete Unicode word segmentation. No independent regex/DOM execution ran. Complete Bug plus full18-row review/creation-to-postlanding timeline read. Object.keys, RegExp.escape and noncapturing-group suggestions are applied. The grouping itself remains for alternation precedence. Sort/reverse origin is explicitly uncertain; adjacent-smiley and word-character-versus-whitespace tradeoffs remain debated and several rows NotDone. Authors/reviewers explicitly choose to land the improvement as-is and defer feature disabling/outgoing changes. No global iteration or feature-removal rule follows from those proposals.
