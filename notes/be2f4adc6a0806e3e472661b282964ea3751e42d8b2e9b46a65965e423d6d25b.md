# EWS CalendarItem shares the Message payload without bypassing fetch checks

The vendor update adds CalendarItem(Message) to RealItem and returns that payload from both inner_message and into_inner_message. Accepted source retains this representation. The message-fetch caller still requires one returned item and MIME content, then handles base64 failure before sending data to its listener. Recognizing the item type does not establish full calendar handling or a successful server fetch.

Scope: ews-real-item-calendar-message-payload.
