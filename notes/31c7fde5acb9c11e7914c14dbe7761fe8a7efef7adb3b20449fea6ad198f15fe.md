# The temporary-attachment comment outlives the removed window guard

The owned DeleteTmpAttachments guard checks only mTmpAttachmentsDeleted after this patch, yet its comment still says an open compose window prevents deletion. The owned success and failure callbacks both call deletion. The accepted source removes that stale comment and uses separate mSendInFlight/window checks in its caller. Keep that later lifetime handling separate; the original comment is not evidence that the removed window guard still exists. No attachment lifetime or failure test ran.

Scope: Compose attachment cleanup phases.
