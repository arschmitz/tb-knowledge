# Normalize both address lookup input and cache keys for the manager lookup contract

Fresh full two-file139-line patch read. AddrBookManager.cardForEmailAddress lowercases the nonempty lookup string before the Map lookup, fixing the manager-level case path used for contact/header/avatar selection. The historical cache loop in this landing stores card.emailAddresses directly; this patch alone does not establish trim/lowercase normalization for every stored key. The added manager test finds fourth@SOMETHING.invalid; the preexisting directory-level tests exercise a different API. Fixed accepted code trims and lowercases both the input and each cached email key. It still iterates directories/cards in reverse to preserve the first ordinary-order match, catches directory errors, and returns Map.get for missing nonempty input. Empty input returns null. Current tests explicitly build the manager cache in one case then query another, check whitespace and mixed-case second addresses, change a card, and check old/new addresses after invalidation. Source assertions were read, not executed.

Scope: Address-book manager cache and header avatar lookup.
