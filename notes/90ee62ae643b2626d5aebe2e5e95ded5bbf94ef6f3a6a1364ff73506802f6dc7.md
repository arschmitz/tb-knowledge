# Standalone EML remote-content permission is process-local filename state

The owned bridge creates nsMsgFileHdr for mailbox-message URIs with the exact number=0#0 suffix, while direct file URIs keep their existing branch. File-header remoteContentPolicy reads and writes use a static filename hash set. Allow2 inserts a name; reads return allow2 or default 0, and other writes do not remove permission. The key comes from nsIFileURL.GetFileName, so it is the filename rather than a full path, message identity, sender or origin. Distinct files with the same returned filename share that source-level lookup key during the process lifetime. The checked UI writes the header property then reloads, and the content-policy consumer reads the override; new header objects can therefore consult the same static state. This class shows no disk persistence or revoke/reset path. URI parsing failure checks are limited, and the added test does not cover collisions, revocation or restart. No content load or permission scenario ran.

Scope: mailnews/local/eml-content-policy.
