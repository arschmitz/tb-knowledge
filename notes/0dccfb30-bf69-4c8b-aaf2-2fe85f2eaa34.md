# Archive folder promises resolve through native URL listener completion

The archiver's identity-folder and child-folder awaits have different native owners. `getOrCreateArchivesFolderAsync()` expands a macro into `nsMsgIdentity::getOrCreateFolderAsync("archive_folder", Archive, "Archives", ...)`. If the stored URI resolves to an existing folder, it resolves the new promise immediately. That fast path does not itself update the special flag. Otherwise it creates a `FolderGetterOrCreator` and tries the preferred URI's server, servers for that identity, and Local Folders without duplicates.

For mailbox URIs it searches the corresponding none, pop3, and rss server schemes. A candidate must allow copies-and-folders defaults on that server. It uses the root message folder, including deferral, then looks for the special flag, the standard name, or starts `CreateSubfolderWithListener()`. A synchronous failure tries the next candidate. A listener failure or a successful callback with no matching child also tries the next candidate. When found, `finishPromise()` writes the identity folder preference, sets the folder flag, and resolves to the actual `nsIMsgFolder`; exhausting candidates rejects `NS_ERROR_FAILURE`.

The getter/creator holds a strong identity, candidate servers, current root, and a main-thread promise holder. The callback driver owns the continuation while creation runs. It has no cancellation interface in these bodies. Later protocol shutdown and all URL-listener owners are not fully traced here.

`nsMsgDBFolder::CreateSubfolderAsync()` creates a promise and a `UrlListener`. Its stop callback rejects a failed result, rejects a failed child lookup or missing child, or resolves to the named created folder. The lambda captures the copied folder name and promise holder by value but uses the initiating `this` through the default reference capture. It calls the virtual `CreateSubfolderWithListener()` and returns the promise. The base method ignores that call's immediate return status, so implementations must actually report completion to the listener for this bridge to settle.

Actual checked targets: local-folder creation is synchronous, emits `NotifyFolderAdded`, then always invokes the listener with its status. IMAP rejects invalid/unsupported/special names by invoking the listener, or calls `ImapService::CreateFolder()`. If that service immediately fails, IMAP also invokes the listener. Successful asynchronous IMAP listener retention and the remaining EWS/Graph/news implementations are unresolved targets, not assumed from the shared method name. The base implementation itself returns `NS_ERROR_NOT_IMPLEMENTED` without a callback.

`UrlListener` owns its callable start/stop handlers. It returns `NS_OK` for an unset handler and otherwise returns the handler result. Its sibling `CopyServiceListener` forwards optional start/stop callbacks, uses no-op progress/key methods, and rejects message-ID retrieval as unimplemented. Its header examples are source comments, not current workflow rules.

IDL text says the special-folder helper uses synchronous local creation, but the checked implementation now calls listener-based creation and can use IMAP. Keep the implementation and the old documentation distinct. The archive unit test directly asserts local and IMAP destination creation through these bridges; the source was checked, and run results are recorded separately.
