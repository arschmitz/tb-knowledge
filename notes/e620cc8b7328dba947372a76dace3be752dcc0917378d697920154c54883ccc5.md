# Keep AutoConfig HTTP status separate from status text

The historical FetchHTTP callback must choose its no-network fallback from the numeric status, not an empty statusText. Entry2889 changes that guard to !errorCode: status0 gets code-2 and localized cannot-contact-server text; a nonzero HTTP status is preserved even if its text is empty. The current async wrapper still uses response.status||-2 and chooses its fallback message separately. Current read tests assert501 for a server error and-2 while offline, but did not execute here and do not directly cover every empty-statusText or DNS case. Required Bug 1951827 comment1 is unavailable and the assigned review was deferred/unread. This is checked source knowledge with zero complete-audit credit.

Scope: AutoConfig FetchHTTP error reporting.
