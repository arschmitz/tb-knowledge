# Distinguish no search cache from an empty cached iterator

The accepted database returns null with NS_OK when no search-results table exists. The extension listing treats no iterator as a reason to search manually; an existing iterator with zero hits contributes no messages. The original landing catches exceptions, but that is not the current miss contract. Preserve absent cache versus empty results in changes and tests for this family. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Virtual search cache absence contract.
