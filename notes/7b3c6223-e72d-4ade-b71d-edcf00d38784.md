# CalDAV request promises separate header arrival, body handling and provider completion

CalDavRequestBase:31–139 retains the actual session, calendar, URI, upload data
and response. reset calls cal.provider.prepHttpChannel with this as the interface
requestor and detection-session authentication flag. commit awaits
session.prepareRequest, applies onSetupChannel, creates its actual responseClass,
opens the channel, awaits response.responded, conditionally saves the entered
username only for response.ok, and resolves to that response object.
HTTP error statuses do not by themselves reject commit. raiseForStatus:354–381
is a separate explicit conversion to named Error classes.

CalDavResponseBase:253–403 creates responded and completed promises. The checked
calendar module tree has no caller that settles _oncompleted/_oncompletederror.
The completed field's existence is not evidence that it represents finished sync.
SimpleResponse:450–516 decodes received bytes with response contentCharset or UTF-8,
stores the channel and stream status, resolves responded for successful transport,
and rejects with the response object for transport failure. Thus HTTP 500 can
resolve commit while native network failure rejects it. XML parse returns null
on a thrown parser error; malformed XML document semantics need separate checks.

LegacySAXResponse:603–640 proxies actual supplied handler. onStartRequest saves
HTTP channel, calls handler.onStartRequest and resolves responded. onStopRequest
calls handler.onStopRequest and resolves responded again. It returns an async
handler promise without awaiting or wiring its rejection. Its try/catch catches
synchronous throws only. commit can therefore finish after headers, before body
parse, cache mutation, batch end, token persistence or changelog completion.
Provider operations finish through their own operation/changelog callbacks.

Direct assertions: test_caldav_requests.js:544–590 checks generic method, body,
headers, status and XML;972–999 checks username saved after accepted response
but unchanged after HTTP500;1000–1024 checks legacy HTTP status and username.

None of these assertions checks completed settlement or awaited storage failure.
