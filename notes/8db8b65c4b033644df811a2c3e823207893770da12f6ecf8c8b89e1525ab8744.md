# The message decoder EOF path discards a possible final callback error

MimeDecoderDestroy returns the final buffered write callback status after freeing decoder storage. The new message-container EOF path calls it without capturing that result, then checks only the superclass EOF status. Thus this caller does not propagate a negative final decoder callback result through that return path. The added fixture does not inject such a failure. This is a static error-contract finding, not an observed malformed output, crash or fresh execution.

Scope: MIME decoder flush result propagation.
