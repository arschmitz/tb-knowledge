# Password cancellation status needs separate checks at the producer, wrapper and retry consumer

The owned EWS wrapper discards QueryPasswordFromUserAndCache's nsresult and returns Ok(password). Accepted shared outgoing code instead preserves the special successful cancellation status and propagates errors; its UI adapter checks that status before reporting Cancelled. This is not an end-to-end cancellation guarantee: accepted JavaScript throws NS_ERROR_ABORT on cancel, despite the IDL's special-success documentation, and the replacement-password failure branch discards a computed ABORT/RETRY match before returning RETRY. An error still propagates before that return. The empty-password branch returns its computed outcome. These are distinct static contracts and phases; no prompt or retry was exercised.

Scope: EWS and shared password prompting.
