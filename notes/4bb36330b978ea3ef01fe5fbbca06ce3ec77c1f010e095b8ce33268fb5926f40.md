# Keep the sparse-row forEach exception separate from the loop preference

D233997 proposed for...of for the original LiveViewRowMap. The author rejected that change because the array can contain many unfilled slots, and the actual landing retains forEach in add/remove handlers with a comment explaining defined-index iteration and the lack of early exit. This is a scoped historical exception to the normal for...of preference for action loops. It does not reverse the user-directed guidance, establish a performance benchmark or justify mechanical replacements. The fixed async adapter has retired LiveViewRowMap, so preserve the reasoning as historical context rather than copying the old caching architecture. The existing sparse-architecture lesson remains separate. No loop timing or Thunderbird test ran.

Scope: Historical Panorama sparse-row iteration.
