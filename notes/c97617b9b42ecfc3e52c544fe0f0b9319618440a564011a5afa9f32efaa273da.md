# Offline move replay resolves operation IDs into recorded server UIDs

Current ReplayOfflineMoveCopy takes srcOpIds and loads source offline operations before collecting GetSrcUid results for OnlineMessageCopy. The source message headers may already be deleted locally. It searches destination counterpart operations to apply pending attributes, but the comment says that counterpart setup exists for moves and not copies. Both move and copy sync callers use this function for destinations on the same server. Manual interface naming and documentation proposal: say whether an array contains operation IDs, header keys or UIDs and preserve the move-only limit on counterpart state. Do not teach successful copy metadata recovery or use the stale aMsgKeys comment as the signature contract. This is current context for 782 and 796, not added chronological coverage of later refactors.

Scope: offline-replay-identity.
