# The safe attachment fallback retains only the existing name suffix

Fresh complete naming hunk read. For names beginning with a file/mail/news URI, AddAttachments extracts the suffix after the last dot before replacing the visible name with the safe localized part name, then appends that suffix only when nonempty and without a literal space. It does not determine a filename extension from text/calendar MIME content or parse/validate every possible suffix. Existing *-message URI names use a separate safe-message-name branch. Current code preserves the same suffix condition, now using asynchronous Fluent strings, before gAttachmentBucket.appendItem consumes the updated attachment object. The complete Bug corrects the original allegation of losing an existing .ics filename: the source invitation had no .ics filename to begin with. The attached sample/screenshots and Outlook reproduction were not opened or run. No test changed, message was forwarded, or filename/MIME compatibility was exercised.

Scope: Compose attachment fallback names.
