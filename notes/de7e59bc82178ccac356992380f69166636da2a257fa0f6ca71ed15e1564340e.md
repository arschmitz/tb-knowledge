# The content-script helper waits for matching tab completion before reporting readiness

This landing installs a tabs.onUpdated listener before tabs.update, accepts only the active tab ID with status complete, removes that listener and awaits it before returning the tab. The parent then applies its own requested-URI predicate before checkContent spawns into the browser. The NoPermissions content scenario uses this helper; its about:blank list separately excludes updateMailTabBrowser. The status wait does not read changeInfo.url. This supports the scoped test ordering. It does not independently prove an actor-race cure, an upstream permission contract or cleanup after a rejected update. Later injection retries are a separate source phase. No runtime test was run.

Scope: extensions browser tests.
