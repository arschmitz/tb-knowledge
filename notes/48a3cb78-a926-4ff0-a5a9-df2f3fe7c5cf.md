# ICS component wrapper clone and multi-value iteration share bundled ICAL storage

Production component wrapper and explicitly third-party bundled ICAL implementation.
This checks actual constructors, return objects and library state; it is not a
conclusion from the method name clone alone.

calIcalComponent.clone, CalICSService.sys.mjs:251–253, creates new ICAL.Component
from innerObject.toJSON. Bundled Component.toJSON at 8716–8718 returns live jCal
array; constructor 8212–8226 assigns that array directly. New wrapper/parent state
is separate, raw content is shared. Controlled exact-source probe confirmed
sameRawJCal=true; changing cloned UID changed both original getter and original
serialization. This concerns calIIcalComponent clone. CalItemBase.clone and
cloneItemBaseInto,319–403, clone separate fields/attendees/recurrence/date values;
the result does not automatically extend to every higher-level calendar item.

Wrapper getFirstProperty/getNextProperty,481–524, stores a generator on the
component. Names are lowercased and ANY means unfiltered. Multi-valued property
case snapshots getValues, then for each value constructs ICAL.Property from
prop.toJSON, removes all values and sets the selected value. Bundled Property
constructor 7802–7812 assigns raw jCal directly and toJSON8150–8152 returns it;
removeAllValues8084–8089 truncates that same array. Therefore the apparent per-value
copy can mutate the source property's raw content.

Controlled probe of CATEGORIES:a,b,c yielded a,b,c, but after exhaustion source
serialization was CATEGORIES:c. This is checked source plus scoped execution,
not yet a proved end-user data-loss scenario in every caller. Callers that iterate
properties then serialize the same component may consume the changed result.
Caller reachability and each item's icalComponent getter remain important scopes.

getNextProperty and component/parameter equivalents restart by calling getFirst
when their generator field is null. Exhaustion returns undefined and clears field;
the next call after exhaustion can restart. Nested/concurrent iteration on the
same wrapper shares and replaces that generator field. It is not an independent
iterator per caller. Actual library getAllProperties/getAllSubcomponents may
return hydrated cache arrays for unfiltered access, creating another owner alias.

Direct tests: test_ics_service.js:174–182 checks cloned alarm has null parent,
not content independence. 237–287 checks property/parameter sequence and restart,
and multi-value categories yield a,b,c. It does not assert unchanged source
serialization after that loop. 184–219 checks basic accessors update one serialized
property. A passing file therefore does not establish clone independence,
read-only iteration, simultaneous iterator ownership or every timezone branch.
No product patch was made from these observations.
