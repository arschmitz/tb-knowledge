# Report the mbox size limit on the read after returning allowed bytes

MboxMsgInputStream::Read may drain parser data beyond the configured output allowance but reports only the permitted use count. If use is smaller than the drained count it sets mOverflow, returns the current read successfully, and fails the next Read with NS_MSG_ERROR_UNEXPECTED_SIZE. Available and StreamStatus do not directly return mOverflow as an error in the inspected implementation. A consumer must handle subsequent Read failure; do not treat a successful partial read or the status accessor as proof of a complete message. No boundary-length runtime case was run. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Mbox input size-limit completion.
