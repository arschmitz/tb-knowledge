# Message creation start and completion have separate error channels

A successful Go return means the operation started. The XPCOM entry point retains its listener and detaches the Rust task. Remote completion later calls the C++ handler, which reports local success or failure through its completion function. If the success callback itself returns an error, DoOperation logs a warning; it does not turn that completed remote operation into another failure callback. A caller must distinguish start failure, remote failure, local database failure and callback-return logging. This is static source evidence, not a tested exactly-once or rollback guarantee.

Scope: Exchange asynchronous creation callback contract.
