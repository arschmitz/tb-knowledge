# Bundled notification cleanup is separate from raw loading and normal expiry filtering

The assigned patch removes the same expired Spring25 entry from all three branding data sets. The checked offline loader returns the JSON data and caches its IDs; it does not itself filter dates. Normal eligibility filtering rejects invalid dates, future starts and past ends, but its explicit bypass returns earlier after the interacted-ID guard. The selected offline data test checks shape and future end dates except a named test-only entry. Data removal, loading, eligibility and display are separate contracts; no notification fetch, clock-dependent test or display ran.

Scope: In-app offline notification data flow.
