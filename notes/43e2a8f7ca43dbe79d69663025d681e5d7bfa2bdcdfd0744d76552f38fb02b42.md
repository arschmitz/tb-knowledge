# Bound hashed folder names even when the illegal character appears late

The newer accepted helper caps the retained prefix at MAX_LEN minus the eight-character hash, even if the illegal character is beyond the limit. It backs off one UTF-16 unit when that length boundary would keep a high surrogate alone. The current gtest adds the late-illegal-character case. Prefer this accepted implementation over the original 1977 prefix rule; the checked test has no explicit surrogate-pair assertion. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check was run.
