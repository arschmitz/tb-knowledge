# Manual incoming forms require a valid numeric port in the non-Exchange path

Correction to lesson ff4d6207c070a7c003a1bc5b414223f4c2bc4a3c30c4bef96c956396686b8d96: the inspected accepted non-Exchange incoming form does not establish an allowed empty/Auto continuation state. Its number input is required with min=1, max=65535 and placeholder=993. #getDefaultConfigValues passes valueAsNumber to InputSanitizer.integerRange(…, 1, 65535). On failure it sets config.incoming.port to undefined, forwards error._message to setCustomValidity, marks aria-invalid and associates incomingPortErrorMessage. The comment “Include default Auto” does not override that branch. AccountConfig.isIncomingEditedComplete requires a truthy incoming.port in its non-Exchange branch; #checkFormValidity also requires native form validity before emitting completed=true. Exchange has a separate URL/user/auth branch and is outside this port requirement. Preserve the actual numeric bounds, failure state and error relationships; do not infer an accepted Auto state from the comment or placeholder. This is static source inspection, not sanitizer/native-validity execution, a reproduced UI failure or proof of spoken error feedback. No browser tests, build or lint ran. The old immutable record is preserved; this corrects source interpretation, not deliberate guidance.
