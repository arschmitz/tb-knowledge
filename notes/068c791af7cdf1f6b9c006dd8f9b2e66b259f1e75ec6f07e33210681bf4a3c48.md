# The custom-account test preserves a stored default while its server is unavailable

The fixture stores account2 as default while server2 has an invalid type. It expects a null default, adds a different valid account and still expects null. After unloading accounts and changing server2 to pop3, it expects account2 as default. These assertions check that the unavailable stored default is not replaced by the newly created account; they simulate availability rather than run an extension restart.

Scope: account-manager-default-test.
