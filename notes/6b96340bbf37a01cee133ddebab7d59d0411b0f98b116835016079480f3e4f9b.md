# Asynchronous Account Hub discovery updates the option widget instead of whichever step is visible

The one-line follow-up changes init after #fetchAccounts to update #states.optionSelectSubview.subview. It no longer writes the account list into #currentSubview, whose result depends on the step visible when the async work finishes. The fixed accepted method retains this explicit target. This is a state-owner contract for refreshing selectable accounts; it is not a rule to reset every subview or proof of tested navigation during discovery. No changed test or live race scenario was executed.

Scope: Account Hub asynchronous state ownership.
