# The Exchange copy failure guard does not see an unassigned root-target error

At the fixed revision, ExchangeFolder::CopyMessages initializes outer rv to NS_OK and installs GuardCopyServiceExit, which only notifies for NS_FAILED(rv). The root-destination branch returns NS_ERROR_FILE_COPY_OR_MOVE_FAILED without assigning rv, so that named branch leaves the watched value successful. The inspected global CopyMessages entry permits a nonempty different-folder request without rejecting a root target, and DoNextCopy marks its source processed before dispatch; its message branch does not clear the request from the returned error. NotifyCompletion is the observed clearing/advance consumer. The original landing already used a captured-rv guard with the same direct root-error return. This is a bounded static status/consumer gap and a focused failure-test target, not a reproduced stuck queue or claim about every caller.

Scope: Exchange copy-service synchronous completion state.
