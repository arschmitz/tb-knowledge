# Removing nsIMsgSend.dontDeliver does not remove the send-method argument

The 1852699 landing removes the unused public dontDeliver attribute, while createAndSendMessage keeps its aDontDeliver method argument. Current MessageSend stores that input as _dontDeliver; createRFC822Message also sets it true, and _deliverMessage then reports completion without sending. A public member, a method argument and private implementation state are different contracts. The own review confirms this distinction, but required Bug discussion lacks a Thunderbird-only selection. These are source/review-only facts with zero full-audit credit; no real send operation ran.

Scope: Compose send interface/member distinction.
