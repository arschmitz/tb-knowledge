# Continue notifying queued prompt consumers when one consumer throws

The prompt runner awaits the first authentication result, cancels that first prompt if it rejects and removes the pending key. It then calls each queued consumer inside its own try/catch; a throwing consumer is logged without skipping later consumers. Finally it decrements the in-progress count and starts the next prompt. 1020 preserves those control-flow boundaries while improving logs; current code uses lazy.log.error. This is source knowledge about shared prompt fan-out, not a new concurrency test.

Scope: Authentication prompt consumer failure isolation.
