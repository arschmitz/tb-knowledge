# The Calendar event helper waits for open only when needed

After calendar readiness, openEvent checks dialog.open before waiting for the open attribute. An already open dialog therefore does not require a new attribute transition. This helper boundary does not establish that the rich-description browser is loaded or painted; the synchronous setter and asynchronous connection have separate completion contracts. No browser test was run.

Scope: Calendar browser-test dialog opening.
