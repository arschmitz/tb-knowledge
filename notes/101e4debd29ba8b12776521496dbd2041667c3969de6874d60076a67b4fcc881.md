# Use received scheduling stamps before the locally modified item timestamp

The accepted cal.itip.getStamp helper reads RECEIVED-DTSTAMP from attendees and X-MOZ-RECEIVED-DTSTAMP from items. Only an item without the received stamp falls back to stampTime, whose getter can materialize a dirty timestamp. An attendee without a received stamp can yield null. Scheduling comparison first compares sequence, then stamp when sequences are equal. Preserve these different sources when changing invitation freshness checks; a newly modified local timestamp is not automatically the last received REQUEST/PUBLISH timestamp. This is accepted context for entry 897, not code newly added by that patch.

Scope: calendar/base/modules.
