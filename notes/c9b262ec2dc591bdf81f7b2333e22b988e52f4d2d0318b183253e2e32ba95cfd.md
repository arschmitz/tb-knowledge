# Task-view startup defers localized placeholder work beyond its startup notification

The owned taskViewOnLoad waits on document.l10n.ready before reading emptytextbase and the platform key label, guarding both values before replacing #1. It clears the filter input and calls taskViewUpdate in that callback. The task tree binding remains in an existence guard, while the deferred update requires the real task widgets. Calendar startup does not await this callback, and calendar-taskview-startup-done is emitted outside it; that notification is not a localization-completion barrier. Current source preserves this ordering after a later filter-message rename and aria-label addition. Existing task-display tests exercise text/filter state after tree refresh, not localized placeholder output; seven inspected retention assertions omit messages. No migration, localization, browser or accessibility test ran.

Scope: Calendar task-view localized startup.
