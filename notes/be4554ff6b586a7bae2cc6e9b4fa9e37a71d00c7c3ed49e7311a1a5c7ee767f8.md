# Do not equate a null comparison guard with a no-change result

The invitation exception comparison currently uses (exc.startDate && exc.startDate.compare(exc.recurrenceId)) != 0, and the duration comparison has the same shape. When the left operand is null, the expression produces null and null != 0 is true. The guard avoids dereferencing a missing date but is not equivalent to requiring an existing changed date. This is a static JavaScript expression observation, not a demonstrated invitation defect. A refactor needs tests that distinguish missing, unchanged and changed values before selecting the intended policy.

Scope: calendar/base/modules.
