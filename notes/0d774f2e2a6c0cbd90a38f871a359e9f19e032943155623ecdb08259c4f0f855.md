# Keep local message keys and Exchange IDs distinct during deletion

The Exchange client API takes message IDs as UTF-8 strings. ExchangeFolder reads kExchangeIdProperty to build that list; local storage deletion uses nsMsgKey values. Headers without an Exchange ID are skipped only in the remote-ID list, while the success listener retains the whole original header array. Do not describe that skip as preserving those headers locally. This narrower behavior is a source observation; missing-ID and mixed-ID runtime outcomes were not tested. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Exchange message identity boundaries.
