# Allow an absent displayed-header hint while preserving reply identity fallback

Entry 2109 adds optional chaining only at the newsgroups hint used when no identity was found. If currentHeaderData is null or undefined, that special first-NNTP-account search is skipped and the existing getIdentityForHeader fallback still selects a reply identity. The fixed accepted code keeps this guard, and the NNTP account lookup itself also permits no matching account. This is a case where absent display metadata is allowed; it does not justify optional chaining on a required initialized object elsewhere. The commit title reports a regression from Bug 11076. No standalone file/news reply, identity-selection, compose-window, keyboard or runtime test was reproduced. Full bug/review context is pending.

Scope: Reply identity hint guard.
