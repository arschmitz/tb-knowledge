# Preserve the sorted-list precondition at the folder/database boundary

AddToNewList permits keys that arrive in descending order. GetNewList only clones; it does not sort. Folder cache/status paths call SortNewKeysIfNeeded when new messages exist, while thread code uses ContainsSorted. Therefore callers must preserve the ordering boundary before the binary lookup. Do not teach that every newly appended array is automatically sorted or copy ContainsSorted into an arbitrary list. The helper’s tail-order check is the inspected implementation, not a general arbitrary-permutation sorting guarantee. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Legacy database new-key ordering.
