# Verify the final OAuth scope rather than trusting an assertion message

The current ewsifyConfig test retains the old oauthSettings.scope URL while an assertion message still says the EWS scope should be updated. The assertion checks the value actually supplied; its prose does not prove a permission was added. Proposed manual test-comment rule: make the expected value and message describe the same transformation, especially after a config refactor. The historical lost-write diagnosis remains in the existing scoped lesson. This note is based on source inspection. Tests were not run, and full review discussion remains pending.
