# Credential recovery returns control to the operation retry loop

In this landing, recoverable authentication handling returns Result<(), ProtocolError>. The token-owning request loop then continues, and send_http_request obtains credentials again before sending. Silent policy and an ABORT outcome return authentication errors; a RETRY outcome returns unit. The removed Credentials::validate and custom NTLM exchange no longer send a separate validation request from the recovery handler. Later accepted code can retry after updating a response realm, which is a distinct phase. No password prompt, retry ordering, concurrent operation or successful native login was executed.

Scope: Shared Exchange operation retries.
