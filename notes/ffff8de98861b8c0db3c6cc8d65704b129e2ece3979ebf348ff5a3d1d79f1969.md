# Compose file callbacks pass a window URL argument separately from the message window

The two file callbacks still await getOrOpen3PaneWindow but ignore its returned DOM window. They pass null for msgComposeWindowURL; the draft call keeps its separate later nsIMsgWindow argument. With an identity available, the service uses the default compose document for null/empty chrome. The draft MIME early-return branch explains why that first argument is not consumed on the same path. Required Bug discussion has four recorded missing bodies; this lesson uses public Git/API code only, with zero full-audit credit and no reproduced compose or external-app result.

Scope: Messenger content-handler compose URL arguments.
