# Clone the caller principal with the intended origin attributes

Accepted getClonedPrincipalWithProtocolPermission uses principalWithOA and defaults absent override attributes to the original principal.originAttributes. It adds open-protocol-handler^ plus the URI scheme to the clone, then returns it. Scoped recommendation: carry the intended container/private attributes through principal construction and permission checks rather than replacing caller identity with an arbitrary principal. This source does not establish a scheme allowlist or a native permission-isolation result. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending.
