# Distinguish IMAP summary paths from folder paths at every caller

Entry 950 moves CreateFileForDB into its IMAP owner. The historical helper returned an unsuffixed folder path. Accepted code now returns the full .msf path; both inspected callers use StripSummarySuffix to obtain a separate folderPath and use OpenDBFromFile with dbFile. The helper clones the input base path, hashes the leaf name and checks collisions. Its old comment still describes stripping the suffix inside the helper and calls the allocation non-atomic. Manual naming and comment proposal: name the representation that each path holds and update helper comments with the callers when that representation changes. Do not promise atomic uniqueness or copy the old unsuffixed return contract into new code.

Scope: mailnews/imap/db-paths.
