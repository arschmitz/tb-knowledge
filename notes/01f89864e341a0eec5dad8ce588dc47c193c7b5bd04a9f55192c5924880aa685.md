# The OpenPGP display test uses a larger total timeout as an accepted alternative

D239728 and Bug 1928030 explicitly choose requestLongerTimeout(2) instead of moving tests to browser_viewMessage2.js. The cited D238929 postlanding discussion says increasing allowed running time is valid and questions duplicated shared setup after a split; moving checkABrowser to a head file is only an agreed idea unless actual code proves application. This scopes the form-picker split example; it does not create a split-only requirement or a ban on harness timeout increases. A larger total timeout does not make an arbitrary fixed delay a readiness signal and does not reverse the deliberate event/state-wait preference. Fixed OpenPGP source retains the request. No tests ran.

Scope: OpenPGP test total runtime budget.
