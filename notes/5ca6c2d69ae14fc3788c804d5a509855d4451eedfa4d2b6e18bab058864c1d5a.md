# Toolbar disabled events follow the actual button and navigation state

The current native button subclass changes tabIndex when disabled and emits buttondisabled on its parent because a disabled button does not emit it there. Reenable emits buttonenabled on the button. Command mutations also synchronize disabled and checked/ariaPressed state. This is a scoped control/lifecycle contract to preserve when reusing the component; the structural 1273 tests do not validate all of this navigation or accessible-state behavior. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/components/unifiedtoolbar.
