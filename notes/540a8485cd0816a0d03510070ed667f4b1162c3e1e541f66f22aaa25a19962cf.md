# About-page variable loading follows the selected content-tab overlay

The original landing adds a document-head variables.css link through a packaged plain script loaded by the profiles and generic about:* content-tab overlays. Add-ons uses its separate overlay and gains a CSS import instead. The actual listener chooses an exact allow-list URL before falling back to a scheme wildcard; address-book and blank entries have separate behavior, and Preferences uses a different mechanism. At the fixed accepted endpoint, the common and Add-ons scripts link aboutExtra.css, which imports variables with the other shared styles. These are static routing and resource identities, not proof of stylesheet completion, accent colors, border radii or rendered accessibility.

Scope: Content-tab about-page stylesheet routing and resources.
