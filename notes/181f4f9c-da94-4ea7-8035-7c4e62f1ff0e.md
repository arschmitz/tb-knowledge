# Quote the macOS app destination when removing it during repackage

On a second local macOS mach build, ChannelPrefs.framework could not be moved because the old destination directory remained. The app bundle path can contain a space, as in Thunderbird Daily.app. The unquoted rm -rf $(dist_dest) split that path, so repackage did not remove the intended bundle. The landed Makefile quotes the destination, matching adjacent MKDIR and rsync commands. The reporter and another affected reviewer confirmed the fix. CI clobber builds did not show this incremental-build failure; current Makefile still quotes the path.

Scope: macOS packaging build.
