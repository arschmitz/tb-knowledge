# The collation port changes key storage before later subject and reuse fixes

The port removes byte collation-key APIs and stores string values in IdKey.key while retaining the old key names. Actual view sorting compares those strings with AppCollator::CompareBase and delegates ties to SecondaryCompare. In the owned port, subject keys come through FetchSubject, which prepends Re: when HasRe is set. Accepted source later uses the decoded subject directly and clears a reused string before field dispatch. Keep that later correction separate from the initial migration; no paired engine ordering or native runtime result is established.

Scope: Message view string sort keys.
