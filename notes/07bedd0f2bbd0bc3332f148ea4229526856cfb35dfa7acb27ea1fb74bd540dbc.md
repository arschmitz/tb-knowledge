# Treat one Exchange copy handler as one sequential multi-message operation

The historical landing extracts a per-operation handler with a cloned input-header array and owned folder/file references. Accepted handler still streams a complete source message into mBuffer, creates its destination and advances mCurIndex after completion. It is not one handler per individual message or a streaming remote upload. Same-server current copies take a separate server-side path; cross-server copies use this handler. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange copy operation ownership.
