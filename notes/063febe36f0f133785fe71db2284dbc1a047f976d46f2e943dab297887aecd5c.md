# Resolve a compose-window promise before using the result as a Window

The deleted promise_compose_window passed promise_new_window’s result directly to _wait_for_compose_window. The accepted compose_window_ready explicitly awaits composePromise first; current open_compose_new_mail likewise awaits its opened-and-loaded promise before passing the window. The old function was removed as unused, so this is a value/timing distinction, not proof of a formerly observed test failure. For this helper family, keep names and parameter documentation clear about whether a value is a Promise or a Window. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: compose helper promise contracts.
