# Suggest blank lines that make logical steps clear

This is a deliberate user-directed clarification for Thunderbird code writing,
review, and verification. Automatic learning must not change it.

## Guidance

When code is too dense or blank lines do not follow the logical steps, suggest
where to add, remove, or move a blank line. Name the steps that belong together
and the boundary that needs separation. Explain how the proposed grouping makes
the flow easier to follow. Keep this as a readability suggestion unless the
current grouping causes a concrete problem or violates an applicable rule. Do
not treat a different but clear grouping as a defect.

Keep closely related statements together. Separate distinct logical steps when
a blank line helps the reader. In tests, make setup, actions, and expected results
easy to distinguish. Follow the affected language, component, file role, local
format, and generated or imported code exceptions. Inspect grouping separately
from lint and formatting. Do not impose fixed counts, add a blank line after every
statement, or require unrelated cleanup.
