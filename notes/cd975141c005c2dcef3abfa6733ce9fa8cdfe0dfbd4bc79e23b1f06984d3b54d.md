# Generate the MDN reply identity outside cached separator setup

The historical review raised the risk that generator reuse could reuse a Message-ID when message utility setup was tied to the cached MIME separator. The author moved utility setup and reply ID generation outside that branch. Current nsMsgMdnGenerator::CreateFirstPart still reuses m_mimeSeparator but obtains the compose utility and generates m_messageId later for each successful header-generation call. The reply Message-ID remains distinct from the original acknowledged message ID. Keep reusable formatting state separate from per-reply identity. The review also raised SMTP MAIL FROM preference handling; the author explained that boundary and the reviewer explicitly retracted the concern. No reused-generator test was run, and no empty-ID failure was reproduced.

Scope: mailnews/extensions/mdn.
