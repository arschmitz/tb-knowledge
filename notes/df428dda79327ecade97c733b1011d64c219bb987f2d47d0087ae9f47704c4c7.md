# Exchange asynchronous completion belongs to the operation and listener contract

The current fetch operation delegates completion to DoOperation::handle_operation: success invokes the safe listener and failures go through handle_error. The fetch listener converts both outcomes into onFetchStop. It uses its own fetch-listener interface because fetching may have no request/channel to pass to nsIStreamListener. At the channel boundary, a failure after AsyncOpen has returned still sends OnStartRequest and OnStopRequest. Empty offline fetch queues dispatch success later rather than invoking completion before Go returns. Manual API proposal for these asynchronous paths: document synchronous start failures separately from later callbacks, and keep completion responsibilities explicit. Cancellation of an in-progress download remains incomplete in current channel code; do not teach full cancellation support.

Scope: exchange.
