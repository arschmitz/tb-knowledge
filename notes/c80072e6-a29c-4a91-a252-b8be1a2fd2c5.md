# Current Gloda compaction checks stable message keys rather than old idBasedHeader null handling

The 2024 fix changed an absent idBasedHeader sentinel from false to null so a stale Gloda record would enter the deletion branch. That historical branch is gone. Current _worker_folderCompactionPass says the old merge logic based on shifting mbox offsets is obsolete, fetches Gloda records in batches, checks each message key with _indexingDatabase.containsKey, and marks missing IDs deleted; it separately restores pending commits after a database swap. Use the current key-based path when fixing compaction, not the old false/null advice. Bug 1898780 did not prove the warning was newly caused by the compaction rewrite.

Scope: Gloda indexing.
