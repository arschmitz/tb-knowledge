# Notification focus tests resolve the scheduler startup gate explicitly

Focus-test setup calls _resolveStartupDelay, awaits _startupDelayPromise and then waits a tick. The production scheduler creates that promise during init and waits before setting ready and adding its idle observer. This controls test startup without changing the production timeout. The tests still wait for notification state and assert the active element separately; startup resolution is not general UI completion. No focus or browser test was run.

Scope: In-app notification browser tests.
