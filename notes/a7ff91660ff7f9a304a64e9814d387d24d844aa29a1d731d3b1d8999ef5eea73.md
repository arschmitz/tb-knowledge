# Document the handler validator’s truthy result before treating it as a strict boolean

isValidHandlerApp documents a boolean result. Its web-handler branch returns uriTemplate directly, while absent and unknown objects return false and the local-handler branch uses executable validation. Existing chooseApp uses the result in an if condition. Proposed local contract check: align the return annotation and implementation, or document a truthy string result before adding a strict-boolean consumer. This is a static type/documentation mismatch; no existing picker failure was reproduced. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.
