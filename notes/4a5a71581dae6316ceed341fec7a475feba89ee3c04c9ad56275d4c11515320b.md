# The input-stream pump receives ownership through forget()

After the redundant slice is removed, the accepted nsMsgProtocol creates its input-stream pump with stream.forget(), checks the result, and keeps a reference to the pump for cancellation. For this XPCOM call, preserve the ownership-transfer form required by the API and the cancellation owner. This is a scoped C++ source pattern, not a blanket rule to call forget() on every smart pointer. No compiler or stream-cancellation test was run. Full bug and review discussion remains pending.

Scope: Mail protocol C++ ownership.
