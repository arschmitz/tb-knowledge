# Thundermail request options use positional API arguments

Api.call takes body, method and headers as separate positional arguments. It defaults to GET and attaches a JSON body only for POST. In both phases, the auth callback and add-on token authentication pass a fetch-style method/headers object as body; that object does not select POST or populate the wrapper's headers argument. The wrapper may separately acquire a bearer token. Both deleteItem callers likewise pass shouldDeleteContent with DELETE, but this wrapper does not serialize that argument. These are caller/wrapper traces; the server's method support, deletion defaults and actual outcomes remain untested.

Scope: Thundermail generated auth and folder API callers.
