# Carry message header strings through the UTF-8 IDL contract

charset, effectiveCharset and accountKey now use AUTF8String. Current native callers pass nsCString outputs directly rather than getter_Copies at the public getter boundary. The database implementation still uses getter_Copies internally for its older row-cell API and flattens the setter string before its char-pointer storage call. Keep those two boundaries distinct; removing every getter_Copies would change an unrelated storage contract. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: message header string API.
