# Address-book selection requested before load is stored until initial setup

Before initial load completes, displayAddressBook stores the requested UID and returns. The load handler selects that pending book before the startup preference, performs initial focus work, emits ready and then marks initialAddressBook false. Later calls select immediately. The async function does not wait for the deferred selection to happen, and the command callback does not return its promise. Keep that return/readiness distinction and last-request state when changing callers. No race or browser test ran.

Scope: Scoped address-book pending UID and readiness contract.
