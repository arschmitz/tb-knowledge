# Keep legacy delete booleans separate from new delete options

messages.delete still normalizes the deprecated boolean to {deletePermanently: value}; the object separately carries deletePermanently and isUserAction. The schema says permanent deletion cannot be restored even when defined as a user action. Keep these separate meanings when changing the compatibility branch. This is the current API shape, not a promise of atomic multi-folder deletion. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: extension message deletion.
