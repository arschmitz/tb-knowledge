# Telemetry preference notifications can repeat the same combined Boolean

The experiment computes enabled with every() across the two Boolean preferences. On each matching preference notification it emits that recomputed value, without saving or comparing the prior combined Boolean. Changing one preference while the other remains false can therefore emit false again. The checked background and bridge forward this state without adding deduplication. The schema describes effective-state changes, so consumers must not infer a changed combined value from the event alone. Fixed accepted source retains this trigger contract. This is static source reasoning; native observer delivery, page handling and telemetry traffic were not run.

Scope: Thundermail telemetry preference observer and bridge event.
