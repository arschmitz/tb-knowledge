# Graph mark-read requires a complete successful-ID count before reporting success

The operation builds per-message PATCHes, waits for the batch and errors when successful returned ID count differs from requested count. Success reports IDs with no legacy fallback. The bridge returns after detached dispatch, while the native success receiver later updates matching local headers. This count test does not prove ID membership, rollback or all-or-nothing remote changes.

Scope: Thunderbird Graph read-status operation.
