# MailGlue startup order and shutdown cleanup

## Entry and responsibilities

`MailGlue` coordinates application startup. Its constructor calls `_init()`, which subscribes to startup, shutdown, locale, and document notifications. The app-startup category is supplied by `MailComponents.manifest`; the constructor mapping is supplied by `components.conf`.

`observe()` routes notifications to the work for that stage. `app-startup` reads `extensions.lastAppVersion` before the add-on manager changes it. `command-line-startup` detects the browser toolbox process. When that process is detected, `_dispose()` removes MailGlue's listeners so normal mail startup work does not continue there.

## Order that must be preserved

On `final-ui-startup`, `observe()` first forces the permission manager to initialize through `Services.perms.all`. It then obtains the IMAP protocol handler and initializes folder and database-view strings before calling `_beforeUIStartup()`.

The source gives two reasons. Loading permissions after folder strings are available can make mail URLs query message databases and cause much more disk access. Registering the IMAP handler early avoids session-restore failures. These are specific ordering constraints, not interchangeable initialization calls.

`sessionstore-windows-restored` calls `_onWindowsRestored()`. `mail-startup-done` calls `_onFirstWindowLoaded()` and removes that topic's observer. `MailGlue.afterStartUp` is a promise resolved by an idle task after most startup work. Its presence does not mean every later idle task has completed.

## Actor registration

`_init()` forces `ActorManagerParent` to initialize. It unregisters `FindBar`, `LoginManager`, and `NetError` before adding Thunderbird's process and window actor definitions. Actors carry work across process or window boundaries. The source says the unregister step avoids errors when shared actors are registered for Thunderbird's message-manager groups.

## Cleanup and locale updates

`xpcom-shutdown` calls `_dispose()`. Cleanup removes topic observers, unregisters the internal browser-console window listener, stops mail usage telemetry, and removes a late-task idle observer when one exists. The `mail-startup-done` observer is removed in its own handler.

When `intl:app-locales-changed` arrives, `observe()` updates folder and database-view strings before sending `folder-strings-changed`. The interface should use the latter notification when it needs the refreshed strings. Reacting to the earlier topic can run before those strings are updated.

This review covers the constructor, `_init()`, `_dispose()`, and the notification routes above. It does not establish all work inside the large migration, telemetry, link handling, and idle-task methods.
