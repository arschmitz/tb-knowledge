# Separate visible allowlist wording from persisted junk-origin values

The lint series changed the junk-origin menu value from whitelist to allowlist. Accepted searchWidgets still emits value: "allowlist", while junkCommands stores "whitelist" and MatchJunkScoreOrigin compares the value with exact string equality. This is a static producer/consumer mismatch worth a focused regression check; no failing search was run. For this stored token boundary, change labels independently from values unless the producer, search consumer and existing data are updated together. Do not treat a terminology or lint sweep as proof that a persisted token can change safely. These conclusions come from static source inspection. No runtime test or accessibility session was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Junk-origin persisted token compatibility.
