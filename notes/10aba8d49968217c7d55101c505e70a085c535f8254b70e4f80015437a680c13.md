# Bind existing UTF-8 database values with the UTF-8 storage API

Entry 2117 replaces conversion to UTF-16 plus BindStringByName with BindUTF8StringByName for already-UTF-8 message fields, folder names and tag-filter values. The fixed message insertion path still binds UTF-8 text and now normalizes fields before binding; encoding choice does not replace normalization. Current tag filters instead pass a UTF8TextVariant as query data, so the old filter preparation method is not current API. The historical messages test changes a tag fixture to $label5 but asserts only total counts, which does not prove tag round trips or leak freedom. Retrieved current live-view tests exercise emoji sender/subject values, and the adapter test checks an accented subject while sender-format checks are disabled. These tests were read, not run. String storage changes in old Message members do not establish a global rule to use nsAutoCString for every class member. No Unicode round trip, SQLite error, leak, runtime or accessibility test ran. Full discussion is pending.

Scope: Panorama storage string binding.
