# Exchange create and delete sync changes are idempotent by remote item ID

The historical EWS client avoided duplicate creation after a partial-sync retry by looking up the remote item ID. A successful null header return was an explicit no-op at that old C++/Rust boundary; do not reinterpret Err(NS_OK) as a general Rust success/error convention. Current ExchangeMessageSync checks for an existing ID before AddMsgHdr and returns NS_OK when it is already present. A delete change also succeeds if that remote ID was already deleted locally. Preserve the idempotent behavior when changing sync retries. Lookup operations that require a header have different contracts: GetHdrForExchangeId returns NS_ERROR_NOT_AVAILABLE when absent. No replay or server test was run.

Scope: exchange.
