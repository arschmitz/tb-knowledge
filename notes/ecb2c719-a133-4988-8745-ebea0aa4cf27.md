# Queued occurrence identity changes preserve backend recurrence rules

`shiftRecurrenceId`, `CalendarEventEdit.sys.mjs:44–119`, was read through every
branch. It converts the string native time to a Calendar date, sets all-day state
from the old series start, and reads the old series timezone and recurrence set.
The actual class/interface checks identify explicit recurrence dates; the
exception lookup identifies edited occurrences.

An explicit date or exception shifts by the difference between UTC series starts.
This preserves the backend's elapsed-time shift. A rule-generated occurrence
instead computes the change between floating local starts, applies that to the
new timezone, and carries the new all-day state. These operations differ across
a daylight-saving transition.

The rule branch asks the new recurrence set whether the shifted occurrence
exists in a one-day all-day window or one-second timed window. If it does not,
the helper finds the old occurrence's position and walks the new recurrence set
to that position. It uses the new start if it is an actual occurrence, otherwise
the next occurrence after a one-second-earlier cursor. Missing old position or
missing replacement leaves the computed shifted date in place. The returned
value is `String(date.nativeTime)`.

The owner is `queueCalendarEventEdit:147–175`. Save requests recurrence shifting
only after `transact` resolves and only for a whole-series start-date change,
`calendar-event-edit-save.mjs:142–150`. The callback stores old/new event objects
locally. The queue updates only pending occurrence routes whose aliases lead to
the saved calendar. Routes for unrelated copies or a whole series with no
recurrence ID are skipped. The updated saved identity reflects the current
request's occurrence route.

Direct assertions read in `test_calendarEventEditSave.js`:

- `test_queuedOccurrencesFollowWholeSeriesShifts`, 1088–1206, checks queued edits
  for the same and another occurrence, both with and without a calendar move,
  stored titles/dates, and undo history.
- `test_queuedSeriesEditsKeepLocalTimeAcrossDaylightSaving`, 1208–1313, uses
  `America/New_York` around November 2026. It separately checks rule, exception,
  and explicit-date routes: rule stays at 09:00; exception/date routes become
  10:00 under the elapsed-time backend shift. It checks returned occurrence IDs.
- `test_queuedWeeklyOccurrenceFollowsUpdatedRule`, 1315–1395, shifts the parent
  from Monday to Tuesday while the rule remains Monday. It checks that the queued
  Monday stays Monday, its exception title, the next Monday, and reversal.

The helper's local algorithm is checked. Full internals of `CalRecurrenceInfo`,
date/time classes, timezone data, every recurrence rule, all-day edge cases,
and the missing-position/replacement branches remain separate verification work.
No claim that every recurrence pattern is correct follows from these examples.
