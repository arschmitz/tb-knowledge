# Calendar preference migration keeps bignum encoding before typed storage

The typed reader chooses a Services.prefs getter, returns null for an absent preference and decodes valid bignum strings. The writer first encodes fractional or out-of-range primitive numbers, clears the prior user preference to permit type changes, then uses constructor-name dispatch for string/int/bool storage. Null and undefined delete without setting. Existing tests recreate calendars before reads to avoid the property cache and directly check large/fractional round trips, a type change and removal. These are read assertions, with missing messages preserved as a test finding; no runtime or upstream policy-helper result is supplied.

Scope: Calendar manager persisted property access.
