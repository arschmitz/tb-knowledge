# Replace the future-notification timer before recomputing candidates

The existing next-start scheduling lesson is reused. Current _scheduleNotification clears its prior timer, chooses the earliest future start_at, and clears the handle before asking the manager to update again. The timer wakes candidate filtering; it does not directly display its selected raw notification. Filtering still rejects malformed or out-of-window dates, subject to the explicit bypass preference. No automatic expiration timer is established by this function. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: In-app notification timer ownership.
