# Keep DAV OAuth migration identity distinct from old opaque login origins

Current CalDavSession takes a username and CalDavCalendar supplies username or calendar ID. The OAuth browser tests cover legacy oauth:id origins, ID-keyed tokens and username-keyed tokens; the backend helper explicitly accounts for legacy origin normalization. Do not interpret the migration as silently reusing every old opaque-origin token. The historical commit says some users may need reauthentication; current source and tests support the credential identity boundaries, not a measured affected-user count. This is static source evidence. No runtime, build or live accessibility validation was run. Full bug and review discussion remains pending.

Scope: CalDAV OAuth migration identities.
