# Reject unsafe changes to synced object identity while updating mutable fields

The 2024 stores refuse to change a calendar type or URL, a CardDAV book type or URL, an identity incoming-server link, and a mail server type during update. They update allowed display names, credentials, host settings, or username fields in their own paths. Tests use Assert.rejects for these forbidden transitions and assert mutable fields separately. Treat such changes as replacement or explicit migration work; simply assigning fields in an update risks changing what local object a Sync record represents. Verify current component behavior before applying this historical rule.

Scope: Thunderbird Sync object identity.
