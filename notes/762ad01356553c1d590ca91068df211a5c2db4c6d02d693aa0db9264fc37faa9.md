# The initial account-removal completion does not await the last login deletion

The original removeAccount function awaits searchLoginsAsync but calls removeLoginAsync without awaiting or returning its Promise. The dialog waits for removeAccount before re-enabling its accept button, so that boundary does not include completion or rejection of the final login deletion. The fixed accepted implementation awaits removeLoginAsync within the same try/catch. This is a historical-versus-accepted source distinction; no race, deletion failure, test result or runtime cure was reproduced, and earlier resource removals are not rolled back by that catch.

Scope: Related-item removal Promise and dialog completion.
