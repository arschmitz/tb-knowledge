# Ingestion calibration: full console search reached its memory limit

During the 2026-10-13 capacity calibration, a fresh standalone knowledge store
imported and retrieved all 15 contribution notes. A separate run against the
existing local library aborted with exit code 134 and a Node.js heap allocation
failure near 3,967 MB. The environment was Darwin arm64 and Node.js v26.3.1.
The first store insertion completed before search. This is an observed failure
of that run, not a claim that all console queries fail.

## Relevant source and diagnostic limit

The published store at revision `20e7a5d4db5d6d188fbf351dbf445d86755372a8`
loads every record body in a repository and parses each JSON body in
`commands/knowledge/store.mjs:113-116`. Its search path at lines187-193 passes
`store.all(repository)` into `claimGroups` when the cached record count changes.
The current local working source has additional changes and the same full-load
operation; its exact content hash is in metadata. The published revision is
supporting source evidence, not a claim that the run used an unchanged checkout.

Exact published expression:

```
cached = { count, ...claimGroups(store.all(repository)) };
```

The observed native stack includes JSON parsing and ArrayMap. That and the source
make full-record loading a plausible contributor. No allocation profile proved
the exact failing object. No source fix or successful full-search rerun occurred
in this calibration. No test of a fix ran.

## Usable fallback and remaining gap

The same `store.put` API can import the contribution without calling full search.
The existing `exactSectionHits` helper can check indexed source sections with a
bounded result limit. This checks local presence and exact candidate retrieval;
it does not check final claim grouping, conflicting claims, supersession,
semantic search, or the console UI. Do not label that fallback a successful full
console search. A clean contribution-only reader also does not validate a full
historical-library rebuild.

The ordinary immutable Markdown notes remain readable with file tools and Git.
This record adds a calibration limit. It does not change retrieval rules or
project instructions.
