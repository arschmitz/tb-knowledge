# The Account Hub event-constructor change still exercises the click path

The 52bd18ab83492f0a8aad47815b8fb566c0c2439d patch changes new MouseEvent to new PointerEvent in test_localAddressBookForwardEventAndCreation. Its event type remains click and its caller remains EventUtils.sendMouseEvent. AccountHubFooter listens for click and dispatches forward; the test waits for that event and checks directoryNameExists(test). These assertions cover a synthetic forward path, not keyboard input. At separately pinned Gecko revision 00aad09a820405643aebd693e60a3333ccf04544, sendMouseEvent rebuilds an event from its properties and chooses PointerEvent for click. That helper has no verified pairing with either comm revision, so the supplied constructor alone does not prove this historical dispatch behavior. Full bug/review context is pending. No test ran.

Scope: Account Hub local-address-book synthetic forward event.
