# Places batches await members but standalone transaction bodies bypass the queue

Each section is a checked body contract at Firefox revision `1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b`. These records describe source behavior. They do not promote source patterns into coding policy.

## PlacesTransactions.batch

Evidence: [PlacesTransactions.batch:314-354](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/toolkit/components/places/PlacesTransactions.sys.mjs#L314-L354).

Trigger: UI or other consumer submits a nonempty transaction/function array.

Validates every element before enqueue. Invokes functions with the accumulated result array; awaits each returned transaction in order. Catches each member failure, logs it, appends undefined and continues. Uses original result index as batchIndex.

Result and completion: Resolves to an array of values or undefined slots. Dependent function members consume previous values; a batch is not an atomic rollback operation.

Errors: Invalid array/elements throw before queueing. Per-member failures are swallowed and recorded as undefined. Queue timeout can still reject.

Ownership and cleanup: Uses the enclosing module or object state; this body does not release that owner.

## Enqueuer.enqueue

Evidence: [Enqueuer.enqueue:487-511](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/toolkit/components/places/PlacesTransactions.sys.mjs#L487-L511).

Trigger: batch, undo, redo or clearTransactionsHistory queues a task.

Creates a four-minute rejection timer immediately at enqueue. Chains execution behind the previous internal promise, then races func() against that timeout. Stores a catch-logged version internally so one rejection does not block later tasks.

Result and completion: Returns the uncaught mirrored/raced promise to the caller. The timeout does not cancel underlying work or its timer.

Errors: Caller gets task failure or timeout rejection. Internal catch logs and allows the next queue job.

Ownership and cleanup: The queue owns its promise chain. setTimeout does not return or retain a cancellation handle. The timer starts before prior queue work completes.

Unresolved: Actual nsITimer ownership and timeout timing were not run. Work still pending after timeout can overlap later queued work; this is a source-supported possibility, not a native timing reproduction.

## TransactionsManager.transact

Evidence: [TransactionsManager.transact:539-570](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/toolkit/components/places/PlacesTransactions.sys.mjs#L539-L570).

Trigger: Proxy transact is invoked.

Gets raw transaction identity; synchronously rejects unexpected or reused objects. Marks raw object as executed before starting it. Calls raw execute immediately and awaits it, then adds history and updates active-window commands. Does not call _mainEnqueuer.

Result and completion: Resolves to the raw execute value. Two standalone transactions can start before either finishes; batch provides ordered awaiting within its queued task.

Errors: Execution rejection leaves history unchanged for that transaction, but cannot undo effects already performed inside execute. Reuse still throws on future calls.

Ownership and cleanup: WeakSet remembers reuse while the raw transaction is reachable. History retains successful transaction closures until entries are removed.

Unresolved: Native database wrappers may serialize individual storage operations; this does not establish serialization of whole standalone transaction bodies.

## TransactionsManager.undo

Evidence: [TransactionsManager.undo:579-602](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/toolkit/components/places/PlacesTransactions.sys.mjs#L579-L602).

Trigger: Public PlacesTransactions.undo or UI cmd_undo.

Queues a task that reads the top undo entry at execution time. Awaits raw undo methods in stored reverse commit order. On a member failure logs, clears undo history and returns. On full success advances undoPosition and updates commands.

Result and completion: No item value; resolves after the undo task. Already completed members are not automatically rolled back on later failure.

Errors: Member failure is swallowed. Queue/task infrastructure failure or timeout can reject despite the public comment saying always resolves.

Ownership and cleanup: Uses the enclosing module or object state; this body does not release that owner.

## TransactionsManager.redo

Trigger: Public PlacesTransactions.redo or UI cmd_redo.

Queues a task, reads top redo entry at execution time, then walks it backwards. Uses raw redo if present, otherwise execute. Failure logs and clears redo entries; success decrements undoPosition and updates commands.

Result and completion: Resolves after redo task with no item value. Already redone members remain changed on a later failure.

Errors: Member failure is swallowed; queue/task infrastructure failure or timeout can reject.
