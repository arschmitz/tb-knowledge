# The null-root import return bypasses normal completion bookkeeping

If ImportMailThread is entered with no destRoot, the guard logs and returns before the normal SetLogs and ThreadDelete calls. threadAlive starts true and GetProgress uses it to distinguish completion. The inspected BeginImport caller already rejects a missing destination before copying it into destRoot and making the direct call. This is a conditional static bookkeeping gap, not an established reachable hang, leak or crash cause.

Scope: Mail import defensive entry guard.
