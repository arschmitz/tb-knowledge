# Resetting message headers replaces attachmentName to drop old attachment handlers

External attachment setup adds mouseover and focus listeners that capture firstAttachment.displayUrl. Reusing attachmentName across messages previously kept old handlers and could display the detached attachment URL from an earlier message. ClearCurrentHeaders replaces the node with its clone, clears attachment data and empties the attachment list. The inspected displayMessage caller performs this reset after setting gMessageURI. The original fix removed duplicate resets; its review accepted this workaround without new state. Current QuickLook cleanup is a later detail. The bug reports Daily/Beta verification and no automated coverage; this study ran no hover, focus, native or timing test.

Scope: Message attachment header lifecycle.
