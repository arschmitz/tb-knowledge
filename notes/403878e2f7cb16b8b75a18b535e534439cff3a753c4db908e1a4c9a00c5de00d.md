# Make hostname certificate errors actionable through an explicit exception dialog

570 sets canMakeException for ERROR_DOMAIN, so a certificate that is valid for another hostname can open the exception dialog from the notification. It matches the existing time and trust categories; other error categories remain non-actionable. The dialog receives securityInfo, prefetchCert and asciiHostPort and records a later exception only if params.exceptionAdded is true. This is explicit user action, not automatic certificate trust. The historical TLS test expectations were read; no live TLS override or security UI test was run.

Scope: Certificate notification behavior.
