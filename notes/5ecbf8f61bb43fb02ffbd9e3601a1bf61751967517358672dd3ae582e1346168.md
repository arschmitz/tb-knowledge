# Name row-only filter actions separately from provider filtering

The renamed applyFiltering/clearFiltering API operates on cached #allRows and replaces the displayed _rowMap. Its documentation says it does not reach into actual calendars and points to calFilter.filterItems for base data filtering. It clears the selection after a filter change; current tests assert the previously selected first row does not transfer to the new first visible item. Insertion/sort selection preservation is a separate existing lesson. Scoped naming rule: action names and comments must identify which layer is filtered.

Scope: calendar/base/content.
