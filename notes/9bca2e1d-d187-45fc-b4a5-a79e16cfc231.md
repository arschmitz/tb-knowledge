# Compose encryption setters validate support and mark explicit choices as user-touched

setComposeDetails rejects unsupported OpenPGP or S/MIME choices, subject encryption without body encryption, and S/MIME signing/encryption without the required configured capability. Once an add-on supplies selectedEncryptionTechnology, the setter marks send/sign and OpenPGP subject choices as user-touched before toggling via onEncryptionChoice, so asynchronous defaults cannot overwrite them. Review dropped a separate S/MIME subject-encryption branch because the schema excludes that property. Current setter retains these checks. Keep schema validation and runtime capability checks distinct.

Scope: Compose encryption setter.
