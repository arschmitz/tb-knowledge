# Calendar add completion starts scheduling; it does not prove message delivery

Scope: Thunderbird Calendar privileged modules. This adds the missing completion detail to the create Save and transaction chain.

`saveCalendarEventCreate()` awaits its supplied transaction. Host `doTransaction()` awaits manager `commit()`. `CalAddTransaction.doTransaction()` awaits provider `addItem()`, then calls `_dispatch()` and stores the returned item. `_dispatch()` calls `cal.itip.checkAndSend()` without an await.

`checkAndSend()` chooses the current-user attendee only for an incoming invitation, constructs `CalItipMessageSender`, builds messages, and calls its `send()` method. The source gives the attendee reason: supplying the current user as an invited attendee marks the operation as an incoming invitation, so the organizer must not be supplied that way.

`CalItipMessageSender.send()` uses `every()` on pending messages. Each `CalItipOutgoingMessage.send()` can leave notification to a scheduling-capable provider, return false when recipients or transport are absent, or call `transport.sendItems()`. These are synchronous call and Boolean-result paths in the read code. The provider or transport implementation controls the next work. The add transaction does not await a remote recipient acknowledgment.

The checked result is therefore provider add completion plus scheduling initiation through this caller path. It does not establish delivery to each attendee. Failure while the synchronous dispatch runs can still reject the transaction; later transport failure handling is a separate unresolved path.

Direct test link: `test_createSelectedCalendarAndUndoRedo` checks local memory storage, observer notifications, and undo/redo. Its helper passes `responseMode: NONE`. The test exercises the add transaction but does not directly check outgoing delivery. A same-name send test is only a possible link until its transport, recipients, and assertions are checked.

Change impact: provider completion, undo history, invitation classification, recipient generation, provider scheduling, and mail transport. Both local storage and message-send failure paths need their own tests.
