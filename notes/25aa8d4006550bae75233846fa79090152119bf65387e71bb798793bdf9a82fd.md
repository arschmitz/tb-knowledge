# userSortOrder is stored state, while sortOrder includes fallback behavior

The new stored userSortOrder key defaults to the unsigned NO_SORT_VALUE sentinel. GetSortOrder uses that sentinel to select the legacy special-folder order; otherwise it uses the user value. New folders retain natural ordering when no sibling has a manual value. The accepted UI updates both stored order and row metadata, and its insertion algorithm has later refinements beyond this landing. Preserve the stored key and distinguish it from the public effective sortOrder API when naming or refactoring. The patch adds no tests, and no persistence/restart/drag test ran.

Scope: Folder ordering state and names.
