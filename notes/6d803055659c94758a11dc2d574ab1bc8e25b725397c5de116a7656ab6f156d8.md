# Header customization preserves the toolbar row and lets the preference observer reload

Fresh full header patch and needed fixed container, preference listener and markup sections read. Leaving all-headers mode skips the from entry when hiding/removing prior rows; MsgHeaderEntry.enclosingRow is the closest message-header-row ancestor, which also owns toolbar controls. Other predefined rows hide and non-predefined rows are removed before the header table is rebuilt. for...in enumerates this header-entry table by name; it is not an action-array style example. toggleAllHeaders now only sets mail.show_headers. The historical aboutMessage preference observer independently calls AdjustHeaderView and timeoutReload, supporting removal of duplicate direct calls; fixed source retains that ownership. The bug includes Windows/Linux confirmations and a later unable-to-reproduce report. Review accepts the change but there is no added popup-state test or runtime proof of all panel lifetimes. No screenshot pixels or keyboard/accessibility behavior were inspected. This is a scoped DOM ownership/reload change, not a rule to skip hiding every sender header or every popup ancestor.

Scope: Message header customization panel lifetime.
