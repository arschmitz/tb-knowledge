# Store footer disabled state before deriving child control state

The current footer disabled setter updates #disabled before toggleForwardDisabled, and the getter returns that field. toggleForwardDisabled combines its argument with this.disabled. The historical setter used the back button’s old disabled state and updated it afterward. Retain the explicit state-first order in this footer so disabling and re-enabling do not depend on a stale child control. Its current component test asserts enabled → disabled → enabled. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Account Hub footer state derivation.
