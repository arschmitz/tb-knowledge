# Bug 2073142: Details used the message document to find the tab editor

## Finding

The reported error requires `calendar.item.editInTab=true` and an event that reaches the editable `modify` branch. The Details action used the first matching calendar item, then called `modifyEventWithDialog` in the message window. `openEventDialog` used `document.getElementById("tabmail")` in that same document. An `about:message` document has no `tabmail`, so calling `openTab` fails. True scheduling invitations and read-only items can instead reach the summary dialog branch, which sets `args.inTab=false`. The report describes Add changing to Details; do not assume every received event is a scheduling invitation.

## Regression history

The strongest source-based origin is Bug 1787094, review [D156262](https://phabricator.services.mozilla.com/D156262), Git commit `bbf4061b4193c7c5a0d747fa12bfc8aff71ddea9`. This patch enabled `mail.useNewMailTabs` by default and loaded `imip-bar.js` in `aboutMessage.xhtml`. Before this change, the normal main-window message pane and its invitation handler shared the document containing `tabmail`. The existing direct lookup was valid in that context.

A later partial fix, Bug 1834952, review [D179036](https://phabricator.services.mozilla.com/D179036), Git commit `8b86548bbcfcbb0bd8425f34ea0572a7f6f787b4`, Hg revision [210d86dcae05](https://hg.mozilla.org/comm-central/rev/210d86dcae05), added `calendar-item-editing.js` to `aboutMessage.xhtml`. This fixed the missing `modifyEventWithDialog` function. It exposed the null-tabmail error for tab editing. Thus Bug 1787094 caused the broken context, while Bug 1834952 exposed this exact TypeError after fixing the earlier ReferenceError. This is source attribution, not a binary regression range.

Bug 1860330, review [D191536](https://phabricator.services.mozilla.com/D191536), Git commit `1b35caf1988b9f9d5d1aa0c4a7a8ae8721b1ab09`, moved the handler to `calItipUtils.sys.mjs`. It retained the caller window through `aWindow.modifyEventWithDialog`; the earlier handler already made the same call in the message context. The module in the reported stack does not establish that this refactor caused the bug.

## Existing fix

Bug 2048214, review [D319211](https://phabricator.services.mozilla.com/D319211), Git commit `a7e5114f3e7261b893b1b622ce8348f6a1270713`, Hg revision [024bf2ce64ef](https://hg.mozilla.org/comm-central/rev/024bf2ce64ef), adds an early return for `X-SHOWDETAILS` and calls `cal.window.getCalendarWindow()?.openEventDialogForViewing(item)`. This uses the main calendar window and mode `view`. `openEventDialog` then selects the summary/read dialog and clears `args.inTab`. Bugzilla lists this fix for the 156 branch. Bug 2073142 lists version 155. This supports an already-fixed assessment for this exact Details stack on code containing the fix; it does not establish the reporter's exact build or a tested release.

At inspected Git revision `2135bbdeb7dd3feafb298c0220b412a66cc41826`, the direct lookup remains in `openEventDialog` for other callers. Do not claim that all message-context editing is fixed. In particular, counterproposal rescheduling still uses `aWindow.modifyEventWithDialog`.

## Validation and limits

An isolated Node VM experiment executed the actual extracted `openEventDialog` function from `bbf4061b419^`, `8b86548bbcf`, `a7e5114f3e7^`, and the inspected HEAD. Calendar and document services were stubbed. For all four revisions, an editable item in mode `modify` opened a calendar event tab when the document supplied `tabmail`; a message document without `tabmail` threw a TypeError reading `openTab` when tab editing was true; with tab editing false, it opened a dialog. An initial harness run lacked a calendar `getProperty` stub and failed before the tested branch; adding that stub produced the stated results.

Git history and exact source show the caller-context transition and later view-mode fix. No Thunderbird build, native browser test, real mail profile, or binary bisection ran. Regression attribution remains a strong source-based conclusion. No Bugzilla fields or comments were changed.
