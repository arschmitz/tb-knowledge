# Filter non-ASCII email identities before serializing mobile account data

Entry 1084 adds the ASCII email restriction both to default-account eligibility and to the identity list encoded by getAccountData. A secondary identity with a Unicode email is omitted while the ASCII default remains. Full display names are still serialized. The regex also rejects an empty email and permits all ASCII code points; it is not a complete RFC mailbox validator or a ban on Unicode names. This note is based on source inspection. Tests were not run, and full review discussion remains pending.

Scope: mail/modules/QRExport.sys.mjs.
