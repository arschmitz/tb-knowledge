# Keep an invalid copy-state error after rejecting assertion-only handling

D231154 proposes assertions for impossible source states. The author explicitly wants protection in non-debug builds and accepts NS_ERROR_UNEXPECTED instead. The actual landing and fixed handler retain unconditional error returns for a source that is neither file nor folder. This does not guarantee queue completion: the complete review also recognizes that OnCopyCompleted itself can fail for invalid source state, and author reports null source notification silently failing. Preserve the explicit guard and its limit rather than claiming that assertions or a Done flag solve the malformed-state route. No failure injection ran.

Scope: Exchange copy invalid-state failure contract.
