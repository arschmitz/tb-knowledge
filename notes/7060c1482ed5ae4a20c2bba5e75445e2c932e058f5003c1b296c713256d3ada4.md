# Return named cache decisions rather than an inverted success boolean

The historical updater init returns !didFetch, which its caller treats as a request to use stored notifications. The newer accepted init returns {loadFromCache, hasCache}; the controller destructures both and decides whether to use stored or offline defaults. For this multi-outcome API, named result fields make the decision contract clear. Do not infer that a successful fetch also completed durable disk writes.

Scope: Notification updater result syntax.
