# The first Panorama message API was explicitly temporary

The 1612 commit says the stub enables development in other areas. Its messages interface, native notification signature and small insert/remove test are historical preparation. The fixed accepted API is messageDB, takes folderId and richer message fields, and is integrated with an nsIMsgDBHdr-compatible message object. Current tests create a local folder and add a generated message through the folder API. Use the current interface when implementing callers; the old stub is not a stable production contract or evidence of complete migration coverage. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Panorama historical message API.
