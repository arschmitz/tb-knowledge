# Preserve string preference fallback and default clearing

The native server string getter falls back to its default branch; the JS implementation uses an empty-string fallback. Both setters clear the user preference for an empty value or a value equal to the default. Preserve these absence/default semantics when editing the UTF-8 accessor migration. The native getter returns NS_OK after its fallback without propagating that fallback result, so it is not a general proof that every read succeeded. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check was run.

Scope: mailnews/base/src.
