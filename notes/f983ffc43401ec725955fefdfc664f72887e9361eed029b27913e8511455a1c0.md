# Register persistent provider listeners in top-level startup code

The implementation distinguishes starting, running, suspending and stopped phases. Current MV3 test registers its persistent listener before the first await and adds/removes a dummy non-persistent listener later. An async callback body is allowed; the registration timing determines persistence. Follow that boundary for this provider rather than assuming all listeners in an async background function are persistent. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Extension provider registration timing.
