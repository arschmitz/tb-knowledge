# Keep the raw XPCOM signature separate from the borrowed Rust callback

D227880 removes an unnecessary &RefPtr callback parameter from the inner Rust method; the actual xpcom_method declaration still uses a raw interface pointer. The inner method receives &IEwsDeleteFolderCallbacks, then creates a RefPtr for detached asynchronous work. These are distinct interface and lifetime boundaries. Do not remove the raw macro signature or the owned pointer needed by work that outlives the call based on the borrowed inner signature. The actual landing has .detach(); a rendered proposal typo is not executable proof. No macro expansion, Rust build or callback runtime test ran.
