# ICS autodetection tries content, DAV, conditional PUT and local file permission paths

CalICSProvider:45–121 resolves location, owns an ICSDetector and its password-site
session, then awaits HEAD, GET, DAV location, conditional PUT and local-file probes
in that order. Detection/auth/cert errors stop; other failures log and continue.
It imports actual CalDAV request classes for HTTP/DAV reuse, not the CalDAV
calendar implementation. Like CalDAV, it calls locationToUri(location) without
username; callers prepare location first in the checked UI chains.

ICSDetectionSession:129–238 owns generated session ID, username, password, save
flag and authorized sites. promptAuth supplies credentials only for an allowed
site and no PREVIOUS_FAILED flag, optionally saves/removes them. Its timer calls
auth available/canceled without returning a cancel handle. prepareRequest and
completeRequest are empty here; it does not use the CalDavSession OAuth setup.
The detector constructor passes all four current session parameters correctly.

_attemptMethod:307–350 accepts successful response if content type includes
calendar/ICS, content disposition suggests .ics or text contains BEGIN:VCALENDAR.
This recognizes content; it does not fully parse/validate every ICS item.
For302/307 it retains original URI; other redirects use final URI. HEAD/GET
getters bind method with correct detector receiver. DAV location:263–297 checks
calendar type or text/calendar, and follows collections to Depth1 directory scan.
Directory entries require exact text/calendar, unlike the broader header check.

attemptPut:368–392 sends PUT with If-Match:nothing and treats conflict as a writable
calendar indication; it is not proof that a valid calendar already exists.
attemptLocalFile:405–432 checks parent exists, builds calendar, stats existing
file or parent and sets readOnly using (permissions ^ 0o200)==0. This is an exact
XOR-equality check rather than a general owner-write-bit check. Source effect is
recorded; no local permission product test was run. handleCalendar:465–482 derives
name/color and optional DAV privileges and returns an unregistered object.

Direct unit tests77–96 verify ordinary/302 original URI;98–121 verify password
sent to same site and absent on a different site. Browser ICS test15–42 uses
openWizard helper to check the authenticated calendar URI/name. These source
assertions do not cover malformed ICS acceptance, probe PUT failure/cancel,
all redirects, parent permissions or registration. No test was run here.
ICSServer implementation is reused from the earlier fixture body study.
