# The JavaScript password module waits synchronously and keeps cache state separate from lookup results

Additive scope correction to lesson 83913ac39282748461bfd3a80feedc4f61eab35d57a069a72623b42165f6cd59: the accepted JavaScript implementation uses async login-manager methods internally, but its XPCOM query and forget methods stay synchronous and spin the event loop until internal work finishes. Native callers do not receive a Promise. A manager lookup miss also does not clear an existing cache: the internal async method returns an empty string, while the public wrapper returns #cachedPassword. The owned native version similarly empties only its return argument on a miss. The IDL's empty-cache wording therefore needs this source limit; explicit forgetting clears the cache. No runtime responsiveness, rejection, account-isolation or stale-cache result was measured.

Scope: Shared password module interface and cache.
