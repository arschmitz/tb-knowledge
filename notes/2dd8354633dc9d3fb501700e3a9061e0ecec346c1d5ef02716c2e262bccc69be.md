# Prefer explicit provider and value names over overloaded Auth in new Rust APIs

D210712 required Auth and related fields to describe their role; it landed Credentials and AuthenticationProvider. Current shared AuthenticationProvider still expresses a provider role, while the old Credentials enum has been replaced. Proposed naming rule: say whether the type stores credentials, supplies authentication details, or performs an operation. Do not impose the historical type name on a different current responsibility.

Scope: rust/ews_xpcom/src.
