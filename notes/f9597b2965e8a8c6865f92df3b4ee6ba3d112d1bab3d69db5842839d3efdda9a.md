# Validate folder type and server identity before reporting remote creation success

The current EWS create-folder response must contain an ordinary Folder with a folder_id. After checking the returned folder-object count, code rejects an absent ID or an unexpected type before producing the success argument. Keep these protocol type and identity checks before local creation in this operation. A successfully decoded SOAP body alone does not prove a usable created-folder identity. This is static source evidence for this operation, not a project-wide rule. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: EWS create-folder validation.
