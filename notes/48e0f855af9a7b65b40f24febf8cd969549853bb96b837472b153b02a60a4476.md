# A dependent spellcheck dialog requires an explicit send-completion wait

The original modal-to-dependent change lets the compose window repaint, but its send caller immediately checks cancelSendMessage after openDialog returns. The fixed caller first waits for the dialog load when needed, then waits for unload, and only then reads cancellation. The visible bug reports a spell-before-send regression and links Bug 1974125; its comment8 and this patch review remain unread. The exact original and fixed callers support the completion-contract difference without proving the upstream repaint mechanism. No message was sent and no native dialog test ran.

Scope: Compose spellcheck completion contract.
