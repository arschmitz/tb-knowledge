# Use the actual property bag interface and carry its dependent uplift

dBTransferInfo is an nsIPropertyBag2 snapshot, not an nsIDBFolderInfo database object. The old misleading interface allowed JS property access that could crash. Current repair queries nsIWritablePropertyBag2 before editing reset properties. If uplifting that consumer, carry the interface change too; the later ESR repair fix failed without Bug 1904799. Current IDL and C++ transfer implementation support this boundary; later review/bug1904799 itself was not newly browsed.

Scope: folder-repair.
