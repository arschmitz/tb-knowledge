# Use completion signals for current async adapter tests

Current adapter tests await the tree invalidation after loading and detach the adapter in finally. Native completion flushes the remaining selected chunk, then resolves the Promise; cancel and error paths reject it. Keep test readiness tied to those signals. Constructor return is not proof that async rows are available, and completion ends are inclusive in the inspected chunk callback. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Panorama async test readiness.
