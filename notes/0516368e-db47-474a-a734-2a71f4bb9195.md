# Cached Calendar adds wait for cache completion and preserve observer order

## The add path

The cached facade presents one calendar while coordinating an uncached provider and a local cache. `addItem(item)` clones the item and calls `adoptItem()`. `adoptItem()` turns the completion callback from `doAdoptItem()` into a promise: it resolves with the result item or rejects with a component exception.

When offline, `doAdoptItem()` calls `adoptOfflineItem()` and waits for its success or failure. When online, it sets the uncached provider's `_cachedAdoptItemCallback` and starts the provider's `adoptItem()`.

The injected callback treats an unavailable server as offline and stores the item through `adoptOfflineItem()`. On remote success, it awaits `mCachedCalendar.addItem(detail)` before notifying success. Other results are forwarded to the listener.

## Why completion cannot be moved earlier

The implementation explains that generic provider observer order is not enough. If completion runs before the cache mutation, callers can observe a successful operation while cached data is still old. It also needs the cached calendar's `onAddItem` event to occur before the uncached provider ends its batch.

In `CalDavCalendar.adoptItem()`, the provider takes `_cachedAdoptItemCallback`, clears the slot, and invokes `doAdoptItem()` on a clone. Its operation-complete listener awaits the taken callback before resolving or rejecting the provider promise. Clearing the slot makes the callback apply to one operation.

The facade also keeps `callbackRan`. Its rejection handler does nothing when the provider already called the injected callback. Without that guard, a provider failure could be completed twice.

## Scope and limits

This traces the add path between the facade and CalDAV. It does not prove every provider uses the same callback contract. Modify and delete have separate paths and need their own checks. Failure in an awaited callback, concurrent operations on one provider, and later offline replay need focused tests before changing this code. No new defect is asserted here.
