# Batch compaction reports the first recorded failure after all folders finish

BatchCompactor moves immediate and asynchronous failures into mFailed and stores matching codes in mFailedCodes. It continues the queue, adds recovered bytes only for successful folders, and waits for retry work to finish before notifying mFinalListener. It logs every failure but uses only mFailed[0] and mFailedCodes[0] for the alert and final status. The first recorded failure can therefore differ from the first input folder when an earlier folder was delayed. The equal-length assertion is the local contract that keeps the two arrays aligned. Keep that pairing when adding failure paths; do not assume a failure aborts all later folder work. Static source and test inspection only.
