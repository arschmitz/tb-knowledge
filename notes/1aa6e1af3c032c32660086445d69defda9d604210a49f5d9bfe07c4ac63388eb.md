# Trace the final assignment after appending an OAuth scope

The historical 756 _ewsifyConfig appends an EWS grant to config.incoming.oauthSettings.scope and then assigns scope from the provider on the next line, overwriting the appended value. This is a statically visible lost write; no authentication failure or review diagnosis is inferred. The newer accepted FindConfig no longer uses that sequence and protocol-specific provider scopes handle the separation. Proposed manual review rule: read the whole mutation branch and its final value, not only the line that appears to add the required permission.

Scope: OAuth configuration mutation order.
