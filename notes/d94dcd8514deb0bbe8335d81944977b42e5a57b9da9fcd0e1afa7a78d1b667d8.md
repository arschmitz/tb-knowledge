# The forwarding merge decodes separately stored body pieces before joining their text

This landing stores eligible later unnamed inline text-body pieces separately, passes each piece’s content type into decoding, and joins the results rather than appending differently encoded bytes into one file first. An explicit charset override still takes precedence. Both success and abort release the added temp parts. The helper may retain raw bytes when no charset is found or UTF-8 replacement allocation fails, so its UTF-8 summary is not an unconditional result contract. The added fake-SMTP mixed-charset test was inspected, not run; it does not establish every MIME, decoder or failure-path outcome.

Scope: MIME inline-forward body assembly.
