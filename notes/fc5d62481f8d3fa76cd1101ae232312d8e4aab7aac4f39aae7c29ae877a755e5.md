# Distinguish output omission from an undefined value in API tests

Current MV3 compose conversion adds additionalFccFolderId only for a valid extra folder ID, and overrideDefaultFccFolderId only when an override exists. accountsRead also gates these fields. The test compares state.property with an expected value; that cannot distinguish a missing property from an own property whose value is undefined. The native helper checks ownership of expected keys with hasOwnProperty, which controls which native assertions run, but does not check ownership on the returned API object. Proposed test guidance for this output contract: assert key presence separately when omission matters, and include a missing-permission case. These checks were not added or run; the existing FCC test grants accountsRead and proves no negative permission case.

Scope: mail/components/extensions.
