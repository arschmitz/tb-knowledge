# Return no URI for an incomplete SMTP server so one bad entry cannot break every consumer

createServer persists a new key before account setup fills its hostname. An interrupted setup can leave a server with a username or port but no hostname; smtp://user@ and smtp://:587 are invalid URIs. After Bug 1882574 moved consumers to nsIURI.host and port, one such entry could throw NS_ERROR_MALFORMED_URI while Account Hub checked all servers, and also break identity and outgoing-server settings. Bug 2069949 changed SmtpServer.serverURI to return null for no hostname or unparseable URI, documented null in the interface, and made consumers show an unspecified value. Preserve the ability to list, edit and delete broken persisted entries. This fix is present in the current checkout; EWS and Graph incomplete-server handling was a separate Bug 2067724.

Scope: Outgoing server recovery.
