# RunnablePrompter.run behavior in mailnews/base/src/MsgAsyncPrompter.sys.mjs

Waits for login initialization, gets the current keyed queue entry, then awaits its first listener. A caught listener failure logs and calls first.onPromptCanceled. It deletes the entry before notifying each additional consumer. Truthy auth result calls onPromptAuthAvailable; false calls onPromptCanceled. Each consumer has its own catch so later consumers still run. It then decrements active count and dispatches the next eligible prompt. The first listener must handle its own successful result; it does not receive the consumer success callback here.

## Calls and triggers

- Own #promiseAuthPrompt; actual first and consumer callback receivers are queue listener objects. OAuth2 and Calendar supplied objects inspected. Calls owning doAsyncAuthPrompt after decrement.

## Result and consumers

Normally resolves undefined after consumer fan-out and next dispatch, not after completion of the next prompt. Native thread dispatch's handling of returned Promise was not traced.

## Errors

Initialization rejection occurs outside try. first.onPromptCanceled can itself throw inside catch and skip deletion/decrement. Consumer exceptions are isolated. No finally protects active count against earlier failures.

## Async completion

Native dispatch triggers async run; initialization then auth callback are awaited. No runner cancellation API. OAuth2 caller cancels underlying authorization and eventually signals false.

## Ownership and cleanup

Owner retains entry/listeners until deletion; local prompter retains them through fan-out. Runnable retains owner; no explicit field clear. Failed early paths can leave queue/count intact.
