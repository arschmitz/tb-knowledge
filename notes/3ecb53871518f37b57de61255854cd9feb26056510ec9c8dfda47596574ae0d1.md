# Migration part validation follows the returned log order

The owned change removes reversal before part-number validation, and accepted code expects part n + 1 at the same returned message index. RepoClient's Git branch requests subject lines without --reverse, while the migration tool increments part numbers before each nonempty snapshot commit. For multiple ascending-numbered commits returned newest first, those contracts can disagree. This is a conditional static order mismatch; no migration run or universal recipe fix is established. The earlier reversal lesson remains a historical phase.

Scope: Thunderbird Fluent migration commit validation.
