# Exchange canceled getter during download and empty reason semantics

Proposed investigation from current source: GetCanceled dereferences mReadRequest without the download-phase guards used by Cancel/Suspend/Resume, then returns canceledReason.IsEmpty(). The separately read Gecko interface says true if canceled; its base implementation uses mCanceled. No call sequence/crash reproduced. Follow up with supported pre-read states and actual canceledReason ownership before changing behavior.
