# Current folder compaction stages a database rather than using the Part 1 live-database strategy

The assigned Part 1 callback commits mDB and can restore a backup when that callback fails. The frozen accepted FolderCompactor first closes the original database, copies it to a staged path and opens that path with no attached listeners. It later installs that staged database in the abortable commit callback. Scoped history/architecture lesson: the original database strategy is historical; it should not be taught as the current contract simply because the Part 1 diff landed. Current staging is comparison context and does not claim full chronology of the later Part 2 change. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: folder compaction historical versus staged database strategy.
