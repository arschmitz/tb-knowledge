# Gecko statement finalization shares cleanup with the asynchronous connection close path

## Directly observed release paths

Explicit `AsyncStatement::Finalize` sets `mFinalized`, asks the shared base to
finalize asynchronously, and clears the JavaScript parameter holder. Repeated
explicit finalize succeeds without repeating the work. The async statement
remains strongly held by submitted `StatementData`, so dropping the caller's
reference does not destroy it while that request still owns it.
Evidence: [storage/mozStorageAsyncStatement.cpp:181–202](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageAsyncStatement.cpp#L181-L202) and [storage/mozStorageAsyncStatement.cpp:286–299](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageAsyncStatement.cpp#L286-L299).

`StorageBaseStatementInternal::asyncFinalize` dispatches an
`AsyncStatementFinalizer` to the helper target. That event retains both statement
and connection, finalizes the native async pointer on the helper thread, then
releases the statement back on the connection's opening target. If no target is
available or dispatch loses a close race, this path lets connection close own the
remaining cleanup. The destructor path uses a separate
`LastDitchSqliteStatementFinalizer` which owns the native pointer and retains the
connection until it can release that connection on its opening target.
Evidence: [storage/StorageBaseStatementInternal.cpp:19–150](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/StorageBaseStatementInternal.cpp#L19-L150).

Synchronous `Statement::internalFinalize` uses the connection's shared execution
mutex to avoid double-finalizing a native pointer that connection close already
owns. It clears its native pointer and parameter/row holders, and chooses explicit
async finalization or destructor finalization for a separate async pointer.
Evidence: [storage/mozStorageStatement.cpp:330–397](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatement.cpp#L330-L397).

## Connection close and state

`internalClose` marks `mConnectionClosed` before calling `sqlite3_close`. If SQLite
reports BUSY, it finalizes remaining native statements while holding the database
mutex, releases that mutex, and tries closing again. It warns/asserts about the
forced cleanup; this is a fallback, not permission for callers to skip finalizing.
Evidence: [storage/mozStorageConnection.cpp:1660–1736](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageConnection.cpp#L1660-L1736).

`AsyncCloseConnection::Run` first dispatches `shutdownAsyncThread` to the main
thread, then calls `internalClose` on the helper thread, then dispatches the
completion event. The main-thread shutdown method waits for the helper thread's
shutdown. The "closed" state flag is thus not by itself proof that physical close,
thread shutdown, and every consumer callback have all finished.
Evidence: [storage/mozStorageConnection.cpp:365–407](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageConnection.cpp#L365-L407) and [storage/mozStorageConnection.cpp:1651–1658](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageConnection.cpp#L1651-L1658).

## Direct test and actual run

`test_asyncClose_does_not_complete_before_statements` submits a statement, finalizes
its user-visible object immediately, awaits async close, and checks finished
statement completion. It directly covers that order of work. The file also checks
sync-opened close and failure to open; its no-callback case executes close without
being able to directly observe completion. It does not prove every fallback,
thread dispatch error, or forced SQLite BUSY cleanup branch.
Evidence: [storage/test/unit/test_connection_asyncClose.js:26–126](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/test/unit/test_connection_asyncClose.js#L26-L126).
