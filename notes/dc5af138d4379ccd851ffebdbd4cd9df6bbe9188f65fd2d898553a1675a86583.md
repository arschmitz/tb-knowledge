# Offline-read recovery happens after the wrapped stop callback in the actual source

In both inspected native versions, OnStopRequest first calls the underlying listener, closes and clears the channel, and then discards the failed offline copy. The ReadFromLocalCache comment describes intercepting and discarding before the underlying handler, which does not match that order. For this wrapper, recommend updating the comment to describe the actual callback order instead of using it as a sequencing guarantee. This is a static comment/source discrepancy and a scoped proposed documentation fix; no reentrancy or runtime failure was reproduced and reviewer disposition is unknown.

Scope: IMAP offline stream callback order.
