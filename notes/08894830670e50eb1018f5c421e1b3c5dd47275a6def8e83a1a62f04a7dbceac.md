# Name Panorama IDs and test files according to the current API

The accepted folder API uses explicit folderId, parentId and childIds meanings. Tests use numeric folder variables and expectedRelations fields such as folderId/rootId/parentId/descendantIds. This helps distinguish a database ID from a path or an nsIMsgFolder object after the original object API was removed. In this test family, files use test_relations.js, test_lookup.js and test_move.js, while task functions use testRelations, testLookup and testMoveToSameParent. Follow these local roles when adding tests; do not rename unrelated test families to make them uniform. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama ID and test naming.
