# Own async deletion inputs before detaching the Rust task

The Rust XPCOM deletion bridge clones ews_ids and wraps the listener before spawning and detaching moz_task. The C++ message listener clones its header array, and the folder callback captures a RefPtr to self. Retain owned inputs across these asynchronous boundaries instead of borrowing call-stack values. The immediate Ok(()) reports task scheduling, not successful remote deletion; success/failure arrives through the listener. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Exchange async input lifetime.
