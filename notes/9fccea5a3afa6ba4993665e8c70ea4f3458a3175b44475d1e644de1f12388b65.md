# The original Calendar retry lookup returns an object to Boolean consumers

The original async lookup retains a pre-existing recently-returned-password branch that resolves { found: false, username }. Its prompt wrappers consume the result by truthiness, so the object does not act as Boolean false. The fixed accepted request-scoped rejected-password branch returns false after deletion. Keep those phases and the stale Boolean-only JSDoc separate; this patch did not introduce the old object branch, and no retry or cancellation outcome was run.

Scope: Calendar authentication return contract phases.
