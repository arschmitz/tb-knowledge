# Storage provider registration packages concrete model owners and its localized name

## Directly observed build and receiver chain

The storage build file installs `CalStorageCalendar.sys.mjs` at the modules root
and helper/model/upgrade files under the Calendar module directory. It registers
`components.conf`. That component entry binds the storage-calendar contract ID
to the root module and `CalStorageCalendar` constructor. The constructor initializes
the provider base. The prototype lists calendar/provider/offline/scheduling/
sync-write interfaces for its QueryInterface and class information helpers.
Evidence: [calendar/providers/storage/moz.build:5–27](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/moz.build#L5-L27),
[calendar/providers/storage/components.conf:5–12](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/components.conf#L5-L12), and
[calendar/providers/storage/CalStorageCalendar.sys.mjs:5–43](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L5-L43).

Once URI and ID are both set, the relevant setter calls `prepareInitDB` only while
no wrapper exists. URI can only be set once. Preparation opens the wrapper and
calls `upgradeDB`; its after-upgrade callback initializes statements and registers
the teardown observer. Initialization selects WAL journaling and a 10 MiB SQLite
cache, constructs statements, then constructs cached-item, offline and metadata
models. Errors in this initialization block are logged rather than rethrown there.
Evidence: [calendar/providers/storage/CalStorageCalendar.sys.mjs:119–174](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L119-L174) and [calendar/providers/storage/CalStorageCalendar.sys.mjs:490–519](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L490-L519).

The actual model factory switch imports and instantiates `CalStorageItemModel`,
`CalStorageCachedItemModel`, `CalStorageOfflineModel`, and `CalStorageMetaDataModel`
for their concrete type keys. Unknown keys throw. The shared base constructor
stores wrapper, statements, and Calendar owner on every model. Those models and
the Calendar therefore retain mutual object references while alive; garbage
collection and explicit teardown are separate from native connection use counting.
Evidence: [calendar/providers/storage/CalStorageModelFactory.sys.mjs:5–43](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageModelFactory.sys.mjs#L5-L43)
and [calendar/providers/storage/CalStorageModelBase.sys.mjs:11–38](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageModelBase.sys.mjs#L11-L38).

## Localization and native service boundary

The lazy localization object loads `calendar/calendar.ftl`. `displayName` consumes
`storage-name`; en-US defines it as `Local (SQLite)`. This is a checked consumer
link, not a name-only guess. Evidence: [calendar/providers/storage/CalStorageCalendar.sys.mjs:21–24](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L21-L24),
[calendar/providers/storage/CalStorageCalendar.sys.mjs:57–63](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/providers/storage/CalStorageCalendar.sys.mjs#L57-L63), and
[calendar/locales/en-US/calendar/calendar.ftl:411–416](https://github.com/thunderbird/thunderbird-desktop/blob/87d0159c7149a43253964c2cb6917939557dc799/calendar/locales/en-US/calendar/calendar.ftl#L411-L416).

Firefox's storage component registration names the `storage` service, its
`mozIStorageService` interface, and native `mozilla::storage::Service` singleton
constructor. The actual `OpenDatabase` implementation constructs a synchronous
connection that can also dispatch async operations. The word "async" in the
Calendar wrapper type therefore does not prove asynchronous database opening.
Evidence: [storage/build/components.conf:5–15](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/build/components.conf#L5-L15) and
[storage/mozStorageService.cpp:573–593](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageService.cpp#L573-L593).
