# Distinguish historical native password prefill from the IDL return signature and later implementation

The historical base GetPasswordWithUI reads the incoming value of aPassword to prefill PromptPassword, and IMAP OnPromptStart seeds the value from m_lastPasswordSent. The final IDL preserves an AString return with two explicit input arguments and documents that native callers may use that value as input; this does not give JavaScript the same extra input parameter. Review disagreement about whether to codify native behavior remains unresolved and is not a universal out-parameter rule. The fixed accepted base implementation now creates a fresh local password output for the password module and overwrites aPassword, without forwarding its incoming value. Therefore the retained documentation note does not establish current prefill behavior in that base implementation. Preserve old implementation, cross-language signature and later delegation as separate facts. No native/JavaScript prompt, password module or compatibility test ran.

Scope: incoming-server password prompt compatibility.
