# Keep ICS backup result handling separate from calendar write completion

The backup callback now receives status/result in its four-argument form, resolves when no source file exists, rejects other failed download statuses and awaits initial/daily copies before explicit resolve. #writeICS awaits the backup before starting the calendar write. These source stages are separate from successful disk output; rejected async-copy callback propagation was not traced and no I/O test ran. The reported historical interface mismatch and Daily/Beta verification remain attributed.

Scope: Keep ICS backup result handling separate from calendar write completion.
