# Exception lookup depends on recurrence date type and timezone

The D332891 verification record at revision dab61204576552c4e7a6bce2f010ccb2b87047c1 reports that reconstructing a recurrence ID through nativeTime lost date-only or floating-time form. CalRecurrenceInfo exception keys preserve those properties, so moved all-day and floating-time exceptions reportedly failed lookup while a UTC control loaded. For this loader, preserve the source date type and floating timezone before exception lookup, while retaining rejection of invalid recurrence IDs. The record describes execution with actual recurrence/date classes and controlled event/calendar objects; restoring those properties reportedly found both exceptions. No Thunderbird runtime test ran. The proposed fix was still being applied, with no completed amendment or acceptance recorded.

Scope: Calendar event source loader.
