# The drag/drop folder test waits for a destination lookup before using the moved folder

After endDrag finishes the input sequence, the test polls folderC.getChildNamed and assigns the resulting folderB before its row-order assertion. A single timer turn in endDrag is not that state condition. The predicate catches every exception and retries, so it does not distinguish all transient and unexpected failures. Successful lookup is narrower than an explicit backend-transaction completion signal. Accepted code later uses TestUtils for the same predicate. Existing affected-task assertions omit messages; no test or native drag was executed. The actual historical/base implementation returns null with NS_OK for a normal missing child; the test comment overstates that absence must throw.

Scope: Folder drag/drop browser-test completion.
