# The POP3 dirty-disconnect test checks a later service run with a new client

The test simulates one truncated UIDL reply, accepts any URL rejection, checks serverBusy, then awaits another retrieval. GetNewMail routes through withClient, whose factory creates a new client for each serialized run in both the owned and accepted phases. The second success therefore does not directly test reconnecting the same LineReader instance. The test also does not assert a specific interruption status or delivered-message count. Preserve those limits separately from the production reset and error-status changes.

Scope: POP3 recovery regression-test scope.
