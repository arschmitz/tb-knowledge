# Preserve UI event id/source contracts while obscuring add-on identity

The migration records an event object { id, source } rather than a separate keyed count per source. Current telemetryId collapses browser/display/compose action suffixes to one process-local addonN identity. Keep this obscuring when adding sources; do not send raw add-on IDs. Source strings such as message-compose and message-display are existing data values, not names to restyle to the underscore examples still found in YAML. Tests inspect event extras and repeated interactions, not pipeline output.

Scope: ui-telemetry.
