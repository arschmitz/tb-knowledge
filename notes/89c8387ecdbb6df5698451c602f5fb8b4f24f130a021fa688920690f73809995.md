# Return a valid config even when Exchange authentication fails

Current discovery waits for both result families with Promise.allSettled. If the ordinary autoconfig result is fulfilled, it returns that config and ignores the Exchange error. Only without an ordinary result can an Exchange rejection with a user-facing Fluent title become an actionable error. Tests cover both the authentication-required case and a valid ordinary config despite bad Exchange credentials. This supersedes treating every Exchange 401 as fatal to all account setup. This note is based on source inspection. Tests were not run, and full review discussion remains pending.

Scope: mail/components/accountcreation.
