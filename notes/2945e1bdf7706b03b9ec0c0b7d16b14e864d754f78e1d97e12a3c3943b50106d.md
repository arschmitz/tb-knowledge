# Compare a select control value when restoring the outgoing no-auth disabled state

The current outgoing authentication-change handler checks event.target.value == 1 before disabling username. The form disabled setter instead compares the select object itself with 1. This is a narrow static inconsistency: reenabling the form may not preserve the No Authentication username state through that setter. A scoped review recommendation is to compare the control value and test disable/reenable with No Authentication selected. No reproduction, binding coercion experiment or failure attribution to 1258 was established. This is source and test inspection only.
