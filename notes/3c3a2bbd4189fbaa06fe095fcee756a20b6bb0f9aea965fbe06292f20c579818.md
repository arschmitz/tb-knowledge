# Do not echo a remote folder deletion through the user-delete override

A folder-hierarchy delete response already reports a remote deletion. The checked EWS sync helper finds the local folder and calls PropagateDelete on its parent. Calling the concrete EwsFolder DeleteSelf would initiate another remote DeleteFolder request; reading only the base implementation gives the wrong contract. The author initially suggests that equivalence in review, then retracts it and documents the actual override. Fixed Exchange source retains separate sync-delete and user-delete routes. The added test checks local presence and absence after fixture sync; it does not directly assert absence of an outbound delete request. No protocol/runtime test ran.

Scope: Exchange folder deletion origin.
