# Pane-layout extraction preserves the stored preference IDs

Entry 1199 moves pane layout into a module but retains the old XULStore IDs through #STORE_MAP. The current mapping still connects folderPaneSplitter to folderPaneBox and messagePaneSplitter to messagepaneboxwrapper; resize persistence chooses width or height from the resize direction. For this extraction, preserve the existing storage identity instead of treating a DOM rename as a preference migration. This is a scoped source pattern; saved-layout restoration and resize behavior were not run. Full bug and review discussion remains pending.

Scope: Three-pane layout persistence.
