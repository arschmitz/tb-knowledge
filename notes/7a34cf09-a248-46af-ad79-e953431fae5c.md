# Confirm message deletion in the front end for every view

The backend DB view did not have the real folder context for unified folders, conversation views, and Search Messages, so Shift+Delete could bypass the warning. The accepted change moves confirmation into MailUtils and command controllers, picks the first selected message folder when needed, and handles Trash, collapsed threads, permanent deletion, and newsgroups by preference. It disables move/delete on expanded grouped-by header rows because the target would be ambiguous. Review asked for direct tests of the prompt text and cancel/accept behavior, not merely clicking through a dialog.

Scope: message deletion confirmations.
