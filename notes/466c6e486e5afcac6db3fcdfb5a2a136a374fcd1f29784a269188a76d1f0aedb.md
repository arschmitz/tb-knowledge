# The socket-type assertions describe connection security as authentication

The updated integration check reads the incomingSocketType localization ID and expects account-hub-result-ssl, but its message says Incoming auth should be expected auth. That names a different concept from SSL connection security. The later accepted mapper explicitly uses the security ID family. This is a diagnostic mismatch in the inspected assertion, not a reproduced test failure or a request to rewrite unrelated messages.

Scope: Account Hub integration-test diagnostics.
