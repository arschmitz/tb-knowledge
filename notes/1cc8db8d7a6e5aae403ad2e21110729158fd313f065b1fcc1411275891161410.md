# The unsafe EWS factory documents valid pointer storage and checking status before output use

The new SAFETY section names valid nsIID input, writable output storage and checking the return status before using the result. The factory itself allocates then delegates QueryInterface, so the comment is a caller contract rather than newly added runtime pointer validation. Current code retains the contract with later explicit unsafe query/attribute syntax and a pub(crate) bridge instead of the historical pub struct. This is one FFI documentation example, not a general visibility/unsafe-style rule. No FFI, build or doc test ran.

Scope: Rust FFI factory documentation scope.
