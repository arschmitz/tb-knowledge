# The reload test probes corrupted offsets inside, near and beyond the mbox

The browser reload test uses four bad tokens: a location inside the file, far past EOF, and two offsets near the end. It checks message body identity, the new token at the old end, file growth and regained Offline state. For this recovery path, keep location classes and body assertions separate instead of proving only that the browser loaded something. This is scoped test guidance; the test was read but not run, and no crash or automatic repair was observed. Full Bugzilla and Phabricator discussion remains pending.

Scope: Displayed-message corruption tests.
