# Read legacy server preferences safely before the UI migration has run

Bug 1882574 added the type preference in UI migration 43 but OutgoingServerService could be read first by an earlier migration. For a UI-version-34 profile, _keyToServer.getCharPref without a default threw NS_ERROR_UNEXPECTED and stopped later migrations. Bug 1897924 changed the read to default to smtp, the only type that existed in old profiles, and added a unit test that loads a key with no type. The reviewer asked the test to remove its server because XPCShell did not clear this preference between tests; the accepted test calls deleteServer. Check old-profile startup order whenever a migration introduces a preference that service getters may read.

Scope: Profile migration.
