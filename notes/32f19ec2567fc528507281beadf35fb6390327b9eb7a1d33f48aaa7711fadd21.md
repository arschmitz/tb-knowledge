# Wait for the actual contacts focus target instead of a fixed number of tabs

The historical keyboard test sent five Shift+Tab events. Current accepted code sends at most ten while checking sidebarDocument.activeElement against cardsList.table.body, then asserts that target. Preserve target-based focus checks as the sidebar gains controls. The same test still uses a 100 ms delay before checking restored sidebar visibility and still checks !sidebar.isHidden there; these are not proof of a fully deterministic visibility wait.

Scope: mail/components/addrbook.
