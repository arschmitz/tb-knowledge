# The original Exchange read-state update touched the header before checking creation failure

In the original landing, a non-draft file-copy completion calls MarkRead on newHdr before checking the failed status. Its same-revision message-create handler can invoke that callback with a failed status and nullptr, and the file-copy lambda forwards the pair. Accepted source later checks failure before using the header and validates the successful header. This is a static source path and phase difference, not a reproduced crash or an inferred cause of a historical failure. The added success-only FCC read-state assertion does not cover this path.

Scope: Exchange copy callback failure order.
