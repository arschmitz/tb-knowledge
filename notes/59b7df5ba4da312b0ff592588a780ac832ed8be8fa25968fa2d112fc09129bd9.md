# The Panorama batch-add path sets messageSize from the complete raw bytes

Fresh complete AddMessageBatch2 change sets each returned header messageSize from the raw nsCString byte length after finishing the stored message, checks the setter result, then appends the header. Fixed code keeps that order and assigns the store token separately. It is the complete raw message size, not just MIME body or Unicode character count; the explicit uint32_t cast remains and oversized-message behavior was not exercised. The entry is limited to the Panorama batch path. Current AddMessageBatch dispatch requires MOZ_PANORAMA plus the startup preference, and the separate path still documents the RSS/filtering limitation. Existing contention/scope-guard lesson is reused. The umbrella Bug later covers attachHdr/copy-key work and Windows pointer aliasing failures, but those later patches are context only, not part of this size assignment. No test changed; no batch/store/database or platform test ran.

Scope: Panorama local batch header size.
