# Deletion selection keeps an original focus anchor while accounting for rows that disappear

GetMsgToSelectAfterDelete prefers the selected range containing currentIndex and otherwise uses the first range. It counts only earlier selected rows that will disappear, then uses originalAnchorIndex to retrieve the backing folder before applying the anchor delete model. This separates the shifted output index from the original lookup index. IMAPDelete rows stay in place; downward selection skips their anchor block, while the sort-order preference can select the preceding row. Fixed accepted source retains this algorithm, with a later folder-helper signature. This is static source evidence; required primary comments 19/20/21 are absent, so this partial does not establish a complete historical outcome or runtime cursor behavior.

Scope: Cross-folder message deletion selection.
