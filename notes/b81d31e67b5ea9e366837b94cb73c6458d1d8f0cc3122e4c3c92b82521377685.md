# An external OAuth success page reports redirect acceptance before token exchange

The original page choice checks stored state and presence of code, then starts page generation before the separately dispatched authorization processing. Valid callback success and error pages both use HTTP 200; malformed requests use 400. The generated success wording does not establish successful token exchange or account setup. The invalid-endpoint test directly checks 400 and NS_ERROR_ABORT, while the redirect fixture compares markup with the same generator. Accepted issuer validation and focus/connection handling are later phases; no OAuth flow ran.

Scope: External OAuth loopback response semantics.
