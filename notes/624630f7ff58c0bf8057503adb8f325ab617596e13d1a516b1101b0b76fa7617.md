# The first manual-flow preference is default off and has a separate binding despite a repeated checkbox ID

The original patch adds a default-false mail.accounthub.manualconfig.enabled Boolean and a checkbox bound to that separate preference. Its checkbox repeats id="accountHub" from the adjacent main Account Hub control, inside HAVE_SHELL_SERVICE. This is a static markup identity concern, not a reproduced selector or accessibility failure. The patch does not implement the flow. At the fixed accepted endpoint, the default is true and actual AccountHubEmail edit/fallback branches use the preference to choose new manual/protocol paths versus the older incoming subview. The historical control block is no longer present in the bounded current section. Keep original preference scaffolding, later default and later consumers separate.

Scope: Account Hub manual-flow preference and preferences markup.
