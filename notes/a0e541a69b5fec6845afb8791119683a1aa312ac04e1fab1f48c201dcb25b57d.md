# Email-to-Calendar conversion keeps Extractor after the optional parser is removed

The patch removes the optional default-false CalExtractParserService branch, its modules/build/docs entries and four parser tests. The surviving conversion still creates the existing locale/day-start Extractor. Its collected array starts with the email date, so a length of at most one selects the default dialog; otherwise the caller uses guessed start/end times. The existing legacy extraction test remains registered. This is source evidence for routing and deletion scope, not proof that an opt-in user saw no change or that conversion/tests ran.

Scope: Calendar email extraction service removal.
