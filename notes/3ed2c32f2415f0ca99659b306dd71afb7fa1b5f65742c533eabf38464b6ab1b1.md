# Keep blocked-image data conversion separate from compose DOM changes

ComposeUtils.loadBlockedImage synchronously returns a data URL or throws; it no longer searches the compose editor or chooses a DOM-update mode. Drop/error callers update one target image, manual unblocking updates all images with the chosen URL, and background/filelink callers assign the value to their own property. Marker and notification cleanup therefore belong to the caller. The helper has no cache, and MIME selection is not validation of the image bytes. The existing pasted-image test checks loaded data/CID and blocked-content outcomes, not direct helper invocation, every caller or all cleanup/error branches.

Scope: Compose image conversion.
