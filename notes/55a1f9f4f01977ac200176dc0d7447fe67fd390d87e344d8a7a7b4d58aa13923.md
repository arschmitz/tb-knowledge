# Use the same field names when writing and reading the signature-row cache

The accepted SigListView initializes and writes prevKeyObj/prevRow, but getSigAtIndex checks lastIndex/lastKeyObj. The scoped query finds no assignments to the latter names in this file. Proposed manual consistency check: use one pair of names for the cache state, then test repeated lookup of a valid row. In the inspected code the intended cache fast path does not use the fields that are written. This is a static cache concern; no performance or visible tree failure was reproduced. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: OpenPGP cache naming.
