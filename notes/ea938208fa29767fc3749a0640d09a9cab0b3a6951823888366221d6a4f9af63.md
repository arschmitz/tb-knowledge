# An awaited certificate helper can still lack an expected verification result

testCertValidity stores the callback PR error code in gCertValidityResult and resolves its promise without a value. The owned argument-repair landing has no local call to the helper. Current source later awaits it for messages with sentDate, but the file still never reads or asserts the stored verifier code. Distinguish adding a callable signature, invoking a path and asserting an expected result. Existing message/decrypt assertions do not establish the verifier result. No certificate or test was executed in this study.

Scope: S/MIME permanent-decrypt unit-test coverage.
