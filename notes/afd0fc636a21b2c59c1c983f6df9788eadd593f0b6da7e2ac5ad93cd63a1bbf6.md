# OpenPGP preview and import still receive different text scopes

The clipboard and URL preview use getKeyBlock(text, false), which can skip earlier armor of another type. After confirmation, both callers pass the original text to importKeyAsync. Its current ASCII path locates only the first armor block and rejects a non-key block with not-first-block. Thus a valid public block after a message armor block can be previewed by the new helper but rejected by the importer. Scoped proposal: pass the confirmed extracted block through import, or explicitly verify the preview/import distinction with mixed-block tests. Ordinary surrounding whitespace is handled by the locator; this conditional mismatch is not a reproduced key import or the reported whitespace bug diagnosis. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: OpenPGP preview and import block scope.
