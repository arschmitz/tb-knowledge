# Keep extension xpcshell setup in the harness lifecycle without losing lexical scope

Entry 2126 moves per-file app-info initialization, HTTP fixture setup and cleanup registration into add_setup. In the reviewed MV3 account test, the setup arrow passes its lexical this directly to AddonTestUtils.maybeInit; the author agrees with the reviewer that a separate scope alias is unnecessary there. The landed and fixed source retain that form. Shared head.js still calls ExtensionTestUtils.init(this) at top level, so the per-file cleanup is not a rule to move all shared-head hooks. The inspected cleanup registration follows some initialization calls; it does not establish protection before every possible setup failure. No harness test ran.

Scope: Extension xpcshell test lifecycle and binding roles.
