# Describe EML save scenarios in separate task names and assertions

Entry 768 originally gave the two new tasks the same test_save_eml_as_file name. Current accepted code distinguishes test_save_eml_as_file1 and test_save_eml_as_file2. The first tests a file opened from disk, writes an output and compares normalized source bytes; the second opens a nested attachment in a new message window and checks its save name. Manual naming proposal for this file: new test names should state the scenario instead of using only a numeric suffix. This is a proposed clarity rule, not a claim that descriptive scenario names are already consistent. Preserve the browser_ file prefix and this file’s test_ task family. Both current tests wait for nonempty output and clean up pickers, files and windows in finally. The extracted attachment comparison allows the additional line ending documented for MIME extraction.

Scope: eml-save-tests.
