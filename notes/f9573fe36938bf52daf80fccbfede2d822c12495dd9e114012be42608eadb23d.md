# Read the loaded Calendar Edit title instead of assigning the expected value in an assertion

3030 contains a functional test correction inside a broad assertion migration. The old Assert.ok argument assigns title to the dialog input and then checks the assigned string. The replacement passes the input value and expected title separately to Assert.strictEqual, so the test can detect a wrongly loaded title without fixing the UI itself. The accepted test keeps this read comparison after waiting for the edit dialog. This supports the exact fixture assertion, not a general production equality rule; no test was run.

Scope: calendar/test/browser/contextMenu.
