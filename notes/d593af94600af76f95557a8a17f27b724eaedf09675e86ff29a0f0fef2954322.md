# Threaded deletion handles root promotion and descendant levels in separate paths

Deleting an expanded root collapses the old visible children, removes the stale row, adds the promoted root and expands it when more than one child remains. A non-root deletion instead saves its old level, removes that row and shifts only the following run of deeper descendants left by one level. A single change notification covers that run. The two added local-folder tests assert root promotion and one descendant-level shift; they do not directly establish every selection, notification or failure-path outcome.

Scope: Visible threaded DB view row deletion.
