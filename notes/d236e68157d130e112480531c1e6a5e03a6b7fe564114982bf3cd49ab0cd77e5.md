# Load template dependencies before using a custom element

The accepted custom element guide generally uses a top-level side-effect import when a template needs another element. For controlled dynamic creation, it shows awaited import(), ChromeUtils.importESModule, or defineESModuleGetters with global: "current". That realm choice is explicit in the examples. defineLazyCustomElement is an alternative when those options are hard to use. Follow the loading method that matches the actual creation path. Do not turn one lazy example into a rule that every dependency must be lazy. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/custom-elements/loading.
