# Early EWS fake item pagination counted filtered results rather than global log positions

The historical fake-server item response slices the shared itemChanges log at offset, filters to one parent folder, caps results, then emits offset+changes.length. Because that count excludes skipped other-folder records, it can revisit selected-folder changes when the global log is interleaved. The initial batching task mainly populates inbox and does not directly cover that cursor boundary. Accepted current MockServer attaches original indexes before filtering/flattening and advances to the last returned global index+1, or log length when exhausted; current EWS response emits nextOffset. Keep this test-server behavior separate from opaque production sync tokens and later helper credit. Static code comparison only; no pagination experiment ran.

Scope: EWS test-server pagination cursor and folder filtering.
