# Calendar WARN removal includes a built-in-type throw and a removed unifinder catch

Part 2 changes built-in calendar type unregistration from warn-and-return to throwing an Error. It also removes the unifinder's per-row catch around getItemAt. The checked receiver is CalendarFilteredTreeView, whose ordinary out-of-range case returns null, so this catch removal does not by itself establish a new bounds failure. A real thrown getter would no longer be swallowed in that loop. Ordinary type removal keeps its map placeholder and option removal. No add-on or selection failure was reproduced.

Scope: Calendar warning migration control flow.
