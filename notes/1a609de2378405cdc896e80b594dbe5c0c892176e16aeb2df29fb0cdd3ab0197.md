# Keep the EWS root-order invariant active for release response mapping

The well-known-folder mapper checks that the developer-controlled distinguished-folder list starts with the root, then checks response count before pairing responses. Review explicitly retained the assertion for release builds because later root handling depends on that order. The reviewer confirmed this purpose even though the reply remains marked Not Done. Keep this invariant and its local reason with the mapping. Server ordering is still an explicit assumption, and response shape/count checks remain separate. This is scoped Rust source and review evidence; no build or runtime was run.

Scope: EWS root mapping invariant rationale.
