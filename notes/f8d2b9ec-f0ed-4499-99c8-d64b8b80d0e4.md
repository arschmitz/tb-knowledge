# Keep the cached search-hit table index after removing a stale row

RefreshCache walks new sorted message keys and existing cached table rows together. It inserts new rows at the current table position, records stale keys before removing their row, and does not advance tableRowIndex after CutOid because the next row moved into that position. It then makes a large commit. The cleanup removed an unused debug-only verification loop but kept this merge behavior. This is a code-level invariant worth checking when changing saved-search cache updates; the current implementation retains the index rule.

Scope: Message database search cache.
