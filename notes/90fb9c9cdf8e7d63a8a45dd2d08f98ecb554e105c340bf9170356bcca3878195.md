# Recovery-file retention starts after a successful compaction handoff

Entry 2063 adds mKeepRecoveryFiles. OnCompactionComplete sets it only after successful DB staging/installation and before returning to the store. If the later lower-level commit fails, OnFinalSummary retains .compacted and .original DB recovery files. Final success clears the flag and removes them; .compacting is removed regardless. This narrows the existing recovery lesson: the code does not promise preservation after every earlier DB rename failure, and there is no atomic mbox/.msf pair install. The historical document gives a file-state table and possible manual recovery steps, explicitly with no automatic recovery. The fixed accepted callback/cleanup keep the phase guard. No power-loss, rename-failure or recovery test ran.

Scope: mailnews folder compaction recovery phases.
