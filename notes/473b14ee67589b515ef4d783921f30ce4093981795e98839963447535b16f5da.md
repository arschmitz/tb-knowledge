# Incoming-server migration fixtures now exercise POP3 rather than the removed IMAP JS variant

1930 changes identity-folder and spam-action migration setup from IMAP to POP3. Current tests expect mailbox:// URLs after host or username changes, while the password and filter tasks retain separate NNTP cases. This is a test-scope change: the current assertions establish those POP3/NNTP expectations in source, not equivalent IMAP migration coverage. Keep the actual protocol fixture visible in task documentation and review; a generic migration test name does not identify it by itself. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.
