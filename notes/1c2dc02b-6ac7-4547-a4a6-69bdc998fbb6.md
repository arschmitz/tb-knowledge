# Certificate alerts cover folder selection; hostname overrides were restored

An IMAP folder selection can connect to the server without the Get Messages URL listener. Certificate failures must reach the mail-session feedback listener through the IMAP server sink so the user sees the error. The alert should explain the certificate problem before an exception dialog opens.

## Evidence

- [Bug 1893899](https://bugzilla.mozilla.org/show_bug.cgi?id=1893899), [D208956](https://phabricator.services.mozilla.com/D208956), and commit `620a0ed38021` added that error path and notifications. The review found a Windows date-format test failure before acceptance.
- That May patch made hostname-mismatch alerts unclickable. [Bug 1903135](https://bugzilla.mozilla.org/show_bug.cgi?id=1903135), [D217353](https://phabricator.services.mozilla.com/D217353), and commit `ce2c0d62764dea69ac3a3f4cd70ab5862d064f2f` restored the option to open an exception dialog after the warning. The later accepted behavior takes precedence over the May restriction.
- [Bug 1894672](https://bugzilla.mozilla.org/show_bug.cgi?id=1894672) records an alert-test intermittent after the May change. An attempted wait fix did not settle it; the bug later closed WORKSFORME. Its proposed race explanations are not confirmed behavior.

## Validation and limits

I inspected the landed diffs, tests, current alert code, bugs, and public reviews on October 6, 2026. I did not run the tests or validate certificate behavior in a build. Current alert internals have changed since these patches, so recheck the current source before editing them.
