# Keep Rust tray documentation tied to action and thread boundaries

Proposal for Rust sys_tray maintenance: keep public-item /// documentation and actor names accurate at the menu-to-main-thread boundary. ActionItem stores an action; selecting the item dispatches that action to the Gecko main thread; handle_action invokes XPCOM there. The 560 review requests these distinctions and the actual landing applies dispatch_action, a named tray callback, item fields and a main-thread restriction beside request_quit. Several badges stay Not Done despite those applied changes. The requested crate-level threading summary is absent. Add that summary if the crate still needs a cross-file explanation, after checking its current callbacks and platform guards. This is a scoped documentation proposal, not a runtime defect or a requirement to narrate obvious code.

Scope: rust/sys_tray.
