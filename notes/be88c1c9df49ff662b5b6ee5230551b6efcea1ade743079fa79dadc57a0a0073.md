# Inspect serialized tombstones instead of only tracker flags

567 adds markDeleted before the asynchronous setData removal and getCreateRecordData checks the guard immediately. The current address-book tracker sets the guard before changed-ID and score updates. Its createRecord marks a tombstone only when both the live book and eligible cached data are absent. The test waits for a changed score, reads a record before clearing tracker state, and checks a tombstone after an encryption/decryption round trip. This strengthens the earlier cached-record lesson with an explicit serialized result. The test does not hold cache deletion pending, so it is not a deterministic test of that race window. These tests were inspected, not run.

Scope: Sync deletion race tests.
