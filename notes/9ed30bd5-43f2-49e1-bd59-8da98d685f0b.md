# Manifest V3 contact APIs use vCard while Manifest V2 retains flat properties

Manifest V3 contact nodes expose vCard directly and contacts.create/update take vCard strings; the legacy properties bag and flat FirstName/PrimaryEmail handling remain for Manifest V2. Conversion requires the extension to choose the version-specific shape. Tests compare full converted contact nodes and reject a changed UID. Current code retains this split. Do not expose internal card fields as a replacement for removed flat properties without an explicit API design.
