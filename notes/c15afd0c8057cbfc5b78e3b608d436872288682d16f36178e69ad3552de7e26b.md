# Register Hub close waits before the key or button that can close it

1260 moves close-event waiting ahead of Escape and close-button input. Current browser_accountHub and shared close helper keep that ordering. A scoped test recommendation is to create the event promise before the action, then await it and verify dialog.open changed. Waiting only after synthesizing input can miss a synchronous close. Other retained advanced-setup tests still register some waits after actions; this source check does not prove that every Hub wait has been fixed. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/test/browser.
