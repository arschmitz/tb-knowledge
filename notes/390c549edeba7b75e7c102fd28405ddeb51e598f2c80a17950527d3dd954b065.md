# Use nullish defaults when false is a meaningful decode override

The message API and MIME utilities use ?? for optional decode or mailbox-policy booleans. An explicit false disables decoding or overrides automatic mailbox handling; using || would erase that choice. Tests include forced true and false handling for TO. Manual syntax proposal for comparable optional flags: choose a default only when the value is missing, and add a false-case assertion when false changes behavior. This is scoped to these option contracts, not a rule to replace every || expression. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/optional-boolean-defaults.
