# The SMTP QUIT fallback timer is canceled before client reuse and on socket closure

The landing adds a five-second close fallback after sending QUIT. A new connect cancels that fallback before reusing or replacing a socket, and the close callback also cancels it. Client pool release is separate: _free can send QUIT and call onFree before the socket closes. The new test models a peer that answers221 but leaves the socket open and waits for a non-open client socket. This does not prove a universal latency bound, real unreachable-peer behavior or second-send race safety; no test or network run occurred.

Scope: SMTP client post-QUIT socket lifetime.
