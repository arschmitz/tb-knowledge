# Make Account Hub input tests explicit about focus, caret and expected value

1260 tightens input interaction and diagnostics, including moving to KEY_End before appending a string. Current form tests register input events with value predicates before sending text, and separately wait for the relevant subview or validation state. A scoped recommendation is to establish the intended focus/caret position and expected value; a generic input event can come from the wrong edit. Source inspection is not proof that all these asynchronous UI paths pass. This is source and test inspection only. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/test/browser.
