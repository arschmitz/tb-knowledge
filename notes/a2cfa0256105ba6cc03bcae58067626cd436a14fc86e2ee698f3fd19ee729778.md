# A folder-repair notification does not turn compaction failure into success

Accepted batch completion logs each failed folder, selects the first failure for user reporting and returns that status through the final URL listener even when IMAP repair is notified. FolderCommands starts updateFolder without awaiting synchronization completion. The emitted recovery request is therefore not a completed repair or a successful compaction result. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/base/src.
