# The LDAP receive cap runs after concatenation and does not cap queued or peak memory

The client checks whether its processed data buffer is greater than 16 MiB. It first allocates and copies a combined partial buffer when needed, and events received while processing are queued before that check. The change is therefore not a hard peak-allocation or total-queue memory cap. Exactly 16 MiB is allowed by the comparison. No boundary, memory-pressure or LDAP execution was performed.

Scope: LDAP receive buffer limit scope.
