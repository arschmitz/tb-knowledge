# Test locked arrival, locked read and unlocked retry as separate states

The fetch-while-locked test uses an owner other than the folder, updates Inbox and verifies the new header exists but has no Offline flag, no token and no mbox body. It reads while still locked and checks those storage facts again. After releasing the lock it reads again, confirms the generated body, confirms Offline and confirms the token points to a From line. Current registration places this byte-level test in the mbox/cpp manifest rather than the shared Maildir suite. Do not reduce it to only a request result assertion.

Scope: mailnews/imap/test.
