# Keep notification ranking stable when the current candidate is still eligible

The docs describe ascending severity, start time and chance, but a currently shown eligible notification is retained when the best candidate has equal or lower priority. Current updatedNotifications checks the current ID’s presence and severity before switching. This is a stable-display rule after filtering; numeric lower severity means higher priority. It does not guarantee a fixed display count or live timing result, and later rate limits are outside this landing. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: In-app notification selection.
