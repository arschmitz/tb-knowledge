# openLinkIn uses a content-tab route before its named new-window fallback

openLinkIn gets the top chrome window. If that window exposes switchToTabHavingURI, it uses that content-tab route and returns. Otherwise it builds URL arguments and calls Services.ww.openWindow with the name _blank. The historical patch replaces null after a reported console exception; apparent support-link success was attributed to a widget fallback. The linked Gecko implementation was not inspected, so no general nullability or fallback guarantee is established. No window or console test ran.

Scope: Thunderbird link routing.
