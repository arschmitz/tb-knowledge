# Check a nullable EWS lookup before passing its header to deletion

The historical DeleteHeaderFromDB checks the nsresult of GetMsgHdrForEwsItemID, then passes its output straight to LocalDeleteMessages. The lookup can return NS_OK with a null output when no row exists; LocalDeleteMessages dereferences each header to read its key. This is a verified static missing-output guard, not a reproduced crash or a claimed historical failure report. The fixed Exchange OnMessageDeleted returns NS_OK when the header is already absent, because user deletion can be followed by the server’s Delete sync change. Reuse the existing shared remote-ID idempotency lesson for that current behavior. The new evidence establishes the historical unguarded boundary. No missing-header, delete-replay, runtime, build or accessibility test ran. External discussion is pending.

Scope: EWS delete lookup and replay boundary.
