# Virtual-folder junk actions must partition messages by their real owning folder

The DB view delegates a single-folder selection directly, but groups a virtual/multi-folder selection by each header folder before invoking folder junk policy. The direct test unjunks a unified Junk selection and checks messages return to two different account Inboxes. It pre-registers both completion promises before the action. The multi-folder loop ignores individual returned results, so this is not an atomic or aggregate-error completion API. No UI test ran.

Scope: Junk actions across accounts.
