# EWS preview metadata is separate from full-body download and on-demand preview fetching

The sync request asks for item:Preview only on the configured Exchange2013-or-newer branch, without requesting MIME content. Current native sync stores nonempty preview metadata in the header preview property. FetchMsgPreviewText uses that cached property, falls back to an offline body if available and reports no asynchronous request. Missing preview is not a promise to fetch the body or clear an older cached value. The notification test asserts only a ten-character prefix. Keep request metadata, storage, display fallback and direct test assertions separate. Static source only; no server or notification test ran.

Scope: Exchange sync metadata and notification previews.
