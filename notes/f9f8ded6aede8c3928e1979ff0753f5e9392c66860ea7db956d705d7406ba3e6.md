# Thunderbird Calendar transaction-manager failed-move recovery

A cross-calendar move does destination `addItem()` then source `deleteItem()`. If source deletion fails after destination add succeeds, both copies can remain. Normal undo is wrong there because it deletes the destination and re-adds an original that is already still present. [Task 1]

Scope: calendar.
