# OpenPGP MIME-loading promises resolve before displayed-message completion

getMessageFromUrl resolves with the string collected when the stream stops. getMimeTreeFromUrl resolves after that string is parsed; getMimeTree returns null when its parser catch runs. The shared string listener does not check request status in onStopRequest. These promises therefore do not establish successful transport or signature verification. Current persistent-crypto and display callers await their following processing steps, but composeStartup starts composeOpen without awaiting it. Nested-part notification callbacks also start the view function and immediately return true. Each view function starts msgOpenMessageFromString without awaiting the temporary-file write and open. Document these completion boundaries and the nullable tree result before callers use the promise as a readiness signal. No failure injection or window-opening test was run in this study.

Scope: mail/OpenPGP/async-loading.
