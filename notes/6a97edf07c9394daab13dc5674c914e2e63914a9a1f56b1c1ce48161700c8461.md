# The vCard add icon change retains the actual name-part visibility contract

The name-part buttons adopt the shared fieldset/add-property/only-icon class family and keep their input IDs, Fluent IDs and button type. CSS generates the icon from --icon-circle-add-sm, icons.css resolves the chrome URL and jar.inc.mn packages the 12-pixel context-fill/context-stroke SVG. The old name-specific hidden selector is removed, while the shared fieldset-button hidden rule remains. The actual click handlers reveal the input and hide the button. Existing test helpers assert those visibility states and synthesize the button click, but were not run. The inspected unchanged checkNFieldState helper also has three assertions without messages at lines 1427, 1450 and 1452; their expected component/input/button roles should be named if that helper is changed. No pixel, focus or accessibility result follows from the new asset alone.

Scope: Address book vCard name-part controls and icon resources.
