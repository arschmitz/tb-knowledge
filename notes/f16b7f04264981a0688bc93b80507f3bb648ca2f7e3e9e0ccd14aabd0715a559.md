# Treat the original Panorama folder object API as historical

Entries 1148–1153 created nsIFolder objects with a loaded parent/child graph and ID/path maps. Accepted source has removed Folder.cpp, Folder.h and nsIFolder.idl. nsIFolderDatabase now operates on numeric folder IDs and DatabaseCore provides folderDB. Current Panorama callers use those IDs in getFolderName, getFolderChildren and LiveView.initWithFolder. Use the current interface for new work; do not reproduce historical object getters or loadFolders/getFolderById calls. This comparison does not count all intervening rewrites as studied. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama folder API evolution.
