# Protocol-specific OAuth overrides preserve provider defaults and clone issuer data

The initial EWS override implementation requires the global feature preference and per-account permission. Unknown hostname details require both issuer and scopes; known details keep defaults when an override is empty. Issuer details come from a shared provider object, so the override path clones that object before changing it. Current code retains cloning and the protocol-specific fallback, while generic OAuth2CustomDetails replaces hostname details completely. The original interleaved-array API and incoming-only limitations are historical; current incoming and outgoing bridges pass IOAuth2CustomDetails. Positive unit assertions do not prove login or all invalid-input paths. No runtime authentication was run.

Scope: OAuth2Module protocol-specific customization contract.
