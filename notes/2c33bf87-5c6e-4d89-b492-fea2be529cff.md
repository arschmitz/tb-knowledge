# Wait for the compose editor and message-load hooks before injecting special scripts

The 2024 scripting-tb implementation registers window listeners for the compose window and the message windows. A compose editor initially looks complete because it is about:blank; the code waits for compose-editor-ready before executeInWindow can find the editor. It warns that reply or draft setup may still modify the editor after that event. Message scripts attach on MsgLoading and use event.target.tabOrWindow to resolve the target tab, then obey runAt. The initial implementation tied registered scripts to the background context; follow-up Bug 1896907 moved registration ownership to the extension so it survives background termination. Current code contains that later correction. Do not assume ordinary document readyState is enough for compose initialization.

Scope: Thunderbird extension API architecture.
