# MailNotificationService registration and notification have distinct listener ordering

The module exports one count-service object. addListener returns for an already registered object, synchronously calls a first listener with the selected new/unread count, then inserts the object into its Set. The listeners getter returns an Array and _notifyListeners iterates that snapshot, so registration changes during one notification do not change that iteration. The callback-before-insertion order does not establish reentrant registration safety. Unit tests directly check immediate current count, subsequent inbox updates and listener identity/removal; they do not directly check duplicate registration or callback mutation. Four changed collection assertions lack messages. No unit or platform test ran.

Scope: mail notification count listener API.
