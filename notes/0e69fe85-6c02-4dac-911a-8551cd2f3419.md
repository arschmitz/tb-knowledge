# Shared search-bar exposes a read-only value and explicit reset operation

Replacing the address book custom search input needed the current term when switching directories. Review rejected copying the old mutable value API merely for drop-in compatibility; the author kept a value getter, removed a placeholder getter that only served tests, and used visible shadow slot text in the test. Current widget has get value, reset, and overrideSearchTerm, with no value setter; address book commands call reset before displaying or editing a contact. Match the widget behavior rather than rebuilding an old input API.
