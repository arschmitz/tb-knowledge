# Range invalidation bypasses the three-pane shim's explicit reset and autoscroll

Three DB-view cleanup paths now call InvalidateRange rather than full Invalidate on mJSTree. The installed three-pane shim's full method resets the tree and calls no-selection autoscroll; its range method forwards without those explicit actions. The inner range update can still add or remove buffered rows and fill visible rows, so this is a specific callback-path distinction rather than a no-DOM-change or performance guarantee. The source preserves the existing selection-restoration and batching guards. No scroll, benchmark, native binding or accessibility test ran here.

Scope: Message view invalidation.
