# Preserve the two extension-popup launch forms

Current extensionPopup handles a string argument used by identity launch by constructing a permission-bearing content principal. The structured windows.create form instead takes createData.triggeringPrincipal, userContextId and linkHandler from its first tab description. The file comments say only the first URL is opened in this popup form. Preserve this argument distinction and its principal source when changing the shared window; a tab-shaped payload is not interchangeable with a string. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
