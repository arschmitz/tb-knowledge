# Document database error normalization with its creation gate

The IDL says OpenDBFromFile never throws NS_MSG_ERROR_FOLDER_SUMMARY_MISSING. The implementation normalizes that result only with aCreate. In the inspected missing-file branch, OpenMDB assigns SUMMARY_MISSING when the path does not exist; CheckForErrors returns that error when there is no nonempty summary file. With creation disabled that result is not normalized by OpenDBFromFile. Recommend aligning the method documentation and missing-file test with this scoped path and output behavior. This is a traced static contract concern; no native file operation or failure case was executed. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mailnews/db/msgdb.
