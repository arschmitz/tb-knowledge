# External signing separates public-key usage from local secret-key availability

findSuitableSigningKeyID asks for a signing subkey with publicKeyUsageOnly enabled, then falls back to a primary key that allows signing. The default isKeyUsableFor signing path separately requires local secret material. GPGME reads the selected externalSenderSigningKeyID rather than the original sender field. This explains how a locally public-only key can name an externally managed signer; it does not prove native key availability, universal validity or a successful signature.

Scope: OpenPGP external signing-key selection.
