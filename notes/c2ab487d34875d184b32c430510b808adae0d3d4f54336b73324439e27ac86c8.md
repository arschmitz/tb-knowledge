# Exchange folder creation treats repeated IDs differently from name conflicts

MaybeCreateFolderWithDetails succeeds immediately when its remote ID already exists. This handles a local folder creation echoed by later sync. If the ID is new but the parent contains the requested name, creation returns NS_MSG_CANT_CREATE_FOLDER instead of merging unrelated identities. Newly created folders receive the remote ID and folder-added notifications. The repeated-ID branch does not reconcile changed parent/name/flags by itself. This is static current-source and historical patch evidence; no Exchange sync ran. Review explicitly distinguishes an expected echoed create from conflicting identity, asks comments to explain both branches and requires checking the ContainsChildNamed result. A proposed no-op for name conflicts was rejected; MaybeCreate is the selected shorter local name.

Scope: Scoped source study.
