# QueryInfo keeps manifest-specific search objects under one type ID

The address-book schema defines one QueryInfo ID with two object choices. The MV2 choice omits parentId; the MV3 choice includes it. The older quickSearch signature accepts a separate parentId and forwards it into the shared query backend, while MV3 query accepts the object. Existing positive tests exercise these argument forms and scoped results. This is exact schema/caller evidence; no runtime binding rejection or documentation generator pass is claimed.

Scope: WebExtension address book search schema.
