# The first UpdateItem response check was a lower bound, not exact cardinality

Entry 1279 rejects a response only when it has fewer response messages than item changes, then examines every response class and aggregates errors. It does not require exact equality, and its collected processed_messages vector is not returned to the folder. The accepted operation now extracts successful item IDs and reports partial success through its listener. Preserve the distinction between the historical count guard and today’s success-ID contract. This is source inspection only; empty, extra or mixed server responses were not executed. Full Bugzilla and Phabricator discussion remains pending.

Scope: Historical EWS response cardinality.
