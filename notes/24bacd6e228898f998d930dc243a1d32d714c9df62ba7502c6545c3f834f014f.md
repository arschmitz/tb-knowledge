# Check the returned Maildir token in the already-moved finish branch

The historical finish still accepts an already-moved message when tmp is absent but cur contains the filename; its header already holds the token in that API. Fixed code uses the database-free interface and mOngoingWrites. In fixed FinishNewMessage833–903, the already-cur success return at 890 precedes the only storeToken assignment at 901. The IDL promises the committed token. Named nsLocalMailFolder caller3467–3471 declares a fresh nsAutoCString immediately before the call and writes its result to the header on success; no earlier assignment populates that newly declared binding. A scoped proposed test should move this issued temporary file into cur before finishing, check the success token equals its filename, and read the same bytes using that token. This is a static return-contract gap for the already-cur branch and that named caller. Whether the legacy filter-moved condition is still reachable, and any runtime impact, remain unproved. These early refactors are not asserted to introduce the later gap. The complete current finish/discard methods and local-store-directory test were read; the latter checks directory existence/type, not this return branch.

Scope: Maildir filename/token lifecycle and staged API migration.
