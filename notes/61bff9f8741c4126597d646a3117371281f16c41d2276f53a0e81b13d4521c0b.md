# Panorama summary migration remaps thread links after inserted keys are known

FolderMigrator first collects old message keys and thread fields, then asynchronously inserts messages and collects their new row IDs. HandleCompletion builds the old-to-new key map before queuing threadId/threadParent updates. It adds a parameter set only when the old thread root maps and the parent is zero or maps too; unresolved mappings do not by themselves reject the whole migration. Property insertion follows this stage, including fallthrough when no thread updates are queued. The inspected current test awaits migration and asserts two independent roots; it does not test nested-parent or missing-key remapping. Treat this as a staged mapping contract, not proof that all migration cases or rollout are complete.

Scope: Panorama database threading.
