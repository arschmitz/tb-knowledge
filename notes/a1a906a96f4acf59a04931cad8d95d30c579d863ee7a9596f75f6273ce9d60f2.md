# Native dialog close and Escape cancellation need separate busy-state handling

The shortcuts component guards close() with #isBusy and prevents the native cancel event while busy. A click routes to close, while Escape routes to onBeforeClosing. For this native-dialog family, keep the two dismissal paths aligned when implementing an actual busy operation. In the full inspected accepted class, #isBusy is initialized false and never set true, so this is reserved scaffolding rather than evidence of tested operation protection. The existing test covers normal Escape and button dismissal only; no busy-state test was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Customizable shortcuts dismissal paths.
