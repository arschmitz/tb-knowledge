# Received and recipient S/MIME certificate checks retain full verification off the main thread

nsCMS maps signer and recipient usage and calls VerifyCert without FLAG_LOCAL_ONLY; its comment says incoming certificate checks require OCSP and run in SMimeVerificationTask/CryptoTask. FindSMimeCertTask asserts it is off the main thread, filters unsupported recipient certificates and performs EmailRecipient verification before accepting one. Keep these paths separate from local-only checking of the user’s configured certificate. No revocation, trust-store or network verification experiment was run. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: S/MIME received-certificate verification.
