# Check per-message read failures before recording a thread as updated

At the fixed accepted revision, MarkThreadRead checks GetDBForHeader, but it does not check the result of IsRead or MarkRead. It appends the key after the write call and ends with NS_OK. The base database IsRead missing-header branch returns NS_MSG_MESSAGE_NOT_FOUND without setting its output. If that query fails, the caller can use an unset read value; if a write fails, it can record that key as updated. These are conditional static concerns, not reproduced failures. Recommend focused tests that force each per-message query/write failure and check the returned status, updated-key list and state/count changes before adopting a fix. Source inspection only; no failure injection, Thunderbird runtime, build, lint or live accessibility validation ran. Complete historical discussion remains pending.

Scope: mailnews/base/src.
