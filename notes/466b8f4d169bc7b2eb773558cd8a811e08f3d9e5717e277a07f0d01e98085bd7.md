# Finalize POP headers before storage flush and publication

The LF-response fix feeds HandleLine("", 0) at IncorporateComplete to ensure buffered headers are parsed before publishing the message. Current code checks the optional parser before that call, then flushes the stream, finishes the stored message, sets its store token and publishes the header. Preserve that parser → flush → storage-finalization → publication order in this sink. The commit reports LF-only server responses and the affected release; no LF server reproduction was run and no new regression test was added in this landing. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: POP header and storage completion.
