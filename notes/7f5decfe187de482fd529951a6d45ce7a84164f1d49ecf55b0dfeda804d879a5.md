# Account Hub can lazily load the exported getAddonsList function

D235568 asks for lazy loading to avoid eagerly importing the add-on lookup. The author initially says a function cannot load lazily; the reviewer explicitly corrects that claim and proposes a named defineESModuleGetters entry. The accepted source uses lazy.getAddonsList, and the fixed module retains that mapping to ExchangeAutoDiscover.sys.mjs. This is an applied local import choice for this exported symbol, not proof that every import should be lazy or that module loading changed startup performance. Install-only test fixture advice checks installation, not Exchange service functionality. No runtime or startup measurement.

Scope: Account Hub exported-function lazy import.
