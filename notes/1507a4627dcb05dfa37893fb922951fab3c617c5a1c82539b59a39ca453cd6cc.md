# Assert the replacement message state instead of its historical UID

The current IMAP attachment test awaits detachAttachments, verifies the saved file, enumerates the remaining inbox message and checks AttachmentDetached content. The historical test assumed that the replacement had UID 2. For this scenario, prefer the resulting one-message state and content contract over a fixed UID allocation. This scoped test recommendation does not guarantee attachment operations retain the original message ID. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Attachment replacement test identity.
