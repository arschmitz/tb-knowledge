# Removing per-process send reports leaves one error string and an NNTP phase marker

Part 1 replaces per-stage report objects with one message and a flag set on entering the NNTP phase. That flag alone is not a delivery-success status. Actual delivery processing returns on failure before the successful news-to-mail handoff. MessageSend keeps its own failure result while report display supplies text; the native compose caller also notifies from its own rv. S/MIME can now assign an empty successfully looked-up message because the old nonempty guard is removed. Later source moves the same state into JavaScript; no combined protocol or dialog run was performed.

Scope: Thunderbird send-report state.
