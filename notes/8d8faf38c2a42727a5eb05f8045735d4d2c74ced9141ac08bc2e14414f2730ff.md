# Progress listener storage is weak, while each callback uses a resolved local reference

nsMsgProgress stores weak listener entries. Before a callback, it resolves the referent into a local nsCOMPtr; if resolution fails, it removes the entry and continues. Listener implementations must support weak references: both the native compose send listener and MessageSend advertise that interface, and the dialog listener already does. Registration rejects duplicates and replays pending notifications. The change also switches reverse traversal to ForwardIterator, so callback ordering is a separate review concern. No new ordering test or complete leak cure is established by this source.

Scope: Compose progress listener ownership.
