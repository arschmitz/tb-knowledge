# Keep internal PDF and attached-message opening as separate branches

AttachmentInfo.open uses an internal content tab for PDFs only when the handler is internal and does not ask. A message/rfc822 attachment instead gets a named .eml temporary file, saved with isTmp=true and cached by URL, then opened as a message. Preserve those distinct handler and message semantics. A file extension alone does not bypass the PDF handler preference. No PDF or EML was opened. Static source and test inspection only. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mail attachments.
