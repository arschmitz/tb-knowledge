# Specific-key header creation remains backend-specific after the API split

The API split makes callers choose automatic createNewHdr or legacy createNewHdrWithSpecificMsgKey explicitly. In Panorama, automatic creation returns a DetachedMsgHdr, while the specific-key method returns NS_ERROR_NOT_IMPLEMENTED. The shared interface and renamed callers therefore do not prove that both backends support forced server-assigned keys. The changed tests exercise deletion and legacy high-water setup, not Panorama's unsupported branch.

Scope: Database header allocation interfaces.
