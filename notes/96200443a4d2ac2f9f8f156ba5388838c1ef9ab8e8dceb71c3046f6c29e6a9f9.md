# Start-in-tray starts delayed initialization without waiting for first paint

Both close-to-tray preferences gate hidden startup. The first window hides immediately; later restored windows wait for the shared loadingWindow state promise and hide only for non-null state. Because a hidden window may not paint, onLoad runs delayed startup immediately in this mode. The tests replace the OS integration service and stub restoration states; they do not prove a real restore-race cure or native startup result.

Scope: Windows hidden startup and session restoration.
