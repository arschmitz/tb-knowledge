# Folder-copy descendants need their newly created destination parents

Fresh complete seven-file folder-copy change read. CopyFolder runs on the existing destination parent, creates one handler and starts an index-controlled growing queue. Successful remote creation first creates local storage/folder and stores the remote ID, then appends immediate children with their newly created destination parent. Nonempty folders wait for message-copy completion before advancing; empty folders advance directly. Queue exhaustion does not implement the same-server source-folder deletion TODO, so the title/bug closure does not prove complete folder moves. Full41-row review preserves deferred callback/readability redesign, direct CopyMessages explanation, reviewer retraction about who creates the local folder, and the disagreement about assert versus release guards. Final source applies a queue-end guard plus a narrower success-callback assertion, not a global replacement of runtime checks by assertions. It uses nsCOMPtr for the client interface, keeps specific local comment clarifications and index-controlled iteration; speculative naming conventions remain proposals.

Scope: Exchange growing folder-copy queue and completion scope.
