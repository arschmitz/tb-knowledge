# Folder-display imports and message-injection setup are separate test contracts

FolderDisplayHelpers no longer constructs MessageInjection. Tests that need generated message injection import MessageInjectionHelpers explicitly, whose top level still initializes its local environment. Folder creation instead uses an existing Local Folders server, and affected manifests declare account state. Keep a no-account scenario in its isolated manifest without importing the injection module. The old display helper still binds a mail window and keeps its harness guard; this change does not make imports free of all side effects. These are scoped test contracts and static source checks.

Scope: Legacy browser-test helper initialization.
