# Check exact token boundaries when comparing returned OAuth scopes

Proposal for OAuth2 scope comparison: add a focused case where one granted token contains the requested token as a prefix but is a different token. The 643 historical warning path calls includes on the returned scope string, while splitting only the requested string. It is insensitive to order but still uses substring membership. Current frozen code instead compares an array of returned tokens; that later source fact is reused separately. A synthetic prefix case can distinguish those contracts. No provider is claimed to return such a grant, no security incident or runtime failure is inferred, and this is not a blanket rule for every includes receiver.

Scope: mailnews/base/src.
