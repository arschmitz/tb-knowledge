# Account Hub busy state disables forward actions while leaving a separate cancel control available

The owned footer change stores disabled in a private field instead of reading the back button state. toggleForwardDisabled still ORs its requested value with this.disabled, so another caller cannot enable forward while the footer is busy. The disabled setter updates forward and visible custom actions while leaving back enabled. The view separately shows and localizes back as Cancel only when an abortable exists. A busy footer has z-index3 above the owned spinner overlay z-index2. The changed component test asserts back stays enabled while forward/footer are disabled. Account creation is a separate boundary: the owned OAuth/password creation paths hide back and restore it only on failure, then enter sync discovery after verification hands off backend addition. That handoff is not awaited, so this UI boundary alone does not prove native account creation completed. Later accepted OAuth tests allow Back cancellation, which is a later phase. No rendered stacking, focus order, accessible name, keyboard or hit-test result was measured.

Scope: mail/account-hub/footer-cancellation.
