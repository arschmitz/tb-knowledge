# The send/save copy-path assertion compares an index with an array

runTest checks the returned-copy count, then uses i < expected.messageCopies instead of the array length for its returned-folder-path loop. The original cases supply [] or string-name arrays such as ["sent"] and ["sent", "draft"], so this comparison does not enter that loop. Its well-worded path assertion is therefore not direct coverage for those cases. Other ID, raw-message and actual-folder-count assertions remain. The fixed accepted helper keeps the same bound. This is a static test gap, not a failed test run.

Scope: WebExtension background send/save xpcshell test.
