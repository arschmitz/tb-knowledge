# Select an OAuth refresh token before constructing the OAuth object

If no reusable OAuth object exists, initialization reads stored refresh tokens before constructing a new object because the lookup can replace requested all-scopes with the stored grant realm. getRefreshToken returns the first matching origin-and-username login whose realm covers required scopes, or an empty string. It does not promise to choose the newest or widest token. Preserve the lookup-before-construction order; the existing synchronous event-loop bridge is observed code, not a recommendation to add new spinning waits. This is static source evidence. No runtime, build or live accessibility validation was run. Full bug and review discussion remains pending.

Scope: OAuth refresh-token selection order.
