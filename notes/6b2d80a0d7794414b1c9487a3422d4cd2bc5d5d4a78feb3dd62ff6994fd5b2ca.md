# Progress dialog arguments and message-window association are separate contracts

openProgressDialog takes a parent window, dialog URL and typed compose parameters. It passes the progress object and parameters directly as dialog arguments and uses fixed chrome/dependent/centerscreen options. sendMsg takes four caller arguments, ending with progress. Message-window association is still an explicit progress property or SetMsgWindow call; shortening the signatures does not remove that caller role. Historical status-feedback wiring differs from accepted source and does not establish a leak cure.

Scope: compose and shutdown progress API.
