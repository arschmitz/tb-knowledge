# OAuth provider activity arguments are validated and old aliases remain explicit

The accepted getHostnameDetails throws when type is missing and explicitly maps types beginning with owl to exchange. The Microsoft EWS branch returns the Exchange issuer and EWS required scopes, including offline_access in the supported scope set. In this API family, recommend preserving named compatibility aliases and validating the required argument at entry. An unrelated type can still work for string-only providers; only mapped providers reject an unknown activity. This is scoped manual guidance, not a rule that all optional arguments must throw. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: OAuth activity validation and alias.
