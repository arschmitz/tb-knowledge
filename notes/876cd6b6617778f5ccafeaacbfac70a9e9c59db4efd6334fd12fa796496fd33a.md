# Graph no-content batch replies default their body separately from status filtering

The landing adds a Default bound and serde default for missing batch response bodies. The mock returns204 for folder deletion and omits body when no JSON content exists. Request empty-body omission is a different serialization direction and is already documented. Generic parsing still occurs before the successful-status filter, so defaulting an absent body is not proof that every error body parses. Accepted direct requests separately turn zero response bytes into JSON null. These are static serialization contracts, not a tested HTTP or serde result.

Scope: Graph no-content batch responses and mock transport.
