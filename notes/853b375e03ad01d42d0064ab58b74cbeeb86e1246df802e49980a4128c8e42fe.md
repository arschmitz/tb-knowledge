# Copy-move resync state selects the item fallback path

The migration names new_ids and requires_resync in CopyMoveSuccess and converts that result for the operation listener. Item copy/move requests new IDs only after Exchange2010; otherwise the item fallback must sync for them. Folder operations return false for this item-resync route, while the source comment preserves the distinct folder-copy hierarchy sync. Accepted code later makes RequiresResync and UseLegacyFallback explicit enums. This flag is not evidence that folder copy never resyncs, and no server or ID-count test ran.

Scope: ews-copy-move-result.
