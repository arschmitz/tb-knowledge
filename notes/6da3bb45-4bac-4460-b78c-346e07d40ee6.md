# XPCOMUtils lazy utilities and native one-shot getter failures

Scope: privileged Gecko JavaScript utility plus its native lazy-getter bridge.
All local bodies in `XPCOMUtils.sys.mjs` were read. Preference observer behavior
has its own record. This extends the checked Thunderbird MailServices boundary.

`redefine`, lines 22–30, replaces a property with an enumerable, configurable,
writable value and returns it. `defineLazyScriptGetter`, 53–70, installs getters
for one or several names. Reading one loads the actual subscript into the target
object; the script must define the requested symbol. Its setter replaces the
property via `redefine`. The JavaScript script getter is distinct from the native
getter and has no identical one-shot state in this method.

`overrideScriptLoaderForTests`, 79–83, checks the automation-only guard, deletes
the lazy loader property, then assigns the supplied loader. `_scriptloader` at
415–417 otherwise lazily resolves `Services.scriptloader`.
`defineLazyGlobalGetters`, 97–108, reads the shared system global, imports a global
only if absent, and returns that global's value. `MessagePort` maps to the
`MessageChannel` import because that import exposes both names.

`defineLazyServiceGetter`, 123–127, installs a native `ChromeUtils.defineLazyGetter`
whose callback calls the actual `Cc[contract].getService(interface)` receiver.
The plural helper, 145–152, iterates entries and invokes this helper. No service
is requested during installation. It does not create an independent factory
instance per target; service ownership follows the component-manager boundary.

`defineLazy`, 345–371, treats strings as ES module URLs, functions as native lazy
callbacks, objects with `service` as service definitions, and objects with `pref`
as preference definitions. It registers accumulated module getters after the
loop and returns the same object. Service wins if both keys exist. There is no
rollback if a later invalid entry throws after earlier getters were installed.
`declareLazy`, 390–392, uses a new object. `defineConstant`, 406–412, creates an
enumerable, non-writable property; omitted `configurable` is false.

The native implementation was read at `ChromeUtils.cpp:927–1037,1156–1166`.
It retains target and callback in a reserved parameter array on the getter.
`JSLazyGetter` clears that parameter slot before calling the initializer. A
second access, recursive access, or a retained descriptor getter called after
initialization sees an undefined slot and returns `undefined` without running the
initializer again. On success, the value replaces the target property. On
initializer failure, it returns the exception without restoring the parameter
slot. Consequently a thrown service initializer is not automatically retried
by simply reading the same getter again at this revision. This statement applies
to this native getter, not to the separate preference getter implementation.

Direct tests: `test_chromeutils_defineLazyGetter` checks zero eager calls, one
initialization, the target as `this`, and cached values. `test_defineLazyGetter_name`
checks descriptor names for string-convertible keys versus integer/symbol keys.
`test_defineLazyServiceGetter` checks enumerable property parity with the directly
obtained console service. Those assertions do not directly check thrown
initializers, recursive initialization, every descriptor flag, script-loader
errors, or all `defineLazy` branches. Native allocation/binding failures and all
callers remain outside this module-level read.
