# MsgAuthPrompt.#promptPasswordInternal behavior in mailnews/base/src/MsgAsyncPrompter.sys.mjs

Rejects session mode, parses realm and decodes username. Label appears only for permanent saving allowed for origin. If no caller password and origin exists, finds first stored matching username, writes password and returns true without dialog. Otherwise opens password dialog. Saves only for accepted dialog, checked state, valid origin and truthy resulting password, and only if primary-password enforcement permits. Declining policy setup preserves dialog Boolean. Unlike username/password method, stored match returns immediately and never sets checkbox state.

## State read

- Save mode, origin permission
- Decoded username
- Caller password truthiness
- Matching stored login
- Dialog result/check

## State changed

- aPassword.value from saved login or accepted dialog
- New persisted login on save path

## Calls and triggers

- Own #getRealmInfo, decodeURIComponent, Services.logins search/add, local nsIPrompt_promptPassword, shared enforcePrimaryPassword.

## Result and consumers

Promise<Boolean>; true may mean stored credential supplied with no UI. Normal save completion waits for addLoginAsync. Synchronous wrapper consumes Boolean/output.

## Errors

Unsupported mode, malformed percent-encoding, URI, search, dialog or login-add failure reject. No catch/rollback; caller's password may already be changed.

## Async completion

Starts with synchronous guards, optionally awaits search, uses modal dialog, optionally awaits login write; no timeout/cancel.

## Ownership and cleanup

Local checkbox/new LoginInfo; caller owns password wrapper.
