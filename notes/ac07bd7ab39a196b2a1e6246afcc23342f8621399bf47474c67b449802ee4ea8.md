# Notification Axe watchers use distinct content and window cleanup paths

The content helper registers a finish callback through the available test cleanup hook, while window callers also retain and finish their watcher before clearing notification state. Finish disconnects observation and waits for a final check; the window path also restores the prior Axe property. The checked notification focus caller supplies an Account Hub dialog message despite watching the in-app notification root, so its diagnostic names a different UI. Actual cleanup ordering and native accessibility behavior were not run.

Scope: In-app notification browser tests / AxeHelpers watcher lifecycle.
