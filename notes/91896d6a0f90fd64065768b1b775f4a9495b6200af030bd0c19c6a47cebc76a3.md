# Outbound EWS rename waits for server success before changing local storage

The historical Rename dispatches a detached UpdateFolder request for folder:DisplayName. Only its successful response calls LocalRenameOrReparentFolder, which copies the hierarchy/data before deleting the old one and rejects name conflicts. Initial dispatch success is not completion. The fixed implementation now uses ExchangeFolder and generic listeners, with virtual folders handled locally. Review accepted a returned-ID fallback in an earlier iteration, but the final assigned callback does not receive that ID; opaque-ID behavior remains uncertain. Vendored XML tests do not directly assert C++ local rename, rollback or metadata preservation. No server or rename test ran.

Scope: Exchange remote/local rename.
