# Keep public priority values separate from message sort keys

MessageManager.convert maps only the five specific Thunderbird priority values to public names; other values become none. Priority sorting instead uses a separate _prioritySortKey and maps nonspecific values to Ci.nsMsgPriority.Default. Tag conversion and sorting follow the tag service's key order. Empty-tag keys use a 1: prefix, so empty groups appear last ascending and first descending; the local comment about the bottom does not describe both directions. Keep these sort keys separate from the public values, and check the explicit expected matrix when changing either path.

Scope: WebExtension messages API.
