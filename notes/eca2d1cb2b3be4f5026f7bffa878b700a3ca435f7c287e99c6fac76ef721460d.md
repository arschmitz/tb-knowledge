# Treat the mbox tail newline repair as a historical boundary fix

The 2025 landing checks whether the existing mbox is empty or ends in LF before appending a message. If not, it records missing_eol and writes CRLF before taking the new message start position. This repairs the separator boundary; it does not reconstruct missing message content. The fixed accepted store no longer contains that checker, probe or test task in the inspected paths. Current MboxMsgOutputStream adds an EOL to a newly written unterminated message, which is a different boundary. The reason for the older repair removal was not studied. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Historical mbox tail repair.
