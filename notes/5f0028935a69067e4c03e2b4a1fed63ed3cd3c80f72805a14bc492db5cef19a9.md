# S/MIME verification failure keeps the configured key while clearing the loaded certificate

The original changed failure branches stop truncating signing/encryption dbkeys or writing empty values back to the identity. They still clear the unusable loaded certificate and fail the send when that certificate is required. The accepted helper keeps these roles separate: a verification failure clears the certificate and returns a normal helper status, then the caller detects the missing usable certificate. DER-read failures remain errors. This is a bounded source contract, not a crypto result.

Scope: Thunderbird S/MIME send-time self-certificate verification.
