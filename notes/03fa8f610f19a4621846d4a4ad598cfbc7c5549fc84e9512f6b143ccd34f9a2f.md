# The Calendar saved-login result migration had a truthy failure branch

The saved-login helper changed from an object result to a Boolean consumed directly by promptAuth and asyncPromptAuth. One historical rejection branch still returns {found:false,username}, which is a truthy object and can incorrectly take the success path. Fixed #getPasswordInfo returns false on miss/rejected credentials and true after writing the password. The saved-login async path still dispatches the callback so the outer function returns first. This is a static historical contract mismatch, not a reproduced authentication failure or a claim the defect remains in fixed source. Cancellation and later request-scoped/provider-username work remain separate.

Scope: Calendar authentication result contracts.
