# A borrowed NTLM output slice does not show ownership of the native allocation

The owned helper receives a raw output pointer from GetNextToken, borrows it with slice::from_raw_parts and base64-encodes the borrowed bytes into a String. It does not construct an owning wrapper or call a deallocator. Its comment that Rust automatically frees the native output is therefore unsupported by the shown ownership path. Keep this historical source concern separate from the accepted implementation, where the helper path is absent. No measured leak, allocator choice or current defect is claimed.

Scope: Historical EWS NTLM raw buffer handling.
