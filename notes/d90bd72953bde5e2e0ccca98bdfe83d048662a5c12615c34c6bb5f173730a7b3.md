# Header reconstruction consumes its finished core map after duplicate lookup

The reconstruction pass borrows core while checking InternetMessageHeaders for duplicates. Once that collection ends, headers.extend(core) consumes the finished map directly instead of cloning every key/value into another iterator. The review requests this change and the original and accepted source adopt it. This is an owned-value choice in this function, not a general rule against clones or a measured performance result.

Scope: ews-header-block-rust-style.
