# Distinguish a browser owner document from the document loaded inside it

Correction to lesson 602803de772600e9a13c1b6280eae66d91c67603c9856661b6c0a5a84ca8a320: entry 1255 (cc88df87b0617125418eeb19157fc50ae1238a54) replaces browser.webProgress?.isLoadingDocument with browser.ownerDocument.readyState != "complete" in five test files. It also adds missing/current about:blank URI guards where absent and changes some browserLoaded URL arguments. It does not replace contentDocument null checks. The inspected accepted predicates still read the document that owns the browser element; that readiness alone does not establish the inner page has completed loading. The extension awaitBrowserLoaded helper separately checks loading state, current URI and the caller’s URL predicate. When editing these waits, inspecting both inner load state and expected URL is a scoped recommendation, not a reviewer-approved universal replacement or a reproduced race diagnosis. Existing supported owner-versus-inner distinction remains. Exact historical diff and bounded accepted source were checked; no browser tests, build, lint or live accessibility validation ran. This additive source-fact correction preserves the old immutable record and changes no deliberate guidance.

Scope: mail/base/test.
