# The deepCopy NaN assertion checks the input instead of the copied result

The new primitive-value loop calls deepCopy in its ordinary branch, but its NaN branch asserts Number.isNaN(value) directly. The message says the helper should return NaN, while that branch never calls the helper. The accepted test retains this coverage gap. A focused test correction should check the copied result and keep a nonempty expected-behavior message. Other clone checks establish separate top-level, array and nested-object identities; they do not make this generic helper preserve arbitrary object prototypes or non-enumerable fields.

Scope: Thunderbird account-creation utility tests.
