# CalDAV refresh routes ACL, collection tags, queued queries and observer completion

CalDavCalendar.safeRefresh:1321–1429 first obtains ACL entry through the actual
aclManager callback, stores returned detail, fills organizer properties and
recurses. That callback does not check operation status. It ensures backing
storage. Digest mode performs synchronous OPTIONS before refresh; open occurs
outside the response-status try/catch, and status failure notification does not
itself stop later refresh work. Those failure paths need separate runtime checks.

No ctag, first refresh or WebDAV support starts getUpdatedItems immediately.
Otherwise a PROPFIND checks CS:getctag. Status -1 and non-ok responses notify
NS_OK here; 404 notifies failure. A changed/missing ctag stores proposed ctag
and fetches remote items; equal ctag notifies completion and may poll inbox.
Transport rejection reports DAV_REPORT_ERROR and uses finally to notify failure.
getUpdatedItems:1466–1514 chooses actual WebDAV sync handler or ETag listing
handler, and rediscovery when disabled. URI, token, capability and disabled state
control this choice; a method name alone does not identify the implementation.

getItems:1241–1287 directly delegates to storage for cached or ready provider;
uncached pre-discovery calls produce bounded streams retained in mQueuedQueries.
The queued query itself does not start refresh. Its onStream reads backing chunks;
onError reports a failed stream. No source cancel/removal of that queued request
was established here. finalizeUpdatedItems:1126–1160 first calls changelog success
or onLoad, then commits proposed ctag, sets firstRefreshDone, starts queued
queries in reverse arrival order, and polls inbox when applicable. Completion
notifications precede those last state changes; queued stream consumption is
not awaited. notifyGetFailed:1170–1191 fails changelog/operation and drains queued
queries through onError.
