# AsyncShutdown integration does not make IMAP exit cleanup asynchronous

The accepted CleanupOnExit still waits for IMAP inbox cleanup and empty-trash flags using bounded monitor waits and pending-event processing. The comment describes a roughly five-second stop for each wait, and cached connections are closed before network shutdown. The introduction of a shutdown blocker in 1212 is therefore not proof that those operations became promise-based asynchronous work. This is a source-only timing/ownership observation; actual durations, cancellation and shutdown responsiveness were not measured. Full bug and review discussion remains pending.

Scope: Account-manager exit cleanup.
