# EWS folder deletion keeps remote success before local hierarchy removal

Entry 1487 refuses non-deletable root/special folders, requests remote HardDelete and calls the base DeleteSelf only after the success callback. The accepted folder implementation keeps the hard-delete callback ordering, while virtual folders and soft deletion have distinct current branches. For this folder protocol boundary, recommend retaining remote-success-before-local-removal in the hard-delete path; do not describe the historical direct DeleteSelf implementation as the entire current deletion policy. No remote folder deletion, retry, permissions or local hierarchy test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange folder hard-delete completion.
