# Compose envelope edits must mark the draft dirty

Changing identity after startup sets gContentChanged. Editing the editable From field also sets it through its input handler. The close check and AutoSave read gContentChanged as well as bodyModified, so changing the envelope must not rely on an editor body mutation. LoadIdentity returns early during startup, which avoids treating initial selection as a user edit. Manual state and test proposal for this compose path: exercise selected-identity and typed-From changes through their actual controls, then check close/save behavior. The 2024 reply-identity test adjustment accounts for a modified compose window; it is not a complete regression test for saving and reopening a draft after typing in From. Current reply matching tests likewise do not prove that persistence path.

Scope: compose-drafts.
