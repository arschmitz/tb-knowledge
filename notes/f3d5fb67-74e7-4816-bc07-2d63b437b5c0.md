# ICS local writes call Gecko IOUtils for temporary-file replacement and promise settlement

Cross-repository chain: Thunderbird CalICSCalendar.sys.mjs:485–504 reads file
permissions, creates a unique file next to destination and passes its returned
path to IOUtils.writeUTF8 as tmpPath. Its checked caller record is
[ICS serialization and completion](1493e123-1336-4136-be3e-8ebca7322420.md). Native source is Gecko C++ with
Chrome-only WebIDL; tests are chrome mochitests, not Thunderbird xpcshell tests.

IOUtils.cpp CreateUniqueFile/CreateUnique, 973–1024, validates parent, appends
prefix and dispatches CreateUniqueSync. That helper, 2204–2223, calls actual
nsIFile.CreateUnique and returns the created path string or contextual error.
Permissions are supplied by the caller. The file already exists before writeUTF8.
Native nsLocalFile platform implementation is still an external scope here.

WriteUTF8, 610–643, creates a JS promise/state, initializes destination path,
converts options, copies the UTF-8 string and owns file/options in a dispatched
closure that calls WriteSync. InternalWriteOpts::FromBinding, 3093–3133, resolves
backup and temp file paths and keeps flush/mode/compress/encrypt flags. It rejects
encryption with append modes. ICS uses default overwrite, flush=false,
compress=false, empty encryption and no backupFile option.

WriteSync, 1493–1706, runs off main thread, stats destination, rejects create-mode
overwrite, optionally moves old destination to backup, chooses temp or destination,
selects OS flags for mode and optional PR_SYNC, applies optional compression then
encryption, opens output stream and writes bytes in chunks. Stream lifetime ends
before moving temp to destination. Directory destination is rejected explicitly
for temp writes. Different temp/destination paths invoke MoveSync; success returns
totalWritten bytes. Errors retain their cause and reject; no unconditional temp
deletion appears in this helper.

MoveSync, 1709–1733, checks source exists then calls CopyOrMoveSync with the actual
nsIFile.MoveToFollowingLinks member. CopyOrMoveSync, 1782–1868, handles existing
directory versus file target, noOverwrite, source-directory mismatch, obtains
parent/name and invokes the platform member. In the ICS same-parent use, intended
replacement occurs after complete temporary write. This note does not certify
every platform rename, symlink race or power-loss behavior. flush=false is not
an explicit request to force all OS buffers to stable storage.

WithPromiseAndState/DispatchAndResolve, 317–357, requires parent process, creates
promise, rejects during shutdown, and keeps worker alive when called there.
EventQueue::Dispatch, 2678–2696, owns operation/promise in background runnable;
Then returns result to original serial event target. ResolveJSPromise/RejectJSPromise,
186–271, settle with value or a DOMException category. GetState, 2509–2553,
lazily owns a shared queue and registers shutdown hooks; full shutdown phases
are not all analyzed here. The public write promise resolves with byte count
after native write/move, not with a Calendar item or a notification result.

Direct generic tests: test_ioutils_read_write_utf8.html:48–182 checks create-mode
refusal, expected final contents, byte counts, backup contents and temp removal
on successful temp write. 199–228 checks multibyte UTF-8 bytes/content; remaining
read/encoding tasks were also read. test_ioutils_create_unique.html:23–76 checks
prefix, existence, type, permission expectations and unique directory paths,
with cleanup. read_write.html:120–214 covers temp/backup/append content; 414–429
checks directory rejection with/without temp and absence of a misplaced nested
file. Helpers read actual bytes/text rather than comparing filenames alone.
All are registered in chrome.toml. They were read, not run in this pass.

These are direct tests of native generic results, but execution-only links to
the Calendar caller contract. They do not prove ICS handles native write failure,
cleans every reserved file, balances survival area, cancels queued writes, or
preserves destination under injected partial-write failure. Those gaps remain
explicit rather than borrowing a generic test's pass as caller proof.
