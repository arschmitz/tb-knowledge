# EventUtils Escape spelling and production XUL keycodes have separate scopes

The small test migration changes EventUtils.synthesizeKey's argument to KEY_Escape while retaining an explicit requestWindow target and cancellation wait. The production browser-request keyset still declares keycode=VK_ESCAPE and routes it to cancelRequest(). The test API string does not by itself prescribe a replacement for a XUL keycode attribute. The actual engine key resolver remains a bounded dependency; no native equivalence or keyboard run is claimed.

Scope: Browser-test keyboard input.
