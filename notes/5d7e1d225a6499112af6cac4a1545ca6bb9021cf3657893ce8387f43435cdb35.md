# Verify permission keyboard actions through the real input and buttons

The URL label names the input through control="url", and the input sends keypress to onHostKeyPress. Return activates btnAllow; the window Escape handler closes the dialog. The inspected remote-content test types into the input and clicks Allow, so it does not demonstrate the Return or Escape paths. Scoped test proposal: check those keys and the intended initial focus using the actual dialog controls. Source markup and handlers are evidence of wiring, not proof of spoken labels or usable focus. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: permissions dialog keyboard checks.
