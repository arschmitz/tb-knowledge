# LDAP advanced-form tests assert visibility and wait for the state that changes

The accepted LDAP test waits for the advanced class with attributes:true and attributeFilter:[class], then wraps isVisible/isHidden results in Assert.ok with nonempty expected-behavior messages. This matches the widget's class toggle instead of treating a synthetic click or an unasserted visibility query as the final result. Each captured advanced input is checked in a for-of loop. The local scroll workaround is separate: it retries click, scrollBy(900) and a tick while the Advanced button is hidden; it has no explicit local bound and is not the proposed elementFromPoint hit-test loop. Keep this scoped test pattern distinct from a general loop/wait rule, production behavior or a live accessibility result. No browser test ran.

Scope: Account Hub LDAP browser-test assertions and waits.
