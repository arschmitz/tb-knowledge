# Bulk body contracts keep classic-script caller targets and runtime tags unresolved

## Correction scope

The 1,125 narrow body-fact notes in knowledge commit `98ee5bf35e367154ad9dd26e1ca9b7743b96d341` remain evidence of primitive/undefined/parameter return bodies. Their local lexical call sites are candidate references under a parser mode, not verified runtime call targets. This correction applies to the 29 recorded lexical sites and to runtime metadata inferred from `.sys.mjs` suffixes. It does not replace the local body return claims or establish a code rule.

`extractDirectBodyFacts` tries module parsing before script parsing. A successful module parse does not prove that a `.js` file loads as a module. Classic-script globals can be replaced by another script or through the global object. The binding resolver also filters definitions to narrow-fact functions before checking for one target; multiple definitions with only one narrow function can therefore leave an unsupported target attribution. Treat actual targets as unresolved until loading, all definitions, writes, and relevant callers are checked.

Runtime suffix labels are path-based hints. They do not prove a loader or privilege level. The source configuration and consumers must establish runtime before a change relies on it.
