# A negative navigation assertion needs an observed navigation signal

The current notification-button test declares loadedUri as false, resets it to false and asserts it stayed false, but the inspected whole test never updates it from the mocked external protocol service. That flag alone cannot prove that navigation was blocked. The implementation separately calls preventDefault, and the test checks the custom event properties. Proposed manual test rule: connect a negative assertion to the actual rejected side effect, then verify the observation hook can detect it. The axe observer in the test is a test setup, not an accessibility pass from this source study.

Scope: Notification test observability.
