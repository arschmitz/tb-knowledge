# Calendar manager creation, registration, refresh, and removal

## Provider creation

`CalCalendarManager.createCalendar(type, uri)` first checks the component contract for the requested provider type. If none exists, it checks `providerImplementations[type]`, constructs that provider, and requests `calICalendar` when the provider offers `QueryInterface`. It sets the URI before returning the calendar.

If neither source supplies a provider, it returns `null` without opening another error dialog. A construction exception is logged and shown through the calendar error prompt, then the method returns `null`. Callers must handle the missing result. Creating an object is separate from registering it.

## Registration and stored state

`registerCalendar(calendar)` ensures the cache exists, assigns a UUID when the calendar has no ID, and rejects an ID already in the cache. It stores the type and URI under `calendar.registry.<id>.`, wraps the calendar when caching applies, calls `setupCalendar()`, flushes preferences, requests an eligible refresh, and sends `onCalendarRegistered`.

`setupCalendar()` stores the calendar, attaches its manager observer, updates network/read-only/total counts, and sets a refresh timer. `requiresNetwork` counts as a network calendar unless the property is exactly `false`; absence is not treated as false.

`calendar-creation.js` supplies a real caller: `registerLocalCalendar()` passes `prepareLocalCalendar(gLocalCalendar)` to `cal.manager.registerCalendar()`. The manager owns registration state, not the creation dialog.

## Timers and removal

`setupRefreshTimer()` uses 30 minutes only when the provider's interval is `null`. It clears an earlier timer first. Positive intervals create repeating slack timers in milliseconds. Zero or negative intervals do not create a timer. Do not replace the null check with a general false-value check: zero has different behavior.

`unregisterCalendar()` sends `onCalendarUnregistering`, calls `unsetupCalendar(calendar, true)`, deletes its preference branch, and flushes preferences. `unsetupCalendar()` removes the cache entry, handles cached-calendar unregister work, removes its observer, updates the counts, and cancels its timer.

`removeCalendar()` also checks the provider's `capabilities.removeModes`. Unsubscribe and provider deletion are different operations. The `REMOVE_NO_UNREGISTER` and `REMOVE_NO_DELETE` flags change which work is allowed. The method rejects leaving a registered calendar while requesting removal without unregistering it.

The registration sequence was read, but provider-specific deletion and every observer implementation were not traced. Do not infer that unregistering always deletes remote calendar data.
