# The hostname migration leaves changed direct assertions without expected-result messages

The inspected historical patch changes the hostname operands in 12 direct Assert.equal calls but leaves those calls without a message argument. The shared import assertion and fixed accepted server-store examples retain the same absence. Under the current explicit assertion guidance, each in-scope call needs a nonempty message stating the expected behavior. This finding concerns the changed calls and the actual assertion API; it does not treat a missing should alone as a defect, rewrite unrelated assertions, or claim that the rename fails at runtime.

Scope: incoming server tests.
