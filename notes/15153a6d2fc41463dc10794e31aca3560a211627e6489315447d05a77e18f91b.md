# Selecting an existing preferences tab bypasses the new completion resolver

openPreferencesTab creates a promise whose only resolve call is in its new onLoad callback. The preferences existing-tab branch selects a pane and returns an index without that callback; tabmail.openTab then returns the existing tab before new-tab setup. The inspected path leaves this specific new promise unsettled, so an awaiting Dock Options call has no continuation from that path. This is a bounded static completion gap, with no reproduced hang or claim about every tab-opening route.

Scope: Preferences tab promise completion.
