# Status messages use a bounded FIFO so a completion message is not immediately replaced

Accepted showStatusString displays immediately only outside its minimum display interval with no active interval. Otherwise it queues up to ten messages and drains one every 750 ms. Those values belong to this status component, not a general timing rule. _stopMeteors requests an empty status through the same queue rather than forcibly replace a pending completion message.
