# Keep expected folder contention distinct from unexpected batch-add failure

In the Panorama AddMessageBatch2 path, NS_MSG_FOLDER_BUSY returns before NS_ENSURE_SUCCESS. The reviewer asks whether the checks are equivalent; the author explains that expected contention should stay quiet while other failures should warn. The landed and fixed code preserve that order, and construct the semaphore-release scope guard only after acquisition succeeds. This is the error-reporting contract of this path, not a blanket rule to suppress busy errors or warnings everywhere. No contention test ran.

Scope: Local message batch storage.
