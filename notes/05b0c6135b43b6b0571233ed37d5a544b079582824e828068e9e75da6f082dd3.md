# Account Hub input properties and initial attributes have different forwarding contracts

The wrapper keeps native input internals private and forwards value and valueAsNumber through public getters. The landing uses light DOM and drops copied-event forwarding. Only localization IDs are observed; initial optional attributes copy truthy strings, which skips an empty-valued required attribute. Accepted source later adds a required setter that mirrors the native field, and the outgoing-username caller uses it. Actual templates use required="required". Attribute mutation and property assignment are separate paths; no form failure or event run was reproduced.

Scope: Account Hub custom input public interface.
