# Use identity assertions when a test promises to retain an object

The IRC join test uses strictEqual for the retained room-field object and returned conversation. The string-parser tests use deepEqual for the produced field values. These assertions check different contracts: an equal copy can still violate identity used by reconnect and later password changes. Manual test style proposal for retained mutable objects: use an identity assertion for the retained object, then use value assertions for its contents and mutations. This is supported by the current IRC tests and related parser tests, not a blanket rule that every test must use strict equality.

Scope: tests.
