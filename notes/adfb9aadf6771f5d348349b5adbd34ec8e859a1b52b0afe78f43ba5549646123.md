# Keep migration tasks sequential while allowing the queue to grow

Current MigrationTasks uses an index loop over live _tasks.length because task actions may add more tasks. Each action is awaited; one subtask level is awaited and status/progress emitted. Replacing this with a captured map/parallel Promise.all could lose late tasks or change ordered migration behavior. The source comment explains why the loop is intentional; no migration run occurred.

Scope: mail/modules.
