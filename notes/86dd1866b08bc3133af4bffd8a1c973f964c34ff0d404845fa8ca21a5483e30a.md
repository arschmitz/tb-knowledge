# Register QR dialog expectations before clicking and await the changed UI

1187 makes showCodes async, so accepted success tests create expectPasswordPrompt before synthesizing the click, await the prompt and wait for the Codes hidden attribute to show that the step changed. The step-through test explicitly disables password inclusion to isolate wizard navigation. Scoped test recommendation: await the dialog and the affected UI boundary rather than asserting the next step immediately after a click. No dialog or mutation ran in this study. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.
