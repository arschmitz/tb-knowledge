# Use unique operation names for cached Panorama statements

DatabaseCore::GetStatement returns a cached statement based on aName and does not compare the supplied SQL on reuse. Current folder mutation methods use operation names such as UpdateFlags and Reparent with named bindings and mozStorageStatementScoper. For this cache, choose a unique key for a distinct SQL statement and preserve parameter binding/reset lifetime; reusing a key for different SQL would retrieve the original statement. This is a scoped manual API recommendation based on current code, not a project-wide SQL formatting rule. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama cached statement keys.
