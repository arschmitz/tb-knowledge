# Let the owning message window confirm and advance deletion

741 delegates shift-delete from a nested about:message to the parent about:3pane before showing the confirmation. The parent owns advancing the selection to the next message; the standalone message window retains its own confirmation and update path. Placing a confirmation in both layers caused the reported double prompt. Current command routing retains the early delegation. Cached summaries mention the symptom and a focused-pane test, but do not preserve complete review requests or establish a runtime result.

Scope: Message deletion ownership.
