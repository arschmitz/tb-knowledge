# Telemetry object keys and generated metric names occupy different naming layers

In this account metric, account_preferences in metrics.yaml becomes Glean.mail.accountPreferences in JavaScript, while object property keys such as socket_type and check_new_mail stay snake_case and match the schema. For this payload, keep those exact field names in the collector and deep-equality tests. This is a scoped generated-API naming pattern; it does not justify converting ordinary JavaScript properties to snake_case or renaming an existing generated metric. Source and tests were read but not compiled or run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account preference telemetry naming.
