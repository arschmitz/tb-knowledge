# Calendar creation skips IDs from the initial registered-calendar snapshot

The selected-calendar loop gets registered calendars once, then uses some() to skip rows with an ID already in that snapshot. CalCalendarManager.getCalendars builds a new array; registerCalendar still rejects an ID already in its cache. This prevents a second registration of those existing calendars. It does not establish deduplication among two new selected rows or refresh the snapshot after registration. The landed Boolean membership check applies the review request to use some instead of find; keep find when its matching value is needed. Exact fixed source and the full three-file landing were inspected. No registration or browser test ran.

Scope: Calendar discovery registration.
