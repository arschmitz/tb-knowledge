# The EWS fake UpdateItem response has one result per requested change

The fake response base now has an empty ResponseMessages element, and the ItemChange loop appends a separate Success/NoError response with its item ID. This matches the read-state client response-count check; one shared response bag would be a different shape. The changed tests wait separately for server acknowledgement and local unread count. The fake still constructs success results and does not add mixed-item failure coverage. No fake-server or protocol test ran.

Scope: EwsServer UpdateItem response cardinality.
