# Alarm preference text entry yields before callers check the saved values

The owned alarm test scrolls menus and text fields to block end. Its text helper becomes async and yields one tick after typing; callers await event and task entries in order before comparing saved preferences. Accepted browser_alarms.js retains this sequence and menu popup shown/hidden waits. A tick is not an explicit preference-write or visibility condition, and the local scroll change does not alter the production pane helper. No headless or UI test ran.

Scope: calendar-tests.
