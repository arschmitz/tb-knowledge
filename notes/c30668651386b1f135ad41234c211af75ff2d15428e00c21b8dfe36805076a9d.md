# Avoid repeated sorting in the cached thread new-message count

The performance fix removes Sort from each thread’s InitCachedValues after the earlier new-message count implementation. Current code clones the database new list and uses ContainsSorted while counting thread children; the initial scan for m_numNewChildren is guarded by m_cachedValuesInitialized. This removes the repeated sort from the per-thread initialization path. It is source evidence of the changed work, not a measured benchmark or a guarantee about every database/view implementation. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Legacy thread cached new count.
