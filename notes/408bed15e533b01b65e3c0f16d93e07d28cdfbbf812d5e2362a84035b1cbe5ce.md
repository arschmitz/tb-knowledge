# Calendar context migration reaches mail fragments and their owning documents

The original Calendar context migration removed conversion DTD entities while mailContext.inc.xhtml and msgHdrView.inc.xhtml still referenced them at that revision. The later accepted message-header fragment uses Fluent IDs, and its owning aboutMessage document loads calendar/calendar.ftl; about3Pane also loads that resource for included mail markup. A fragment migration must be checked with its real document consumers before calling the change behavior-neutral. This exact add/backout study does not audit the later reland or prove platform/browser behavior. No runtime or migration test ran.

Scope: Calendar Fluent migration and Thunderbird document resources.
