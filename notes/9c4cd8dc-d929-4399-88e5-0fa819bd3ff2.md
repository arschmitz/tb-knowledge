# Console retrieval follows the task through workflow phases

This provisional implementation separates a focused knowledge request from the
complete agent task contract. It applies to tb-tools console task retrieval.
It is implementation evidence, not a new shared instruction or style rule.

## Observation and change

Searching a workflow prompt can spend the bounded search terms on general
instructions. Checkout-wide changed paths can also describe work outside the
selected task. The implementation now constructs `knowledgeRequest` from the
bug, selected patch, specific review comment, current human guidance, or failed
job. The request carries the question, task type, paths, symbols, selected
revision, and explicit filters. Repository identity still comes from the actual
checkout. The complete original task remains in `knowledgeQuery` for evidence
checks and private capture.

Implementation, review, patch update, verification, Try repair, and rebase callers
supply task data before adding workflow instructions. The same request survives
preparation, evidence review, writing, and final review. A new implementation does
not inherit the files changed by its base commit. A selected patch uses its own
commit paths. A follow-up action uses the selected comment, even if the displayed
comment index differs.

The question, symbols, and paths each receive a separate bounded exact search.
Each search retains the existing 80-term bound. Paths receive half the question
or symbol weight. Repeated matches do not increase the record's authority.
Standalone searches keep their previous behavior. Semantic retrieval receives
the focused task query. Explicit filters still control exclusion.

Private observations preserve the normalized request and effective query parts.
Gap grouping distinguishes different task scope. Scheduled checks replay those
parts. A question shortened by the 6,000-character limit cannot automatically
close its original retrieval gap.

## Validation and limits

- The related Node test run passed all 324 cases. Three monitor cases initially
  could not bind their localhost server under the sandbox; all three passed with
  local server access. External model/API calls were blocked by the test preload.
- An independent assistant reviewed the final task-specific changes and ran 34
  focused tests. All passed. The review found no concrete correctness defect;
  it remains assistant judgment.
- ESLint passed on the changed JavaScript files. Git whitespace checks passed.
- Regression cases cover long workflow prompts, crowded question terms, separate
  path and symbol searches, unrelated checkout changes, selected comment actions,
  request preservation through phases, explicit scope, saved query replay, and
  refusal to resolve a gap whose task question was truncated.
- This validates query construction, routing, retrieval fixtures, and replay.
  Better answers from live tasks and lower full-library latency were not measured.
  No live AI task was started for this validation. The work does not add multiple
  source sections per record, a new vector index, or a complete-task evaluation.
