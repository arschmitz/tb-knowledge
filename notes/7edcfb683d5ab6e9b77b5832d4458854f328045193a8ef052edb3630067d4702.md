# Compare telemetry event extras as strings in secure-message tests

The old encrypted-event filter used e.extra.is_encrypted as a truth test. Both "true" and "false" strings satisfy that condition, so it could count an event whose encrypted value was false. Entry 2039 compares the extra with "true" explicitly. The frozen test now compares both is_signed and is_encrypted with String(expectedBoolean), checks exactly one event for each technology/state combination and checks the total secure-event count. Preserve the wire representation in assertions even when the record call takes Booleans. The historical subject/body reports misleading passes and reload effects; those logs and intermittent failures were not independently reproduced. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: Secure-message telemetry extra representation.
