# Virtual-folder migration depends on new-database state and an existing folder hierarchy

nsMsgAccountManager calls migrateVirtualFolders after account folder hierarchy initialization. EnsureConnection sets sDatabaseIsNew only when it creates the profile database, and the migration returns early otherwise or when virtualFolders.dat is absent. Eligible definitions resolve an existing parent before creating a virtual child; smart-mailbox/tag definitions are skipped. Fixed code later stores resolved scope IDs in virtualFolder_folders and keeps searchStr/searchOnline properties. Missing-parent/add failures continue to later entries; unresolved scopes and unchecked final writes mean NS_OK is not a complete-migration guarantee. The method does not clear the created-session flag. The inspected fixture asserts populated folders/wrapper/table state, not repeated-call, skip or error recovery. No migration or test ran.

Scope: Panorama virtual-folder migration.
