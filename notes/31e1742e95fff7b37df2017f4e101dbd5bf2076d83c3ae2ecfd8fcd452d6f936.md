# A folder deletion callback can arrive after its view closes

DBViewWrapper.close clears _underlyingFolders to null. FolderNotificationHelper.folderDeleted iterates a cloned wrapper list, so callbacks can still reach a wrapper whose state has closed. _folderDeleted handles Trash and the displayed folder first, then returns if _underlyingFolders is absent. A live empty backing-folder array follows a different path and closes the view. Keep those states distinct when changing deletion handling. No crash or runtime test was reproduced.

Scope: DBViewWrapper lifecycle.
