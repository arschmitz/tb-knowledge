# Store support and empty compaction batches have distinct outcomes

Current mbox reports compaction support true; Maildir reports false. Shared AsyncCompactFolders filters unsupported stores and still begins an empty BatchCompactor; its documented contract promises a completion listener for an empty list, no start listener, no callback before return, and no callback if the call returns failure. Preserve these distinctions when testing Exchange CompactAll with an unsupported store or no candidates. This is source/documented-contract inspection, not an executed callback order guarantee for a modified implementation. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.

Scope: Exchange compaction callback contract.
