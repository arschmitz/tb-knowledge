# Early Gmail Trash failures and expunge failures have different exits

The inspected Gmail path falls through to ordinary StoreFlags when COPY fails, a destination UID set is missing or selecting Trash fails. Once it reaches UidExpunge, a reported command failure is logged, the original mailbox is selected and the branch breaks; it does not enter that earlier fallback. Proposed failure-path tests should distinguish those stages, including source-mailbox restoration. No failure injection was run, and no all-command transactional rollback guarantee is inferred. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Gmail deletion failure stage boundaries.
