# Keep the surviving draft notification action and its window-reuse assertion

MsgComposeDraftMessage still forwards Draft with the activating event. setDraftEditMessage creates an Edit button with an access key and returns true from its callback to retain the notification. The current draft test registers its compose waiter, clicks Edit, then clicks it again and asserts that the original compose window gains focus without increasing the window count. Preserve that specific reuse expectation. The test was read, not run; it does not check keyboard activation or announcement of the notification. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.
