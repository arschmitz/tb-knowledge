# The LDAP overflow callback object does not match the search and SASL terminal receivers

The overflow path calls pending callbacks with a plain result object carrying resultCode -1. The inspected search receiver switches on response constructor names and the SASL receiver handles only in-progress or success codes, so neither converts that object into a terminal listener notification. The overflow path closes the socket without calling its explicit onError path, while onClose only logs. This limits the comment's claim that higher layers cannot hang; it is a static notification concern, not an observed hang, exploit or cure.

Scope: LDAP overflow callback receiver gap.
