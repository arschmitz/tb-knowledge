# EWS copy and move propagate response errors before extracting new IDs

The old copy/move ID conversion skipped individual response errors after logging them. The generic response_into_messages conversion now collects Result values before ID extraction, returning the first error; warnings still log and become successful typed messages. Current move_generic retains this order. It prevents a success result from that conversion when an error exists, while it does not roll back server changes or establish transactional batch behavior. A separate historical count change accepts the first of multiple single-operation responses with a warning. No move, copy or response test ran.

Scope: EWS copy/move response completion.
