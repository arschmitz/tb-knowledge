# Graph request generation enables filters from resolved query-parameter metadata

The owned loader reads component parameters before operations and resolves a parameter reference by its last path component. Missing keys panic; inline parameters still parse directly. Extracted location metadata reaches predicates that require both $filter and in=query, then field/default/trait/URI templates emit matching support. Six inspected collection/delta Get outputs gain filtering; singleton outputs only change selection handling. Empty selection no longer emits a select pair, although the original URI template still adds a question mark for an empty parameter string. Current generator predicates retain the metadata condition. The existing loader body/section limits are reused separately; no external schema or generator run was verified.

Scope: Graph OpenAPI parameter loading and generated filter methods.
