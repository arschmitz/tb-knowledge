# Notification endpoint telemetry records a user preference override

The mail.inappnotifications.url labeled Boolean records !prefHasUserValue. It does not compare formatted endpoint strings or report whether notifications are enabled. _getUrl separately expands %IAN_SCHEMA_VERSION% and URL formatter placeholders. init records the Boolean even when it returns cached data; the lazy preference getter records later preference changes. The enabled label is separately set from the enable preference during messenger startup. A same-string user override remains a user value. Keep that distinction in metric descriptions and assertion messages: the current init-user test says notifications are disabled, but its assertion checks only endpoint preference provenance. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.
