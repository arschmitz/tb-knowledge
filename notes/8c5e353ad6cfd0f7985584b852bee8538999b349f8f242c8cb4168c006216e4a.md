# Message display completion is not a proof of selected message identity

The removed plan_for_message_display helper was empty. Its remaining wait_for_message_display_completion helper yields a tick, waits for about:message and a non-loading browser, and requires only a nonblank URI when loadDemanded is true. It returns early for multiselection or a collapsed message pane. Proposed test rule for consumers: when the next assertion depends on a particular message, also check that message identity. This is a static helper-contract limit, not a reproduced stale-message race. Complete Bugzilla and historical Phabricator timeline/inline discussion remains pending.

Scope: mail / test.
