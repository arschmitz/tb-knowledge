# MIME failure must survive the encrypted-content wrapper as null

MsgHdrToMimeMessage documents a null MIME result on failure. By default its callback wrapper strips encrypted contents, and stripEncryptedParts now returns null for a missing input instead of throwing while reading parts. It clears an encrypted container rather than exposing its children; examineEncryptedParts explicitly bypasses stripping. The existing S/MIME test checks both the empty encrypted container and the opt-in attachment content. Manual callback proposal for this path: preserve the upstream failure value through privacy filters and document it in both helper and public callback contracts. These existing encryption tests do not test the newly guarded null failure. This is not a rule to silently convert arbitrary exceptions into null.

Scope: mime-callbacks.
