# Live-view mutation assertions need expected-state messages

The shared ListenerTree checks callback state and expected indices/deltas without assertion messages. Added mutation cases also omit messages on scalar, Boolean and array assertions. The surrounding comments and named tasks do not supply the assertion API's message argument. Under the direct review requirement, these changed assertions need nonempty messages that state the expected row or callback state. The reset failure assertion already has such a message. This is a test-diagnostic finding, separate from whether the add/remove implementation is correct or the tests passed.

Scope: Panorama mutation test diagnostics.
