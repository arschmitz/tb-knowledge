# ICS connection failure and restoration change notification and provider state

Observed production trigger: stream download reports failure while currentStatus
was NS_OK → ConnectionNotifications.connectionFailed → native alert service;
provider notifyError sets READ_FAILED. Later successful stream completion with
non-OK state sets NS_OK and calls connectionRestored with the same calendar ID.
Source: CalICSCalendar.sys.mjs:363–383. This directly identifies actual caller,
state guard, consumer and result; no matching-name link is assumed.

Every body in ConnectionNotifications.sys.mjs (90 lines) was read. It creates
nsIAlertNotification through a Components constructor and owns the alerts-service
singleton. connectionFailed, 31–79, returns for successful codes, maps specific
host/refused/timeout/reset/interrupt failures to message keys, and shows only
mapped failures. It formats the hostname into messenger.properties, uses ID as
alert name, title as calendar name, empty image on macOS or branding image on
other platforms, and silent=true. connectionRestored, 87–89, closes alert by ID.
Native alerts implementation remains an external Gecko/platform boundary.

Actual message consumers: messenger.properties:219–229 defines unknownHostError,
connectionRefusedError, netTimeoutError, netResetError and netInterruptError.
This is string-bundle localization, distinct from the conflict dialog's Fluent
IDs. Provider errors not in this mapping still change provider status but do not
receive an alert from this helper.

Direct tests: providers/head.js runConnectionError1 (156–202) closes server after
calendar load; waits for mock alert; checks image, exact calendar title, hostname,
refused-connection text and READ_FAILED. Restarts server, refreshes, waits for load
and alert closure, checks NS_OK. runConnectionError2 (208–251) creates calendar
with server already down and checks the same failure/restoration behavior.
Both cached and uncached ICS files invoke these helpers. A short fixed delay
remains in the helper after alert display; this does not establish all background
work is finished in every harness. MockAlertsService replaces system alerts, so
green tests check content/calls, not real operating-system notification delivery.
