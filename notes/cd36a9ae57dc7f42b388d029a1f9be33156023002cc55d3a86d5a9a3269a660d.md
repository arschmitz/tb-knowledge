# The scripting test now uses scripting.executeScript for both code and file injection

The file case in testExecuteScriptViaScriptingAPI previously called tabs.executeScript even though its inline case used the scripting API. The owned patch corrects the file receiver, and the accepted test uses scripting.executeScript for both paths before waiting for named injection messages and inspecting DOM results. A test name and expected mutation alone do not identify which API was exercised. Later retry wrappers are a separate phase. This is static receiver and assertion inspection, not a browser run.

Scope: Content-script test receiver accuracy.
