# The expiry dialog closes only after the key change reports success

The dialogaccept listener prevents the default close before awaiting onAccept. A false result leaves the dialog open. Success calls the parent modified callback and then closes. The RNP layer releases every constructed unlock tracker in finally, including early false returns. Keep completion and cleanup attached to the actual key-change result when touching this path. Initial missing, unavailable or revoked keys now throw from onLoad; this source does not prove that every error is shown visibly. Rejected promises and closing or cancelling during a pending change need runtime checks. Scope: this dialog and key-expiry operation. Only source and historical reported manual checks were inspected.

Scope: OpenPGP expiry lifecycle.
