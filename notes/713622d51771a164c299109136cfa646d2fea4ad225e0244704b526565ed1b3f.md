# NNTP connection timeout is configured separately from the idle error gate

NntpIncomingServer.connectionTimeout keeps positive values or -1 and replaces other values with a stored 170 seconds. NntpClient installs TIMEOUT_READ_WRITE on socket open only when the value is positive. Only a NET_TIMEOUT with no runningUri takes the quiet quit path; an active request uses the normal error path. Request reset clears runningUri and _actionDone resets before returning the client to idle. This source fact does not establish real socket timing, every reconnect outcome, or RFC compliance. No direct timeout regression test or network run was found in the inspected scope.

Scope: mailnews NNTP connection lifetime.
