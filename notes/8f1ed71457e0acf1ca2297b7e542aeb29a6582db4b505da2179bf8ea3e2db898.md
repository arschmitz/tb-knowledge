# The Trash-ancestry deletion fix initially skipped the receiver and accepted code includes it

The original patch walks from GetParent to detect a folder below Trash; that fixes the child-folder policy but drops the former receiver's own Trash flag check. Accepted HandleDeleteOperation starts at folder=this, so self and ancestors count. The helper is shared by message deletion, which passes aDeleteStorage, and DeleteSelf, which passes false. The added test checks an EWS child directly inside Trash and its remote deleted ID; it does not cover deleting messages from Trash itself or every caller. This is a static phase distinction, not a reproduced regression or deletion result.

Scope: Exchange folder deletion policy phases.
