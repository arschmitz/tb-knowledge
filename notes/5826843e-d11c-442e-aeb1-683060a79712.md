# Changing a shared reader to async can expose unrelated client errors

The first LineReader change was backed out after tests reported an unhandled promise rejection. The revised patch added a null guard for runningUri in NntpClient, a different consumer of the shared reader. This is a concrete cross-protocol failure from an async boundary change. When changing LineReader.read, check both POP3 and NNTP call sites and run their tests; a POP3-only manual check did not catch the NNTP failure.

Scope: Mail protocol line reader.

Paths:

- `mailnews/base/src/LineReader.sys.mjs`
- `mailnews/news/src/NntpClient.sys.mjs`
