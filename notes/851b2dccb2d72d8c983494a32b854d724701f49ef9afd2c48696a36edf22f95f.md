# Migrate ancient msgOffset values lazily and preserve zero

Accepted nsMsgHdr::GetStoreToken first reads the string property. If it is empty, it reads the legacy msgOffset column with the maximum uint64_t value as the unset sentinel, converts a real value to decimal and persists it through SetStoreToken. Zero is a valid first-message token. The current test inserts msgOffset through setUint32Property to exercise compatibility after messageOffset was removed. The old column remains; the getter/setter do not erase it. Clearing a string on an ancient header can therefore expose the fallback again, so empty-string deletion must not be taught as unconditional permanent removal.

Scope: mailnews/db/msgdb.
