# The original first-run reopen assertion checks the earlier dialog reference

The original first-run task captures dialog once after its first open. After closing and reopening the Hub, it repeats Assert.ok(dialog, "The dialog element should be created") without reading the DOM again. That checks the earlier reference's truthiness, not whether reopening created or retained the expected node. The later class and controller-value assertions still inspect their respective state. This scoped source issue is separate from the reported backout cause, which was not diagnosed or reproduced.

Scope: Account Hub first-run reopen test.
