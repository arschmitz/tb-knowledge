# The first authentication-popup follow-up checks hidden flags but reverses its diagnostic text

The test switches from computed visibility checks to comparing popup menuitem.hidden with hide = !authMap[protocol].includes(item.value). The new message says NOT hidden when hide is true and hidden when false, so the message contradicts the expected flag in both branches; this remains in the accepted helper. The form itself assigns hidden flags to named authentication options, but that does not prove native popup mirroring or style/property equivalence. The accepted helper has later animation-frame and click changes that are separate from this first assertion rewrite. No test failure or cure was reproduced.
