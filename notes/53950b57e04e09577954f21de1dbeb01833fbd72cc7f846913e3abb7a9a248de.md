# Calendar storage logs failures, but native cancellation has a separate naming gap

The async failure branch creates NS_ERROR_FAILURE, logs the exception with database context and rejects with that exception. The source also contains an intended abort branch labelled REASON_CANCELLED. Do not claim that actual native cancellation reaches it: existing paired evidence at comm87d0159c7149a43253964c2cb6917939557dc799 and Gecko1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b shows that Gecko defines REASON_CANCELED, so reason1 reaches the default failure branch there. The fixed history-study wrapper retains the same two-L spelling; its paired Gecko interface was not rechecked in this audit. This corrects the earlier unqualified cancellation sentence while preserving the failure logging finding. No new database cancellation or corruption experiment ran.

Scope: Calendar storage diagnostics.
