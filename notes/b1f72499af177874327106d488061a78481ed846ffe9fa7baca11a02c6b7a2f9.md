# The no-auth Account Hub browser scenario checks routing with verification stubbed

The new OAuth2-incoming/none-outgoing fixture exercises the passwordless UI path. Its browser helper stubs ConfigVerifier.verifyConfig and directly checks the hidden password form, account creation and stored auth methods. The unit cases separately check the none combinations in the predicate. This is UI/dataflow test-code coverage, not successful server authentication. The shared calledOnce message still says GSSAPI for the mixed no-auth scenario; the predicate itself is generic.

Scope: Thunderbird no-auth Account Hub test scope.
