# EWS deletion sends sequential ID batches and stops after a failing batch

DoDeleteMessages groups IDs into chunks of at most 1000 and awaits each HardDelete request before starting the next. Each response count is checked against its own block. A missing item is tolerated; other processing errors stop later blocks, without compensation in this function for earlier requests. Empty input sends no request. The cap comes from an observed Microsoft 365 error; other operations and servers were not established. The checked shared handler dispatches its terminal callback after the operation result.

Scope: EWS delete operation and terminal listener.
