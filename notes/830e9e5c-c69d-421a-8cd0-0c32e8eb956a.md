# Compose encryption schema describes enabled settings without promising successful delivery

The security review rejected wording that said a message will be encrypted solely because a setting is on: missing or unusable keys can prevent sending. The accepted schema calls encryptBody, encryptSubject, and signMessage enabled settings, and the ComposeDetails update documentation says modified settings are treated as user-initiated so automatic changes stop. Current schema keeps that distinction. For security APIs, describe selected configuration precisely and state send-time preconditions separately; do not imply silent unencrypted delivery.

Scope: Compose encryption API documentation.
