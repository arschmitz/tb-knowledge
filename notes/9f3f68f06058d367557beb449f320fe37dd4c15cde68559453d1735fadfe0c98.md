# LDAP advanced visibility, validation and captured settings are separate contracts

The initial advanced LDAP patch adds controls and local validation; it does not yet add captureState or the parent LDAP creation branch. In accepted later code, mode clicks toggle #isAdvanced and the advanced class, while input events call #formUpdated and the parent enables Forward from config-updated.detail.completed. A mode click alone therefore does not establish that completion was recalculated. Current nonempty advanced max-results values go through valueAsNumber and numeric range conversion; an empty value is skipped. Later captureState reads advanced fields only in advanced mode and resets their defaults in Simple mode before directory creation. The owned follow-up tests directly assert visibility and -1-to-1 validity, not mode-only completion, all numeric boundaries, saved settings or a network bind. Existing reset/error-description limits remain separate. No UI, LDAP or accessibility run occurred.

Scope: Account Hub LDAP advanced form mode and completion.
