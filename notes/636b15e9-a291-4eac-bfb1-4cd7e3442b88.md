# Use `skip_if` for conditional xpcshell tasks

In xpcshell tests, `.skip(condition)` skips the task even when `condition` is false. For a conditional skip, pass `{ skip_if: () => condition }` as the first argument to `add_task`.

## Evidence

- [Bug 1895453](https://bugzilla.mozilla.org/show_bug.cgi?id=1895453), [D209656](https://phabricator.services.mozilla.com/D209656), commit `21736b0856326a3ecea1c7a1ad66a52afd5e620d` replaced the private `__skipMe` property with `.skip(condition)` in browser and xpcshell tests.
- [Bug 1898449](https://bugzilla.mozilla.org/show_bug.cgi?id=1898449) identifies the regression: “In xpcshell tests, calling .skip is unconditional.” Commit `2946798335fc5c72d60550a39d79d829f5900f59` changed affected tests to `add_task({ skip_if: () => condition }, async function ... )`. [D211325](https://phabricator.services.mozilla.com/D211325) accepted that fix and noted that the test harnesses have similar but different interfaces.

## Validation and limits

I inspected both landed diffs and the public bug and review discussions on October 6, 2026. I did not run the tests. This rule applies to xpcshell `add_task`; it does not replace the browser test harness's skip API.
