# Historical infallible Folder shortcuts keep the string getter implementation

Entry 1213 marks the old Folder interface’s simple properties infallible so XPIDL can provide C++ shortcuts, while string getters need explicit nsCString-returning overloads in Folder.h and Folder.cpp. Those overloads delegate to the existing out-parameter getter and assert its result. For that historical interface, keep the declaration and implementation paired instead of assuming XPIDL creates every shortcut. The accepted Panorama interface now uses folder IDs and no longer has this Folder class, so this is not a current API recommendation. No C++ build was run. Full bug and review discussion remains pending.

Scope: Historical Panorama Folder API.
