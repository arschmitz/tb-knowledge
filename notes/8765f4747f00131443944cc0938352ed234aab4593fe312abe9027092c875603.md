# Downloaded-message notification triggers folder work without a message-key array

The EWS handleDownloadedMessages cleanup removes the unused key array and the callback captures that existed only to pass it. The accepted later ExchangeFolder method remains parameterless and calls PerformFiltering; its IDL describes notification that some messages reached the local store. The message channel notifies only after successful fetch and then reads from the store. AutoSync keeps keys for the download request but not its callback; its callback releases the semaphore, notifies a matching folder and reports download status, without the channel success-only guard. This is a folder follow-up notification, not per-key filtering or implemented protocol unification. No fresh download, filter, lifetime/cancellation test or build.

Scope: exchange-offline-download.
