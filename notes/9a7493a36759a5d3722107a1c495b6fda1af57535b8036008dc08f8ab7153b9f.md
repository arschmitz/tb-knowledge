# Keep Owl information navigation separate from the install action

The config-found widget uses addonInfo as an external information link and addonInstall as a native type=button. The link calls openLinkExternally with its href; the button disables itself and emits install-addon for the email controller to handle asynchronously. Keep those separate actions when changing the Exchange add-on offer so reading product information does not initiate installation. The controller’s installation promise and the widget’s later metadata refresh have different completion points. Current enterprise builds omit these controls. No add-on installation, link navigation or accessibility test ran.

Scope: Account Hub add-on information and installation.
