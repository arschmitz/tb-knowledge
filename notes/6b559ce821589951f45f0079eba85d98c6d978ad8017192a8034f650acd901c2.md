# Handle EWS server deletes through local content and header removal before advancing sync

Entry 2108 replaces the unsupported Rust Delete sync case with an IEwsMessageCallbacks method that finds the local header by remote EWS ID. Both that callback and successful user deletion call EwsFolder::LocalDeleteMessages. The helper collects local keys, removes downloaded content only for offline messages, then removes database headers. Rust propagates the callback’s error before the later batch sync-token update, so token advancement follows completed local changes. The fixed accepted implementation relocates the deletion helper to common OfflineStorage and adds a folder deletion notification. Keep content deletion, header deletion, visible-list notification and checkpoint advancement as separate responsibilities. No server sync, local replay, partial failure, token persistence, message-list focus or announcement test ran. Full external context is pending.

Scope: EWS deletion sync architecture.
