# Choose the Exchange URL type from current content-policy consumers

Historical 603 removed the nearly empty EwsUrl and used standard URIs through NS_NewURI. That simplification is no longer current: the fixed factory creates ExchangeUrl for ews, ews-message, graph, graph-message and their internal channel schemes. ExchangeUrl implements nsIMsgMessageUrl because nsMsgContentPolicy::ShouldLoad expects it when channel security checks run. Manual architecture proposal: check the interfaces required by consumers before simplifying a protocol URL class. A class with little local logic can still carry an interface needed by security policy. Preserve the 2024 removal as history; do not turn it into a continuing rule to use plain standard URIs for Exchange.

Scope: exchange.
