# HandleCustomFlags keeps a local message key while its IMAP callers expose the UID boundary

The owned clarification keeps HandleCustomFlags typed nsMsgKey and aligns parameter names, junk-score writes and debug labels with that local database role. Server custom-flag retrieval still takes a UID. The original callers bridge the roles with explicit casts and TODOs; accepted callers use a header key or MsgKeyFromUid. The existing helper remains an identity placeholder, so the clarified names are not completed UID/key mapping or a changed keyword policy.

Scope: IMAP custom flag local database identity.
