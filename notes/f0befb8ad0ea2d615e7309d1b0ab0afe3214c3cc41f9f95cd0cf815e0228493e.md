# The Calendar reland still leaves generated Properties buttons on an old attribute contract

The reland removes propertiesbuttonlabel from the calendar discovery list, but its unchanged renderCalendarList still reads that attribute and assigns the result to generated Properties buttons. Current accepted code instead applies calendar-context-properties directly to each generated button. Keep the markup producer and generated consumer together when checking localization migrations. This is a static source mismatch and later comparison, not a reproduced blank-button failure or attribution of a later regression. No dialog or translation ran.

Scope: Calendar discovery localization producer and generated-button consumer.
