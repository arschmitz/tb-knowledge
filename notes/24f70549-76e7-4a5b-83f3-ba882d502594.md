# Gecko asynchronous execution takes each bound parameter array and retains its statement owner

## Directly observed transfer chain

Both statement classes expose internal `bindingParamsArray` methods that return
`mParamsArray.forget()`. The execution request transfers that strong reference
out of the statement into `StatementData`; it does not leave the statement pointing
to the submitted array. `AsyncStatement::getAsynchronousStatementData` supplies a
null SQLite statement for lazy preparation. The synchronous statement variant
first obtains its separate async statement, then transfers its binding array.
Evidence: [storage/mozStorageAsyncStatement.h:49–55](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageAsyncStatement.h#L49-L55), [storage/mozStorageStatement.h:59–65](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatement.h#L59-L65),
[storage/mozStorageAsyncStatement.cpp:255–262](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageAsyncStatement.cpp#L255-L262), and [storage/mozStorageStatement.cpp:287–296](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatement.cpp#L287-L296).

`StatementData` holds the array and a strong `StorageBaseStatementInternal` owner.
Copies of `StatementData` share these strong references. Its SQLite pointer is
borrowed from the owner; `reset` resets and clears SQLite bindings, then clears
that pointer. It does not directly destroy the owner. A request therefore keeps
its submitted values and statement owner alive after the caller drops references
or prepares a later request. This is reference ownership, not a claim that every
value has been deeply copied.
Evidence: [storage/mozStorageStatementData.h:21–75](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatementData.h#L21-L75) and [storage/mozStorageStatementData.h:117–132](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatementData.h#L117-L132).

The actual connection's `ExecuteAsync` resolves each supplied statement to
`StorageBaseStatementInternal`, obtains its `StatementData`, and moves the list
into the asynchronous executor. It asserts that each statement belongs to this
connection. That same-connection check is an assertion here, not a documented
release-build rejection guarantee. The single-statement `ExecuteAsync` path
also builds `StatementData` and calls the same executor.
Evidence: [storage/mozStorageConnection.cpp:2586–2610](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageConnection.cpp#L2586-L2610) and [storage/StorageBaseStatementInternal.cpp:162–179](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/StorageBaseStatementInternal.cpp#L162-L179).

## Consumer and release

`StatementData::getSqliteStatement` asks its retained owner for the async native
statement when needed. `needsTransaction` returns zero for read-only or failed
preparation; a write returns its binding-row count or one if no array exists.
The executor can therefore treat one multi-row write as multiple write actions
for transaction selection. Full executor cleanup is recorded separately.
Evidence: [storage/mozStorageStatementData.h:41–52](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatementData.h#L41-L52) and [storage/mozStorageStatementData.h:95–105](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/mozStorageStatementData.h#L95-L105).

## Direct tests and limits

`test_last_multiple_bindings_on_statements` creates five statements, alternating
synchronous and asynchronous types, binds five rows to each, submits the batch,
checks finished completion, and directly checks 25 added rows.
Evidence: [storage/test/unit/test_connection_executeAsync.js:95–164](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/storage/test/unit/test_connection_executeAsync.js#L95-L164). It verifies submitted multi-row values and
mixed statement types. It executes ownership transfer but does not directly prove
all reference-count or destruction timing branches.
