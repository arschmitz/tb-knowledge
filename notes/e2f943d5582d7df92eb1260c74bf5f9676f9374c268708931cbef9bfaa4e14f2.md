# Mbox reader tests vary chunk sizes but do not establish race freedom

The current gtests compare full decoded messages across read sizes 1, 3 and 4096, long messages/lines, odd cases and malformed missing-From input. Helpers call Continue after each message and the file is registered in xul-gtest. These are semantic/chunk-boundary tests, not simultaneous Read/Close/getter or ThreadSanitizer assertions. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/base/test.
