# Explicit mail-tab sorting collects the view before returning list pages

getListedMessages takes the explicit-sort branch only when options.sortType is set. It collects all current view headers, sorts a separate result through sortMessages and passes it to startList. Without sortType, the scheduled addMessage loop keeps the earlier fast-page path. Missing views return an empty list. This is source control flow, not a measured latency or pagination result.

Scope: WebExtension mail-tab message lists.
