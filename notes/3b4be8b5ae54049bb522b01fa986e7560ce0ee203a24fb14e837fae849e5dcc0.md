# Treat a request-notifications event as a cached-candidate request

The manager emits REQUEST_NOTIFICATIONS_EVENT after its delay. InAppNotifications handles that event by updating the manager from current filtered data; it does not directly fetch the server. A late listener may also receive the current notification immediately without a new candidate being selected. Keep event meaning, network scheduling and selection history separate. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: In-app notification event boundaries.
