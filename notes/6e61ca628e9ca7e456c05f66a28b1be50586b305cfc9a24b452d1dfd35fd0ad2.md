# Keep context-menu target messages separate from selected messages

In the tested thread-pane case, a context-click on another row supplies that row in menus.onShown.selectedMessages while getSelectedMessages and getDisplayedMessages still return the prior selected collapsed thread. The test checks that no selection-change event fires. Retain this separation in mailTabs and menu tests; do not infer that a menu target changed the active selection. Other selection modes are outside this case. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Thread-pane context-click selection contract.
