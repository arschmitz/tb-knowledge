# NickServ success matching clears only an active authentication notice queue

Entry2135 adds the You are successfully identified prefix to success handling only while nickservMessageQueue exists. It sets isAuthenticated, cancels/deletes the timer and drops the queue; unrelated notices in that queue remain queued. The protected-nickname prompt changes from exact equality to startsWith to allow suffix text. Replay uses an existing reentrancy flag to fall through the normal handler. Fixed0b93 retains these contracts. Review preserved simple == for the remaining exact string comparisons; that historical request does not require coercive equality for unrelated types. The author did not block landing on missing tests, and suggested handler/state tests were not added by this diff. No IRC login or queue/timer test ran.

Scope: IRC NickServ authentication notice handling.
