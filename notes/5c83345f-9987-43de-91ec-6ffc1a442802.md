# Yield long protocol line loops without draining the whole event loop

POP3 processing of 35k to 38k LIST and UIDL lines could hang inside spinEventLoopUntilEmpty until the server timed out; UI activity would unstick it. Bug 1893307 made LineReader.read async and yielded with a timer every 1000 lines. The author reported about 33 yields each for LIST and UIDL with 38k messages and no observed UI slowdown. The shared reader also serves NNTP. Its first landing was backed out after NNTP tests failed; the later reland kept this loop and adjusted NNTP completion handling. Current LineReader.sys.mjs retains the timer yield. The 1000 count is observed in this path, not a general project-wide threshold.

Scope: MailNews line processing.
