# EWS message-list completion follows applied changes, not detached task launch

The owned Rust bridge detaches sync work and returns before completion. The message-sync loop applies remote pages through local header/read/delete callbacks and advances sync state before OnSyncComplete reports URL stop. This is message-list state, not a completed-body-download guarantee. The root wrapper fans the same listener to descendants; PromiseUrlListener has no aggregate counter, and the changed root test still TODOs message population. Accepted0b93 uses ExchangeMessageSyncHandler and forwards an explicit status after count/summary bookkeeping, while filtering/offline body work can remain queued. Tests replace selected polling with listener promises and assert actual server/local state; they do not prove all failure paths or all-folder completion. No tests were run.

Scope: mailnews/protocols/ews.
