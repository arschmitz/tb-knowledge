# The split IMAP helpers retain different key and staged-UID error contracts

This landing replaces the combined builder with separate producers. MsgGetKeysFromHdrs propagates getter failures and rejects nsMsgKey_None; the inverse DB lookup helper can omit missing keys. UidsFromHdrs is still staged: its active body reads and casts message keys, while its TODO describes a future GetUidOnServer implementation. The header's missing-UID omission description is broader than that active staged body. These distinctions prevent treating the refactor as complete UID storage separation or equivalent error handling across all callers. No direct failure-path test or runtime result is claimed.

Scope: IMAP message-key and UID extraction phases.
