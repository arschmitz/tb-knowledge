# The Fluent count follow-up nests total variants inside each unread variant

The follow-up changes one Fluent message from two adjacent selectors into nested selectors. It keeps the message ID, unread/total arguments, span markup and four English one/other combinations. The actual dummy-row caller chooses this message only for a nonzero unread count and uses a separate total-only message otherwise. The accepted file retains the nested syntax. The migration-checker rationale is historical attribution; no checker, locale or rendering test ran, and this does not establish a rule for every Fluent selector.

Scope: Thread-card count localization syntax.
