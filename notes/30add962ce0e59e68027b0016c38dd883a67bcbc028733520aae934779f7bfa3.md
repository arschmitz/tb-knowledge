# Wait on provider state instead of an unrelated network ping

The CSP change removes /ping fetches from calendar provider idle helpers. Accepted cached CalDAV waits for mPendingSync to clear; ICS waits for an empty queue and unlocked state. The uncached CalDAV helper is empty despite its caller comment about finished deletion. Preserve the explicit state checks and do not describe an empty async helper as proof of idle completion. This is a test-code contract and a scoped documentation concern. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Calendar provider idle helper meaning.
