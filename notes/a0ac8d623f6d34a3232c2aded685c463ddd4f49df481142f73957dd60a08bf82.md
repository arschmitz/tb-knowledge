# Popup event listeners must target the instance contract rather than the constructor function

The 2024 port registers PopupNotifications itself as a button listener. A later selected-file correction removes those listeners and their handler cases; its commit message reports that the constructor was called with an event and points to the ownerGlobal.PopupNotifications lazy instance getter. Accepted source retains the removal. Keep constructor and instance roles distinct when porting this component. The stated diagnosis comes from the later commit message; paired Gecko widget behavior and addon installation were not tested. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mail/modules/GlobalPopupNotifications.sys.mjs.
