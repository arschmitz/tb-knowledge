# Include absent migration labels in the documented field type

Proposal: document MigrationTask.fluentID as string|null|undefined rather than string alone. The field starts as null; its constructor accepts an optional string and assigns the supplied value. Current MigrationTasks also passes undefined when it queues an unlabelled task. An absent label keeps the task out of the progress list, while the action still runs. This is a scoped documentation refinement. The historical521 patch adds type braces and replaces @note syntax; it does not introduce the absent-label behavior. No migration run or lint check was performed.

Scope: mail/modules.
