# Calendar storage failure logging preserves rejection

When async storage completes with an error reason, CalStorageDatabase creates an NS_ERROR_FAILURE exception, passes its message and object to logError, then rejects with that same exception. logError can add ready-connection diagnostics and the last statement. Cancellation remains a separate NS_ERROR_ABORT rejection. The original report guessed a SQLite-file problem and the patch only improves diagnosis; it does not establish data recovery or corruption repair. No database failure experiment ran.

Scope: Calendar storage diagnostics.
