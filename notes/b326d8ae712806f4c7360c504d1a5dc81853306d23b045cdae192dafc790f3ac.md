# Choose the delete model for each folder in a cross-account operation

649 determines the deletion model inside ProcessNextFolder. It separates removing storage, moving to Trash and setting the IMAP deleted flag. The fixed accepted source now uses a local deleteModel from GetServerDeleteModel(curFolder), rather than temporarily mutating the view-wide mDeleteModel. Non-IMAP folders default to MoveToTrash. Marking messages read occurs before a non-storage deletion; the view count decreases only when rows are being removed. These are code contracts, not a claim that mixed-account runtime deletion passed.

Scope: Cross-folder deletion policy.
