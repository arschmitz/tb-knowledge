# Message-store failure completion still requires start and stop callbacks

In the historical 1483 completion path, download failure discards the offline record but the later display/read attempt is still present. The accepted channel only reads the store on successful download; on failure it invokes OnStartRequest then OnStopRequest with the failure status. The accepted fetcher also avoids early exits from OnFetchStop because callers require start/stop pairing. Preserve terminal callback delivery while preventing a failed download from becoming a successful store read. This is scoped static failure-path evidence, not a reproduced failure cause. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange fetch failure callback completion.
