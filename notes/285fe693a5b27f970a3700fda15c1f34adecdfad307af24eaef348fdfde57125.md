# Removing numberOfCopies leaves copy-destination storage and indexed lookup in place

This landing removes only the count attribute and its getter. Copy destinations remain in the stored list, with append, serialization and GetCopyDestination still present; the inspected playback consumer reads index zero. Scoped text searches find no direct count-getter caller before removal and no retained reference afterward. Later accepted comments explicitly leave multiple-copy behavior uncertain. This does not change the stored format or establish generated-interface compatibility, external callers or successful IMAP playback.

Scope: Offline IMAP copy operation API.
