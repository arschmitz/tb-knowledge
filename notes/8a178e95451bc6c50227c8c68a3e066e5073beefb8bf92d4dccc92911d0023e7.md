# Exchange keeps distinguished flags while selecting trash from its stored path

Assigning the ewsId property selects a lock bit for a recognized distinguished folder ID before the creation caller sets folder flags. The trash-path setter can leave the old server Trash flag locked while marking a newly selected trash folder. The folder's trash getter delegates to the incoming server, whose stored path selects the destination instead of the first flagged folder. The soft-delete caller checks for a missing destination; ancestor Trash flags still separately affect permanent deletion. The mock tests assert selected flags and destination counts, not that every real-server or multiple-folder report is resolved.

Scope: Exchange distinguished folder flags and delete destination.
