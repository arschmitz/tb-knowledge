# The raw-message comparison omits its expected-behavior assertion message

The newly added getMessageTest compares fetched bytes with messages[i].toMessageString() without a message argument. This one lexical assertion site runs in both EWS and Graph scenarios and needs a nonempty description of the expected content under the deliberate review requirement. The folder-count assertion already has such a message. This finding is separate from the should wording preference and does not claim a failing content comparison or test execution.

Scope: Exchange raw-fetch xpcshell test review.
