# Keep external-link history completion separate from protocol dispatch

Accepted openLinkExternally initiates Places history insertion without awaiting it and catches that rejection separately before dispatching loadURI. test_linkHelper explicitly waits for PlacesTestUtils.promiseAsyncUpdates after observing the protocol call. Scoped test recommendation: wait for the operation whose result is asserted. A returned external URI is not proof that the history write has completed, and the helper does not report native application launch success. This is source and test inspection only. Full Bugzilla and historical review discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check ran.

Scope: mail/modules/LinkHelper.sys.mjs.
