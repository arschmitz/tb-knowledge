# Calendar item creation checks the target before a five-pixel double-click

In the accepted Calendar test helper, a supplied target is scrolled into view and must have width and height greater than 5 before a double-click at (5,5). The helper also checks visibility. The no-target path clicks the side-panel new-item button instead. It starts the edit-dialog wait before the action, then returns after iframe load/focus and size settling. The biweekly recurrence test supplies a day-view hour box; its occurrence assertions were not changed by this patch. These are static target and completion contracts, not proof that the intermittent timeout was cured. The new size assertion messages are nonempty but vague; a local diagnostic improvement would name the expected threshold, for example, "The click target width should exceed 5 pixels." This is a scoped suggestion, not a new global rule.

Scope: calendar/test.
