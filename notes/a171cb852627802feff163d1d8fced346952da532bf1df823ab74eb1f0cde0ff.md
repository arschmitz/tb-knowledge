# Test Compose FCC output without accountsRead

Proposal: add a permission-negative case in the existing Compose API browser harness. Use an extension with compose permission and no accountsRead, then call getComposeDetails with the normal encryption control present. The call should succeed and omit the FCC folder/identity properties. Assert own-property absence, not only an undefined value. Set an unrelated compose field and check the native FCC fields remain unchanged. The historical repair adds the permission guards; the read FCC test grants accountsRead and does not cover this failing permission state. Suggested messages: “Compose details should omit FCC folders without accountsRead.” and “An unrelated update should preserve the native FCC settings.” No test was added or run.

Scope: mail/components/extensions.
