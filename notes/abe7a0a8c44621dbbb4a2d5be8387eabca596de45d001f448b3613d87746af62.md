# Distinguish account-count chunks from QR size limits

Current getQRCodes groups three accounts per QR code and warns when the JSON string length exceeds 800. It does not split a long account by bytes or enforce an 800-character maximum. The part index is one-based even though the loop and slice offsets are zero-based. MAX_CHUNK_LENGTH names a warning threshold in this implementation. Changes to capacity need long and multibyte data checks rather than assuming the existing four-account test proves scanability.

Scope: mail/modules/QRExport.sys.mjs.
