# Archive option controls write identity state consumed by the archiver

`ChangeArchiveHierarchy()` opens the archive-options subdialog with the explicitly edited identity, or the current account's default identity. The dialog `load` listener reads that identity's granularity, folder-structure, and Inbox-recreation values into controls. It registers `command` listeners on those controls. `dialogaccept` writes the three control values back to the same identity. These document/window listeners have no explicit removal in this small script; they belong to the dialog's lifetime.

`updateArchiveExample()` changes the simulated hierarchy only. It hides year/month levels below the selected granularity, toggles the `children` class, moves the Inbox/sibling/child list items under the selected level, and disables Inbox recreation when folder structure is off. It does not clear the checked Inbox value when disabling the control, so accept can store `true` while folder structure is false. That stored combination only matters when production code also enables folder structure.

The actual XHTML includes the script and accountManage stylesheet and declares the control IDs and root/year/month classes the script reads. Its localization link names `am-archiveoptions.ftl`. Every `data-l10n-id` in the dialog has a matching ID in that checked Fluent file. Radio/checkbox entries supply label and access-key attributes; title and tree example names use text values. `accountManage.css` contains scoped `#archiveOptions` descendants and root icon styling that match the HTML list. The older `#archiveTree > treechildren::-moz-tree-image` selector does not match the dialog's `ul/li` structure; no rendered effect for that selector is claimed.

The Copies & Folders panel's `identity.archiveEnabled` checkbox names `mail.identity.%identitykey%.archive_enabled` and calls `setupArchiveItems()`. That function disables `.depends-on-archive` controls when off and restores picker mode/Gmail hierarchy restrictions when on. `updateArchiveHierarchyButton()` reads the archive destination's server, not the identity's incoming server. Gmail IMAP disables hierarchy options. Missing destination returns without updating the previous button state.

Native identity macros map the properties to `archive_enabled`, `archive_granularity`, `archive_keep_folder_structure`, and `archive_recreate_inbox`. Setters write the identity preference branch. Boolean/integer getters try that branch and fall back to the default identity branch. The archiver reads these properties when preparing each header, and separately reads the matching default preferences for RSS/no-identity headers. The identity preference owner was read in selected sections; no all-pref observer analysis is claimed.

Direct tests check Gmail button state using a destination on a different server, all initial control combinations, saved values, additional identity isolation, archive-enabled checkbox state, and a user click that disables archiving. They exercise opening and accepting the dialog. They do not directly assert the example DOM hierarchy or every CSS/localization rendering result. Those links are source-checked, but no browser run occurred.
