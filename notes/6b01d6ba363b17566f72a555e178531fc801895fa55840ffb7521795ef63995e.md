# A failed post-vendor policy check does not imply a rollback

run_tb_rust_vendor removes the existing comm vendor directory, runs cargo vendor and writes config.toml.in before check_unwanted_crates. The check then exits with an error before cleanup_vendor when a prohibited package is found. The printed sentence says new crates were not vendored, but the inspected ordering has already performed file mutations. Manual tooling and diagnostic proposal: distinguish policy acceptance from filesystem mutation and say which stage failed. Preserve the partial working-tree state for inspection or explicitly design rollback; this code does not show one. No failed vendor run was executed and no filesystem outcome is claimed beyond the code order.

Scope: rust-vendor-failure-stage.
