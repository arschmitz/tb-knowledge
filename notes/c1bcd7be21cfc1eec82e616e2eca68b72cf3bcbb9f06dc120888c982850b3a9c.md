# IMAP rename snapshots settings before rebuilding the database and has two notification phases

OnlineFolderRename reads the old folder's flags, retention settings and sort order before RenameLocal replaces its summary state. After RenameClient builds the new folder, it uses the same encoded name for lookup and reapplies selected settings outside Trash. RenameClient's FolderRenamed notification occurs before the caller's restoration, while the later kRenameCompleted event follows it. Keep those notification boundaries distinct when checking consumers; unchecked native results and an additive flag mask are not a guarantee that every setting failure is handled. No native rename or event-order test ran.

Scope: IMAP folder rename settings and events.
