# Recurrence consumers distinguish date and rule representations before using them

The assigned consumers check either the JavaScript recurrence class or the XPCOM interface before accessing date/rule-specific data. The detailed formatter rejects an unsupported rule shape before its formatting branches. Next-occurrence and restore paths keep date and rule handling distinct, and iTIP compares only negative recurrence dates when identifying EXDATE-only changes. These are scoped source checks, not a global preference for instanceof or proof of every custom implementation. No recurrence or iTIP operation was run.

Scope: Calendar recurrence representation guards.
