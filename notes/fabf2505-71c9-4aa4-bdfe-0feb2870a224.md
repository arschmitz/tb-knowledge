# Treat IMAP URL encoding as message identity and display behavior

Changes to standard URL escaping can affect mail display, fetches, read status, and security origin comparisons. IMAP/mailbox/news message schemes use the specification before the query as origin because each message is a trust domain. A2024 caret-escaping port changed only a URI test but required backout with upstream; manual preescaping caused a second fetch/read-state failure in the bug discussion. Check full behavior and upstream landing state before treating a changed expected string as a complete fix. Current endpoint retains %5E. The suggested separator workaround was not established as safe.
