# iTIP temporary-file creation now propagates failure instead of returning null

The temporary iTIP file helper removes its catch-and-null fallback, and its caller removes the if(mailFile) wrapper. Serialization or local file-write failure can therefore leave this call chain rather than becoming a false/no-file send result. The selected sendItems and outgoing helpers return the transport call without adding a catch. A normal path calls sendMessageFile and returns true; that is not delivery completion. The concrete filename is itipTemp. No file failure, cleanup result or mail send was exercised.

Scope: Calendar iTIP email transport failure boundary.
