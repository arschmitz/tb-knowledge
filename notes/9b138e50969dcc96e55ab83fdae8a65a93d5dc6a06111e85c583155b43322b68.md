# Clearing Calendar dialog state and settling show are separate actions

The initial positioning patch moves the missing-ID clear after the reload check and removes its resolver/null reset. The owned loader already created showPromise, while clearData only resets displayed values; show awaits that promise. The later accepted code instead rejects an Error for missing IDs and has separate close/promise setup. Keep that later contract and the exact inverse backout separate from the original. This is a static state trace, not a reproduced hang or proof of a positioning cure.

Scope: Calendar read-dialog load lifecycle.
