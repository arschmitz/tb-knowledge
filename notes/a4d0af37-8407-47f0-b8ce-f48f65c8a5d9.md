# Decoded MIME body and attachment APIs have distinct contracts

With decodeContent enabled, messages.getFull includes body only for nonattachment text parts; binary/attachment data is suppressed. Raw mode can expose rawBody. Related images use listAttachments/getAttachmentFile and an optional contentId stripped of angle brackets. Current classification treats binary inline parts as attachments even without content-disposition, but nameless inline text with content-id remains inline text so getFull keeps its body. Historical2024 classifier still required disposition; later accepted fixes and changed tests override that older pattern.
