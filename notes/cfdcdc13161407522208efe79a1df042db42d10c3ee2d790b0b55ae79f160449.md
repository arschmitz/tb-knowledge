# Suppressed-add-on wording keeps card attributes and install value strings separate

The wording update renames the installed-card .message entry and both install-popup value entries, then updates all three local consumers. The text calls the APIs legacy and uses the loaded brand term. The installation headline deliberately keeps literal <> because its local caller still supplies options.name for the existing toolkit contract; it is not replaced with a Fluent $addonName argument. This is a scoped copy/consumer change, not a new suppression predicate or proof of rendered localization and accessibility.

Scope: Add-on suppression localization consumers.
