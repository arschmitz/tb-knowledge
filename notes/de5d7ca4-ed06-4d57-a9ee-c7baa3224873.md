# ICS HTTP and file transport hooks read validators and decide whether to reuse or write

Production privileged JavaScript. URI setter selects actual httpHooks, fileHooks
or dummyHooks. All hook methods and nested HTTP completion callback were read,
CalICSCalendar.sys.mjs:1042–1266. Validators belong to a hook instance and reset
when URI selects a new instance; they are not a global stored preference.

Dummy hooks allow get/put and immediately call put completion callback.
HTTP onBeforeGet adds Accept text/calendar/plain/any. When not forced, sends
If-None-Match for saved ETag, else If-Modified-Since for saved Last-Modified.
Forced refresh skips those conditional validators. onAfterGet reads actual HTTP
status: inaccessible status, 304 and 404 reuse old data; 410 disables calendar;
other 4xx/5xx disable and set auto-enabled. Accepted content updates validators,
with missing headers clearing the corresponding value. Disabling uses string
"true" in this body; downstream property handling is not rewritten by this study.

onBeforePut adds WebDAV If header with saved ETag when available, then allows put.
This is conditional protection for a server that honors it. The source reason
is server compatibility for this header; it is not evidence every server rejects
a changed resource. Unlike file hook, this method cannot synchronously verify
that remote state remained unchanged.

onAfterPut first reads response ETag and calls completion. If that try throws
(including a throw from the completion callback itself), prepares PROPFIND with
Depth 0 to fetch ETag, sends via actual prepHttpChannel/sendHttpRequest, and calls
completion from its stream listener. Listener decodes/parses XML under a catch,
then uses evalXPathFirst with /D:propfind/D:response/D:propstat/D:prop/D:getetag.
It does not check aStatus before XML lookup. Error during lookup/callback has no
finally that guarantees completion. Exact XML receiver/parser behavior is an
external boundary still to read. getInterface only provides nsIProgressEventSink.

fileHooks tracks lastModifiedTime. GET reuses old data if equal to a truthy saved
timestamp; otherwise updates timestamp and accepts new content. Before PUT,
a changed timestamp returns false to stop overwrite. After PUT updates timestamp
and completes. This is a check-then-write sequence, not an OS lock against another
writer changing the file after the check. Native atomic replacement addresses
partial write, a different failure boundary.

Fixture ICSServer.sys.mjs serves HEAD/GET/PUT with ETag but ignores validators
and does not implement PROPFIND. Cached ICS CRUD and offline fixture tests
execute normal ETag handling; their results do not directly establish real server
conditional rejection, the missing-Etag fallback, file timestamp race, or cleanup
after an XML failure. Those test links remain execution-only for these branches.
