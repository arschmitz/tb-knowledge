# The EWS updated-message storage assertion reads the separate deletion callback array

The changed client scenario updates two messages and also moves/deletes two others. Its assertion for updated-message store deletion reads _deletedItemIds.length, although the listener records updates separately in _updated. The preceding assertion already expects the two moved/deleted IDs, so this count can pass without checking the update callbacks or store invalidation named by the message. The mismatch remains in the renamed accepted test. This is a static assertion/coverage finding, not a reproduced test failure or the reported build-failure cause.

Scope: Exchange sync test assertions.
