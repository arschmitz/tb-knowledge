# Removing the old sender helper does not remove the recipient check at that landing

Entry 2082 removes mime_sanity_check_fields and NS_MSG_NO_SENDER. The deleted helper trims leading whitespace, rejects missing From, then calls the recipient helper. At that same landing, mime_sanity_check_fields_recipients remains and nsMsgCompFields::GetHasRecipients still calls it for To/Cc/Bcc/Newsgroups. Keep this method boundary clear when reviewing the cleanup: the diff does not delete every validation or prove empty sender/recipient acceptance. The fixed accepted sendMessageFile path differs and delegates delivery without this helper; the old recipient API has also changed later. No malformed-field, send or UI test ran.

Scope: mailnews compose historical field validation.
