# Header Actions waits for the message browser after aboutMessageLoaded

The new-tab and conversation scenarios first await aboutMessageLoaded, then wait on the returned window's message pane browser before opening the header popup. The local helper observes document readyState and keeps a 500 ms actor workaround. It does not directly prove actor readiness or use the shared helper's about:message/msgLoaded conditions. This is the test's scoped wait contract, not a general delay rule or reproduced timeout cure.

Scope: Thunderbird Header Actions browser-test readiness.
