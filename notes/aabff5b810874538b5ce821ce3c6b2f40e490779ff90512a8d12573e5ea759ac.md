# Refresh copied message keys through destination notifications

The undo transaction records message IDs before an undo or redo copy, listens on the destination folder, then uses OnMessageAdded to find the newly assigned keys. m_undoing chooses the source or destination key array. The listener is removed after the expected number of matching headers arrives. Reusing the old local keys after a new copy would not describe the new headers. This mechanism assumes matching message IDs and completion notifications; this study did not prove failure cleanup or duplicate-ID behavior. This note is based on source inspection. Tests were not run, and full review discussion remains pending.

Scope: mailnews/local/src.
