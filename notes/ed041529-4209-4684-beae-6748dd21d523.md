## PT.NewBookmark.prototype.execute

Trigger: NewBookmark facade transacts or Tag invokes its raw execute internally.

Filters requested tags against current URI tags. Inserts bookmark, stores returned info for stable GUID redo, and adds only previously absent tags. Undo removes bookmark and those tags. Redo runs the same creation closure.

Result and completion: Resolves to info.guid. A later dependent batch member or BookmarkState consumes it.

Errors: Insert/tagging errors reject. Undo/redo methods are installed only after initial creation finishes; initial partial effects are not automatically undone.

Ownership and cleanup: Raw transaction owns info, URL and newly-added tag list through undo/redo closures.

## PT.NewFolder.prototype.execute

Evidence: [PT.NewFolder.prototype.execute:1122-1171](https://github.com/mozilla-firefox/firefox/blob/1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b/toolkit/components/places/PlacesTransactions.sys.mjs#L1122-L1171).

Trigger: NewFolder facade transacts.

Creates a folder GUID and child GUIDs before insertTree. Writes child GUIDs into reused child objects. Inserts the tree, then applies a nondefault folder index using update. Undo removes folder. Redo reuses the same tree GUIDs.

Result and completion: Resolves to folder GUID, used by dependent batch constructors and BookmarkState.

Errors: insertTree/update errors reject; a failure after insertion can leave effects without a history entry.

Ownership and cleanup: Undo/redo closures retain folder/tree/child input. Dates for children are not captured as a full restored tree.

## PT.Move.prototype.execute

Trigger: Move facade transacts with guids/newParentGuid/newIndex.

Fetches every original item first and rejects nonexistent entries. Calls moveToFolder once. Undo updates original infos one at a time; redo repeats moveToFolder with original input GUID order/index.

Result and completion: Resolves to input GUID array, unlike the overview statement that non-create transactions have no value.

Ownership and cleanup: Undo retains original item infos and redo retains destination parameters.
