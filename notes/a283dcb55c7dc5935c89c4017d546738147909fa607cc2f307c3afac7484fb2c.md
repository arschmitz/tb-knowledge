# Offline-message discard policy now lives at the streaming failure caller

Entry 1460 simplifies the discard preference check to GetBool with a true fallback. The accepted nsMsgDBFolder::DiscardOfflineMsg no longer contains that policy check, but OfflineMessageReadListener checks mail.discard_offline_msg_on_failure with the same true default when streaming fails, then calls DiscardOfflineMsg. The preference was moved out of the store mutation function; it was not removed from the failure policy. Keep policy gating distinct from the mutation operation in this family. Existing notes already cover clearing token, size and Offline state together and avoiding mbox rewrite for a corrupt message. No corrupt-store stream, redownload or preference test was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Offline discard policy caller.
