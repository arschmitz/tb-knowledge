# Repair Summary locks local mbox conversion separately from offline-cache removal

Current FolderCommands returns a busy alert for an already-locked folder. It deletes cached offline data for supportsOffline folders; the berkeleystore branch instead acquires a semaphore, awaits repairMbox and releases the semaphore in finally, logging conversion failure before later reindexing work. Scoped architecture recommendation: preserve the store/offline distinction and completion-independent lock release. The assigned landing placed the flow in about3Pane; the current module is its later owner, not proof of chronology for the move. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran.
