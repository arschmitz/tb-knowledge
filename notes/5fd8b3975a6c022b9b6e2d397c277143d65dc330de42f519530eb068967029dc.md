# Notification cache expiration and scheduler delays use different units

Accepted getExpirationTime reads cache expiration in seconds since the epoch; getRemainingCacheTime multiplies by 1000 and clamps against Date.now to return milliseconds. Missing/zero and NO_EXPIRATION_TIME produce immediate refresh, and init schedules the remaining valid time. A scoped manual rule is to name and document the unit at this conversion boundary rather than mix cache seconds with timer milliseconds. This is static source and test-code inspection.
