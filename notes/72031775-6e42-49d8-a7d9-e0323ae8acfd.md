# Calendar pending Save closedby attribute to Gecko close-watcher state

This resolves part of the native-dismissal gap in the earlier
[narrower dismissal record](9926c9e6-c286-41ca-814d-2942d230a1c2.md).
Thunderbird and Firefox paths below refer to their separate pinned revisions.

The Thunderbird renderer `#renderSave`,
`calendar-event-create-edit-dialog.mjs:471–478`, sets `closedby="none"` while the
operation is pending and `closedby="closerequest"` otherwise. It also writes the
busy state. This attribute is an additional native mechanism beyond the
JavaScript `close` and `requestClose` guards.

The actual Gecko implementation is `dom/html/HTMLDialogElement.cpp`.
The enum table, 24–36, recognizes `none` and `closerequest`; `GetClosedBy`,
108–123, reads that state when `dom.dialog.light-dismiss.enabled` is enabled.
`AfterSetAttr`, 519–540, calls `SetCloseWatcherEnabledState` for a change to the
attribute. The latter, 757–761, disables an existing close watcher when the
computed state is None. Both `dom.closewatcher.enabled` and the light-dismiss
preference have source defaults true at
`modules/libpref/init/StaticPrefList.yaml:2771–2780`. A source default does not
establish the effective preference value of every running Thunderbird profile.

`dom/closewatcher/CloseWatcher.cpp:53–94,131–140` returns from a close request when
the watcher is disabled or already running its cancel action. A disabled watcher
does not dispatch the cancel/close actions. With the older fallback path,
`dom/base/Document.cpp:15920–15963` also checks computed None before requesting
dialog closure when light dismissal is enabled. If that preference is disabled,
the top-layer fallback queues cancellation instead; the same attribute claim
cannot be assumed for that configuration.

When closure is permitted, the native watcher listener,
`HTMLDialogElement.cpp:42–87`, forwards cancel to the actual dialog and uses its
default-action result. Its close action calls native `HTMLDialogElement::Close`.
It does not call the JavaScript subclass's `close()` by name. Native
`RequestClose`, 240–290, temporarily enables the watcher even with closedby None;
the ordinary attribute guard is not a universal block on explicit native
request-close calls or direct native close commands. The custom JavaScript API
overrides are a separate layer.

Ownership: setup at `HTMLDialogElement.cpp:692–755` creates a watcher, registers
cancel/close listeners, and inserts it into the window manager. The listener
holds a weak dialog reference. Cleanup, 764–777, destroys the watcher and clears
the dialog's pointer. `CloseWatcher::Destroy`, 124–129, removes it from the actual
window manager. Manager groups own watcher references and are copied while
processing close requests, `CloseWatcherManager.cpp:32–49`; removal clears the
entry and empty group, 68–78. The watcher header's `DisconnectFromOwner` also
destroys it before inherited owner disconnection. Closing route work, resize
timers, and Redux subscriptions remain separate lifetimes.

Direct generic browser-standard test:
`testing/web-platform/tests/html/semantics/interactive-elements/the-dialog-element/dialog-closedby.html:52–144`
opens ordinary dialogs in modal/modeless/open-attribute modes, sends Escape,
clicks outside, and asserts the expected open state and reflection. Cases for
None expect no Escape or outside closure. It executes direct `dialog.close()`
for cleanup, demonstrating why None must not be described as blocking every
explicit close operation.

The additional Thunderbird Edit Save browser task
`test_escapeDismissesReadyAndFailedButNotPending`,
`mail/components/calendar/test/browser/browser_calendarEventEditSave.js:539–602`,
directly checks None while pending, unchanged return value after `requestClose`,
Escape retaining an open pending dialog, then CloseRequest and Escape dismissal
for ready/failed edits, restored focus, cleared draft, and unchanged storage.
The call to `dialog.requestClose` goes through the JavaScript override; its
assertion message alone does not prove a direct native-prototype request.
`test_nativeCloseRequestsKeepReturnValues`, 604–625, checks explicit and omitted
return values and cleared draft for permitted close requests.

These tasks use the customized production dialog class in a fixture document.
Setup at 21–72 installs memory calendars and a host transaction bridge. The
pending path delays a replacement transaction that rejects. The file is listed
in `mail/components/calendar/test/browser/browser.toml:71`; it has not been run
for this study. Thus an actual direct test link was missing from the earlier
records; it is now checked. Production route selection, input/process routing,
and non-default preference combinations still need separate verification.
No product test ran.
