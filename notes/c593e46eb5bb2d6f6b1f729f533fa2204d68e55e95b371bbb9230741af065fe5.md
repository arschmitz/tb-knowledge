# Appending an outgoing server preserves warmed references but does not populate a cold persisted cache

The creation fix saves the new key and pushes one initialized server into _servers instead of clearing and rebuilding existing objects. This preserves references when the cache was already loaded. The servers getter loads persisted keys only when _servers is empty; createServer reads persisted keys without forcing that load before pushing. A new nonempty array therefore does not by itself prove old persisted entries were loaded. Current initialization can also returnnull after catching an error. Existing multiple-server tests start empty and compare key presence, not warmed object identity or cold persisted membership. Preserve that scope and test those states separately; no runtime cache, creation or failure test ran.

Scope: outgoing server service cache.
