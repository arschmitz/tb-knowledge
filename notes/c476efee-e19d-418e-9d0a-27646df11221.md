# Respect generated XPCOM output names despite the leading underscore

D209890 noted that C++ style normally avoids identifiers beginning with an underscore. The author explained that XPIDL generates _retval for a method with a return value, while the shared linter requires implementation parameter names to match the generated declaration. The accepted method therefore keeps nsIMsgDBHdr** _retval. This is a generated-interface exception, not a rule to name hand-written parameters with leading underscores. The name remains in the current implementation.

Scope: XPIDL and C++ naming.
