# Exchange attachment channels expose writable response metadata and a property bag

1927 changes the channel to inherit nsHashPropertyBag and adds stored content-disposition and content-length values. The accepted channel retains that base and initializes disposition to inline, length to -1 and content type to message/rfc822. Disposition filename/header remain unavailable in the inspected methods. Preserve these distinct defaults and supported interfaces when refactoring attachment channels; property-bag support is part of this channel shape, not a requirement for every protocol class. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Exchange attachment channel interfaces.
