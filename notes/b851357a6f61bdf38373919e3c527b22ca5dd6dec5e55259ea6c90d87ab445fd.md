# Protocol client allocation changed from per-call creation to initialized caching

The historical CreateProtocolClient constructs a new component each call, initializes it, then transfers the reference. Its IDL explicitly says every call creates a new client. Accepted later GetProtocolClient instead initializes a temporary only when mClient is absent, assigns the cache after success and reuses it. A method name or an old lifetime comment cannot prove the current lifetime contract. Initial Graph Initialize is a NOT_IMPLEMENTED stub, so component registration is not a working protocol operation.

Scope: Exchange protocol client lifetime.
