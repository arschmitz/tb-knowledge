# Set focus after the event dialog becomes visible

D331224 at revision b484a481f7fbfc7d5c4befd12d215f3a32fbfb05 reports that opening the Calendar event create/edit dialog left keyboard focus on the opening button. The review attributes this to PositionedDialog.show() hiding the dialog during native opening and restoring visibility without setting focus. The local amendment reportedly focuses the enabled calendar selector, or the dialog when selection is unavailable. Minimum test coverage: start with a focused opening control, open the dialog, and assert focus inside without a later manual focus() call; also check that repeated show calls preserve existing dialog focus. The record reports passing headless accessibility, lint, syntax, and diff checks, but contains no independent test output or source diff. This is a scoped review finding and reported local fix, not proof of landing or a repository-wide convention.

Scope: Calendar event create/edit dialog focus.
