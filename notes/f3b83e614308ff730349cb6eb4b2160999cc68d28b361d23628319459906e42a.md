# Current Exchange creation attaches the server-created message even if caching fails

Entry 1485 writes the copied file to the local store before final header/database addition. The accepted ExchangeMessageCreate instead confirms the remote result, builds the local header, attaches it, then treats the offline copy as best effort; a storage error is warned rather than treated as undoing the already created remote message. The comment explicitly says remote creation has already happened. Preserve that external-commit boundary in this flow; no rollback or atomic remote/local transaction is established. This later accepted behavior is context, not full study of its introducing changes. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Exchange remote creation versus local caching.
