# Make lazy message tracking an explicit side effect of requesting an ID

CachedMsgHeader can be constructed without tracking via addToMessageTracker:false. hasId is a check, while reading id can register the header and can throw if registration fails. getIdentifier and getId reuse an already cached ID rather than deriving a stale folder/key pair. MessageManager conversion accepts the cached object; compose classification also supplies the tracker to its constructor. Keep that side effect visible in documentation and caller choices rather than treating every getter as a pure read. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/lazy-header-tracking.
