# The empty mbox scan branch ignores a failed start callback

For an empty file, BeginScan queues OnStartScan and OnStopScan(NS_OK) on the main thread to avoid callbacks before return. It discards the OnStartScan result, while the nonempty path checks that result. Scoped test/API recommendation: explicitly test a rejected start callback on an empty mbox and decide whether the same abort/status contract must apply. This is a static branch difference, not a reproduced loss or a claim about the distinct empty batch-compaction contract. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: mbox empty scan callback status gap.
