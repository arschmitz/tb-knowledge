# Name folder-ID input properties with an Id suffix in Manifest V3

When an extension property takes a MailFolderId rather than a MailFolder object, this accepted API change names it displayedFolderId, overrideDefaultFccFolderId, or additionalFccFolderId. Schema min_manifest_version 3 exposes the new names; max_manifest_version 2 keeps the older displayedFolder and ComposeDetails fields for existing add-ons. mailTabs.create/update resolve either version to a native folder. This is a deliberate public API naming convention: an Id suffix tells callers the value is an ID, while version gates avoid silently breaking Manifest V2.

Scope: WebExtension API naming.

- `mail/components/extensions/schemas/mailTabs.json`
