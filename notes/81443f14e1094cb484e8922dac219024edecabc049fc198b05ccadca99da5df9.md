# Select a news posting server through account state rather than the retired header

Current MessageSend passes its account key into nntp.postMessage. NntpService uses that account incoming server and falls back to the first NNTP server when no matching server exists. Send-later resolves the saved identity key separately. Keep account selection, identity restoration and header serialization distinct. The historical commit says the news-host header is ineffective, but the accepted routing source does not support an unlimited claim that only one identity header controls every posting. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: NNTP posting server and identity routing.
