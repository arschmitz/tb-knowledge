# Invitation acceptance distinguishes a chosen-calendar lookup failure from a write failure

This landing makes the non-recurring REQUEST:NEEDS-ACTION operation check the chosen calendar when it differs from the found item's calendar. It adds a copy if the lookup succeeds without an item and modifies the chosen copy if one exists. A failed lookup deliberately falls back to the found calendar instead of risking a duplicate; a failed add or modify reports failure through the operation listener. The dispatcher still ignores operation promises, so the tests await listener completion and check concrete memory-calendar destinations and statuses. Missing-attendee early returns, other recurrence/provider cases, transport and general concurrency remain outside this result; no test was run.

Scope: calendar-itip.
