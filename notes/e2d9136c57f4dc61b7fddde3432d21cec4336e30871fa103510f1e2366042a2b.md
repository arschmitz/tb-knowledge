# The NFC unsafe comments explain nullness but rely on a stronger caller contract

nfc_normalize checks both pointers for null, then creates shared and mutable Rust references. Its local SAFETY comments state only that each pointer is not null. The function Safety section requires valid allocated nsACString instances that do not point at the same data; that caller contract must also hold for the references during the call. The inspected C++ wrapper passes its input and a separate local output, but the guard does not validate arbitrary pointers or all future callers. A scoped comment improvement would name the valid, allocated and distinct-object contract beside those borrows. This is a source explanation gap, not a reproduced invalid-pointer defect or a global comment template.

Scope: mailnews_string_glue NFC raw-pointer safety comments.
