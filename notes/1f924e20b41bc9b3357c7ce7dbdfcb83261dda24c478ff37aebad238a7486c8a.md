# Panorama virtual scopes use folder IDs while wrapper cleanup remains a compatibility no-op

The Panorama-selected nsIVirtualFolderWrapper stores its virtual-folder ID and reads or replaces source-folder IDs in virtualFolder_folders. The default JavaScript wrapper instead uses URI properties. GetSearchFolderURIs derives text from the selected backend source folders, so callers must not infer legacy URI sorting from the common interface. Fixed C++ CleanUpMessageDatabase returns NS_OK without the legacy close-and-null action. The scope getter has no ORDER BY; the test orders its own table query. These are scoped static differences, not a global database ordering or cleanup rule.

Scope: Panorama virtual-folder wrapper.
