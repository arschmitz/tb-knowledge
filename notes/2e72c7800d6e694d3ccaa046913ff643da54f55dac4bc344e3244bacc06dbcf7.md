# The header-download UID port leaves key-named storage and return docs for later

The original patch changes the output type/name to ImapUid/aUids but keeps m_keysToFetch and its nsMsgKey array, plus a return comment describing message keys and chunk size. The author explicitly defers the wider rename despite Done labels. The accepted source later uses m_uidsToFetch, returns a UID array and moves/resets the pending array. Keep this small type-port phase separate from the later naming and control-output cleanup; no fetch or native binding ran.

Scope: IMAP header UID interface phases.
