# Generic EWS backoff checks the whole-request fault or first response message before retrying

The historical patch moves a SyncFolderItems-specific backoff branch into the generic request path. A whole-request SOAP fault with typed backoff data or a first response message carrying ServerBusy causes the whole operation to wait and retry. It does not scan later messages for busy errors. Generic borrowed/owned message accessors support that boundary. Current parser returns Continue(Duration), and the shared sender waits then repeats; that queue infrastructure is later context. No bound on retries, idempotence, mixed-batch rollback, cancellation or every-server behavior is proven here. No request or retry test ran.

Scope: EWS generic response handling and retry boundary.
