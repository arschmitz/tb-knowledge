# Folder-copy queue success is separate from copy-service completion notification

Fixed ExchangeFolder now separates same-server handling and virtual folders from the cross-server handler. The current handler uses closure-based ExchangeSimpleFallibleListener and the copy service for contained messages, unlike the historical direct destination CopyMessages. The growing-parent map still preserves descendant destinations. Stored original listener is not used in the shown handler and the terminal queue branch returns NS_OK; the needed copy-service caller expects NotifyCompletion and only clears a request on immediate failure. Completion/failure signaling remains an explicit static investigation gap, with no reproduced queue hang or all-path claim. Review manual cross-account testing found remote read status incorrect despite correct local display; this is handled by separate2284, not by2283. No automated tests changed. Rust remote-folder callback failure dispatch, full server move semantics, cancellation/error recovery and native copy completion were not executed or fully audited.

Scope: Exchange folder-copy completion investigation.
