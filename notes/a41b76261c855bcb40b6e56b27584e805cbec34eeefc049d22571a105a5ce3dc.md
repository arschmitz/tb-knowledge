# Model-readiness events should describe their data, not a button implementation

The incoming/outgoing and auto forms emit config-updated with detail.completed; the controller consumes completion as form state. Proposed rule in this family: keep the event name dashed and semantic, and document what completed means at each step. Incoming completeness and outgoing retest status differ, so the boolean alone is not proof of authentication. Existing private-field and layer-specific naming rules are reused. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: Account Hub event contract.
