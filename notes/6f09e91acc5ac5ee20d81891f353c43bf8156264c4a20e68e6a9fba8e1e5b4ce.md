# Give compaction logs explicit identifiers, reasons and paths

Entry 982 adds labeled storeToken-to-msgKey mapping and explicit skip reasons for no token and pendingRemoval. Those logs remain in current BuildKeepMap. Current MboxCompactor also logs source and destination paths, file access conditions and rename results. Scoped manual logging rule: name the identifier domain and operation, and log the reason when a message is skipped. Log severity follows the outcome, with conditional Debug/Error for rename results. Logging does not itself repair corruption or establish that an operation succeeded.

Scope: mailnews/base/src.
