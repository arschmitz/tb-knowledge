# Password validity, labels and submission are native form contracts in Account Hub

The accepted password template has a required password input, an explicit label for password, a wrapping label for the remember checkbox and a hidden submit button. Its input handler emits config-updated with checkValidity, and the form focuses the password on entry/reset. Preserve these native associations when styling the step. They support structural accessibility and Enter submission, but source inspection alone does not verify screen-reader labeling, access keys or focus execution. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
