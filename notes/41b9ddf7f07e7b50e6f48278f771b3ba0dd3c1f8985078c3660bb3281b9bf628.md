# SMTP rebuilds capability and authentication lists from each new EHLO response

The handler clears both the capability list and supported authentication methods before parsing a successful new EHLO response. An ordinary unsupported-EHLO fallback clears both before HELO, whose authentication consumer sees no advertised methods. MAIL construction reads the current extension list, while reuse of an already-open socket does not run a new EHLO just for each message. Required STARTTLS failures and other rejected responses have separate error branches. This is static protocol-state inspection, not a live reconnect, TLS or send result.

Scope: SMTP EHLO/HELO state and extension consumers.
