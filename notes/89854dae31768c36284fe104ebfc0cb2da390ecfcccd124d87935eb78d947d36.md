# S/MIME verification detail travels separately from the overall signature status

This landing carries optional certificate-verification detail beside the existing overall result code through the async callback, MIME sink and UI. Only selected verifier failures have detail; other failures or statuses can carry null. The untrusted-status UI compares eight reason-name strings to existing explanations and uses a fallback for absent or unmatched detail. Review explicitly defers keeping every upstream pkix value synchronized and accepts retaining the RefPtr wrapper. The changed test sinks log the new reason but add no reason or explanation oracle. Native certificate/crypto/thread/binding behavior and all upstream enum semantics were not executed or fully paired.

Scope: smime-verification.
