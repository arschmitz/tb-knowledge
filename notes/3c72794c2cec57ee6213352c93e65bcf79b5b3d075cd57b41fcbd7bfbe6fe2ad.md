# Cached OAuth2 objects require endpoint and user identity as well as sufficient scopes

The accepted OAuth2Module reuses an in-memory OAuth2 object only when loginOrigin, authorizationEndpoint and username match and its scopes are a superset of requiredScopes. The current test describes and exercises these separate reuse conditions. Preserve all identity predicates when changing this cache; matching a provider or having broad scopes alone is insufficient. Stored-token scope-set matching and string-order independence already have shared evidence. This is a scoped cache contract and manual review recommendation. No token-vault test, build or runtime operation ran. Full Bugzilla and Phabricator discussion remains pending; source adoption does not establish reviewer approval.

Scope: OAuth scope-set token reuse.
