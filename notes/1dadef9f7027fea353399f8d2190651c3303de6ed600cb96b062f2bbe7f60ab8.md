# The NNTP header-download prompt uses the most recent main window as its dialog receiver

When the existing new-message range guard requests user input, the code calls openDialog on Services.wm.getMostRecentWindow("mail:3pane") instead of _msgWindow.domWindow. It keeps the modal flags and property bag, then consumes hitOK/downloadAll and the server settings. The call has no guard for an absent3pane, which is a source precondition rather than a reproduced new failure. Threshold logic and the existing unload copy-back contract are unchanged; no live dialog or download ran.

Scope: NNTP range selection and modal dialog parenting.
