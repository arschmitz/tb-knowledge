# EWS back navigation does not read a separately owned outgoing form

The incoming-config back-action case reads outgoingSubview.captureState only when the config does not derive outgoing settings from incoming. The actual predicate delegates to isExchangeConfig; after that guard the controller copies current config into the displayed form. The original regression test drives EWS edit→password→back and checks restored fields/no notification with authentication bypassed in its mock. Accepted later harness/form gates are separate. This does not verify every navigation path, Graph account creation or provider authentication.

Scope: Account Hub back-navigation config ownership.
