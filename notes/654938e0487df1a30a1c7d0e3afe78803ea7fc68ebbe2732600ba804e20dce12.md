# Thundermail provider hiding retains an instance and returns a separate result

The reland API stores the provider instance before unregistering it. A flag causes later providerRegistered callbacks to undo registration while signed out; registerProvider clears the flag and reuses the captured object. These async helpers resolve result objects and can return success:false, so promise settlement alone is not successful provider registration. The native unregisterProvider also drops matching cached account entries. Generated sign-in/out callers and final UI/persistence behavior remain separate source gaps; no runtime race or user data loss was reproduced.

Scope: Thundermail CloudFileAccounts API lifecycle.
