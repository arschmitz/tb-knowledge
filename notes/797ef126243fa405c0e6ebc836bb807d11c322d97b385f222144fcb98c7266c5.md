# Custom OAuth Boolean flags replace issuer defaults even when the value is false

This landing moves usePKCE out of the truthy string override loop and assigns usePKCE and useExternalBrowser directly from custom details. A supplied false therefore replaces an existing issuer Boolean value instead of being skipped as an empty string override would be. Exchange's preference getters initialize PKCE to false and external-browser use to true, while the actual browser branch also requires a global preference. Unit assertions directly check the resulting OAuth object flags; the browser test toggles the controls without adding explicit post-save assertions for those two incoming-server values. No provider,redirect,crypto or native UI result was executed here.

Scope: OAuth custom issuer flags and Exchange settings.
