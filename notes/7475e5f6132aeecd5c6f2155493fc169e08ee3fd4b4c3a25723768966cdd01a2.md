# EWS HTTP500 bodies can carry retryable SOAP backoff without being successful HTTP responses

The owned client retains a500 response for SOAP parsing while keeping connection-success reporting in the non-error HTTP branch. Recognized ServerBusy message/fault details supply a delay and retry; other faults and parse errors still fail. Accepted code separates that policy into EwsResponseProcessor and a shared sender. The scoped500 log remains at error level. The fake-server test checks completion after two configured busy responses, without measuring retry timing or solving later connection concurrency. No request or test ran.

Scope: EWS response error and backoff handling.
