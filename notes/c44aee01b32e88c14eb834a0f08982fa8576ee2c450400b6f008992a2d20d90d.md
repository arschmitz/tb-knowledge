# Current message post-load work checks that the original URL is still displayed

The accepted onEndMsgDownload compares its URL with browser.currentURI before doing message-specific work and checks again after an awaited document load. The message pane can navigate away during the wait. For this post-load path, preserve that URL guard when adding asynchronous work so a previous message does not update the new one. This is a limited current refinement of the historical 1297 path, not a full study of the later fix or a general navigation guarantee. No rapid-selection or delayed-load test was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Message post-load navigation guard.
