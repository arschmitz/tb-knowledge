# Outgoing removal uses the generic server interface and persistent UID

Sync’s outgoing removal path queries nsIMsgOutgoingServer and marks that server UID deleted. Missing EWS UIDs are generated and stored by the server implementation; fixed code delegates this to protocol_shared. The getter stores a newly generated preference before caching, while set_uid caches first then stores, so no all-or-nothing failure guarantee is established. The original console error did not fail its test. No Sync or persistence-failure test ran.

Scope: Outgoing server identity and persistence.
