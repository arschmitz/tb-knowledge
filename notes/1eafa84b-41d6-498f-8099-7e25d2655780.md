# Confirm deletion once in the controller that performs it

`MailUtils.confirmDelete()` handles the warning before a delete command runs. It covers unified folders, conversation views, Search Messages, Trash, collapsed threads, permanent deletion, and newsgroups. When `about:message` is nested in `about:3pane`, delegate to the parent controller before showing the warning. Otherwise both controllers can prompt.

## Evidence

- [Bug 958088](https://bugzilla.mozilla.org/show_bug.cgi?id=958088), [D208902](https://phabricator.services.mozilla.com/D208902), and commit `96f004a2f25fa5b4f417983ac9e22a8f3a42be37` moved warnings out of `nsMsgDBView` and added browser tests. The review requested checks of the prompt text and cancel/accept results. It also asked new tests to use `KEY_Delete` rather than `VK_*`, and new JavaScript methods to omit the `a` parameter prefix.
- [Bug 1915255](https://bugzilla.mozilla.org/show_bug.cgi?id=1915255), [D220376](https://phabricator.services.mozilla.com/D220376), and commit `fb23317ecf0550c0e7a0d81a1e58e86e6e8dfd96` fixed the later double prompt. The test moves focus to the message pane before Shift+Delete.

## Validation and limits

I inspected the landed code, tests, bugs, and reviews on October 6, 2026. I did not run the tests. The parameter rule is a reviewed choice for new JavaScript methods; it does not rename interface-required or older parameters.
