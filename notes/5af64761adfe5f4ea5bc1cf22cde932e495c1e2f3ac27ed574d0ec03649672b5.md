# The historical secure-telemetry test refined its completion event after an earlier test leaked a late load

After initial acceptance, the author reports an unsuccessful Try caused by the preceding test’s late ordinary message load reaching this test. The assigned patch narrows and renames the event to MsgSecurityTelemetryProcessed, while plain-message checks use MsgLoaded. That is an attributed diagnosis and source-applied isolation change, not proof of final intermittent reliability. The historical500ms timer reset was explicitly defended as a quiet period after each update. Fixed source now uses crypto-processing completion and SecureMailLoaded instead, so retain the rationale without copying the retired timer/event into new tests. No new runtime validation.

Scope: Secure-message telemetry tests.
