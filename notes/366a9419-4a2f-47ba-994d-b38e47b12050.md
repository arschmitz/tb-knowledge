# WebGL wrapper starts target navigation from the preference callback

Firefox repository `git:314d8065c5ad68c7e5c5f92d`, revision `1a097ed8d31f6b307a5d0ebc34a82ceaf7f3727b`. Scope: DOM Canvas WebGL conformance tests and the shared Mochitest harness. Languages in the cited files: HTML. File roles are listed in the metadata. No production WebGL implementation is claimed.

The outer wrapper loads SimpleTest and embeds mochi-single with the target URL in its query. mochi-single creates a nested iframe and exposes window.webglTestHarness before requesting preferences. It asks the parent SimpleTest to wait for explicit completion. It requests webgl.force-enabled and webgl.enable-draft-extensions, passing runTest as callback. runTest removes only the first query question mark and sets frameElem.src to the remaining target URL, preserving the WebGL2 query.

## State and ownership

The outer generated document loads SimpleTest. The inner `mochi-single` document owns `frameElem` and `window.webglTestHarness`. The loaded target owns its own DOM. Frame removal and document-release timing were not followed.

**Errors:** Only platform timeout detection is caught. A missing SpecialPowers object or pushPrefEnv rejection has no local recovery/catch. The truthy parent guard does not by itself establish that parent supplies SimpleTest; standalone use is outside the proved embedding.

**Completion:** Setting iframe src starts navigation; it does not mean the target loaded or finished.
