# Keep both MSIX package publisher values in step with the signing certificate

Bug 1894264 ports the MSIX publisher fix for an updated signing certificate. The change replaces Mountain View with San Francisco in the publisher distinguished name for shippable builds in both repackage-msix and repackage-shippable-l10n-msix kinds. Level 1/2 builds still use the fake publisher and msix-store has its own publisher. Bug 1894145 describes a Windows 11 Add-AppxPackage open failure, 0x80073CF0. D209020 was accepted, later reopened and backed out for build bustage, then relanded with the same two-line change. The review does not establish the exact build failure cause. Packaging changes need coverage of release signing and localized MSIX, not just source checks.

Scope: Windows packaging.
