# Treat the notification-filter inversion as a payload-contract change

D230925 final acceptance followed an explicit JSON-structure clarification after the first accepted version was still reported wrong. During normal filtering, separate include/exclude profiles are OR alternatives, while supplied conditions inside one profile must all match. A language exclusion and a previously interacted notification exclusion therefore need separate profiles when either should exclude the notification. The checked filter and expanded assertion cases support this scoped contract. The review does not establish compatibility with the earlier payload or prove the producer deployed a replacement. Existing profile-composition and historical-polarity lessons remain relevant; this adds the confirmed payload-change boundary. No tests or live notifications were run.

Scope: Notification targeting review and payload contract.
