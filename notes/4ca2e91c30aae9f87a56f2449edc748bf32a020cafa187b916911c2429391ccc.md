# Prepare message state before publishing database notifications

The stub resets its SQL statement before notifying listeners. Current AddMessage scopes statements with mozStorageStatementScoper, copies returned fields into CachedMsg and inserts that cache entry before OnMessageAdded. Current removal captures the returned fields and old flags before OnMessageRemoved. Preserve this preparation-before-notification order in this database family, so callbacks observe the new logical state and do not depend on a live returned SQL row. No transaction-wide atomicity guarantee is inferred. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending.
