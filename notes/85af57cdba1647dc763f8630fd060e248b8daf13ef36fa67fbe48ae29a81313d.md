# Message-display script tests wait for a real content page before testing non-injection

The MV2 and MV3 register/runAt scenarios now navigate a real content.html fixture and await its requested URL/readiness before observing that message-display scripts do not affect a plain content page. Registration checks expected colors and absent foo; runAt relies on extension-message accounting. The existing 1000 ms negative wait remains, so this does not establish that all timing assumptions or late injections are covered. Existing tab assertions lack messages. No extension or browser test ran.

Scope: WebExtension message-display script browser tests.
