# Panorama test databases duplicate the production schema and must start after fixture setup

The test helper opens panorama.sqlite, creates its schema, inserts supplied SQL, closes that connection and only then calls loadExistingDB. That function initializes the account manager before obtaining DatabaseCore. Set preferences and any existing database before calling it. Production CreateNewDatabase explicitly asks for head.js to stay in sync; the review suggestion to eliminate this duplicate schema was deferred, not implemented by acceptance. Current production has a messages_threadId index absent from the checked helper, so matching table columns alone does not prove complete schema identity. This is static setup knowledge; no test database or runtime failure was reproduced.

Scope: Panorama test SQL setup ordering.
