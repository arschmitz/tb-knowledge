# Address-book public mutation methods protect read-only directories

Accepted addCard, modifyCard and deleteCards check _readOnly. Their corresponding Internal methods deliberately omit the check for subclass server synchronization, and document that ordinary callers must use the public methods. The Internal suffix names a permission boundary in this family; it is not a general promise that every internal method is unsafe. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/addrbook/modules.
