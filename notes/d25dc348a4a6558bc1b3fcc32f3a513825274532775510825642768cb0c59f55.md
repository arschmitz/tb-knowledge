# Test database closure without reopening it through the getter

The retention test drops the folder database reference, forces garbage and cycle collection to release leftover headers, and then checks cachedDBForFolder. Only afterward does it use msgDatabase again to inspect counts. Follow that local observation boundary when testing closure. Clearing one reference is not proof the database is destroyed while headers still hold it. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Message database closure test boundary.
