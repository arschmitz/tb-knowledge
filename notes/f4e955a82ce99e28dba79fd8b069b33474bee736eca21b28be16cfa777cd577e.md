# Destination creation is outside the recorded backend import try block

Proposed import failure tests: make address-book or calendar destination creation fail before backend startImport. Current controllers create/register a missing destination before entering the try block that records result=failed. A creation failure therefore is outside that inspected telemetry catch boundary. This is a static event-scope limit, not a reproduced lost event; discussion is needed before deciding whether the metric should include setup failures.

Scope: mailnews / import.
