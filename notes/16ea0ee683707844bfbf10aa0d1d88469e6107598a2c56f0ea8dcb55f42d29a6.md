# Autodiscover OAuth cancellation joins the abortable chain and avoids treating cancellation as a lookup miss

The owned OAuthAbortable extends Abortable and is installed through ParallelCall.setAbortable before provider initialization. Its cancel closes the OAuth prompt through cancelPrompt and marks cancelled; the prompt module rejects authorization and finishes request cleanup, whose checked OAuth2 listener closes its window. The connect Promise failure handler then calls the Exchange listener. Exchange tests callerAbortable.cancelled, reports UserCancelledException and returns before ordinary Basic-auth fallback. FindConfig also changes a cancelled discovery result from null to a thrown UserCancelledException; its view caller rethrows before guessConfig can run after a normal no-config result. This wrapper explicitly monitors no OAuth token effects, and it does not establish token revocation or full legacy setup correctness. The newly relevant pre-existing setAbortable assert has no message argument, yielding the helper generic fallback. Later accepted Exchange code uses AbortSignal/async fetching and keeps the cancelled-error-versus-Basic-fallback distinction. No OAuth popup, transport or malformed-state path was exercised.

Scope: mail/accountcreation/autodiscover-oauth-cancellation.
