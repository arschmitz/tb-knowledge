# Search policy and preferences expose different initialization promises

The accepted SearchEngines policy returns its init/async-work chain; that return is a later phase beyond the original receiver port. Preferences updateWebSearch is async but does not return or await its init.then callback, so its own promise is not proof that the list is populated. The policy test helper has a different contract: reset, apply policy, observe settings-written, await init and return that notification. Do not use a method's async spelling or the provider replacement alone as a completion guarantee. No policy/UI test ran.

Scope: Search policy and preferences asynchronous state.
