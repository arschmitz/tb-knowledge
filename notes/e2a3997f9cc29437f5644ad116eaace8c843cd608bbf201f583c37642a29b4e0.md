# Exchange body-dependent filters keep pending keys until offline data is ready

New-header synchronization queues keys once. Body-dependent filtering leaves a target pending until Offline is set; downloaded-body callbacks retry selection. Ready targets leave the queue before ApplyFilters starts, so removal is dispatch state, not a successful-filter receipt. The notification wrapper ignores the filter result, and the completion lambda does not inspect its status before notification/classification. Fixed source uses a later header-block map. No failure, filter or download scenario ran.

Scope: Exchange filter queue and download notifications.
