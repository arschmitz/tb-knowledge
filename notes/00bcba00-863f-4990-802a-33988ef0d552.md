# Check shared protocol callers when an async change exposes old callback failures

The first LineReader async landing for Bug 1893307 caused permanent NNTP test failures and was backed out. Bugzilla and D210555 attribute this to an exposed promise-chain rejection and a null runningUri during NNTP completion. The reland added optional chaining before SetUrlState and passed a full Try run. The reviewer asked for an automated long-response test, then accepted with the stated I/O testing limit. This illustrates that a shared parser timing change needs POP3 and NNTP test coverage and careful review of completion callbacks; a green local POP3 observation alone did not cover the change.

Scope: NNTP completion.
