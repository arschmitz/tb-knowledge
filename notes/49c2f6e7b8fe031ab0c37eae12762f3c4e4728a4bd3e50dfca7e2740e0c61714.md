# Panorama Message-Id lookup binds the folder in the query

Review correctly distinguishes querying a Message-Id inside its folder from finding an arbitrary global Message-Id then rejecting another folder. The final assigned Git already binds folderId and messageId together, despite the older accepted-but-deferred discussion. Its fixed query retains both criteria. The adapter maps failed Message-Id lookup to NS_ERROR_ILLEGAL_VALUE. No uniqueness or deterministic choice among duplicate Message-Ids inside one folder is established. Changed tests verify the owning folder, reject a Message-Id present only in another folder, store messageSize and exercise both folder bridges. Their SQL fixture gives each message a distinct Message-Id, so they do not directly exercise the same Message-Id appearing in two folders. A focused proposed test is a duplicate Message-Id across folders with each owning DB returning its own key; this would test the exact review concern rather than only a missing-in-this-folder result. No test or SQL ran.

Scope: Panorama scoped header identity and test coverage.
