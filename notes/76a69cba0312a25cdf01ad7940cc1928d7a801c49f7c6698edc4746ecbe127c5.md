# A POP assertion does not replace the optional-parser guard

POP parser initialization can fail, set m_newMailParser to null, and continue. IncorporateComplete has an assertion for the parser, but the LF blank-line workaround must still test the pointer before HandleLine. The crash fix adds that runtime guard. When adding work on this tolerated failure path, preserve the optional-parser contract rather than assuming an assertion establishes a non-null pointer in release builds. The separate LF workaround is already covered by prior source lessons. This is static source evidence. No runtime, build or live accessibility validation was run. Full bug and review discussion remains pending.

Scope: POP tolerated parser initialization failure.
