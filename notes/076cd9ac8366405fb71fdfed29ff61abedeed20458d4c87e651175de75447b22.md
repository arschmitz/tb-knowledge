# A token buffer must grow beyond the token length before the terminator write

The historical square-root cap stops doubling at 65536 even if the token length is still at least 65536, then reads size bytes and writes buffer[size]. Static inspection therefore does not support that cap as a safe allocation recipe. Fixed accepted readTokens instead checks the next doubling against UINT32_MAX/2 and continues while size is at least bufferSize, leaving space for the terminator. Later Bug 1961413 metadata identifies a growth fix; that later patch and discussion were not audited here. No malformed-file or exploit test ran, and other short-read handling remains outside this narrow claim.

Scope: Bayesian corpus token bounds.
