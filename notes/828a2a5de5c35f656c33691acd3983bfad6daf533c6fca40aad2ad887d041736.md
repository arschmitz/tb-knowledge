# EWS EmptyTrash separates task dispatch from remote and local completion

EmptyTrash gathers fallback IDs and captures local headers before starting the client operation. The Rust bridge returns after detaching a task, so successful dispatch is not completed deletion. For a supported server version, EmptyFolder uses HardDelete with delete_sub_folders=true, preserving the target folder while requesting recursive content deletion. Only the success callback re-enumerates local child folders, deletes them, then deletes the captured local messages. Its scope-exit handler reports the local result to an existing URL listener. This is ordered reconciliation, not a remote/database transaction, and the captured headers are a snapshot. OnStartRunningUrl is still called before EmptyTrash returns; do not turn the historical review aspiration about callback timing into a source guarantee. No remote deletion or callback order was executed.

Scope: mailnews/exchange/trash.
