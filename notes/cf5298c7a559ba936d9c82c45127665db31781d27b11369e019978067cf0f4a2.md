# Track one current mbox write per folder and guard stale discard by stream identity

The accepted current store keeps mOngoingWrites by folder URI with a captured file position and stream. Starting a new write closes and rolls back the prior one. FinishNewMessage requires the issued stream, calls nsISafeOutputStream.Finish, returns the captured store token, then removes the entry. A discard for a preempted old stream must not erase the newer write entry. This is newer architecture than374, not a claim that its logging patch implemented the transaction model. Failure/overlap tests were not run, and the current discard log access after map removal was not verified safe.

Scope: Mbox write ownership and transactions.
