# Folder compaction preserves staged recovery files after a successful database commit but failed store commit

mKeepRecoveryFiles becomes true when the database commit callback succeeds, since the low-level store commit can still fail. Final success clears it; otherwise the final handler removes partial output but keeps completed/backup DB files when that flag is true. It releases the semaphore and performs completion notifications in the final phase. This scopes the cleanup by commit state; it does not prove a working recovery procedure for every surviving file combination. This is static source and test-code inspection at the frozen accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator timeline and inline discussion remain pending; a landing does not prove approval of a proposed manual rule.

Scope: folder compaction recovery state and final cleanup.
