# Updatebot release selection and development reruns have explicit boundaries

The setup script clones hg-evolve, sorts tags by version and selects the second row before hg up. That source records the intended release-tag selection instead of an unreviewed tip, but it assumes the tag ordering and does not prove what a fresh clone selects today. run_check_upstream returns true for a successful normal check, false for return code 88, and also false after a successful check in dev mode to force the complete vendoring path. Other process errors are rethrown. Manual automation proposal here: document and test the boolean control-flow meaning and development override, and keep release-selection assumptions explicit. No clone, package installation or vendoring command was run.

Scope: rust-updatebot.
