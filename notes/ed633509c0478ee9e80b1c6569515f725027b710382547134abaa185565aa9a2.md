# Keep the database insertion boundary consistent with its folder identity

The notification landing moves folderId to the first addMessage argument across IDL, native implementation and fixtures. Accepted helper source keeps that ordering and supplies typed message metadata after it. Review callers and fixture builders together when changing a positional API; a folder identifier is not a message key. This is this API contract, not a rule that every method must put its container first. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Panorama insertion argument boundary.
