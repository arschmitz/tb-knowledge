# Recipient pill creation consumes one parsed address object despite array-shaped JSDoc

createRecipientPill reads address.email, address.name and address.toString from one parsed address object. Its caller parses a list, loops over the results and passes one object on each call. The accepted JSDoc still labels this parameter msgIAddressObject[], which does not match that scalar contract. This is a scoped source/documentation discrepancy; it does not establish an array contract for this method or change other parser APIs. Static inspection only.

Scope: compose-recipient-pill-contract.
