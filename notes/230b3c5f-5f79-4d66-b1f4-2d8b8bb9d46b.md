# Keep logical blank-line groups in code

This supplement makes an existing layout instruction explicit for Thunderbird
writing, review, and verification. The user requested this update on October 13,
2026 after reporting missing blank-line groups in recent implementation tasks.
It is deliberate guidance. Automatic learning must not change it.

## Guidance

Keep useful blank-line groups and local method organization. Separate distinct
logical steps with a blank line when it makes the flow easier to follow. Follow
nearby accepted code and keep closely related statements together. In tests,
make setup, actions, and expected results easy to distinguish. During writing,
review, and verification, inspect this grouping separately from formatter and
lint results. A formatter pass does not establish readable grouping. Do not
impose fixed blank-line counts or add a blank line after every statement.

Let the applicable formatter choose mechanical layout. Preserve the exact
language, component, file role, and section rules. Do not rewrite unrelated code
or report a harmless alternative as a defect. When grouping obscures the flow,
identify the affected steps and explain why a separator would help.

## Evidence

The [existing practical guide](08ac54d5-331d-4ab5-bc8f-6120318565a3.md) says:

> Keep useful blank-line groups and local method organization.

That sentence is present in the guide at shared revision
`b6fa416fef14fe89f573b7e9ea6639145b0364d3`. It was absent from the concise guidance
supplied directly to console turns. This supplement brings that instruction
into the direct guidance and adds an explicit manual check. It does not replace
the guide or create a fixed method order or line-count target.

A local static check found long function bodies whose statements retained normal
line breaks but lacked blank-line groups. The installed Prettier 3.8.5 left the
two inspected Save controller files unchanged with their resolved settings. It
also preserved an inserted blank line in an in-memory formatting check. Thus a
passing formatter result did not establish readable grouping in those examples.
This is a scoped observation, not a claim about every formatter or language.
