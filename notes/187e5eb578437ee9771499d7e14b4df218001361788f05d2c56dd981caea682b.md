# The IMAP probe observes a stream without consuming it

Peeker checks a leading header colon or From marker and returns NS_BASE_STREAM_WOULD_BLOCK so the stream buffer is not consumed. OnDataAvailable then either starts the deferred listener and forwards the same segment, or falls back to the IMAP connection on bad cache. The bounded probe is a heuristic, not full RFC message validation. Runtime cache fallback and ReadSegments callback behavior were not executed. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
