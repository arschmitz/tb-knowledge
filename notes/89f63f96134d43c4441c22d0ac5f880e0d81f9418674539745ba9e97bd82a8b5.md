# Test size corruption through the message-service boundary

The accepted malformed-mbox unit test creates messages larger than 512 bytes, halves their database messageSize, then streams them through the message service and checks the unexpected-size error inside catch and the Glean count. This exercises the folder-to-store size-limit path rather than only parser fixtures. Its catch-only error assertion does not explicitly fail on unexpected stream success. The test does not independently assert exact-limit success or read-by-read transitions, and no test was run here. Existing minimum-chunk and envelope-reset lessons remain separate. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Mbox size-corruption test coverage.
