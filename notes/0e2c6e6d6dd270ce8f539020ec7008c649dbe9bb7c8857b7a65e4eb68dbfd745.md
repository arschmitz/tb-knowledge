# Await about:3pane readiness before reading initialized message browsers

about3Pane resolves hasDOMContentLoaded only after custom elements, folder/thread initialization, messagePane readiness, state restoration and initial selection setup. getMessageDisplayTab awaits that promise before inspecting web or multi-message browsers. Keep DOM document loading separate from this feature-ready promise; a source rejection before resolve is not shown to be propagated through a reject handle, so this is not a complete failure-path guarantee. These are fixed accepted source and test-code observations. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint, live accessibility or crypto/TLS validation ran.
