# OAuth request classes keep UI-specific flow details behind request operations

The patch separates InternalRequest and ExternalRequest and stores the selected request on OAuth. Selection then calls the common start operation, while finishAuthorizationRequest closes and clears the selected object. The reviewer requests this split to keep UI-specific detail out of the selection path, and exact source adopts it. The oauth owner name distinguishes that object from an account. This is a scoped accepted design choice, not a requirement to split every authentication flow into classes.

Scope: OAuth flow ownership and local class organization.
