# IMAP keyword filtering drops whole outbound tokens and the accepted code later restores legacy ampersands

StoreCustomKeywords filters additions and subtractions before placing them in the internal customKeywords URL. A prohibited byte rejects its whole token; remaining tokens are joined for the URL. The original blacklist includes ampersand, while the fixed accepted predicate omits it and the IDL names legacy modified-UTF-7 keys as the reason. The actual generic atom parser also accepts ASCII38. This is a scoped outbound filter with additional local restrictions, not a proof of full standards compliance or a universal invalid-character list. Empty sanitized fields do not bypass service dispatch; the protocol action only issues each corresponding Store call for a nonempty field. Local database changes occur earlier in the caller.

Scope: IMAP custom-keyword request boundary.
