# Count discarded attachment bytes and describe a prefix threshold accurately

The filter emitter increments currentPart.size before it may discard attachment data. Encryption checks temporarily retain an initial body portion, then endPart clears attachment bodies when excludeAttachmentData is enabled. The body.length < 300 condition is checked before appending an entire chunk, so it is not a hard 300-byte cap. A first large chunk may exceed that value. Manual comment and test proposal for this stream path: distinguish retained data, accounted size and the pre-append threshold. Preserve inline-encryption and encrypted-attachment detection while avoiding retention of the whole attachment. The source does not prove peak memory usage or a fixed chunk size.

Scope: mime-filter-byte-accounting.
