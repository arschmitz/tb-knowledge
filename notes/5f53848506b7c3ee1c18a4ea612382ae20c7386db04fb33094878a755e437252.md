# Notification locale targeting uses exact shipped language tags

checkProfile uses Array.includes with Services.locale.appLocaleAsBCP47. A target en therefore does not match en-US. The accepted documentation links the maintained shipped-locales file instead of promising a fixed locale count. Keep this separate from localization fallback in other APIs. The neighboring empty-array sentence conflicts with code and direct include/exclude assertions: a locales:[] profile does not match. That prose needs a scoped correction; no runtime locale switch or global fallback behavior was tested.

Scope: Notification locale matching.
