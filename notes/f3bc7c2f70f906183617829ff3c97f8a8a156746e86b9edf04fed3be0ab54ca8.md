# DoH bootstrap configuration and provider records carry different fields

The packaged doh-config snapshot has one global record with provider IDs and separate rolloutEnabled, steeringEnabled and autoDefaultEnabled fields, all false in this owned snapshot. The doh-providers snapshot maps each ID to a URI, UIName and provider-level autoDefault value; Cloudflare has true there. Keep the global and per-provider fields distinct when reading these dumps. Their names and stored values alone do not establish the active runtime DNS mode; the controller and resolved preferences also matter. Both JSON blobs match the fixed accepted tree. No network, settings sync or runtime test ran.

Scope: remote-settings-doh.
