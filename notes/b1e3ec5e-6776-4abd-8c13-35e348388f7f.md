# Account Hub title changes can expose empty headings

An accessibility observer can see the interval between clearing a heading's old
title and Fluent, the localization system, inserting the new text. In the Account
Hub, the requested title visibility and the presence of title text are separate
states. A successful accessibility check alone does not prove that a populated
heading appears again.

## Evidence

At comm revision `25465b9913429a550f202168fa211a756b1fab16`,
`AccountHubStep.#setHeader` clears `title.textContent` before it sets the next
Fluent ID. The title span is in the light DOM of `account-hub-header`; the heading
and its title slot are in the header's shadow root.

The local Bug 2081044 implementation, commit
`bbf659e1d2834ede320711b8ef453ab0389ddd8e`, hides the heading after clearing old
text and observes the slotted text to show the populated heading later. It keeps
the caller's requested visibility in a separate Boolean. The observer stops on
removal and starts again on reconnection without resetting that Boolean.

The Header regression test failed before the fix: waiting for an empty heading
to become hidden timed out, and axe reported `empty-heading`. After the fix,
the test verifies all three states: a title disabled by the caller stays hidden
through reconnection, an empty title hides its heading, and restored title text
shows the heading again. The Step tests also check removal and restoration after
translation.

A temporary CSS probe for `:host(:has(> [slot="title"]:empty))` passed the
empty-heading hiding assertion but failed the populated-heading visibility
assertion. The final patch does not contain that selector. This is an observed
result in the tested runtime, not a general claim about `:has` support.

## Validation and limits

The final native browser run passed all 25 Account Hub component test files:
1,118 passing checks, 30 expected TODO results, and zero unexpected results. The
focused Header, Step, and ManualConfig run had 223 passing checks and no failures.
The runtime was a Thunderbird 161.0a1 artifact, BuildID `20261104172015`, with the
current isolated source resources. No native compilation or remote Try run was
performed.

The implementation is local and unsubmitted. These observations are scoped to
Account Hub's current text title slots. They do not establish an accepted global
component pattern or support for headings whose titles consist only of images.
