# LDAP form CSS places the qualified class before its stacked-state pseudo-class

The finalized Account Hub LDAP grid uses &.expanded:not(.stacked &) and &.full:not(.stacked &) for the affected input-cell variants. Each selector places the concrete class before the state pseudo-class; the nested & inside :not is part of the checked selector and must remain meaningful when refactoring. This is a source-confirmed local arrangement for this grid. The review also recalled a broader tag/ID/class/attribute/pseudo-class/pseudo-element order, but that recollection is a suggestion rather than evidence of a repository-wide configured rule. This supplement does not create a global selector order or spacing rule. Current row counts and control layout have later changes, and no CSS render, parser experiment or accessibility test ran.

Scope: Account Hub LDAP nested CSS selector style.
