# Direct import-test clicks retain explicit state waits

The test replaces synthesized pointer actions with programmatic HTML clicks and scrolls controls before activating them. It still waits for pane, progress, finish and notification state; the controller can start asynchronous picker/import work that the click call does not await. The main task directly checks UI state and exact success telemetry, while the large-ZIP task waits for any error notification rather than a specific error message. This describes this harness and these actual controls. It does not establish pointer/focus coverage, all imported settings, reliable timing or an intermittent cure, and no test ran here.

Scope: Import browser tests.
