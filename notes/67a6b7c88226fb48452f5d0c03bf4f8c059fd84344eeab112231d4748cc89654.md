# External GnuPG key input validation is separate from saving its normalized value

The assigned first patch adds hexadecimal constraints and interactive delayed fingerprint truncation. Available Bug discussion says the later approach normalizes at save time after a test-fixture backout; the first landing must stay historical. Fixed openPgpExternalComplete calls normalizeKeyInput, checks for a matching public key/user email, then stores the key ID and calls okExternalCallback. Its markup now accepts key IDs and longer fingerprint forms. This inspection does not establish every normalizer/GPGME behavior or real key validity. Bug comment1 is unavailable and review is deferred; no OpenPGP test ran.

Scope: OpenPGP key setup boundaries.
