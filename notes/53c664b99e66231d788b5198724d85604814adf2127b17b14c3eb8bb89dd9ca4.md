# Tag SQL helpers have an explicit null and argument-type policy

Current TagsMatchFunction requires two arguments. A null tag-list input leaves found false, yielding false for include and true for exclude; for a non-null list it requires both values to be text. The second argument type check is inside the non-null branch, so the null-list path does not validate it. Keep this branch-specific contract explicit when changing the helper; the inspected tag SQL tests do not exercise null or wrong-type arguments. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Panorama tag SQL argument behavior.
