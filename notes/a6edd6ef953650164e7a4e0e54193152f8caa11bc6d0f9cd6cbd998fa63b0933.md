# Keep weekday offset adjustment separate from message time formatting

Entry 2112 subtracts the current GMT and daylight-saving offsets from the exploded message offsets immediately before formatting weekday components. The time string is still formatted separately from the original PRTime. FetchDate uses local exploded dates to choose today/this-week/default formats and joins weekday plus time through the regional connector pattern. The separate accepted Gecko component formatter builds a time-zone string from the supplied offsets and implodes the supplied time. These are distinct inputs; reviewing only the final concatenated string misses the offset boundary. The commit reports wrong weekdays, but no exact runtime trigger or output was reproduced. The Gecko source is at 00aad09a820405643aebd693e60a3333ccf04544 and pairing is unverified. No midnight, non-hour offset, DST change, Date/Received fallback, regional-format, runtime, build or accessibility test ran. Full discussion is pending.

Scope: Message date weekday formatting.
