# Calendar properties Fluent patterns follow their XUL receiver attributes

The repair moves color/location/refresh strings into .value attributes and menuitem/checkbox strings into .label, including the matching migration destinations. It points the refresh label at the actual menulist and removes the duplicate static FluentID from that menulist. The earlier migration used message values and had the old nonexistent control target, so the two phases must stay distinct. Provider text remains a value and dialog button attributes remain explicit. This is XUL receiver-specific mapping, not a universal Fluent rule. No localization migration or UI test ran.

Scope: Calendar properties localization migration repair.
