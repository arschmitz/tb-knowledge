# Treat notification type strings as behavior contracts

Entry 969 actually changes donations_old to donation_old in code and its test, despite the reversed spelling in the subject. Current code instead uses donation_browser and donation_tab to distinguish website actions from popup notifications. The same predicate gates both selection events and replay to newly registered listeners. Manual naming proposal: trace exact discriminator values through producer, consumer and fixtures; do not treat a plural change as cosmetic or use the commit title as the runtime schema. The historical value is not a rule for new current notifications.

Scope: mail/inappnotifications/type-contract.
