# EWS OAuth retrieval defers Inbox discovery and revokes server validity without clearing the client cache

The EWS OAuth scenario starts with the root folder in allInboxes to avoid connecting during setup. When a connection is expected, waitForMessages discovers Inbox, replaces that shared entry and its local parameter, then checks unread/pending state and server idle before marking read. Bad-token setup first fills the client OAuth cache, then revokeToken deletes server-side validity so retrieval exercises authentication failure. The helper rename does not change token deletion or clear client cache. These are fake-server test boundaries, not real-provider authentication proof. No runtime tests.

Scope: ews-oauth-test-fixture-state.
