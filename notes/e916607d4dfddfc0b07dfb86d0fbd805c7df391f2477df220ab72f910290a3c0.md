# New-mail tests compare persistent and awakened listeners but still set biff state

The current default task compares the folder, message-list ID and messages returned to a live listener and a terminated MV3 background that is awakened by the event. Its setup still assigns biffState, hasNewMessages and the new-message count. Scoped test recommendation for the 1923 change: add a case that relies only on msgAdded plus New, without setting BiffState, and separately exercise deduplication/reset. The current source proves the new implementation does not read BiffState here; this test alone does not isolate that independence. This is static source inspection. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: WebExtension new-mail test scope.
