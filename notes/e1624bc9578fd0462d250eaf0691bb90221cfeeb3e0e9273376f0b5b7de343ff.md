# IMAP filter actions recheck database lifetime on each iteration

ApplyFilterHit acquires its database before the sorted action loop and checks mDatabase again at each iteration. If the database is absent, it logs the action index and returns before running that action. The initial successful acquisition does not establish validity for the entire action sequence. The guard does not roll back earlier actions or prove why the database disappeared. This is the checked IMAP callback boundary, not a general null-check rule. No crash or filter test ran.

Scope: IMAP ApplyFilterHit database lifetime.
