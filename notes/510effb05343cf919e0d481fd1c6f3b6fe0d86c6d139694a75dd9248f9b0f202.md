# Check concrete Exchange class naming separately from interface names

Proposal for new Exchange C++ classes: compare accepted classes with the same component and interface role before adding or removing a prefix. The historical EwsMessageChannel implements the shared nsIChannel rather than a dedicated nsIEwsMessageChannel. Review explicitly keeps its concrete name after a prefix request is rebutted; a broader documented naming decision is deferred. Preserve required interface names and public identifiers. This is evidence for this concrete class family, not a repository-wide ban on ns prefixes or proof of a formal convention. Also separate author tooling reasons for C++ from benchmark claims about Rust; review corrects the claim that every stub must repeat a signature.

Scope: mailnews/protocols/exchange.
