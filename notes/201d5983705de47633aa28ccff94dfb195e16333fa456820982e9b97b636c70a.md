# Microsoft Graph OAuth metadata selection is gated separately from EWS scopes

For the Microsoft issuer, getHostnameDetails selects Graph scopes only for type graph when mail.graph.enabled is enabled. The ews/exchange branch remains separate and uses EWS scopes. The mail caller passes server.type, while configured custom details can select another metadata path. This is a provider-metadata contract, not proof of Graph autodiscovery, token issuance or a working login. The owned patch used a false default and User.Read-only scopes; the fixed accepted declaration defaults true and the scope group has later mail permissions plus offline_access. The current negative test forces false before checking absence. Scope claims and defaults must name their revision, and this Microsoft branch does not define a universal gate for every extension provider.

Scope: mailnews/oauth/graph.
