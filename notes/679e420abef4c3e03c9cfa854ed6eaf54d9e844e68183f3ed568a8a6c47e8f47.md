# Check hidden-state precedence when a shared button modifier sets display

The 2024 modal-close selector explicitly excluded [hidden]. At the fixed endpoint, .button[hidden] sets display:none earlier in widgets.css, while the later .button.modal-close-button sets display:inline-flex. They have equal class/attribute specificity, so source order matters. An Account Hub placeholder currently combines hidden with modal-close-button. Retain a focused hidden-state check when changing this shared modifier. This is a static cascade concern, not a rendered visibility finding; other stylesheet rules were not exhaustively traced. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Shared button hidden-state cascade.
