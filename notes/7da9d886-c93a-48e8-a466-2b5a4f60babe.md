# ComposeDetails reports enabled encryption even after identity selection makes it invalid

D211558 review established that selecting an identity without encryption support must not silently clear encryption already selected in the compose window. The composer may show an invalid state with error banners, and getComposeDetails must report the actual selected state. Landed code checks the encryption button and configuration before returning selectedEncryptionTechnology; current code still prefers the button state and falls back to gSendEncrypted if the button is absent. Tests cover the invalid state after identity changes. An extension-facing getter must report what the user selected, not silently normalize it to what the identity can send.

Scope: Compose encryption state.
