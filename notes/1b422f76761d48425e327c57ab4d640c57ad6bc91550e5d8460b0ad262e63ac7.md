# Maildir candidate filenames separate storage identity from the Message-ID header

Fresh full two-file299-line filename patch read. Maildir stops percent-encoding/clipping a Message-ID at finish and generates a candidate name from seconds, microseconds, pid, per-store count and hostname before opening tmp. It retains .eml for OS-search integration, fails if that tmp path already exists, stores the filename as token, and keeps the name when moving tmp to cur. The public wrapper/header coupling still exists in this early step; it is not the completed database-free API migration. Hostname capture is explicitly NUL-terminated when truncated and is not treated by the source comment as adding meaningful uniqueness. The final source still has that candidate format, .eml, explicit existence failure and byte lookup via cur/storeToken. Reviewer time-based uniqueness confidence is an attributed belief, not a proof of collision freedom across processes, clock changes or concurrent writers; no global filename-standard compliance claim or linked specification audit.

Scope: Maildir filename/token lifecycle and staged API migration.
