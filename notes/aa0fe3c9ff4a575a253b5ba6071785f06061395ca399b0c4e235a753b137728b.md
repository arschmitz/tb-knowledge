# Use Object.entries when destructuring a notification mapping

Production setNotificationData uses for (const [key, value] of Object.entries(attributes)) to translate backend keys into DOM attributes. The current browser helper instead uses for (const [key, value] in observedProperties), which destructures each property-name string rather than the object’s key/value pair. In these mapping loops, use Object.entries before pair destructuring and verify each expected pair. This is a syntax-focused test concern, not a runtime result or a project-wide iteration ban. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Notification mapping iteration syntax.
