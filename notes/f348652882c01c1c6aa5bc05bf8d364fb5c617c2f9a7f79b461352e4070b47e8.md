# Folder propagation can finish after a per-folder failure

MailUtils catches each synchronous action(folder) exception inside the generator, warns with folder.URI and keeps yielding. The timer therefore continues to later descendants and resolves when iteration ends. The column and view callers then emit propagated observer topics, even if a folder action failed. They release each folder database reference after writing. Manual completion-contract proposal: describe resolution as traversal finished, not all writes succeeded, and include the failed folder identity in diagnostics. This callback is not awaited, so an asynchronous callback rejection is not covered by the per-folder catch. The timer uses INTER_FOLDER_PROCESSING_DELAY_MS = 10; the nearby 100 ms comment is stale and is not evidence of the real delay.

Scope: folder-propagation-partial-success.
