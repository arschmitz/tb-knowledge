# State the real target-window requirement in the mail mouse helper comments

Current mouse helper comments say aWindow is optional and defaults to the current window. The implementation dereferences aWindow.windowUtils and calls aWindow.synthesizeMouseEvent without providing a default. Current draft callers pass an explicit window. Scoped documentation proposal: document the required target window or deliberately add and test a default, rather than relying on this comment. This is a source contract mismatch, not a reproduced failing caller. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: mail event-helper documentation.
