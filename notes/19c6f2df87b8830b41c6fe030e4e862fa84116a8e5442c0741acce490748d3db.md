# Unthreaded navigation uses the result row when the thread index is unset

Entry2166 treats both 0 and nsMsgViewIndex_None as an undetermined thread index and passes the result index as firstIndex to scrollExpandedRowIntoView. Fixed source retains that decision; the consumer uses firstIndex in the expanded-branch bottom calculation. The change does not add an addedRows==0 early return: the author withdrew that drive-by optimization after it hid a broken attempted fix. The added test marks message404 unread, starts the unthreaded viewport at 400, navigates from405 to 404 and asserts first visible400 after a locally excepted 500ms negative-observation interval. Cleanup deselects and marks404 read, but calls sortUnthreaded again; it does not prove restoration of a previous threaded mode. This negative-observation fixture does not reverse the event/state-wait preference. Reviewer reports and Try links are historical, not executed here. Bug 1941139 comment2 remains unavailable, so this is source/full-review partial knowledge with zero complete-audit credit.

Scope: Message navigation scroll bounds.
