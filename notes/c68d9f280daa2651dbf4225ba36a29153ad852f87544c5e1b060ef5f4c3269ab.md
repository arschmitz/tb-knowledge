# Notification ordering uses nested targeting chance after severity and start time

sortNotifications returns a sorted array copy with severity, parsed start_at and targeting.percent_chance in ascending priority order. The nested targeting field fixes the old top-level lookup. Direct tests check the complete order and tied entries; manager-event tests separately expect IDs1 then2. updatedNotifications can retain an existing candidate of the same or better severity, so the sorted first entry does not always replace what is visible. This is ranking, not weighted random selection. No test execution.

Scope: inappnotifications-candidate-order.
