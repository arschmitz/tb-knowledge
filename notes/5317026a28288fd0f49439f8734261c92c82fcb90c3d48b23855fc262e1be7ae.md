# Keep cached-hit absence separate from storage diagnostics

GetCachedHits discards the GetSearchResultsTable status and returns NS_OK with a null enumerator whenever the table output is absent. ExtensionMessages then searches manually. This boundary does not identify whether the table was never created or a storage operation failed. Keep claims about storage diagnostics conditional on tracing that result, and use a focused failure test if a caller needs that distinction. The current null-versus-empty iterator contract and physical database identity are already shared. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion is pending.

Scope: mailnews/db/msgdb.
