# Do not equate a nullable smart-folder result with creation failure

Accepted getSmartFolder returns an existing URI match, but the creation branch reaches return null even after creating and notifying a folder. The extension boundary treats a falsey result as a missing folder. A scoped documentation or return-value repair should clarify that branch before callers use null as proof of failure. This static mismatch was not reproduced as a user-visible defect, and the initial URI lookup is outside the creation catch. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Smart folder creation result boundary.
