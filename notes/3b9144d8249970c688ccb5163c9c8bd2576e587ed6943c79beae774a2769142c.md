# Keep EWS References mapping separate from the superseded In-Reply-To concatenation plan

The landing requests message:References and forwards the optional EWS string through MessageHeaders into SetReferences. It uses References alone; an early In-Reply-To concatenation plan was not applied, and a later participant explicitly warned that concatenation can repeat the parent ID. The server-synthesizes-References rationale remains attributed, not a universal Exchange guarantee. Fixed active sync now requests the same property, maps it into a HeaderBlock and passes that block to its creation listener. The relocated shared optional adapter/setter is separate; a bounded Rust source search found no outside populate_from_message_headers call. Keep active consumers distinct from retained helper code. No EWS sync, threading, build or test ran.

Scope: EWS References header fetch and database handoff.
