# EWS connectivity selects a per-operation authentication failure policy

Connectivity requests the distinguished root folder with IdOnly and explicitly selects Silent authentication-failure behavior. Ordinary requests default to ReAuth. The current failure handler checks Silent before prompting through handle_auth_failure, then propagates the original error. This controls failure recovery, not whether any initial credential acquisition can authenticate or prompt. Current realm correction can retry before that guard, so Silent is not a universal no-retry guarantee. The original patch also checks native client Initialize status and changes SOAP request Content-Type; no real EWS, native compile or server interoperability result was produced. Preserve the exact operation option and current handler order when extending this path.

Scope: EWS connectivity and request failure handling.
