# Published attached events have a distinct Add-to-calendar path

The accepted test documents METHOD:PUBLISH as an attached event rather than an invite. It clicks Add, looks up the exact event UID in the calendar and then opens Details in the enabled new read dialog. That source test contract keeps a publish attachment distinct from meeting-reply UI and checks no party-crashing dialog is needed. No event import, dialog interaction or calendar backend ran in this study. This is static source and test-code inspection. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending; source landing does not prove approval of a proposed manual rule.
