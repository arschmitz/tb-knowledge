# Summary-file migration has separate enumeration, insert and property phases

The first migration implementation enumerates legacy headers in groups of 100 on the main event queue, asynchronously inserts messages, collects their new keys and then writes only selected properties. Its test covers two surviving fixture messages and decoded values/tokens/sizes, not yielding, rollback or concurrent runs. The fixed version adds threading/key mapping and closes the retained old DB; reuse that existing closure lesson. No front-end migration orchestration was included in the assigned patch, and no runtime migration ran.

Scope: Panorama migration phases.
