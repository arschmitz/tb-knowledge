# Use the accepted browser chrome constant in the window fallback

The unused getBrowserURL wrapper is gone. The accepted openLinkIn fallback passes AppConstants.BROWSER_CHROME_URL directly to Services.ww.openWindow. Before that fallback it tries the top chrome window’s switchToTabHavingURI. Use this actual owner and constant when reading the fallback; the getter deletion alone says nothing about a browser-chrome URL migration. This is static source and test-code inspection at the fixed accepted revision. No runtime, build, lint or live accessibility check ran. Full Bugzilla and historical review timeline and inline discussion remain pending.

Scope: mail link opening.
