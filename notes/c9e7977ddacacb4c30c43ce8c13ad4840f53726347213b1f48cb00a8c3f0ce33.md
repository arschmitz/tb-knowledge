# Account Hub password tests correlate events with entered values and verify backend results separately

The accepted IMAP password test waits for visibility, sets the remember-signons preference both ways, correlates input events with the full password value, checks a wrong-password notification and later waits for an account with the target identity email. A scoped testing recommendation is to assert the form state and eventual native account separately, rather than rely on a hidden subview as proof of successful creation. These are inspected assertions, not a rerun. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mail/test/browser.
