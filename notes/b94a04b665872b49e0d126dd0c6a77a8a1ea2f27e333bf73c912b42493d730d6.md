# The first outbound EWS folder rename had no callback for an outer async failure

The historical update_folder wrapper spawns a local task, awaits the request, and only logs an Err result. Its diagnostic incorrectly says delete folder. Successful UpdateFolder responses invoke the success callback and update local state, but an initial dispatch result does not report remote completion or this failure. The assigned callback interface has only success; UI failure feedback and recovery were not traced. Fixed code uses a generic operation/listener path, so this wrapper is historical evidence, not a current error-handling template. Link the existing remote-first rename lesson for the success and storage sequence. No live server, failure injection or UI test ran. Review: https://phabricator.services.mozilla.com/D243726

Scope: Historical EWS async completion.
