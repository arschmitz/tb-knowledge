# Reset every mailbox parser state when a colon opens a group

The colon fix builds a cleaned group name from displayName and then resets address, local-part, comment and spacing states before collecting group members. A partially parsed mailbox before that delimiter must not become the member address after it. Keep those state resets together when changing this parser. The security report and exact exploit context remain unread, so this is the tested parsing contract, not a claim that all spoofing cases are closed. This is static source evidence. No runtime, build, lint or live accessibility check was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Address header group parsing.
