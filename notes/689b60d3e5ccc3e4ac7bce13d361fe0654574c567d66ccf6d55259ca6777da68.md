# An unresolved explicit message account key stays visible instead of falling back to its folder

FetchAccount uses the containing folder only when the message account key is empty. If a nonempty key has no usable server, including a server of type none, it displays that literal key. A usable server still provides its pretty name. Account-column text and byAccount sorting share this helper; the change does not rewrite message headers or change reply identity selection.

Scope: message-account-column-key-fallback.
