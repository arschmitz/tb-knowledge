# Keep memory retention explanations distinct from Rust unsafe safety requirements

D210712 removed Safety labeling from a generic memory-leak comment; reviewer said leaks are not a safety issue. It retained and praised the concrete immutable XPCOM-reference explanation for cloning the OAuth result. Proposed manual comment rule: document the actual ownership constraint or memory cost, and reserve safety claims for unsafe invariants. This does not justify deleting useful ownership reasons or claiming all memory bugs are harmless.

Scope: rust/protocol_shared/src.
