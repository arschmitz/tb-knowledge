# The SMTP prompt test helper drains the event loop after starting a login save

The test promptPassword helper calls addLoginAsync and then spinEventLoopUntilEmpty before returning ok; it does not await or retain the login-save promise. The affected SMTP test separately supplies an async saved-login condition to TestUtils.waitForCondition. Its exact Promise-await behavior is an unpaired harness dependency, so these calls do not prove login-save completion or a timing fix. The four field/status assertions in the changed callback also lack message arguments. Keep the source calls, required diagnostic gap and execution limits explicit rather than making a general async-wait rule.

Scope: Mailnews prompt test login-save boundary.
