# MIME instance storage keeps placement construction and explicit destruction paired

This landing keeps PR_MALLOC/PR_Free storage while adding a type-specific placement constructor and explicit destructor to each MimeDefClass descriptor. mime_new zeroes storage, constructs members, assigns its class/header state and then calls MIME initialize. Both initialization failure and normal mime_free run the MIME finalizer, the C++ destructor callback and PR_Free in that order. The actual plain-text class embeds an nsCString and container cleanup calls mime_free for children. These are scoped source contracts, not a delete-based rewrite, complete audit of all MIME types, sanitizer result or proof about every partial-initialization path. Required private discussion remains denied/partial, and no compiler or parser test ran.

Scope: MIME parser object lifecycle.
