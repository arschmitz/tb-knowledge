# NS_IMETHODIMP distinguishes an XPIDL implementation from an ordinary C++ helper

The EWS rename review explains that NS_IMETHODIMP semantically marks implementation of an XPIDL interface method. The fixed ExchangeFolder::Rename uses it, while the extracted free LocalRenameOrReparentFolder helper returns nsresult. Use the declaration and actual interface role when choosing this spelling; the shared helper is not an XPIDL implementation simply because it returns the same result type. The suggestion to centralize methods on nsIMsgFolder was part of a broader unresolved design discussion, not an accepted requirement to move every helper there. Scope: the inspected rename helper and interface implementation, not all C++ result types. No compile test ran. Review: https://phabricator.services.mozilla.com/D243726

Scope: C++ interface implementation style.
