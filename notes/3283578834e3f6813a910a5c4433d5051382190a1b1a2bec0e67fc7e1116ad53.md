# A nested message has its own attachment part-number namespace

The 863 tests exercise an attached message as an external MessageHeader with its own API ID. Its getRaw content matches the bytes obtained through getAttachmentFile on its parent, but listAttachments on that attached message starts another part-number namespace. Current #parseMessage also removes the API root level when passing pruneat to jsmime. Manual naming and test proposal in these APIs: keep message IDs, message-id headers and partName strings distinct, and state which message owns a partName. Decoded tree size and serialized EML File size are different measurements; protocol-specific metadata can alter serialized size. This adds encrypted examples to the existing forwarded-message attachment lesson.

Scope: nested-message-part-names.
