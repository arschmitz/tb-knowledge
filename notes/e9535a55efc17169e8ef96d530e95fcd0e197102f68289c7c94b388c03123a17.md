# ListenerResult names the buffered future output without changing its shape

The historical cleanup introduces ListenerResult<T> for Result<(RefPtr<T>, ThinVec<u8>), nsresult> and uses it in poll_listener and Future::Output. The return still carries the interface reference and buffered bytes or a status error; pending and completion branches remain unchanged. This is a scoped type-name/readability change, not new streaming, readiness or cancellation support. The old crate path is absent at the fixed accepted revision, so it is historical evidence rather than a current API recommendation. No compiler or request test ran.

Scope: historical-xpcom-async-result-type.
