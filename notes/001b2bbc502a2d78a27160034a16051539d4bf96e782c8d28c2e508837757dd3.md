# Feed menu checks must be set in each popup context

The message header popup and global View menu own different document nodes. Each reads FeedMessageHandler.onSelectPref and updates its own ordered website, summary and per-folder radio items. The new feed browser test drives both real entry points. This augments the existing feed visibility lesson: a correct preference alone does not prove that a second menu shows the selection. Current checked state uses toggleAttribute and tests use hasAttribute. Manual review proposal for these menus: update and test the menu that the user actually opens; preserve the ordering that maps the preference integer to the item index. This is scoped to feed menus, not a general rule for all radio widgets.

Scope: feeds.
