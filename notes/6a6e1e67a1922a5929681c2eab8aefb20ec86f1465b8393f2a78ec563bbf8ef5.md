# Some copy-handler comments still name the old callback owners after the rename

The renamed folder-copy sequence still names FolderCreateCopyCallbacks, while the inspected implementation constructs ExchangeSimpleFallibleListener lambdas and calls OnFolderCreateFinished directly. The message-copy sequence still labels methods as MessageCopyHandler::... although the class declaration is ExchangeMessageCopyHandler. The same header blobs remain accepted. These are concrete comment/receiver mismatches; they do not imply a runtime failure or authorize unrelated wording changes.

Scope: Exchange copy handler documentation receiver accuracy.
