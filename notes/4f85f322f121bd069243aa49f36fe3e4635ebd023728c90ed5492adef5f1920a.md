# Separate notification icon roles from input status positioning

The accepted account-hub stylesheet gives .form-icon shared size, but limits absolute input positioning to .input-warning and .input-success. Within .notification-bar it hides the icons by default and shows the matching severity icon. Recommend preserving this scoped selector split when reusing an icon in a notification; a shared base class must not also impose the input-overlay layout. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
