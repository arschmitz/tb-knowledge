# Account-preference telemetry omits inactive dependent settings

The accepted collector adds check_time only when check_new_mail is true, NNTP max_articles only when notify.on is true, and POP retention details only within leave_on_server. The days field has its own delete_mail_left_on_server condition. For this metric, preserve the actual per-field conditions instead of emitting a value for every possible protocol preference. This is a scoped source recommendation; the existing test covers default POP3 and IMAP objects, not the active NNTP and nested POP branches. No telemetry test was run. Full Bugzilla and Phabricator discussion remains pending.

Scope: Account preference telemetry conditions.
