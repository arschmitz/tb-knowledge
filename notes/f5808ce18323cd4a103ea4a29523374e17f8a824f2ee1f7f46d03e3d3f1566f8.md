# Distinguish notification fetch completion from asynchronous controller update completion

The accepted updateNotifications method awaits default ID retrieval before manager update and saveSoon. The registered onUpdate callback does not return that Promise, and NotificationUpdater._fetch invokes onUpdate without awaiting it. Therefore successful _fetch or init completion is not source proof that controller cleanup/display update/save scheduling has finished. Recommend specifying the completion contract before a caller relies on it; no race or rejection was reproduced. These are fixed accepted source and test-code observations.
