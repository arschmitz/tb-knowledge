# Explain protocol sentinels at the repair boundary where they are serialized

The existing repair lesson already records resetting IMAP counts and UID validity while preserving view settings. The current caller additionally explains that the string "-1" is kUidUnknown and names nsImapMailFolder::UpdateImapMailboxInfo as the consumer. The current consumer compares stored UID validity with the server value and calls HandleUidInvalidation on a mismatch. Manual comment proposal for this boundary: name the protocol meaning and the consumer beside a serialized numeric sentinel, instead of leaving a bare magic string. Do not replace the value with a differently typed constant without checking the property-bag representation. Current source, not private review prose, supports this proposal; the cached review summary remains private and incomplete for replay.

Scope: imap-repair-comments.
