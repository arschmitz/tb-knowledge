# Keep the SecondaryCompare byId early return ahead of generic field lookup

Current SecondaryCompare compares message keys directly when already in secondary recursion or when secondary sort is byId, respecting the secondary ascending direction. The kU32 branch can then fetch fields without a redundant byId branch. Entry 737 removes that dead branch. Preserve the early return and isSecondarySort context flag when changing tie-break behavior; it prevents recursion and explains why the generic branch cannot handle byId.

Scope: mailnews/base/src.
