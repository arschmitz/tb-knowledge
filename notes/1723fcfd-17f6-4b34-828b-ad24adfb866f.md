# FreeBusy service provider fan-out, result meaning, cancellation, and direct checks

Production privileged JavaScript. Every local body in CalFreeBusyService.sys.mjs
was read. The exported singleton owns a strong Set of actual
calIFreeBusyProvider interface objects. Add/remove at 88–95 use QueryInterface.

`getFreeBusyIntervals`, 69–85, creates a group listener with provider count,
calls each provider with the same listener, and retains returned pending operation
handles in OperationGroup. No providers calls onResult(null,[]) immediately.
Provider calls themselves have no per-provider exception catch here.

`CalFreeBusyListener.onResult`, 35–50, decrements outstanding count when no
operation is supplied or it is no longer pending. Final count marks group
completed. Successful array results are forwarded; failure or non-array results
become an empty array. A child failure does not automatically become the group's
status. Result callbacks may occur while other providers remain pending.
Completion depends on provider callback behavior; matching count alone is not
a per-provider once guard against duplicate completion.

`notifyResult`, 24–32, clears the final listener before calling it if the group
is complete. Cancellation creates a null-result callback through the group's
cancel function. [OperationGroup cancellation order](a3e61d84-1dc0-47d3-9d1c-84f712e4b2f6.md) means
the consumer sees null before children are cancelled. Later callbacks are ignored
after final listener is cleared. No combined interval sorting/deduplication occurs
in this service. Consumers interpret each result array.

`calProviderUtils.sys.mjs:320–333` creates FreeBusyInterval with calId, CalPeriod
start/end, and provided type or UNKNOWN. Its QueryInterface method returns a
generateQI function; this read does not certify every interface conversion caller.

Direct tests: `test_freebusy_service.js:1–206` adds/removes mock providers through
the actual service, checks returned interval start/end/type, no-provider empty
result with status success, and failed-provider empty result with group status
success. Cancellation test queues provider work and cancels group; inside final
null callback it checks child cancellation has not happened yet. That assertion
directly verifies order, not post-return child cancellation completion. Tests use
controlled providers, so no real CalDAV network availability or all provider error
shapes are covered. No passing product run is implied.
