# OAuth cooldown is keyed by endpoint and checked before interactive transport selection

The three-second deadline is stored by authorizationEndpoint after the original external-open call returns. Unexpired cached access tokens and refresh-token exchange bypass this guard; interactive connection checks it before choosing a transport. Finishing a request clears its connection flag but leaves the cooldown. Accepted source retains the deadline in loopback ExternalRequest, while the later custom-scheme start method does not set it. Keep endpoint throttling, account identity, active-window locking and later transports separate. No timing or browser flow ran.

Scope: OAuth external-browser rate limiting.
