# LDAP connections no longer expose a protocol-version choice

The LDAP cleanup removes LDAPDirectory.protocolVersion and the version and closure arguments from nsILDAPConnection.init. It also removes version inputs from synchronous query, directory query, replication, certificate lookup, and their callers/tests. Thunderbird had stopped supporting LDAP version 2 in v102, so the apparent choice was dead. For current code, initialize LDAP connections with URL, bind name, and listener; do not revive a configurable protocol version without new support. The broad Bug 1851535 later lists an unrelated MessengerProfileMigrator registration regression; it is not evidence that this LDAP patch caused it.

Scope: LDAP address book.
