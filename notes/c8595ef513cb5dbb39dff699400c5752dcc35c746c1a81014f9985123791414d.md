# Derive descendant paths from the current parent chain after a move

Historical 1153 updated only the moved child in a stored path map. The accepted implementation has no path map: lookup resolves each parent/name component and getFolderPath walks cached current parents. moveFolderTo updates the moved folder parent and clears its ordinal after the database write. The current test also checks that the old path of a descendant stops resolving and the restored path resolves again. This avoids teaching the initial child-only map update as sufficient for subtree moves. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: Panorama move and path lookup.
