# Filelink generated labels remain separate from stable node identity

Accepted Filelink uses cloudAttachmentListRoot/Header/List/Footer DOM IDs and cloudfile-* metadata classes, while a retained paperClipIcon class uses older camel case. The compose placeholder now uses the same root/header identity as the inserted list. A scoped naming recommendation is to preserve those queried IDs and existing class contracts during markup cleanup; this mixed local history does not justify renaming every class to one case. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mail/components/compose.
