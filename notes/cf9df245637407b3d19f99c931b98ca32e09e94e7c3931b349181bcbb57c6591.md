# The copy-then-move count wait changes the refresh contract

The original test proposal replaces explicit updateFolderWithListener operations with waits for two local database headers in each destination. The fixture already awaits its copy listeners, and folderCount reads the message database. Accepted later source instead performs explicit refresh/listener waits and retains a timeout workaround. Passive count observation and requesting a folder update are different contracts; this historical proposal does not establish that refresh is unnecessary. Primary Bug comments 11 and 13 remain unavailable, so this source study has zero full-audit credit. No xpcshell or server test ran.
