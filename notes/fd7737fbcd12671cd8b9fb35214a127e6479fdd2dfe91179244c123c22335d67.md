# Mail-tab toolbar buttons inherit message-completion refresh from the base class

The base MailTabButton observes load and MsgLoaded, so SpamButton no longer repeats that event list and Reply to List uses the base customized button instead of a dedicated subclass. The template, required module and package entry change together. The base stores exact target/event/callback triples per tab, adds missing listeners, redirects message events to the inner message browser when present and removes listeners on tab close or disconnect. Each event calls the subclass's command-context method or the base command check. This is a scoped refresh and lifetime contract, not proof that every command needs both events or a measured performance result.

Scope: Unified toolbar mail-tab event ownership.
