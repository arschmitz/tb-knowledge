# IMAP move playback must set `nsMsgFolderFlags::OfflineEvents` from the operations still in the folder database before closing that database

IMAP move playback must set `nsMsgFolderFlags::OfflineEvents` from the operations still in the folder database before closing that database. Clearing the flag merely because one playback list was exhausted could leave newly queued moves unplayed and lose messages. The landed regression tests check what reached the server, in both message stores. https://phabricator.services.mozilla.com/D318396 and https://github.com/thunderbird/thunderbird-desktop/commit/9bdc099e6cefe74155e2d7c9043c8c691721d07a
