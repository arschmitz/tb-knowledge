# Check the floored day boundary and current identity in the OpenPGP expiry warning

The checked compose warning gets the openpgp_key_id attribute from gCurrentIdentity and removes the old notification before checking that key. It floors remaining seconds into days and returns only when the result is greater than 31. Thus a future expiry less than 32days away can show the warning; the summary phrase less than 31days is not the exact condition. The expired branch uses nowInSeconds > key.expiryTime, so equality takes the soon branch. The selected tests directly check expired, ten-day and non-expiring notification outcomes. They do not assert the 31/32-day boundary, exact expiry second, secondary-identity switch or button navigation. The button opens the first server for the current identity; exact identity-settings navigation was deferred in review. The direct identity-change caller does not await the async adjustment, so no atomic switch-completion claim follows. Bug 1840861 comment1 is missing. This is source-only knowledge, with no runtime test or completed audit credit.

Scope: Compose OpenPGP expiry warning.
