# Canceling export authentication keeps the QR workflow at the start

Entry 1211 returns from showCodes when password inclusion requires authentication and authentication returns false. It no longer silently changes includePasswords to false and advances anyway. The accepted handler retains that early return before QR initialization. For this action, cancellation stops the requested export rather than changing its contents implicitly. The two tests check that the start control remains visible; they were read but not run, so focus restoration and actual primary-password or operating-system prompts remain unverified. Full bug and review discussion remains pending.

Scope: Mobile QR authentication flow.
