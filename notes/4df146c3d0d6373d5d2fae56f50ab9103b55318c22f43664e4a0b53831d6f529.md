# Current batch compaction retries blocked folders in bounded rounds

The original 1617 design uses a 3000ms retry after a skipped folder. Fixed accepted StartNext instead moves blocked folders to mRetry, continues the other queued work, then schedules a 5000ms round. mAttempt is bounded by kMaxAttempts=5, after which outstanding folders receive NS_MSG_ERROR_BLOCKED_COMPACTION. Use the accepted round strategy when extending this scheduler; the old per-folder timing is historical, and no retry timing was measured. This is static source and test-code inspection. Full Bugzilla and review timeline and inline discussion remains pending. No runtime, build, lint or live accessibility validation ran.

Scope: Batch compaction retry architecture.
