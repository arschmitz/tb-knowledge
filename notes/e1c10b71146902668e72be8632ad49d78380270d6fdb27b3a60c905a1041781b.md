# Treat Account Hub busy state as controls and a delayed visual overlay

Email #startLoading shows an informational notification, sets busy, disables the current subview and footer, and schedules spinner after 3000ms. #stopLoading clears the notification, restores controls, clears the timer, and removes busy/spinner. CSS displays the overlay only for spinner and limits its reveal animation to prefers-reduced-motion: no-preference. For this flow, clean up both the control state and the delayed timer on success, failure and cancellation. Repeated concurrent starts were not validated and are not guaranteed safe by these methods. This is static source evidence. No runtime, build or accessibility session was run. Full bug and review discussion remains pending.

Scope: Account Hub loading lifecycle.
