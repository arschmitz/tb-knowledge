# The IMAP wait loop keeps wait failure and idle timeout distinct

The readiness wait records nsresult, breaks on a failed wait or idlePending, and later handles a pending interrupt error separately from idle processing. Idle entry additionally requires connected/selected state and the capability/user setting. Preserve these distinct exit reasons when simplifying the loop; the current source does not justify replacing it with a single readiness boolean. This is static source and test-code inspection.
