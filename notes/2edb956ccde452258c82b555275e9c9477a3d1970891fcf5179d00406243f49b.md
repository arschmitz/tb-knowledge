# Removing the mailbox parser class does not remove caller-owned folder locks

The removed nsMsgMailboxParser supplied unused stream-listener and path/lock machinery. Current nsParseNewMailState opens its database in Init, while POP3 BeginMailDelivery and the legacy AddMessageBatch manage folder semaphores themselves. Keep locking with the delivery owner when modifying this parser boundary. Old class names remain in a few comments; removal of a class does not prove all references or historical explanations vanished. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/local/src.
