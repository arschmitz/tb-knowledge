# Describe null and undefined separately in extension API schemas

Bug 1894193 came from downstream TypeScript definition generation. An optional callback parameter must be marked optional even though the schema validator had ignored missing markers. On a callback result or object property, optional: true means the value may be undefined or omitted; a returned null needs an explicit null choice. The patch changes account and message-list result schemas and many callback declarations. For example, messages.MessageList.id is string or null, while cloudFile.getAccount may return undefined. Read actual returned values before changing a schema; do not use optional as a substitute for a null union.

Scope: WebExtension schema contracts.

Paths:

- `mail/components/extensions/schemas/accounts.json`
