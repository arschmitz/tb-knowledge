# Explain nullable prompt arguments beside the unsafe call

The ConfirmEx call keeps its nsString owners alive, names the positional arguments inline and explains nullable arguments beside the unsafe block. Its flags choose string titles for buttons0 and 2 and the built-in Cancel title for 1, so the unused button1 title is null. The checkbox message is null to omit the checkbox. When writing a safety explanation for this call, identify the owner, the flag that makes a value unused and how long each pointer remains valid. Pointer null guards alone do not establish validity. This is a scoped accepted-source example and writing suggestion, not an upstream API proof or a claim that all unsafe calls use this format. No native prompt or memory-safety test ran.

Scope: Rust mailnews UI glue safety comments.
