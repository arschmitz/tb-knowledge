# Status service payload fields are not all processed together by the current consumer

Accepted FeedbackService broadcasts {statusMessage,meteors}, and compactor callers send a nonempty status plus start/stop-meteors. The window message handler processes a truthy statusMessage in an if branch and processes meteors only in its else branch. This is a scoped static integration limit, not a confirmed throbber failure: actual message delivery, other consumers and UI execution were not exercised. Do not claim both fields are always applied because both are emitted. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/base/src.
