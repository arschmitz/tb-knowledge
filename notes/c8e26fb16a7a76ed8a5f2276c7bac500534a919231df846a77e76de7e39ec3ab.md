# The OAuth scope retry keeps the retry result instead of reawaiting the rejected promise

The original non-expected-failure test path retries verification once after rejection and telemetry presence, then keeps that result in configOut for account creation. It no longer reawaits the original rejected promise later. Existing token/account assertions do not directly assert a retry count or timeout. The accepted test later retries the whole OAuth flow up to ten times after checking its result; that is a separate phase. No intermittent cure or OAuth execution was verified.

Scope: Account creation granular OAuth scope regression test.
