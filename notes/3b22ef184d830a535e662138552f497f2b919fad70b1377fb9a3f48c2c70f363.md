# EWS empty Basic values and optional authentication headers have different caller contracts

At the original test-extension commit, an empty Basic password returns an empty String. The same-revision client passes that value to header("Authorization", ...), despite the credential comment saying not to set the header. These two source facts do not prove that the HTTP request omits Authorization; lower-level serialization and wire behavior were not checked. The accepted later authentication provider uses Option<String>: Basic and NTLM return None, and the request builder adds the provider header only for Some. That later contract does not remove a header already supplied by the original request and does not prevent Necko authentication. Read both the credential producer and request consumer before treating an empty value as header omission. No network request, authentication dialog or native test ran; full external discussion is pending.

Scope: EWS Basic authentication value and request construction.
