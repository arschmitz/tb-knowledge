# MarkAsJunk uses a successful missing-ID result to request legacy resync

DoMarkAsJunk returns optional moved IDs. For a modern server it validates and returns MarkAsJunk IDs; for an older server it may perform MoveItem and return None when IDs require resync. The success adapter turns None into empty IDs with the legacy-fallback flag. Missing legacy destination on an old server is an error instead. The native callback treats fallback as a request to sync destination and source, rather than local ID reconciliation. Keep this successful resync state separate from operation failure and from a success callback that itself returns an error. No server, store or test was run.

Scope: EWS junk operation result mapping.
