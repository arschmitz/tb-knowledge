# FetchHTTP distinguishes pre-aborted requests from in-flight cancellation

fetchHTTP calls throwIfAborted before XHR setup when the caller supplies a signal. Its test expects the exact original reason and no server request. After the request starts, the abort listener cancels XHR and rejects; the test expects a ServerException with code -2, the original URL and the abort reason as cause. The accepted source retains both phases. These direct static assertions do not establish a fresh cancellation, network or test run.

Scope: mail/components/accountcreation.
