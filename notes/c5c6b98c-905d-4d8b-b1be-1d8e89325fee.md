# CalDAV autodetection orders DNS and principal requests then creates unregistered calendars

CalDavProvider.detectCalendars:45–132 checks requested OAuth scope/refresh token
when given OAuth2 auth method. It resolves location, creates CalDavDetector and
authorizes the initial password site. The sequence is Google OAuth, explicit
location, DNS SRV/TXT, well-known, root. Each is awaited before the next starts;
the dynamic detector[method] target is resolved to these actual class methods.
Detection/auth/cert/canceled errors stop the sequence; other errors are logged
and the next method tried. A truthy result is returned, so [] would also stop
fallback. Location conversion is called with location alone; empty-location
username inference needs a caller-supplied location or explicit contract fix.

CalDavDetector:143–449 owns one DetectionSession. attemptLocation skips root.
dnsSRV:168–224 only runs for root, chooses _caldav/_caldavs based on HTTP scheme,
sorts priority ascending and weight descending and uses the first SRV record.
It adds that target's password site, tries first TXT path= value, then well-known
at target if no calendars. It does not loop all SRV targets or randomly apply
weights. attemptGoogleOauth:255–273 checks known host/MX then uses configured
username in Google calendar URI. DNS.srv/txt/mx call actual singleton worker
through DNS.lookup; worker/native platform parsing is a separate source pass.

detectCollection:284–329 uses PROPFIND and response's actual final URI. Auth errors
throw; non-ok returns null. Calendar resource produces one object. Home-set
property takes precedence over current principal, then owner. handlePrincipal:
340–373 sequentially searches all returned home sets and collects results.
handleHomeSet:385–413 uses Depth1 PROPFIND and keeps entries with C:calendar.
Missing resource-type Sets are not guarded in every path. Request/response-class
behavior is reused from the checked CalDAV network pass, including failed setup.

handleCalendar:425–448 chooses display name/fallback decoded URI, strips an
eight-digit hex alpha suffix from color, creates calendar, assigns color/name/ID/
username and installs a fresh base session. It derives readOnly from actual
privilege Set. It returns an unregistered object; the dialog/Account Hub later
registers selected objects. Detection success does not itself start account
subscription or prove remote item reads succeed.

Direct browser testDNS:27–60 checks requested SRV/TXT names and UI calendars,
