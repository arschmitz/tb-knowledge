# The IMAP noselect teardown drains pending thread events after stopping the fake server

The teardown processes the current thread while hasPendingEvents is true after stopping its fake server. It adds no fixed deadline, later-timer check or result assertion. Accepted code retains the drain while separately changing the preceding server check. Treat this as a local cleanup sequence, not proof of a timeout cure or global event-loop quiescence.

Scope: IMAP unit-test teardown completion.
