# S/MIME usage mapping must match the certificateUsage family passed by its callers

Fresh complete two-case correction, whole historical implementation and needed public callers read. CheckUsageOk accepts SECCertificateUsage; the signing/encryption wrappers already pass certificateUsageEmailSigner/Recipient. This landing changes switch labels from the different certUsage* family to the same certificateUsage* family, then maps to VerifyUsage::EmailSigner/Recipient. It does not change the cert-verification policy. Fixed0b93 preserves this corrected family. Integer-equivalent type/compiler limitations are attributed reviewer rationale; underlying NSS numeric definitions were not newly inspected. Existing local-verification and result-status behavior are separate. No certificate or build test ran.

Scope: S/MIME certificate usage mapping.
