# Successful scheduling is different from successful Exchange folder creation

The Rust XPCOM bridge rejects empty parent_id/name, then spawns a detached local task and returns Ok. The current IExchangeClient contract describes asynchronous operations with listeners. Preserve the listener as the completion/error boundary; a synchronous successful call only says the operation was accepted for work. Current safe listener wrappers replace the old direct callback RefPtr path. Static source and test-code inspection only. Full Bugzilla and Phabricator timeline and inline discussion remains pending. No runtime or live accessibility result is claimed.

Scope: Exchange asynchronous completion.
