# Test cleanup without try/finally

This is deliberate user-directed guidance for test changes. It is separate from
automatic source learning.

Do not add `try/finally` blocks to tests. Use the test harness setup and cleanup
hooks. Register cleanup before setup can fail. Use separate cleanup callbacks
when one failed action must not prevent another cleanup action. Preserve
unrelated existing tests.

## Scope and evidence

This adds the test-cleanup rule to the
[practical code-style guide](08ac54d5-331d-4ab5-bc8f-6120318565a3.md).
The rule applies when writing or changing tests. It does not create a general
ban on `try/finally` in production code. Automatic learning must not change it.

Thunderbird browser tests run registered cleanup callbacks separately. The
browser-chrome harness in `testing/mochitest/browser-test.js` catches a callback
failure and continues with the remaining callbacks. Check the actual harness
for other test types. Do not assume that all harnesses have this behavior.

## Validation and limits

The browser-chrome cleanup loop was inspected in the Gecko source paired with
D332509 verification. The new rule is a user instruction, not a conclusion from
source counts or a claim that existing tests already follow it. The original
style study and its coverage limits remain unchanged.
