# Secret-key tests distinguish password failure from protected storage

The checked secret-key unit test first rejects a wrong password, then imports with the right password and checks secret availability. It also imports protected and unprotected fixtures and asserts that the resulting RNP store has protected keys and zero unprotected keys. These assertions cover password and storage protection; they do not test permissive malformed public input or every import exception path. This is static source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.
