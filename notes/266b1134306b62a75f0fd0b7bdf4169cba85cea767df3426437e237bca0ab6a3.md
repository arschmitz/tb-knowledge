# Re-fetch the Calendar event box after scrolling before returning it

The historical test helper retains one eventBox, scrolls it, then waits for that object to have nonzero dimensions. The selected fixed helper instead calls weekView.getEventBoxAt inside the wait, checks the current box with BrowserTestUtils.isVisible, and returns that current object to openAndShowEvent. The source comment explains that scrolling can recycle or re-render the box. This is a scoped fixture object-lifetime contract, not proof that all geometry, viewport tolerance or native dialog failures are fixed. The review later abandons the old patch after a reported fallback conflict, and Bug 1966578 comments5–8 are unavailable. This remains source-only knowledge with zero full-audit credit; no Calendar test ran.

Scope: Calendar fixture event-box lifetime.
