# Verified chain: keyboard Calendar Save to state, storage, closing, and tests

Scope: Thunderbird Calendar. Language: JavaScript. Production runs in privileged application documents and calendar modules. Browser and xpcshell tests have different harnesses. The provider traced for storage is memory, not CalDAV.

| Step | Checked relationship and stable anchor |
| --- | --- |
| Trigger | The browser task `test_keyboardSaveSelectedCalendarAndUndoRedo` focuses Save and synthesizes Enter. `connectedCallback()` registers the dialog object as the Save button's click listener. |
| Handler | `customElements.define()` registers this exact class as the customized dialog element. `handleEvent()` handles click by starting `save()`. In create mode, `save()` calls the imported `saveCalendarEventCreate()` with a closure around the host's `doTransaction("add", ...)`. |
| State | Save reads the create/edit session and draft, takes a snapshot, assigns a request ID, and dispatches pending. Validation updates section results. Matching kind/request guards control failure, release, and success. |
| Storage | Host `doTransaction()` constructs `CalAddTransaction`, calls the chosen manager's `commit()`, then updates the undo/redo menu outside a batch. `commit()` adds the transaction to undo history, awaits its work, and removes only that transaction if it fails. |
| Provider | `CalAddTransaction.doTransaction()` awaits `calendar.addItem()`, calls `_dispatch()`, and stores the returned item. `CalMemoryCalendar.addItem()` clones the item and calls `adoptItem()`. Adoption checks read-only state and ID, stores an immutable parent item in `mItems`, sends `onAddItem`, and resolves with the item. |
| Consumer | Current Save completion dispatches success. The dialog's `handleStateChange()` schedules closing and checks the request and baseline again before clearing the route and draft. The menu consumes transaction history; calendar observers consume the added item. |

## Async and ownership contract

The click handler does not await the promise itself. Save owns the pending state and error conversion. The host owns the transaction path. The manager retains the transaction in undo history. The memory provider retains the stored parent item. The dialog retains its listeners on its own DOM nodes; it registers them only once with `hasConnected`.

Closing and native dismissal are blocked while Save is pending. A stale result prevents changes to a replacement dialog session; it does not roll back a provider write that already completed. The request ID is valid for that pending request. The retained baseline object identity is valid until the draft is reset or replaced.

The source mixin's `disconnectedCallback()` disconnects the route controller, clears route start state, and clears route data. A DOM-owned listener is different from a global observer. This study did not prove the full release of every inherited store subscription or every pending callback.
