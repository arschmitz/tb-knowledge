# A new selection during message loading cancels saved-selection restoration

The select handler forgets saved state while allMessagesLoaded is false unless _selectionIsBeingRestored is true. restoreSelection brackets its own onSelectionChanged call with that flag, so its synthetic notification does not cancel the saved state it is using. The test change only renames cleanup calls; it adds no direct partial-loading/user-selection regression. Minimum test coverage: load a folder in stages, change selection before the final load, and check later rows do not restore the old selection; also check restoration notifications keep saved state when discard is false. Preserve the guard at the event boundary, including when the message pane is collapsed. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: Thread tree saved selection during incremental loading.
