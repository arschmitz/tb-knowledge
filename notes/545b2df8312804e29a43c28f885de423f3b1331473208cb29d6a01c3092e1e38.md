# The original AccountHub listener forwards an unresolved refresh-token promise

At the original import revision, AccountHub.onServerLoaded calls getRefreshToken without await, tests the promise for truth and passes it as detail.token to fire.async. The event schema requires token to be a string, while the actual native getRefreshToken method is async and awaits login lookup. This is a static promise-versus-string mismatch at the real receiver/caller boundary. Accepted AccountHub source makes onServerLoaded async and awaits the token before the empty-token guard and event. The original comment about a token already being stored does not make lookup synchronous. No account-creation or event-validation failure was executed.

Scope: Thundermail AccountHub incoming-server listener.
