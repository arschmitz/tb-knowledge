# The OpenPGP text extractor selects the first block of the requested type

Entry 2043 extracts getKeyBlock(contents, wantSecret) from the file reader and uses it before URL/clipboard previews. It repeatedly locates armor, skips a wrong block type and returns the first wanted block using inclusive offsets. No wanted block returns an empty string. The async file wrapper maps read failure to empty input and resolves to that same string; its current @returns {string} tag omits the Promise<string> wrapper. Document the two distinct contracts: the text helper is synchronous, while the file helper completes after I/O. This is extraction of a block, not just trim(), and it does not promise every public block is returned. Static source and test inspection only. No Thunderbird runtime, build, lint or live accessibility check ran. Full Bugzilla and Phabricator discussion remains pending-single-browser-reader.

Scope: OpenPGP public/private key block extraction.
