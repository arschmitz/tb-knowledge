# The nsMsgProtocol sink removal leaves IMAP transport-status forwarding in place

This cleanup removes nsMsgProtocol's nsITransportEventSink interface, OnTransportStatus implementation and null-sink teardown after its old OpenNetworkSocketWithInfo registration path was removed earlier. Accepted nsMsgProtocol still handles file transport closure and channel notification callbacks. IMAP still derives from the base and separately installs nsImapTransportEventSink on its socket transport; that sink forwards to its proxy. Keep the retired base callback separate from this active IMAP registration. The change does not establish that Thunderbird has no transport-status reporting or that all related cleanup in the umbrella Bug is unreachable. No replacement callback or tests were added by this entry.

Scope: mailnews/protocols/transport-status.
