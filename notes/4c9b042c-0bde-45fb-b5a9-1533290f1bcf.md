# Page EWS changes and fetch only header fields before advancing sync state

The 2024 client calls SyncFolderItems with IdOnly and at most 100 changes, then fetches unique message IDs with GetItem in batches of 10. GetItem requests selected header fields instead of Default, which includes bodies that the message list would discard. After committing a batch, it saves the returned sync state; when interrupted, the next refresh can resume near that batch. It loops until includes_last_item_in_range. This is a network and recovery contract, not just a data conversion helper.

Scope: EWS message sync architecture.
