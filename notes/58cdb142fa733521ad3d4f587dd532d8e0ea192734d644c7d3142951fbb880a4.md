# Distinguish notification fetch rejection from its retry scheduling outcome

The accepted updater returns false without scheduling when the URL is empty or about:blank. Offline, policy and missing-callback restrictions schedule another attempt; HTTP, JSON or synchronous callback failures use the fallback retry path. A false return alone therefore does not say whether another attempt is pending. Preserve these exit meanings when changing startup callers. Existing knowledge separately covers the owned pending timer and clearing its handle before a fetch. Static source inspection only; no runtime, build, lint or live accessibility validation. Full Bugzilla and Phabricator discussion remains pending.

Scope: In-app notification timer ownership.
