# Check the required XPCOM interface separately from object presence

762 sets msgWindow.statusFeedback only if the progress object implements nsIMsgStatusFeedback. An nsIMsgProgress annotation or a non-null object does not establish this additional interface. Proposed scoped JavaScript rule: use optional chaining for an optional member access and an interface check for interface-specific behavior; they solve different contracts. This augments the earlier optional status-feedback boundary lesson, without prescribing instanceof for every object.

Scope: Compose progress interface boundary.
