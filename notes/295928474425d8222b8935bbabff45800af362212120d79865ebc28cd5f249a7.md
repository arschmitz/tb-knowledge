# Exchange custom-header filters keep aligned message/header arrays and a NUL-buffer contract

Incoming Exchange filtering carries each new message key with its IHeaderBlock. When full bodies are required, the queue can hold null and waits for offline content; header-only filters can run without a body download. ApplyFilters accepts an empty header array or one aligned with the message array and rejects a nonempty length mismatch. The common executor converts supplied fields to NUL-delimited name/value strings because the filtering body reader consumes that format. Preserve those index, lifetime and serialization contracts when changing the queue or API; a database header alone need not retain arbitrary server headers.

Scope: Exchange arbitrary-header filtering.
