# Distinguish extension IDs, database keys and internal message identifiers

The tracker maps extension IDs to internal folder/key identifiers and has a reverse map. A delayed IMAP key change can swap two keys, record the mirror update as pending, replay a multi-step sequence and discard a no-op. Decoupling removes reverse/cache entries while preserving the ID-to-identifier entry that was just remapped; full removal deletes both maps. Manual naming proposal for this tracker: retain messageKey, headerMessageId and id as separate namespaces, and names such as idAssociatedWithOldKey when mapping roles would otherwise be unclear. Static inspection supports this component scope. No runtime test was run for this lesson, and full Bugzilla and Phabricator discussion is still pending.

Scope: mail/extensions/message-identity-names.
