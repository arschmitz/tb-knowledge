# The search override caller gates default changes on canChangeToConfigEngine separately from installation

The historical port reads canChangeToConfigEngine instead of canChangeToAppProvided and aligns comments with the config-engine role. A true value awaits setDefault(engineName,true); a separate canInstallEngine flag decides whether to return or install an engine. Current Thunderbird caller retains that separation through a later imported SearchService. The shared claim is this caller flow, not every upstream allowlist/config decision or a fresh successful override. No engine, prompt or test operation ran.

Scope: WebExtension search override result fields.
