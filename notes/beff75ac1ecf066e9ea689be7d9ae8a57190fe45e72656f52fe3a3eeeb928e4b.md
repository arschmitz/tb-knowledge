# The EML remote-content test action and its final completion wait use different windows

checkEMLMessageWindow obtains aboutMessage from the newly opened standalone window, checks blocked image state, awaits showRemoteContent and checks allowed state before closing. showRemoteContent performs its menu and notification actions on that passed aboutMessage, but its final wait_for_message_display_completion call passes the global window. The checked helper resolves the message browser from its win argument. Therefore that final shared wait does not itself establish that the standalone browser finished reloading. The fixture later checks image dimensions after an animation frame; this is a separate state observation and does not prove no network attempt. This is a scoped source-level completion-contract gap, with no reproduced timing failure or new runtime result.

Scope: mail/test/content-policy.
