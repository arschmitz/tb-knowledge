# The success fallback currently passes a different state shape

The accepted no-resource success path calls setState(this.#account), but the discovery catch calls setState(this.#currentConfig). The success component reads this.#account?.incomingServer for Account Settings. This is a branch-specific static shape concern: the catch does not show the same created-account contract. Its exact runtime settings selection, error reachability and user effect were not reproduced, and the inspected happy-path browser test does not exercise this catch. Do not attribute a crash cause or claim a repaired branch. No test, build or runtime operation was run. Full Bugzilla and Phabricator discussion is pending; source adoption does not establish reviewer approval.

Scope: Account success catch state-shape validation.
