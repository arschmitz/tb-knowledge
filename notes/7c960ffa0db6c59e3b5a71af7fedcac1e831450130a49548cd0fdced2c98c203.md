# EWS subtree updates need explicit copying beyond the local-folder store recursion

The 1956568 landing handles a server-driven rename/reparent by copying each folder and its children, then deleting the source subtree. The old store CopyFolder only recurses when its destination supports nsIMsgLocalMailFolder; an ordinary Exchange folder does not gain that behavior from the method name. Review first tolerates a future store refactor, then the author finds a hierarchy failure and adds the explicit recursive path and tree test before landing. Fixed source moves this logic to LocalRenameOrReparentFolder. Tests directly check names, membership and EWS IDs; the requested sync-token check is not present in the checked tasks. No complete data-copy, rollback, crash-safety or runtime result is established.

Scope: EWS local subtree update contract.
