# Calendar bounded streams: count, buffering, closure, and consumer cancellation

Production privileged JavaScript. Every local body in
`CalReadableStreamFactory.sys.mjs` was read, including source callbacks.
This records implementation behavior beyond the structural function map.

`CalBoundedReadableStreamController`, 70–213, retains the underlying source,
native controller, item buffer and counters. `maxTotalItemsReached` means count
of flushed items reached a nonzero maximum. Maximum zero is unlimited.
`queueFull` compares buffer length to the configured item threshold. desiredSize
proxies the native controller; queueFull is not a native backpressure decision.
Start and pull await the matching source method with this wrapper as receiver.
Cancel marks `_closed` and awaits source.cancel(reason), if present.

`enqueue`, 156–167, flushes a full buffer, skips additions after maximum count,
adds items, and flushes when threshold is met. `flush`, 176–189, truncates the
buffer to remaining count, enqueues one array chunk, increments count, clears
buffer, and closes the native controller at the maximum. It does not set
`_closed` there and does not cancel the upstream source when the maximum is met.
`error` marks closed and calls native error. `close`, 204–212, flushes remaining
items, marks closed, then calls native close if it thought it was open.

If flush reaches the maximum, subsequent explicit wrapper close can call native
close again. The same can happen when close's forced flush itself hits the limit.
A controlled exact-source Node experiment observed TypeError on the second close.
The pinned Gecko controller checks likewise reject close-requested/closed state;
that native evidence is in the reader/controller relationship note. Node is not
a Gecko product run. `enqueue` has no `_closed` guard, so cancellation/error
does not itself stop producer code from attempting later native enqueue.

Factories at 235–307: generic passes the source directly to ReadableStream;
empty closes immediately; combined reads source streams one at a time and
forwards chunks; mapped awaits one mapping result per chunk and enqueues it.
Combined/mapped use async start and have no explicit upstream cancel handler.
A rejected read/map rejects source-start; completion means sources were read
to exhaustion and output controller close was called, not that consumers have
already consumed every queued chunk.

Actual producer: `CalMemoryCalendar.sys.mjs:389–454` accumulates matching items,
enqueues once and explicitly closes. Its final close interacts with bounded
automatic closure. Actual consumer utility `calIteratorUtils.sys.mjs:217–244`
flattens chunks in mapStream/streamToArray or returns the custom iterator.
Changing chunk shape, maximum enforcement or close behavior affects provider
query results and cached sync, not just this factory test.

Direct tests: `test_calreadablestreamfactory.js:17–199` checks bounded item totals,
array chunk sizes and buffering, overflow truncation, sequential combined output,
mapped values, and empty stream. Bounded test sources enqueue without explicit
close after reaching their limit. The tests do not directly check that second
close boundary, native reader release, upstream cancellation, mapping rejection,
or source failure. A green result would not establish those missing properties.
