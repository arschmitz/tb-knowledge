# Calendar provider transitions own alert lifetime and recovery tests observe both completions

Providers decide when a failure is new and when the same calendar ID is restored; the notification module has no deduplication cache. ICS closes on stream success before document processing, while CalDAV closes after finding a valid calendar resource in its disabled state. Cached/uncached scenarios assert refusal alerts and wait for both onLoad and mock closure before checking NS_OK. The mock permits the null listener passed by production. These tests do not establish every error/repeat case or native notification behavior.

Scope: calendar-connection-alert-state-and-recovery-tests.
