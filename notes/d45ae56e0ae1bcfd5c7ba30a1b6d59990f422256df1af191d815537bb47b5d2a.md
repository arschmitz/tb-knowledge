# StoreIndexer attaches parsed headers without notifications and only warns on an attach failure

At the end of a scanned message, StoreIndexer sets parsed metadata, calls AttachHdr with notify false and receives a live-header out parameter. The interface permits different detached and live header objects; legacy Mork same-object behavior is separate. This caller does not use the returned handle afterward. If AttachHdr fails, the checked code logs a warning, clears per-message parser/token state and returns NS_OK. These are exact caller and error-reporting facts, not a recommendation to suppress errors or proof that every rebuild failure reaches its caller. No changed test or scan ran.

Scope: Message-store summary reconstruction completion.
