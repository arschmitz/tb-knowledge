# Keep omitted, null and empty FCC values inside the permission guard

Current MV3 setter uses strict null to restore defaults, empty string for nocopy://, and truthy IDs for folder overrides. Entry 523 keeps those meanings inside accountsRead. The extension tests explicitly pass undefined to reset. The schema declares these optional keys as omit-key-if-missing, with no default. Local Gecko ObjectType.checkProperty maps a present null or undefined optional key to its default, null, while an absent omit-key-if-missing key stays absent. Its async stub normalizes before forwarding arguments; the accepted comm wrapper then forwards details unchanged to setComposeDetails. This explains the test and direct setter at the inspected local binding revision. The fixed comm .gecko_rev.yml does not pin GECKO_HEAD_REV, so that exact Gecko pairing and runtime behavior remain unverified.

Scope: mail/components/extensions/parent.
