# Check scalar key validation when replacing a header pointer parameter

MarkNotNew now takes nsMsgKey but still uses NS_ENSURE_ARG_POINTER(aKey). The IDL declares nsMsgKey as unsigned long and documents 0xffffffff as an unavailable-key placeholder. Recommend checking the exact allowed key domain and using a scalar condition when changing this method. The pointer-style spelling is a static concern; this study did not prove whether a zero key is valid for a particular caller or reproduce a failure. This is source and test-code inspection. Complete Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/db/msgdb.
