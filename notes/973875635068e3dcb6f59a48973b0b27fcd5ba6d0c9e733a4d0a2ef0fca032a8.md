# POP stream copying separates unfinished-write discard from finalized-token cleanup

WriteMsgFromStream guards an unfinished write with DiscardNewMessage. After FinishNewMessage succeeds, it releases that guard, writes the token and copied-byte size into the header, and attempts DeleteStoreMessages if those header updates fail. The token deletion result is ignored, so this is an explicit recovery attempt rather than guaranteed rollback. The accepted implementation retains this ordering.

Scope: POP destination store writing.
