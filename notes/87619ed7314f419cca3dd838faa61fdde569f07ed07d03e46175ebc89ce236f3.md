# Certificate testing keeps an existing override distinct from a failed connection

The widget uses exception-exists for a stored host/port override and retains that state after a successful probe when an override is present. Its CSS uses warning tokens and its message stays neutral: an exception exists. The corresponding test expects fetch/remove actions before probing and view/remove afterward. This state does not identify the exact certificate used by a later connection or prove account authentication.

Scope: certificate-check-state.
