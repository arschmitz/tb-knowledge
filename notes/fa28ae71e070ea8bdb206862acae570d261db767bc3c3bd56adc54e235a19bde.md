# Restore help text descriptions after clearing a select warning

AccountHubSelect gives the warning priority over help text when syncing aria-describedby, then uses the help text ID or removes the attribute when no description exists. Recommend keeping this reversible description ownership in the component; simply removing the warning text without restoring the other description changes the native control's accessibility relationship. These observations are scoped to the cited accepted source and historical changes. Full Bugzilla and historical review timeline/inline discussion remain pending. No Thunderbird runtime, build, lint or live accessibility check was run.

Scope: mail/components/accountcreation.
