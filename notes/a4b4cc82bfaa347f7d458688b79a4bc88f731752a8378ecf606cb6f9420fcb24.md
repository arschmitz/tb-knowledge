# The state-management guide scopes shared frontend data to one page instance

The frontend guide recommends one shared store per page, with frequently reused controls keeping instance-local state and receiving document state through attributes or methods. It explains why a globally shared system module could couple tabs. This is documented design intent, not verified page isolation or adoption. The examples need correction against the actual constructor and declared identifiers; they are not tested recipes. This study leaves deliberate project instructions unchanged.

Scope: state/documented-scope.
