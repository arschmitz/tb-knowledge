# Parallel custom-header metadata needs a shared length and reset contract

Accepted parser construction sets m_customDBHeaderData length to m_customDBHeaders length. Parse and finalize assert the pair stays synchronized; lookup checks explicit nsTArray<nsCString>::NoIndex. Clear resets each data value and length along with the header buffers. This is a scoped manual recommendation for these parallel arrays, not a general assertion that a debug check makes release indexing safe. This is static source and test-code inspection. Full Bugzilla and historical review timeline/inline context remain pending. No Thunderbird runtime, build, lint or live accessibility validation ran.

Scope: mailnews/local/src.
