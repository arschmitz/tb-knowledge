# Refresh QR account data without registering duplicate observers

init calls showIntro on each entry, then uses initialized to register listeners and the account preference observer only once. The observer defers repopulation so a newly added account can finish appearing, and unload removes the observer. Preserve the distinction between refreshing pane data and registering lifecycle hooks. The source comment justifies this timeout at the account-addition boundary; it does not establish a general rule to replace event waits with timers.

Scope: mail/qrexport/pane-lifecycle.
