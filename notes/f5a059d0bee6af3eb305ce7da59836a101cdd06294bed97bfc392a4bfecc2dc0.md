# Cache shipped notification IDs separately from notification objects

OfflineNotifications fetches branding-specific JSON and caches only its ID Set; notification objects belong to the primary storage system. Non-OK or thrown fetches return an empty array, and the ID accessor can cache an empty Set if none was initialized. Preserve this distinction when changing startup defaults. In a failed-fetch path, that empty cached Set is a fallback assumption, not proof that branding has no notifications. These are fixed accepted source and test-code observations.
